# 모듈 Spec

2층 문서 — 모듈 하나의 명세다. 모듈 공개 인터페이스(시그니처 포함) · 이벤트 계약, 규칙 · 불변식, 작업 · 리스너, 데이터, 설정, 외부 의존, 모듈 용어를 담는다. 문서 위계는 [docs/README.md §1](../README.md#1-문서-위계)에 있다.

- **담는 것**: Spec 목록(§1), 모든 Spec 이 따르는 공통 구조(§2), 쓰는 규칙(§3)
- **담지 않는 것**: 모듈 사이의 의존과 이벤트 흐름([overview.md §5](../overview.md#5-모듈-지도)), 여러 모듈 · 화면이 쓰는 용어([overview.md §8](../overview.md#8-용어)), 판단의 이유([adr/](../adr/README.md)), 개발 인프라 · 운영 문서([development/](../development/README.md) · [operations/](../operations/README.md))

## 1. Spec 목록

Spring Modulith 모듈(`net.yozmnews` 바로 아래 패키지) 하나가 Spec 하나(`{모듈}.md`)를 갖는다.

| 모듈 | Spec | 책임 |
|---|---|---|
| `article` | [article.md](article.md) | 같은 기사 판정 · 중복 제거, 기사 저장, 피드별 기록, (미구현) 본문 추출 |
| `source` | [source.md](source.md) | 소스 등록 · 켜기 · 끄기, 수집 일정, 피드 요청, RSS 정규화, 새 항목 발행 |

## 2. 공통 구조

모든 Spec 은 아래 아홉 절을 같은 번호로 갖는다. 담을 것이 없는 절도 제목을 남기고 "해당 없음"이라 적는다. 그래서 `docs/specs/{모듈}.md §n` 은 모듈과 무관하게 같은 종류의 지식을 가리킨다 — 코드 주석이 이 표기로 Spec 의 절을 가리킨다. 절 제목은 `## {번호}. {절 이름}` 이고, 절 안은 하위 제목으로 나눠도 된다.

| § | 절 | 담는 것 | 담지 않는 것 |
|---|---|---|---|
| 1 | 책임과 범위 | 모듈의 책임을 펼친 서술, 이 모듈이 하지 않는 것 | 다른 모듈과의 의존(→ [overview.md §5](../overview.md#5-모듈-지도)) |
| 2 | 용어 | 이 모듈 안에서만 쓰는 용어 | 여러 모듈 · 화면이 쓰는 용어(→ [overview.md §8](../overview.md#8-용어)) |
| 3 | 공개 인터페이스 | 모듈 최상위 패키지의 공개 타입 · 이벤트 — 선언(Java 코드 블록)과 필드 · 상수의 의미 · 제약, 이벤트의 발행 주체 · 시점 · 횟수, 소비자가 기댈 수 있는 것. 공개 타입이 없으면 없다는 사실. 모듈이 내는 HTTP 엔드포인트(경로 · 메서드 · 용도) | 내부 타입 · 비공개 시그니처(→ Javadoc), HTTP 요청 · 응답 형식(→ `api/openapi.json` — [ADR-0020](../adr/0020-screen-api-contract-from-committed-openapi-spec.md)) |
| 4 | 규칙과 불변식 | 입력이 무엇을 뜻하는지 정하는 규칙(정규화 · 판정 · 상태 전이 · 일정 · 검증)과 정본 상수의 값. 항목마다 식별자(§3 규칙 2) | 알고리즘 상세 · 클래스 구조(→ Javadoc), 판단의 이유(→ ADR 링크) |
| 5 | 작업과 리스너 | 모듈이 가진 반복 작업 · 예약 작업 · 이벤트 리스너 · 기동 시 동작 — 계기 · 주기 · 멱등성 · 겹침 방지 · 실패 처리 · 트랜잭션 경계 | 작업 프레임워크 설정(→ 개발 인프라 · 운영 문서) |
| 6 | 데이터 | 모듈이 가진 테이블 — 주요 컬럼 · 의미 · 제약의 뜻 · 다른 모듈을 가리키는 ID | 컬럼 타입 · 인덱스 · 제약 문면(→ Flyway 마이그레이션), 모듈 사이 관계 · 보존 정책 · 프레임워크 테이블(→ [data-model.md](../data-model.md)) |
| 7 | 설정 | 모듈이 읽는 설정 키와 그 값이 바꾸는 규칙 | 환경 변수 표 · 값 예시(→ 운영 문서) |
| 8 | 외부 의존 | 포트(외부 의존 인터페이스) · v1 구현 · 로컬 대체물, 신뢰할 수 없는 입력과 그 방어 규칙의 식별자(규칙 자체는 §4 — §3 규칙 2) | 라이브러리 버전(→ `backend/build.gradle.kts`) |
| 9 | 결정 | 이 모듈의 설계를 정한 ADR 목록(번호 · 한 줄) | ADR 본문의 반복 |

## 3. 쓰는 규칙

1. **경계** — 공개 인터페이스(§3 절)는 Spec 이 정본이고 코드는 Spec 을 따른다. 코드의 선언은 그 사본이다 — 공개 인터페이스를 바꾸는 변경은 Spec 과 코드를 함께 고친다. 내부 상세는 Javadoc 이 정본이다. 판단의 이유는 ADR 이 갖고 Spec 은 번호로 가리킨다
2. **규칙 식별자** — §4 의 항목마다 항목 머리에 식별자 `{모듈}-R{번호}`(예: **source-R12**)를 단다. 번호는 Spec 안에서 1 부터 늘고, 지운 규칙의 번호는 다시 쓰지 않는다. §5 · §6 · §8 의 동작 · 제약 가운데 지켜야 하는 불변식(멱등성 · 겹침 방지 · 고유 제약의 뜻 · 입력 방어 등)도 §4 에 규칙으로 쓰고, §5 · §6 · §8 은 그 식별자를 가리킨다. 테스트는 자기가 지키는 규칙을 이 식별자로 가리킨다 — 테스트 쪽 표기 형식은 코드 주석 규칙이 정한다
3. **미구현 표시** — 아직 코드가 없는 항목은 항목 앞에 `**(미구현)**` 을 적는다. 그 항목을 구현하는 변경이 표시를 지운다. 구현된 것과 아닌 것이 한 문장에 섞이면 미구현 부분을 떼어 별도 항목으로 표시한다
4. **현재 상태 · 자기완결 · 상대 링크 · 절 번호 유지** — [docs/README.md §4](../README.md#4-작성-규칙)를 따른다
