# 모듈 · 화면 Spec

2층 문서다. Spring Modulith 모듈(`net.yozmnews` 바로 아래 패키지) 하나마다 모듈 Spec 하나(`{모듈}.md`)가 있고, 프론트엔드에는 화면 Spec 하나(`web.md`)가 있다. 문서 위계는 [docs/README.md §1](../README.md#1-문서-위계)에 있다.

- **담는 것**: Spec 목록(§1), 모든 Spec 이 따르는 공통 구조(§2), 쓰는 규칙(§3)
- **담지 않는 것**
  - 모듈 사이의 의존과 주고받는 이벤트: [overview.md §5](../overview.md#5-모듈-지도)
  - 주인을 한 모듈로 정할 수 없는 횡단 용어: [overview.md §8](../overview.md#8-용어)
  - 판단의 이유: [adr/](../adr/README.md)
  - 개발 인프라와 운영: [development/](../development/README.md) · [operations/](../operations/README.md)

## 2. 공통 구조

모든 Spec 은 아래 여덟 절을 같은 번호로 갖는다. 바깥(책임 · 공개 인터페이스)에서 안쪽(내부 구조 · 규칙 · 데이터)으로 읽는 순서다. 담을 것이 없는 절도 제목을 남기고 "해당 없음"이라 적는다. 그래서 `docs/specs/{모듈}.md §n` 은 모듈과 무관하게 같은 종류의 지식을 가리킨다. 코드 주석이 이 표기로 Spec 의 절을 가리킨다([CONTRIBUTING.md §7](../../CONTRIBUTING.md#주석)). 절 제목은 `## {번호}. {절 이름}` 이고, 절 안은 하위 제목으로 나눠도 된다.

| § | 절 | 담는 것 | 담지 않는 것 |
|---|---|---|---|
| 1 | 책임과 범위 | 모듈의 책임과 이 모듈이 하지 않는 것. 모듈 책임의 정본이다 | 다른 모듈과의 의존(→ [overview.md §5](../overview.md#5-모듈-지도)) |
| 2 | 용어 | 이 모듈이 소유한 개념의 용어. 다른 모듈이 같은 말을 써도 정의는 여기 있다 | 주인을 한 모듈로 정할 수 없는 횡단 용어(→ [overview.md §8](../overview.md#8-용어)) |
| 3 | 공개 인터페이스 | 모듈 최상위 패키지의 공개 타입 · 이벤트와 모듈이 내는 HTTP 엔드포인트. 아래 "§3 공개 인터페이스"를 따른다 | 내부 타입(→ §4 · Javadoc), HTTP 요청 · 응답 형식(→ `api/openapi.json`, [ADR-0020](../adr/0020-screen-api-contract-from-committed-openapi-spec.md)) |
| 4 | 내부 구조 | 패키지와 구성 요소, 그 협력, 트랜잭션 경계, 포트 선언. 아래 "§4 내부 구조"를 따른다 | 아래 "§4 내부 구조"의 "담지 않는 것" |
| 5 | 규칙과 불변식 | 입력이 무엇을 뜻하는지 정하는 규칙과 정본 상수의 값. 항목마다 식별자를 단다(§3 규칙 2). 아래 "§5 규칙과 불변식"을 따른다 | 아래 "§5 규칙과 불변식"의 "담지 않는 것" |
| 6 | 데이터 | 모듈이 가진 테이블의 주요 컬럼 · 의미 · 제약의 뜻과 다른 모듈을 가리키는 ID | 컬럼 타입 · 인덱스 · 제약 문면(→ Flyway 마이그레이션), 모듈 사이 관계 · 보존 정책 · 프레임워크 테이블(→ [data-model.md](../data-model.md)) |
| 7 | 설정 | 모듈이 읽는 설정 키와 그 값이 바꾸는 규칙 | 환경 변수 표 · 값 예시(→ 운영 문서) |
| 8 | 결정 | 이 모듈의 설계를 정한 ADR 목록(번호 · 한 줄) | ADR 본문의 반복 |

### §3 공개 인터페이스

- 공개 타입 · 이벤트마다 하위 절을 둔다. 제목은 타입 이름이고 번호를 달지 않는다
- 하위 절에는 선언(Java 코드 블록), 필드 표(필드 · 뜻 · 제약), 계약, 관련 규칙 식별자를 쓴다. 계약은 소비자가 기댈 수 있는 것이고, 이벤트의 계약에는 발행 주체 · 시점 · 횟수가 든다
- 공개 타입이 없으면 없다는 사실을 쓴다
- 모듈이 내는 HTTP 엔드포인트는 경로 · 메서드 · 용도를 쓴다

### §4 내부 구조

하위 절 다섯을 둔다.

- **개관** — 패키지와 그 책임, 구성 요소 사이의 협력. 협력은 과정마다 한두 문장으로 쓴다. 문장에는 계기 · 결과 · 관련 규칙 식별자를 담는다
- **들어오는 쪽** — 반복 · 예약 작업, 이벤트 리스너, 컨트롤러, 기동 시 동작. 각각 아래를 쓴다
  - 계기와 주기
  - 멱등성과 겹침 방지
  - 실패 처리
- **`application`** — 유스케이스와 트랜잭션 경계
- **`domain`** — 저장 단위와 판단의 정본
  - 저장 단위: aggregate · 상태 객체 · 저장소와 쓰기 경로
  - 판단의 정본: §5 규칙의 정규화와 검증, 판정, 상태 전이와 일정
- **나가는 쪽** — 밖으로 나가는 의존과 그 방어. 규칙 자체는 §5 에 쓴다
  - 포트 선언과 계약
  - v1 구현과 로컬 대체물
  - 저장소 구현
  - 신뢰할 수 없는 입력과 그 방어 규칙의 식별자

구성 요소는 이름(인라인 코드)과 책임 한 줄로 쓴다. 값 · 결과 · 예외 · 보조 타입은 패키지 줄에 묶는다. 이름을 드는 구성 요소는 아래다.

- 들어오는 쪽과 유스케이스
- aggregate 와 상태 객체, 저장소
- 판단의 정본
- 포트와 구현, 로컬 대체물

시퀀스 다이어그램으로 그리는 과정은 §3 규칙 6 이 정한다. 그린 과정의 클래스 호출 순서는 그림만 갖고, 개관에는 그 과정의 한두 문장만 남긴다.

로그를 남기는지와 그 수준은 §5 의 규칙으로 쓰고, 로그 문구는 코드에 둔다.

§4 가 담지 않는 것:

- 필드 · 메서드 · 알고리즘 · 비공개 시그니처(→ Javadoc)
- 저장소 메서드 선언, SQL, 로그 문구, 응답 타입 열거
- 작업 프레임워크 설정(→ 개발 인프라 · 운영 문서)
- 라이브러리 버전(→ `backend/build.gradle.kts`)

### §5 규칙과 불변식

규칙은 입력이 무엇을 뜻하는지 정한다. 입력의 정규화와 검증, 판정, 상태 전이와 일정이 그렇다. 규칙의 꼴과 배치는 §3 규칙 2 가 정한다.

§5 가 담지 않는 것:

- 알고리즘 상세(→ Javadoc)
- 구성 요소의 배치(→ §4)
- 판단의 이유와 측정 기록(→ ADR, ADR 이 없으면 쓰지 않는다)
- 변경 이력
- 화면 동작(→ 화면 Spec)

### 화면 Spec

화면 Spec(`web`)은 같은 여덟 절을 프론트엔드의 뜻으로 쓴다.

| § | 화면 Spec 이 담는 것 |
|---|---|
| 1 | 독자 화면과 운영자 화면의 범위, 화면이 하지 않는 것 |
| 2 | 화면 이름과 개발 용어의 대응. 화면 이름의 정본이다 |
| 3 | 화면 경로와 그 화면, 화면이 부르는 화면용 API |
| 4 | 기능 폴더(`frontend/src/features/*`)와 공용 부품 |
| 5 | 화면 동작 규칙. 식별자는 `web-R{번호}` 다 |
| 6 | 브라우저에 남기는 값. 없으면 "해당 없음" |
| 7 | 프론트엔드 설정 |
| 8 | 화면 쪽 결정을 정한 ADR 목록 |

## 3. 쓰는 규칙

1. **경계** — 공개 인터페이스(§3 절)와 포트 선언(§4 나가는 쪽)은 Spec 이 정본이고 코드는 Spec 을 따른다. 코드의 선언은 그 사본이므로, 둘을 바꾸는 변경은 Spec 과 코드를 함께 고친다. 모듈의 내부 구조는 Spec 이 갖는다. 내부 구조는 구성 요소와 그 책임 · 협력, 저장 단위, 판단의 자리, 트랜잭션 경계를 말한다. §4 에 있는 구성 요소를 새로 만들거나 지우거나 이름 · 책임을 바꾸는 변경은 Spec 을 고친다. 클래스 내부 상세(필드 · 메서드 · 알고리즘 · 비공개 시그니처)는 Javadoc 이 정본이다. 판단의 이유는 ADR 이 갖고 Spec 은 번호로 가리킨다
2. **규칙 식별자와 규칙의 꼴** — §5 의 항목마다 항목 머리에 식별자 `{앞말}-R{번호}` 를 단다(예: **source-R12**). 앞말은 모듈 이름이고, 화면 Spec 은 `web` 이다
   - **번호** — Spec 안에서 1 부터 늘고, 폐지한 규칙의 번호는 다시 쓰지 않는다
   - **불변식** — §4 · §6 의 동작 · 제약 가운데 지켜야 하는 불변식도 §5 에 규칙으로 쓰고, §4 · §6 은 그 식별자를 가리킨다. 멱등성 · 겹침 방지 · 고유 제약의 뜻 · 입력 방어가 그렇다
   - **인용** — 테스트는 자기가 지키는 규칙을 이 식별자로 가리킨다. 테스트 쪽 표기 형식은 코드 주석 규칙([CONTRIBUTING.md §7](../../CONTRIBUTING.md#주석))이 정한다
   - **판단 하나** — 규칙 하나는 판단 하나를 말한다. 하위 항목은 그 판단의 조건과 예외만 쓴다. 판단이 여럿이면 쪼갠다
   - **쪼개기** — 원래 식별자는 묶음 머리로 남긴다. 묶음 머리에는 무엇을 덮는지 한두 문장과 하위 규칙 식별자의 목록만 쓴다. 쪼갠 판단은 그 Spec 의 새 번호를 받는다. 묶음 머리를 인용한 곳은 하위 규칙 전부를 가리킨다
   - **배치** — §5 의 하위 절은 주제별로 두고, 하위 절 안의 규칙은 번호 오름차순으로 놓는다. 하위 절 이름은 링크 앵커이므로 바꾸지 않는다. 바꾸면 그 앵커를 가리키는 링크를 함께 고친다
   - **폐지** — 규칙을 없앨 때는 항목을 지우지 않는다. 식별자를 남긴 채 내용을 `(폐지 — {대체 식별자 또는 사유})` 로 바꾸고, §5 마지막 하위 절 "폐지한 규칙"으로 옮겨 번호순으로 둔다
3. **미구현 · 측정 전 표시** — 아직 코드가 없는 항목은 항목 앞에 `**(미구현)**` 을 적고, 그 항목을 구현하는 변경이 표시를 지운다. 구현된 것과 아닌 것이 한 문장에 섞이면 미구현 부분을 떼어 별도 항목으로 표시한다. 아직 재지 않은 잠정값인 상수에는 값 옆에 `(측정 전)` 을 달고, 그 값을 재서 고치는 변경이 표시를 지운다
4. **작성 규칙** — [docs/README.md §4](../README.md#4-작성-규칙)의 작성 규칙을 모두 따른다
5. **코드 이름** — 코드의 타입 · 패키지는 인라인 코드 이름으로만 쓰고, 코드 파일 · 디렉터리로 링크하지 않는다. 타입은 이름 그대로(`FeedPoller`) 쓰고, 중첩 타입은 바깥 타입부터 점으로 잇는다(`FetchResult.Fetched`). 패키지는 모듈 패키지 기준 경로로 쓴다(`domain/poll`). Spec 의 코드 이름이 코드와 맞는지는 공개 인터페이스 · 포트 선언의 사본처럼 리뷰가 본다
6. **다이어그램** — 시퀀스 · 상태 다이어그램(Mermaid)을 쓸 수 있다. 트랜잭션 경계 · 외부 호출 · 실패 갈림 · 잠금 가운데 하나라도 있는 과정은 시퀀스 다이어그램으로 그린다. 다만 단계가 하나뿐인 과정, 곧 참가자 사이 호출이 하나이고 갈림도 하나 이하인 과정은 그리지 않는다. 쓰기 · 잠금 · 외부 호출 · 실패 처리(결과에 따라 다시 하거나 다르게 처리하는 것) 없이 읽기만 하는 조회 과정은 공개 조회를 여럿 엮거나 요청 검사가 있어도 그리지 않는다. 저장하지 않는 미리보기도 읽기다. 그림은 설명이고 규범은 §5 의 규칙이다. 둘이 다르면 규칙이 맞고 그림을 고친다. 그림의 단계 · 전이에는 해당 규칙 식별자를 단다. 클래스 다이어그램은 쓰지 않는다
7. **하위 제목** — §3 · §4 의 하위 제목은 같은 Spec 의 §5 하위 제목과 이름이 겹치지 않게 한다. 겹치면 먼저 나오는 쪽이 앵커를 가져, §5 하위 절을 가리키던 링크가 깨지지 않은 채 다른 절을 가리킨다
8. **화면 동작** — 모듈 Spec 의 규칙은 서버가 지키는 것만 쓴다. 화면이 무엇을 언제 그리고 부르는지는 화면 Spec 에 쓰고, 모듈 Spec 의 규칙은 그 `web-R` 식별자를 가리킨다

공통 구조와 이 규칙을 정한 결정은 [ADR-0034](../adr/0034-module-spec-as-public-interface-specification-and-docs-by-kind.md) · [ADR-0036](../adr/0036-module-spec-holds-internal-structure-and-port-declarations-in-eight-sections.md)에 있다.
