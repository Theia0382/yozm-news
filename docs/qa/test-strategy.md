# 테스트 전략

이 문서는 이 프로젝트가 **무엇을 테스트 증거로 인정하는가**의 정본이다. 테스트 계층마다 증명할 수 있는 것과 없는 것, 가드를 세우는 방법, 오라클의 조건, 거짓 통과(false-green)를 막는 규약, 결과를 보고하는 방식, 커버리지의 뜻을 정한다.

테스트 실행 명령은 [CONTRIBUTING.md](../../CONTRIBUTING.md)가 소유한다. 이 문서는 명령을 다시 적지 않는다.

---

## 1. 범위

- 대상은 자동 테스트 전 계층과 사람의 확인이 **증거로서** 갖는 자격과 한계다
- 범위 밖
  - 실행 명령 · 실행 시점 — [CONTRIBUTING.md](../../CONTRIBUTING.md)
  - 모듈 고유의 테스트 명세 — 규칙 · 불변식은 모듈 Spec 이 식별자와 함께 갖고([specs/README.md](../specs/README.md) §3), 어느 테스트가 지키는지는 테스트가 그 식별자로 가리킨다
  - 테스트 도구와 버전 목록 — `backend/build.gradle.kts`

---

## 2. 테스트 계층과 역할

계층은 소스 위치가 아니라 **무엇을 관측할 수 있는가**로 나뉜다. 백엔드 자동 테스트는 모두 `backend/src/test` 에 있고 실행 경로가 같다. 프론트엔드 자동 테스트는 `frontend/` 안 대상 옆의 `*.test.ts(x)` 다(화면 코드는 `frontend/src`, 개발 서버 · proxy 설정은 `frontend/proxy`). 배포 구성 스모크(⑩)는 `deploy/smoke.sh` 다. 공개 마크다운의 링크 검사(⑤)와 그 단위 테스트는 `tools/docs-check` 에 있다.

| # | 계층 | 증명할 수 있는 것 | 증명할 수 없는 것 |
|---|---|---|---|
| ① | **순수 단위** (Spring 없이) | 도메인 로직 · 상태 전이 · 판정 규칙(태그 임계값 등) · 정규화 · 파싱 — 프레임워크를 거치지 않는 로직 전부 | 프레임워크 결선, SQL, 트랜잭션, 직렬화 |
| ② | **슬라이스** (`@WebMvcTest`, `@DataJdbcTest` · `@JdbcTest` + Testcontainers PostgreSQL) | 컨트롤러 매핑 · 보안 필터 · 요청 검증 · JSON 직렬화, 실제 PostgreSQL 위의 SQL · 매핑 · 마이그레이션 | 슬라이스 밖의 결선, 커밋 이후에 일어나는 일(§3 ③) |
| ③ | **모듈** (`@ApplicationModuleTest`) | 모듈 하나의 결선과 그 모듈이 발행 · 수신하는 이벤트 | 다른 모듈과의 실제 상호작용 |
| ④ | **통합** (`@SpringBootTest` + Testcontainers PostgreSQL + WireMock) | 모듈 경계를 넘는 흐름 — 실제 DB, 실제 작업 큐, 외부 HTTP 를 WireMock 으로 대체한 상태의 동작 | 대체해 둔 외부 서비스의 실제 거동(§3 ⑤) |
| ⑤ | **구조 · 잔존 게이트** | 모듈 의존 구조(Modulith `verify()`), 소스 문면의 존재와 부재, 공개 마크다운의 상대 링크 · 앵커 | 실행 의미(§3 ①), GitHub 이 실제로 그리는 앵커(검사는 같은 규칙을 따를 뿐이다) |
| ⑥ | **프론트엔드 단위 · 컴포넌트** (Vitest + Testing Library, jsdom) | 컴포넌트 렌더링 · 라우팅 · 상태 · 사용자 입력 처리 — 사용자가 보는 역할 · 이름으로 조회한다 | 실제 백엔드와의 결선, 실제 브라우저의 레이아웃 · 스타일(⑦ · ⑨) |
| ⑦ | **브라우저 E2E** | 실제 브라우저에서의 화면 흐름 (도입 전) | 사람의 판단 |
| ⑧ | **실제 외부 서비스 확인** | 실제 Jev · LLM · OIDC 공급자와의 호출 형식 · 응답 형식 · 오류 거동. 사람이 키를 넣어 수동으로 돌린다 | 결정적 재현(응답이 매번 다르다) |
| ⑨ | **사람 확인** | 화면 · 사용자 흐름의 실제 결과, 다이제스트 내용의 품질 | — (자동 계층이 대신할 수 없는 것의 최종 증거다) |
| ⑩ | **배포 구성 스모크** (배포 이미지 빌드 + `deploy/compose.yaml` 기동 + `deploy/smoke.sh`) | 배포 이미지가 두 아키텍처로 빌드되는지, 실제 컨테이너의 기동 순서 · healthcheck, proxy 가 넘기는 경로와 넘기지 않는 경로, 호스트 공개 범위 | 브라우저에서 화면이 그려지는지(⑨), 운영 호스트 · Tunnel · 레지스트리 경로, 앱 기능의 동작(① ~ ④) |
| ⑪ | **품질 평가** (라벨 평가 세트) | 정답 라벨을 붙인 표본에서 사건 묶기의 묶음 정확도(B-cubed F1)와 큰 사건 판정 정밀도, 그 수치를 근거로 한 임계값 | 표본 밖 운영 분포에서의 품질, 사용자가 받는 다이제스트의 경험(⑨) |

- **계층 번호는 고정이다.** 계층이 없어져도 뒤 번호를 당기지 않는다 — 다른 문서가 번호로 인용한다
- **통합 테스트는 별도 실행 계층이 아니다.** 같은 소스셋 안에서 실제 협력 객체를 결선한 테스트를 부르는 이름이다
- **⑧ 은 CI 에서 돌리지 않는다.** 외부 계정 · 비용 · 비결정성 때문이다. 공급자 연동을 바꾼 작업에서 설계 단계가 지정한 경우에만 수동으로 돌리고 결과를 기록한다
- **⑪ 은 CI 에서 돌리지 않는다.** 실제 Jev 와 수집한 실제 기사를 쓰기 때문이다. 결과는 수치와 표본 정보(기간 · 건수 · 라벨 기준 · 모델 버전)로 기록한다. 표본의 실제 기사 텍스트는 공개 저장소에 넣지 않는다([security.md](../security.md))
- **사람에게는 자동화할 수 없는 것만 맡긴다.** 측정으로 판정되는 항목을 사람의 체감으로 다시 확인하지 않고, 이미 받아들인 항목을 다시 묻지 않는다

## 3. 증거 등급

1. **실행 오라클이 구조 · 잔존 게이트보다 앞선다.** 게이트(⑤)는 구조와 문면만 재므로 실행 의미에 눈이 멀다. 부정 단언은 추출이 빗나가 빈 문자열이 되면 무조건 통과한다. 게이트는 **단독으로 1차 근거가 될 수 없는 보조 등급**이다
2. **화면 · 사용자 흐름을 바꾼 변경은 사람 확인(⑨)이 AC 판정의 1차 근거다.** 자동 테스트가 전부 통과해도 대신하지 않는다. 그런 변경에 사람 확인이 없으면 완료가 아니라 "수동 확인 항목 남음"이다
3. **계층이 관측하지 못하는 성질에 대한 단언은 증거가 아니다.** 예:
   - 모의 저장소나 PostgreSQL 이 아닌 DB 로 SQL 의미를 단언하는 것
   - 테스트 전체를 트랜잭션으로 감싸 롤백하는 테스트로, 커밋 뒤에 일어나는 일(커밋 후 이벤트 발행 · 트랜잭션 밖 외부 호출)을 단언하는 것
4. **산식 검증은 화면 결과의 검증을 대신하지 않는다.** 도메인 모델이나 공용 판정 규칙을 바꾸면 규칙 자체의 검증과 별도로, 그 규칙이 만드는 사용자 결과(후보 목록 · 화면)를 검증한다
5. **WireMock 응답은 공급자 계약의 증거가 아니다.** 대체 응답은 실제 응답 형식 · 공식 문서에서 따온 것이어야 하고, 공급자 쪽 변화는 ⑧ 에서만 드러난다. LLM 이 만든 다이제스트의 품질은 단위 테스트의 단언으로 판정하지 않는다 — ⑨ 의 표본 검토로 본다

## 4. guard-first

결함을 고치는 변경은 **결함을 잡는 가드를 먼저** 세운다.

### 4.1 수정 가드

- 수정 가드는 **고치기 전 코드에서 실패(pre-fix RED)해야** 한다
- 판정은 **검증자가 재현해서** 한다 — 변경 전 기점의 프로덕션 코드에 변경 뒤의 테스트를 얹어 가드를 실행하고, 실패한 단언과 그때의 현재 값을 기록한다. 작업 기록의 RED 서술을 근거로 삼지 않는다. 가드를 세운 쪽의 사전 실측은 선택이다
- 같은 실행에서 **인접 안전 대조 leg** 가 통과하는 것도 함께 확인한다. 대조 leg 는 결함 조건만 비켜 간 이웃 입력으로, 가드가 결함이 아닌 이유로 실패하고 있지 않음을 보인다
- 기점 조합이 컴파일되지 않으면(가드가 변경으로 새로 생긴 심볼에 기대는 경우) 컴파일 실패는 RED 로 세지 않는다. 같은 변경 안에서 앞서 고친 코드에 가드가 기대어 기점에서 결함과 무관한 이유로 실패하는 경우(대조 leg 의 실패로 드러난다)도 RED 로 세지 않는다. 두 경우 모두 검증자는 변경 뒤 코드에서 그 가드가 겨냥한 수정만 되돌린 임시 변이(§4.2 와 같은 처리)로 가드의 실패와 대조 leg 의 통과를 보인다
- 구현 뒤에는 선행 가드 전부와 대조 leg 가 함께 통과해야 한다

### 4.2 봉인 가드

현재 상태를 지키는 가드(불변식 트립와이어, 잔존 금지 게이트, 모듈 구조 검증 등)는 고칠 결함이 없으므로 **지킬 상태가 성립한 코드에서 통과하는 것이 정상**이다. 판별력의 증거는 pre-fix RED 대신 **임시 변이(probe)** 로 얻는다.

- 가드가 잡아야 할 위반을 임시로 만들어 가드가 실패하는 것을 관측한다
- 변이는 커밋하지 않는다. 변이마다 작업 트리가 원래대로 돌아왔는지(추적 파일 변경 없음) 확인한다

### 4.3 선례 없는 오라클은 실현성부터

그 계층에서 한 번도 쓴 적 없는 오라클은 가드로 쓰기 전에 **통제 실험으로 성립을 확인**한다. 확인 없이 가드를 세우면 고치기 전부터 통과하거나(전제 위반) 영원히 실패해(착수 차단) 가드 순서가 무너진다.

## 5. 오라클 규약

- **수기 독립 리터럴** — 기대값은 사람이 독립적으로 계산해 적은 리터럴이다. 테스트 대상 코드의 산식 · 규칙을 테스트 안에서 다시 계산해 기대값으로 쓰지 않는다(§6 replica)
- **실제 PostgreSQL** — SQL · 매핑 · 마이그레이션을 판정하는 테스트는 Testcontainers 의 PostgreSQL 에서 돈다. 다른 DB 나 인메모리 대체로 SQL 의미를 판정하지 않는다
- **고정 시계** — 시각 · 날짜 · 시간대에 따라 결과가 달라지는 로직은 주입한 `Clock` 으로 시각을 고정하고, 날짜 경계 · 시간대 경계를 명시적인 입력으로 다룬다
- **외부 응답 픽스처** — WireMock 픽스처는 실제 응답 형식 · 공식 문서에서 따온다. 오류 응답(401 · 429 · 5xx · 시간 초과)도 픽스처로 둔다
- **커밋 경계를 지나는 동작** — 커밋 뒤 이벤트 발행 · 트랜잭션 밖 외부 호출을 판정하는 테스트는 테스트 자체를 트랜잭션으로 감싸지 않는다
- **테스트 간 데이터 격리** — 테스트는 다른 테스트가 남긴 데이터에 기대지 않는다. 실행 순서가 바뀌어도 결과가 같아야 한다

## 6. false-green 유형과 차단

통과했지만 아무것도 증명하지 않는 테스트를 false-green 이라 한다.

| 유형 | 모습 | 차단 |
|---|---|---|
| **replica** | 테스트 대상 산식 · 규칙을 테스트 안에서 재현해 기대값으로 쓴다 — 규칙이 틀려도 같이 틀려서 통과한다 | 수기 독립 리터럴(§5) |
| **vacuous** | 항상 참인 단언(`assertTrue(true)` 류), 또는 추출이 빗나가 빈 값이 되면 무조건 통과하는 부정 단언 | 추출 대상이 비어 있지 않음을 먼저 단언한다. 스캔 게이트는 스캔 대상 수의 하한을 둔다 |
| **oracle 우회** | 측정해야 할 값을 테스트가 주입하고 그 값을 다시 읽어 통과한다 | 실제 생산 경로를 거쳐 나온 값을 잰다 |
| **mock 상호작용만 검증** | 협력 객체를 전부 모의로 바꾸고 "이 메서드가 불렸다"만 단언한다 — 결과가 틀려도 통과한다 | 관측 가능한 결과(저장된 행 · 응답 · 발행된 이벤트)를 단언한다. 모의는 외부 경계에만 쓴다 |
| **계층 부적합 단언** | 계층이 관측하지 못하는 성질을 단언한다(§2 "증명할 수 없는 것", §3 ③) | 성질을 관측하는 계층으로 옮긴다 |
| **denylist 잔존 검사** | 알려진 문자열 몇 개만 찾는 잔존 검사 — 목록 밖 변형이 새어 나간다 | 구조적 정규식 묶음(family)을 추적 파일 목록 전체(`git ls-files`)에 적용한다 |
| **stale-pass** | 빌드 도구가 입력으로 모르는 파일을 테스트가 읽으면, 그 파일만 바뀌었을 때 테스트가 최신 상태로 오판되어 건너뛰어진다 | 테스트가 읽는 파일 · 디렉터리를 테스트 태스크의 명시 입력으로 배선한다 |
| **시간 의존** | 현재 시각에 따라 날짜 경계 · 시간대 경계에서만 실패하거나 통과한다 | 고정 시계(§5) |
| **순서 의존** | 다른 테스트가 남긴 데이터 때문에 통과한다 | 테스트 간 데이터 격리(§5) |

## 7. 결과 보고

- **통과는 실행 출력 인용으로만 말한다.** 빌드 도구의 성공 한 줄이 아니라 결과 파일의 집계(tests · failures · errors · skipped)로 말한다
- **skipped 는 통과가 아니다**
- **실행 0건은 통과가 아니다.** 대상 이름 오타, 테스트가 없는 패키지, 필터가 대상을 전부 거른 경우가 이렇게 끝난다. 통과는 실행된 테스트가 1건 이상일 때만 말한다
- **전체 실행은 결손을 대조한다.** 테스트를 선언한 클래스마다 결과가 있어야 한다 — 결과가 없거나 전부 skipped 인 클래스가 있으면 완주가 아니다
- **부하에서만 나는 실패도 실패다.** 단독으로 다시 돌려 통과해도 통과로 세지 않는다. 실패로 보고하고 단독 재실행 결과를 함께 적는다. 변경 전 기점에서도 나는 실패는 기존 실패로 분리한다
- **전체 실행이 덮는 범위를 따로 다시 돌리지 않는다.** 전체 실행에 포함된 게이트 · 테스트를 별도로 한 번 더 돌리는 중복 검증 층을 두지 않고, 전체 실행의 결과를 인용한다

---

## 8. 커버리지

- **판정 축은 AC 커버리지다.** 수용 기준(AC)마다 그 AC 를 지키는 자동 가드가 있는지를 본다. 자동 가드가 없는 AC 는 "사람 확인이 유일한 증거"라고 명시하고 수동 확인 항목으로 넘긴다
- **라인 커버리지는 진단으로만 잰다.** 정기 측정 · 수치 목표를 두지 않고, 완료 판정과 게이트에 쓰지 않는다
- 용어는 "AC 커버리지"와 "라인 커버리지"로만 쓴다

---

## 9. 테스트가 요구하는 프로덕션 seam

실행으로만 판별되는 결함이 걸린 표면은, 그 실행을 재기 위한 프로덕션 seam 추출을 허용한다(`Clock` 주입이 대표적이다). 세 조건을 함께 요구한다.

1. seam 은 그 자체로 책임이 분리된 단위여야 한다 — 프로덕션에서 의미가 없는 테스트 전용 후크는 허용하지 않는다
2. 가시성은 테스트가 구성할 수 있는 최소로만 연다
3. 기존 구조 · 잔존 게이트는 폐기하지 않고 보조 가드로 존치한다

---

## 10. 알려진 공백

- **브라우저 E2E(⑦)가 없다.** 실제 화면 흐름이 생기는 작업에서 도입한다. 그 전까지 화면 흐름의 증거는 ⑨ 사람 확인이다
- **실제 외부 서비스 확인(⑧)의 절차가 정해지지 않았다.** 첫 외부 연동 작업에서 정한다

---

## 11. 비활성 테스트

비활성 테스트(`@Disabled` 등)를 두지 않는다. 쓰지 않는 테스트는 지우고, 되살릴 근거는 git 이력에 둔다.
