## 한 줄 요약

특정 뉴스 사이트의 기사를 수집하고, AI를 활용해 사용자의 관심 조건에 맞는 뉴스를 선별·분류·요약해 보여주는 개인용 뉴스 다이제스트 서비스.

## 배경

관심 있는 뉴스와 각종 동향을 꾸준히 확인하려면 여러 기사를 직접 읽고 중요한 내용을 선별하는 데 시간이 많이 든다.

사용자가 어떤 분야에 관심을 가지는지는 서비스의 핵심 도메인에 고정하지 않고 설정 가능한 조건으로 다룬다.

처음부터 여러 뉴스 사이트를 통합하기보다는 **하나의 뉴스 사이트 또는 제한된 관심 조건을 기준으로 시작**해 구현 범위를 작게 유지한다.

단순한 기사 목록보다는 주요 내용을 빠르게 파악할 수 있는 요약과 트렌드 정리를 제공하는 것이 핵심이다.

## 핵심 기능

- 설정된 관심 조건에 맞는 뉴스 기사 수집 및 선별
- 기사 제목, 링크, 발행 시각 등 기본 정보 저장
- 기사 본문 또는 주요 내용을 기반으로 요약 생성
- 비슷한 주제의 기사 분류
- 그날 또는 일정 기간의 주요 이슈 정리
- 중요 뉴스와 추가로 읽어볼 만한 뉴스 구분
- 기사별 좋아요 / 싫어요 피드백
- 제3자 서비스가 다이제스트와 기사 데이터를 조회할 수 있는 외부 API 제공

## 기본 사용자 흐름

1. 서비스가 정해진 뉴스 소스에서 새 기사를 가져온다.
2. 설정된 관심 주제 또는 조건에 대한 관련성을 평가해 필요한 기사만 선별한다.
3. 각 기사의 핵심 내용을 짧게 요약한다.
4. 중요도가 높은 기사를 주요 뉴스로 보여준다.
5. 나머지는 헤드라인 위주로 제공한다.
6. 사용자는 관심 있는 기사를 열어보거나 좋아요 / 싫어요로 피드백한다.

## 초기 구현 범위

첫 버전은 가능한 한 단순하게 만든다.

- 초기 뉴스 소스로 네이버 뉴스 API 사용
- 관심 주제 또는 키워드 기반 수집
- 기사 중복 제거
- Jev를 이용한 관심 조건에 대한 기사 관련성 판별
- Jev를 이용한 기사 분야 분류 및 중요도 평가
- 평가 결과를 기준으로 요약할 기사와 주요 기사 후보 선별
- 기사 요약
- 일일 다이제스트 생성
- 주요 기사 몇 건 + 추가 헤드라인 목록
- 좋아요 / 싫어요 저장

## 결정 사항

개인화 추천이나 복잡한 사용자 프로필은 초기 범위에서 제외한다.

- 초기 국내 뉴스 소스는 **네이버 뉴스 API**를 사용한다.
- 뉴스 공급원은 구현에서 `ArticleSource`와 같은 인터페이스 뒤에 추상화해 특정 서비스에 강하게 결합하지 않는다.
- 네이버 API의 제약이나 품질 문제가 생기면 다른 공급원으로 교체할 수 있도록 설계한다.
- 기사 전문이 필요할 경우, 네이버 검색 결과의 원문 URL을 기준으로 별도의 본문 추출 단계를 둔다.
- 기사에 대한 관심 조건 관련성 판별, 카테고리 분류, 중요도 평가 등의 구조화된 판단에는 **Jev**를 우선 사용한다.
- Jev는 기사 요약이나 다이제스트 문장 생성에는 사용하지 않고, 생성형 LLM 호출 전에 기사를 평가·선별하는 용도로 사용한다.
- 기사 평가 기능은 `ArticleEvaluator`와 같은 인터페이스 뒤에 추상화하고, 초기 구현체로 `JevArticleEvaluator`를 사용한다.
- 서비스가 다루는 뉴스 주제는 도메인 로직에 고정하지 않고 설정으로 관리한다.
- `ArticleEvaluator`는 특정 관심 분야를 전제로 하지 않으며, 현재의 관심 조건과 카테고리 후보를 입력받아 관련성·분류·중요도를 평가한다.
- 애플리케이션의 핵심 로직이 Jev API에 직접 의존하지 않도록 하여, 향후 다른 decision model이나 평가 방식으로 교체할 수 있게 한다.
- Jev가 반환하는 확률 또는 confidence를 저장하거나 활용할 수 있도록 설계하고, 일정 기준 이하의 애매한 판정은 별도 처리하거나 필요할 경우 상위 LLM으로 재평가할 수 있게 한다.

## 기사 평가 계층

수집된 모든 기사에 생성형 LLM을 바로 호출하지 않고, 먼저 저비용의 평가 단계를 거쳐 필요한 기사만 후속 처리한다.

초기 평가 계층에는 **Jev**를 사용한다.

대략적인 처리 흐름은 다음과 같다.

`기사 수집 → 중복 제거 → 본문 추출 → Jev 평가 → 기사 선별 → LLM 요약 → 다이제스트 생성`

Jev는 주로 다음 판단을 담당한다.

- 설정된 관심 조건과 관련된 기사인지 판별
- 설정된 카테고리 체계에 따라 분류
- 다이제스트에서 다룰 가치 또는 중요도 평가
- 주요 뉴스 후보 여부 판단

Jev는 자유로운 텍스트를 생성하는 용도로 사용하지 않는다. 기사 요약, 여러 기사의 종합, 일일 주요 이슈 설명 등 자연어 생성이 필요한 작업은 별도의 생성형 LLM이 담당한다.

평가 기능은 특정 모델이나 관심 분야에 종속되지 않는 `ArticleEvaluator` 인터페이스로 추상화한다. 관심 조건과 카테고리 후보는 평가 시 입력으로 전달한다.

초기 구조는 대략 다음과 같다.

`ArticleEvaluator → JevArticleEvaluator`

향후 필요하면 OpenAI Decisions API 등의 다른 구현체를 추가해 동일한 평가 데이터로 비교하거나 교체할 수 있다.

## 향후 확장 아이디어

- 여러 뉴스 사이트 지원
- 국내 / 해외 뉴스 분리
- 관심 주제와 카테고리 체계의 확장
- 특정 주제의 변화 추적
- 사용자 피드백을 이용한 기사 우선순위 조정
- 주간 트렌드 요약
- 이전 기사와 현재 기사의 연관 관계 표시
- 비슷한 사건을 다룬 여러 매체의 기사 묶기
- 특정 기술이나 기업의 장기적인 변화 추적

## 외부 서비스 연동

서비스에 저장된 다이제스트와 기사 데이터를 다른 애플리케이션이나 AI 서비스에서 활용할 수 있도록 외부 인터페이스를 제공한다.

대표적인 사용 사례는 **ChatGPT와 연결해 오늘 받은 다이제스트를 불러온 뒤, 해당 내용을 바탕으로 후속 질문이나 토론을 이어가는 것**이다.

외부 연동은 특정 서비스에 종속되지 않도록 일반적인 API를 기반으로 설계하고, ChatGPT와 같은 AI 서비스에는 별도의 MCP/플러그인 어댑터를 제공하는 형태를 고려한다.

초기에는 읽기 기능을 중심으로 다음 정도를 제공한다.

- 오늘의 다이제스트 조회
- 특정 날짜의 다이제스트 조회
- 다이제스트에 포함된 기사 목록 조회
- 개별 기사와 저장된 요약 조회
- 키워드나 주제 기반 기사 검색

향후에는 외부 서비스에서 좋아요/싫어요 같은 피드백을 남기거나 사용자 설정을 변경하는 쓰기 기능도 검토한다.

구조적으로는 대략 `Digest Service API → MCP/ChatGPT adapter → ChatGPT` 형태를 고려한다.

## 구현 시 고민할 부분

- 네이버 뉴스 API로 찾은 기사 원문에서 본문을 어떤 방식으로 추출할지
- 기사 본문 전체를 저장할지 필요한 정보만 저장할지
- Jev의 관심 조건 관련성 판별 기준과 confidence threshold를 어떻게 설정할지
- 요약 품질과 비용의 균형
- Jev 중요도 평가 결과를 주요 기사 선정에 어떤 기준으로 반영할지
- 같은 사건을 다루는 중복 기사 처리
- 좋아요 / 싫어요 피드백을 실제 추천에 어떻게 반영할지

## 현재 방향

이 프로젝트의 목표는 대규모 뉴스 플랫폼을 만드는 것이 아니라, **매일 확인할 만한 관심 뉴스를 짧은 시간 안에 파악할 수 있는 개인용 도구**를 만드는 것이다.

처음에는 데이터 수집과 요약에 집중하고, 실제로 사용해본 뒤 필요한 기능만 추가한다.
