# ADR-0347: 반복 회차는 뭉치를 마친 뒤 가져올 대기가 남았으면 시간 예산 안에서 같은 크기의 뭉치를 다시 가져온다

- 상태: 승인
- 날짜: 2026-11-26
- 근거: [이슈 #204](https://github.com/Theia0382/yozm-news/issues/204) — 실측 인스턴스에서 14일치 스토리라인 다시 잇기(사건 8,492)가 321분 걸렸다. 판정 시각 사이 간격을 세면 45초 이상 간격 300곳의 합이 약 261분이고 판정 간격의 중앙값은 0.57초였다 — 회차가 뭉치 하나를 마친 뒤 다음 분의 실행을 기다린 시간이다. 사건을 다시 묶은 날의 배정은 시간마다 1,920건(= 32 × 60)으로 뭉치 크기에 막혔고, 관계 대기 823건은 판정 71건으로 263분 걸렸다. 구현 커밋 `9a0f9e0` · `1e35185` · `cdcb189` · `05e80c7`

## 맥락

- 사건 묶기 · 스토리라인 잇기 · 관계 · 태그 평가 같은 반복 작업은 1분마다 회차 하나를 돌리고, 회차 하나는 대기에서 정해진 수(뭉치)를 점유해 처리한다. 다시 잇기 · 다시 묶기 · 태그 재평가로 대기가 크게 밀리면 몇 시간을 기다리거나 상수를 고쳐 다시 배포해야 했다.
- 같은 반복 작업의 실행은 겹치지 않는다(ADR-0023). 회차가 일찍 끝나면 다음 분까지 아무것도 하지 않는다.
- 판정을 부르는 대기의 점유 기간은 판정 한 번의 가장 긴 시간 × 뭉치 크기 × 항목마다 판정 수 + 여유다(ADR-0259). 뭉치를 키우면 점유 기간이 같이 커져, 프로세스가 재기동하면 그 뭉치의 행이 점유 기간만큼 멈춘다 — 잇기 뭉치 320이면 약 8시간이다. 점유 기간을 실측에 맞춰 줄이면 평가기가 느려졌을 때 두 회차가 같은 행을 판정한다.
- 사건 묶기 작업은 표현 → 배정 → 재판정 → 병합 회차를 한 작업에서 차례로 부른다.

## 결정

- **회차는 뭉치를 마친 뒤 가져올 대기가 남았으면 같은 크기의 뭉치를 다시 가져온다.** 뭉치 크기와 점유 기간은 바꾸지 않고, 점유는 뭉치마다 그 뭉치의 지금으로 쓴다. 상한만큼 가져와 멈춤 · 일시 실패 없이 마친 뭉치(`FULL`) 뒤에만 이어 간다.
- **회차를 시작한 지 시간 예산(5분 — 측정 전 목표)이 지나면 새 뭉치를 가져오지 않는다.** 상한보다 적게 가져왔거나(가져올 대기 없음), 일시 실패가 하나라도 난 뭉치, 회차를 멈추는 경우로 끝난 뭉치 뒤에도 끝낸다. 일시 실패 뒤에 끝내는 것은 외부 호출 한도에 거듭 부딪히지 않게 하려는 것이다. 경과는 앱 시계의 경과다(측정용 시계가 넘긴 시간을 뺀다).
- **반복과 끝 조건은 `platform` 의 회차 실행기 하나가 한다.** 각 모듈의 회차는 뭉치 하나(지금까지의 회차 본문)를 내고, 끝난 꼴(`FULL` · `DRAINED` · `BACKED_OFF` · `STOPPED`)을 돌려준다. 끝 조건 판정은 `platform/domain` 의 순수 함수다.
- **대상은 뭉치 하나로 끝나던 회차 일곱이다** — 기사 표현 · 사건 배정 · 사건 재판정 · 사건 병합 · 흐름 잇기 · 흐름 관계 · 태그 평가. 이미 채움 하나를 끝까지 처리하는 빠진 태그 채움과, 하루 한 번 지울 것이 없을 때까지 도는 사건 정비는 옮기지 않는다.
- **지금 시각과 회차 첫머리에서 읽던 값(태그 체계 · 저장 기준 · 모델 버전 · 말의 무게)은 뭉치마다 읽는다.** 태그 평가의 저장 바닥 읽기 지연이 "저장 기준을 읽은 시각부터 평가 시각까지가 뭉치 하나의 점유 기간 안"에 기대기 때문이다. 기준 이력 등록은 회차에 한 번이다 — 값이 같으면 한 행이라 결과가 같다.
- **개발 용어는 "뭉치"다.** 회차가 한 번 점유해 처리하는 단위(`RoundBatch`)를 뜻한다. "묶음"은 사용자 스토리라인의 꼭대기 집합(`group`)이라 쓰지 않는다([ADR-0331](0331-a-development-term-has-only-the-meaning-of-one-code-name-and-words-with-several-meanings-are-renamed-per-meaning.md)). 빠진 태그 채움이 채움 하나를 나눠 처리하는 단위는 뭉치가 아니라 "쪽"이다(ADR-0331) — 그 회차는 실행기를 거치지 않는다.

## 결과

- 밀린 대기는 판정 속도로 빈다. 회차 사이에서 다음 분을 기다리는 시간이 시간 예산마다 한 번으로 준다. 실제로 빨라지는 정도는 재지 않았다 — 판정 간격 합으로 어림하면 14일 다시 잇기 321분이 약 60분 근처다.
- 같은 일의 Jev 비용은 같고 시간당 지출이 커진다. 늦출 손잡이는 없다.
- 점유 기간 · 점유 규칙(ADR-0023 · ADR-0059 결정 · ADR-0259)은 그대로라 같은 대기 행을 두 회차가 동시에 판정하지 않는다. 재기동 뒤 멈추는 행도 지금처럼 뭉치 하나 몫이다.
- 사건 묶기 작업의 실행 하나는 회차 넷이 시간 예산을 다 쓰면 20분 남짓 걸린다. 그동안 새 기사의 표현이 늦다.
- 점유를 푼 행(시도 상한 소진 · 쌍이 남은 스토리라인 등)은 같은 회차의 다음 뭉치에 다시 잡힌다. 횟수로 정한 상한(표현의 거부 상한 · 잇기의 실패 상한)이 지금보다 짧은 시간에 찬다.
- 평가기 일시 장애가 잦으면 일시 실패가 난 뭉치마다 회차가 끝나 지금보다 빨라지지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 운영자 설정(DB · 변경 이력)으로 뭉치 크기를 바꾼다 | 점유 기간이 산식으로 같이 커져 재기동 뒤 멈춤이 몇 시간이 된다. 막으려면 상한을 두는데 그 상한이 빨라지는 정도의 한계다. 운영자가 밀린 것을 보고 값을 올렸다 내려야 한다 |
| 환경 변수로 뭉치 크기를 바꾼다 | 위와 같고, 바꾸려면 작업 역할을 다시 띄워야 하며 바꾼 근거가 남지 않는다 |
| 반복 작업의 주기를 줄인다 | 주기가 작업 서버의 폴링 주기(15초)보다 짧으면 폴링 한 번에 실행 여럿이 예약돼 회차가 겹친다. 하한이 폴링 주기라 빈 시간이 남고, 대기가 빈 평소에도 실행이 는다 |
| 대기가 빌 때까지 시간 예산 없이 이어 간다 | 사건 묶기 작업의 네 회차 가운데 앞 회차가 비기까지 뒤 회차가 차례를 얻지 못한다 — 다시 묶는 몇 시간 동안 새 기사가 묶이지 않는다 |
| 회차마다 반복을 따로 쓴다 | 끝 조건과 기록이 일곱 벌이 된다 |
| 일시 실패가 나면 그 자리에서 뭉치를 멈춘다 | 지금 동작(뭉치의 나머지는 처리)을 바꾸고, 다른 항목은 성공할 수 있다 |
