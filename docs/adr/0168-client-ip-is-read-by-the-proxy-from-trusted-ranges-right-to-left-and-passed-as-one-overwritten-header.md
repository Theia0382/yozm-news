# ADR-0168: 클라이언트 IP 는 배포 proxy 가 신뢰 범위(기본 사설 대역)의 앞단에서 오른쪽부터 읽어 덮어쓴 헤더 하나로 넘기고, 앱은 그 헤더만 읽는다

- 상태: 승인
- 날짜: 2026-11-15
- 근거: [이슈 #152](https://github.com/Theia0382/yozm-news/issues/152) — 앱의 클라이언트 주소 읽기 `bc453f5`, proxy 설정 `dfbafbc`. 배포 proxy 의 Caddy 이미지(v2.11)에서 설정 해석과 헤더 읽는 방향을 실측했다
- 관련: [ADR-0012](0012-swappable-external-dependencies.md)("클라이언트 IP" 행 부분 대체 — 신뢰할 프록시 헤더 설정이 앱이 아니라 배포 proxy 에 있다), [ADR-0006](0006-deployment-compose-cloudflare.md)(앞단은 Tunnel 또는 리버스 프록시)

## 맥락

- 요청 제한을 IP 로 센다. 배포 구성은 클라이언트 → 앞단(Tunnel · 리버스 프록시) → proxy(Caddy) → 앱이고 앱은 호스트에 공개되지 않는다. 앱이 직접 연결한 주소는 늘 proxy 이고, proxy 가 직접 연결한 주소는 앞단 뒤에서는 늘 앞단 하나다 — 그대로 세면 IP별 제한이 인스턴스 전체의 공용 한도가 되어, 한 사람이 모두의 로그인을 막는다.
- 앞단이 클라이언트 IP 를 `X-Forwarded-For` 에 덧붙이는 꼴이면 그 헤더의 왼쪽 값은 클라이언트가 마음대로 적은 값이다. Caddy 는 신뢰 범위를 두면 헤더를 기본으로 왼쪽부터 읽는다.
- 운영 문서의 정상 구성은 같은 호스트의 앞단이나 컨테이너로 띄운 Tunnel 이 사설 주소로 proxy 에 붙는 것이다.

## 결정

- **클라이언트 IP 는 배포 proxy 가 정한다.** proxy 는 신뢰 범위 안의 연결에서 온 요청만 헤더(기본 `X-Forwarded-For`, 운영자가 고른다)의 IP 를 읽고, **오른쪽부터** 읽어 신뢰 범위의 주소를 건너뛴 처음 주소를 클라이언트 IP 로 정한다. 신뢰 범위 밖의 연결이면 그 연결의 주소다.
- **신뢰 범위의 기본은 사설 대역이다**(사설 IPv4 · IPv6 과 루프백). 운영자가 범위를 바꿀 수 있고, 값을 비우면 아무것도 믿지 않는다 — 앞단 없이 proxy 를 직접 공개할 때 쓴다.
- **proxy 는 정한 IP 를 앱으로 넘길 때 헤더 하나(`X-Real-IP`)에 덮어쓴다.** 앱은 그 헤더만 읽고(없으면 직접 연결 주소 — 개발 · 시험), 신뢰 판단을 다시 하지 않는다. 앱은 proxy 뒤에만 있어 그 헤더를 믿는다.

## 결과

- 신뢰 판단이 배포의 가장자리 한 곳에 있다. Tunnel · 일반 리버스 프록시 어느 쪽이든 같은 규칙이고, 헤더 고르기(`CF-Connecting-IP` 등)도 proxy 설정이다.
- 정상 구성(앞단 뒤 · 루프백 공개)은 설정 없이 맞는다. 앞단 없이 proxy 를 직접 공개하면서 범위를 그대로 두면, 사설 주소에서 붙는 클라이언트(같은 LAN, 원래 주소를 지우는 포트 전달 뒤)가 헤더로 주소를 바꿔 요청 제한을 비켜 갈 수 있다 — 운영 안내가 이 경우 범위를 비우라고 한다. 반대로 앞단 뒤에서 범위를 비우면 모두가 한도를 함께 쓴다.
- 앱을 proxy 를 거치지 않고 공개하면 헤더를 위조할 수 있다 — 배포 구성은 앱을 호스트에 공개하지 않는다.
- 헤더 이름은 앱의 상수와 proxy 설정 두 곳에 있고, 시험이 원문을 대조한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 앱이 정한다 — proxy 는 사설 대역을 믿어 사슬을 넘기고, 앱이 신뢰 범위 설정으로 `X-Forwarded-For` 를 오른쪽부터 읽는다 | 신뢰 범위가 앱 설정과 proxy 설정 두 곳에 걸친다(proxy 도 앞단을 믿어야 사슬을 이어 받는다) |
| Cloudflare 전용 — `CF-Connecting-IP` 만 믿는다 | Tunnel 은 선택 구성이다. 일반 리버스 프록시 뒤에서 제한이 무너진다 |
| 기본은 아무것도 믿지 않고 운영자가 적어야 동작한다 | 정상 구성(앞단 뒤)에서 모든 사용자가 앞단 주소 하나로 세여, 실패 모드가 "모두 막힘"이다 |
| 운영자가 반드시 적게 한다(없으면 proxy 가 뜨지 않음) | 업데이트하는 기존 인스턴스를 멈추게 한다 |
| 헤더를 왼쪽부터 읽는다(Caddy 기본) | 덧붙이는 앞단 뒤에서 클라이언트가 적은 값을 믿게 된다 |
