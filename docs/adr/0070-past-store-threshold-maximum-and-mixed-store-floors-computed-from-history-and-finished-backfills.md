# ADR-0070: 지난 저장 기준 최댓값과 평가 현황의 저장 기준 섞임은 이력과 끝난 채움 기록으로 평가 시각 축의 저장 바닥을 계산해 낸다

- 상태: 승인
- 날짜: 2026-11-04
- 근거: [이슈 #76](https://github.com/Theia0382/yozm-news/issues/76) — 기점 `45b16f3` 의 경고 입력(이력 전체의 저장 기준 최댓값), 평가 현황 표시(이력에 저장 기준이 바뀐 행이 있는가), 회차의 기준 읽기(회차 시작 때 한 번 — 평가 시각은 결과 뒤)를 확인. 구현 `151164b`(저장 바닥 계산 · 채움 기록 테이블)
- 관련: [ADR-0055](0055-tag-and-store-thresholds-change-with-history-and-warn-instead-of-blocking.md)(부분 대체 — 결정 "그 버전에서 써 온 저장 기준의 최댓값", 결과 "기준을 바꾼 이력으로만 판단한다"), [ADR-0069](0069-missing-tags-filled-by-the-evaluator-rereading-stored-raw-responses-over-an-operator-chosen-period.md)(빠진 태그 채움), [ADR-0059](0059-evaluation-job-limits-concurrency-and-retries-with-db-leases-on-queue-rows.md)(회차의 점유 기간)

## 맥락

- 경고 "태그 기준을 지난 저장 기준 최댓값 아래로 내림"과 평가 현황의 "저장 기준이 바뀐 적이 있다"는 같은 지식을 쓴다 — 평가마다 저장된 확률의 하한(저장 바닥)이 다를 수 있다. 둘 다 이력만으로 판단했다.
- 빠진 태그 채움(ADR-0069)은 덮은 범위 평가의 저장 바닥을 채운 기준까지 내린다. 이력만으로 판단하면 채운 뒤에도 같은 경고 · 표시가 계속된다. 채움은 기간 한정이라 기간 밖 평가의 빈 구간은 남는다 — 지금 값으로 되돌리기만 하면 그 경고를 잃는다.
- 평가마다 쓴 저장 기준은 기록하지 않는다. 회차는 기준을 시작 때 읽고 평가 시각은 결과 뒤에 찍는다 — 회차는 점유 기간(30분) 안에 끝난다.
- 운영자 화면의 기준 상태 표시(#73)도 같은 지식을 쓴다.

## 결정

- **저장 바닥을 평가 시각 축에서 계산하는 순수 함수 하나가 정본이다.** 입력은 그 버전 · 태그 종류의 이력과 끝난 채움의 덮음(덮은 범위 · 채운 기준)이다. 지난 저장 기준 최댓값과 기간 안 바닥이 섞였는지를 이 함수가 낸다 — 경고 · 평가 현황 · 기준 상태가 함께 부른다.
- **평가 시각 t 의 바닥은 `[t − 30분, t]` 에 유효했던 저장 기준의 최댓값이고, t 를 덮은 채움이 있으면 그 값과 채운 기준 가운데 작은 것이다.** 이력 행은 다음 행까지 양 끝을 포함해 유효하다. 읽기 지연 30분은 평가 회차의 점유 기간이다.
- **끝났고 그 버전에서 건너뛴 평가가 없는 채움만 덮음이다.**
- **평가 현황의 표시는 집계 기간 안에서 바닥이 둘 이상인가다** — 응답 필드 이름(`storeThresholdChanged`)은 그대로 둔다.
- **판단은 모두 바닥을 크게 잡는 쪽이다** — 경고를 놓치지 않는다. 시각 축으로 판단해 실제 평가가 없는 시각도 본다.

## 결과

- 채운 만큼 경고 · 표시가 사라지고, 기간 밖 빈 구간의 경고는 남는다. 버전 전체를 덮으면 지난 저장 기준 최댓값이 지금 값까지 내려온다. 채움이 없으면 경고는 이전과 같다.
- 저장 기준을 내린 뒤 30분 안에 채움을 요청하면 "요청 시각부터 내린 시각 + 30분까지"가 덮이지 않아 경고가 남는다 — 운영 안내가 30분 뒤 요청을 권한다.
- 평가 현황 표시는 채움이 없어도 기간 밖의 변경을 더는 알리지 않는다 — 기간 안 평가의 바닥이 하나면 거짓이다.
- 경고는 여전히 그 구간에 실제로 평가된 기사가 있었는지 모른다 — 이력과 채움 기록으로만 판단한다.
- 채움 기록은 계산의 입력이라 지우지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 경고 · 표시를 이력만으로 그대로 둔다 | 채운 뒤에도 같은 경고가 계속 떠 곧 무시된다(ADR-0055 가 기각한 "변경마다 경고"와 같은 문제) |
| 평가 행마다 쓴 저장 기준을 기록하고 채움이 낮춘다 | 평가 행을 고쳐야 하고, 이미 있는 행의 값은 결국 이력으로 되짚어야 하며, 기준 변경마다 버전 전체 평가를 훑는다 |
| 채운 뒤 지난 최댓값을 지금 값으로 되돌린다 | 기간 밖 평가의 빈 구간 경고를 잃는다 |
| 진행 중 채움도 커서까지 덮음으로 본다 | 계산이 복잡해지고 건너뜀과 섞인다 |
| 평가 현황 표시를 이력만으로 두고 경고만 바꾼다 | 같은 지식이 두 계산이 되고, 채운 뒤 표시의 뒷부분("평가마다 다른 기준으로 저장됐다")이 틀린다 |
| 응답 필드 이름을 뜻에 맞게 바꾼다 | 계약 · 화면 · 기준 상태가 함께 바뀌는데, 지금 이름도 기간 안 평가의 저장 기준이 달랐다는 뜻으로 읽힌다 |
