# ADR-0162: KEK 가 없거나 형식이 틀리면 두 역할 모두 기동하지 않는다

- 상태: 승인
- 날짜: 2026-11-14
- 근거: [이슈 #150](https://github.com/Theia0382/yozm-news/issues/150)
- 관련: [ADR-0161](0161-the-kek-comes-from-a-file-in-the-configuration-directory.md)(KEK 를 주는 방법), [ADR-0061](0061-worker-role-does-not-run-without-an-evaluator.md)(필수 값이 없으면 기동하지 않는 선례 — 작업 역할)

## 맥락

- KEK 가 없으면 키를 등록할 수 없고 저장한 키를 열 수 없다. 사용자는 로그인은 되지만 키 화면에서 더 나아가지 못한다.
- 화면 역할은 등록에, 작업 역할은 재암호화와 저장한 키의 호출에 KEK 를 쓴다.

## 결정

- **KEK 설정이 없거나, 파일이 없거나 읽지 못하거나, 형식이 틀리면 두 역할 모두 기동하지 않는다.** 문구는 설정 이름 · 환경 변수 이름 · 경로 · 문제의 줄을 말하고 값을 담지 않는다.

규칙은 [credential Spec](../specs/credential.md#kek) credential-R5 에 있다.

## 결과

- 키를 등록할 수 없는 인스턴스가 조용히 뜨지 않는다.
- 이미 돌고 있는 인스턴스는 이 판으로 올릴 때 KEK 파일을 만들어야 뜬다. 시험 · 로컬 개발 · 배포 스모크도 값을 가져야 한다.
- 두 역할 모두에 필수인 설정은 이것이 처음이다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 키 기능을 닫은 채 뜬다 | 사용자가 아무것도 못 하는 인스턴스가 경고 하나로 뜬다. 닫힘 상태의 화면 · API 갈래가 하나 더 생긴다 |
| 없으면 앱이 KEK 를 만들어 쓴다 | 만든 값을 어디에 둘지가 다시 문제다 — DB 에 두면 감싸는 뜻이 없고, 파일에 쓰려면 설정 디렉터리가 쓰기 가능해야 한다 |
