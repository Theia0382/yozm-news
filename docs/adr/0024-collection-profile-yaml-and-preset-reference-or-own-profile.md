# ADR-0024: 수집 프로필은 YAML 로 쓰고, 소스는 프리셋을 참조하거나 자기 프로필을 갖는다

- 상태: 승인
- 날짜: 2026-10-27
- 근거: [이슈 #17](https://github.com/Theia0382/yozm-news/issues/17) — 기점 `ee32e8f` 의 저장소와 snakeyaml-engine 3.0.1 · jackson-dataformat-yaml 3.1.7(Maven Central 바이너리 · 소스 jar)을 실행해 확인
- 관련: [ADR-0015](0015-source-presets-and-collection-profiles.md)(수집 프로필 · 프리셋 — 프리셋이 있는 소스를 운영자가 다루는 방식을 이 ADR 이 대체한다), [ADR-0013](0013-architecture-patterns.md)(판단은 `domain`)

## 맥락

- [ADR-0015](0015-source-presets-and-collection-profiles.md)는 수집 프로필의 내용과, 프리셋과 운영자 프로필이 같은 형식 · 같은 엔진을 쓴다는 것을 정했다. 텍스트 표기, 스키마의 정본, 운영자 프로필과 프리셋의 관계, 수집 주기를 누가 정하는지는 정하지 않았다.
- 프로필은 사람이 손으로 쓴다. 개발팀은 프리셋 파일을 PR 로 리뷰하고, 운영자는 화면에서 원문을 편집한다. 보정 규칙마다 왜 필요한지 옆에 적을 자리가 있어야 리뷰가 된다.
- 프로필의 내용(피드 목록 · 사전 보정 규칙 · 필드 매핑 · 날짜 형식)은 그 언론사 피드에 대한 사실이다. 같은 피드를 읽는 운영자마다 달라질 이유가 없고, 다르다면 프리셋을 고칠 일이다. 수집 주기는 다르다 — 피드에 대한 사실이 아니라 운영자가 고르는 운영 선택이다.
- 운영자 값을 프리셋 위에 합치려면 병합 규칙, 값마다 누가 정했는지의 표시, 프리셋 갱신이 저장된 운영자 값과 부딪히는 경우의 처리가 함께 필요하다.
- YAML 은 별칭 · 태그 · 같은 매핑 안 중복 키처럼 값을 조용히 바꾸거나 해석기에 따라 뜻이 달라지는 구문을 가진다. 파서 설정에 거부를 맡기면 규칙이 메커니즘에 숨는다. Jackson 3 YAML 모듈의 스트리밍 파서는 매핑 첫 키의 태그를 보여 주지 않고, 매핑의 앵커를 첫 키에 한 번 더 보여 준다.

## 결정

- **텍스트 표기는 YAML 이다.** 프리셋 파일과 운영자 원문이 같은 표기를 쓴다. 해석은 YAML 1.2 JSON 스키마 규칙을 따른다 — 불리언은 소문자 `true` · `false` 뿐이고, `no` · `015` 는 문자열이다. JSON 텍스트도 같은 읽기기로 읽힌다.
- **YAML 은 snakeyaml-engine 의 이벤트 API 로 읽는다.** 객체를 만드는 단계(Composer · Constructor)를 거치지 않으므로 태그로 Java 객체가 생기는 경로가 없다. 키와 값의 앵커 · 태그 · 위치를 모두 그대로 받는다. Spring Boot 가 버전을 관리하지 않으므로 버전을 직접 고정한다.
- **읽기와 판정을 나눈다.** 읽기기는 판정 없이 트리를 만들고, 거부는 `source` 모듈의 `domain` 코드가 한다. 어디서든 거부하는 것은 알 수 없는 키, 같은 매핑 안 중복 키, 앵커 · 별칭 · 명시 태그, `null` 값, 여러 문서, 최상위가 매핑이 아닌 문서, 상한(65,536자)을 넘는 텍스트다. 문제는 경로 · 줄:열과 함께 한 번에 모두 돌려준다.
- **스키마의 정본은 `source` 모듈 `domain` 의 모델과 검증기다.** JSON Schema 파일은 두지 않는다. 날짜 패턴 컴파일 · 시간대 · 필드 기준 고유성처럼 JSON Schema 로 표현하지 못하는 규칙이 있어, 두면 규칙이 두 곳이 된다.
- **프리셋은 `backend/src/main/resources/source-presets/{key}.yaml` 에 하나씩 둔다.** 파일 이름이 프리셋 키(`sources.preset_key`)다. 프리셋 파일에는 이용조건 검토일(`termsReviewedAt`)이 반드시 있다. 기동 때 모든 프리셋을 검증하고 하나라도 실패하면 기동을 멈춘다.
- **소스는 프리셋을 참조하거나 자기 프로필을 갖는다.** 프리셋을 참조하는 소스는 프로필을 DB 에 복사하지 않고 `sources.preset_key` 로 가리키므로, 프리셋이 바뀌면 다음 배포부터 바뀐 프리셋으로 수집한다. 그 밖의 소스는 자기 프로필(운영자 프로필)을 갖는다.
- **운영자 프로필은 언제나 완결된 프로필이다.** 프리셋 원문을 복사해 고쳐 쓸 수 있지만, 모델은 그 프로필이 어느 프리셋에서 왔는지 모르고 프리셋 위에 값을 합치지 않는다. 운영자 프로필과 프리셋 파일은 같은 읽기기 · 검증기를 거친다.
- **이용조건 검토일은 프로필에 있다.** 프리셋은 반드시 적고, 운영자 프로필은 선택이다 — 없으면 활성화 관문이 켜지 못하게 막는다. 그래서 프리셋 원문을 그대로 복사해도 운영자 프로필로 통과한다. 검토일을 DB 의 소스 행에 따로 두지 않는다.
- **프로필의 수집 주기는 권장 기본값이고, 실제 주기는 운영 설정이다.**
  - 프로필에는 소스 주기와 피드별 주기를 적을 수 있다(둘 다 선택).
  - 운영자는 소스 · 피드 단위로 주기를 정할 수 있다. 프리셋을 참조하는 소스도 프로필을 고치지 않고 정한다.
  - 실제 주기는 운영자 피드 설정 → 운영자 소스 설정 → 프로필 피드 값 → 프로필 소스 값 → 15분 순으로 처음 있는 값이다.
  - 하한 15분은 프로필 값과 운영 설정 모두에 적용한다. 기본값과 하한은 운영 데이터로 다시 판단한다.
  - 수집 주기 밖의 프로필 항목은 운영 설정으로 바꾸지 않는다.

## 결과

- [ADR-0015](0015-source-presets-and-collection-profiles.md)의 "프리셋이 있는 소스는 운영자가 켜고 끄기만 하고, 프리셋을 참조하면서 필요한 항목만 덮어쓴다"는 이렇게 바뀐다 — 프리셋을 참조하는 소스에서 운영자는 소스 · 피드를 켜고 끄고 수집 주기를 정한다. 그 밖의 항목을 바꾸려면 프리셋을 복사해 자기 프로필로 만든다. 덮어쓴 항목을 표시하는 일은 없다.
- "프리셋을 고쳐 배포하면 모든 운영자에게 전달된다"는 프리셋을 참조하는 소스에서 성립한다. 프리셋을 복사해 고친 소스는 이후 프리셋 수정을 받지 못하고, 받으려면 운영자가 다시 복사한다.
- 병합이 없으므로 프리셋 갱신이 저장된 운영자 프로필을 검증에 걸리게 만들지 않는다. 대신 프리셋 배포가 피드를 빼거나 프리셋 파일을 지우면, 그 프리셋을 참조하는 소스의 피드 · 프리셋 키가 가리킬 곳을 잃는다. 수집 쪽이 이것을 처리한다.
- 운영자 프로필에는 코드를 넣을 수 없으므로, 프리셋 전용 코드([ADR-0015](0015-source-presets-and-collection-profiles.md))에 기대는 프리셋은 원문을 복사해도 그 보정이 운영자 프로필로 옮겨지지 않는다.
- 개발팀은 프리셋의 보정 규칙 옆에 주석으로 이유를 적고, 운영자가 프리셋 원문을 복사하면 주석도 함께 온다. 운영자 원문을 jsonb 로 저장하면 주석 · 서식은 남지 않는다. 원문을 함께 보존할지는 소스 저장 · 편집 화면을 만들 때 정한다.
- 프로필의 키 이름 · 프리셋 키 · 피드 식별자는 DB 에 저장된 값이 가리킨다. 바꾸려면 데이터 이행이 함께 있어야 한다.
- snakeyaml-engine 의 버전은 직접 올린다. 판이 바뀌면 읽기기 테스트가 이벤트 동작(키 · 값의 앵커 · 태그, 별칭, 중복 키, 위치)의 변화를 드러낸다.
- 수집 주기를 15분보다 짧게 할 수 없다. 넘침(수집 간격 동안 새 기사가 피드에 싣는 건수를 넘는 경우)을 감지하는 신호로 다시 판단한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| JSON 표기(프리셋 · 운영자 원문 모두) | DB 저장 형태와 같지만, 사람이 손으로 쓰기 어렵고 보정 규칙 옆에 이유를 적을 주석이 없다 |
| 프리셋은 YAML, 운영자 원문은 JSON | 프리셋을 복사해 운영자 프로필을 시작하거나 운영자 프로필을 프리셋으로 옮길 때 변환이 필요하고, 두 표기를 문서화 · 테스트해야 한다 |
| Jackson 3 YAML 모듈의 스트리밍 파서로 읽는다 | 매핑 첫 키의 태그가 보이지 않고 매핑 앵커가 첫 키에 한 번 더 보여, 태그 · 앵커 거부가 어디서든 성립하지 않는다 |
| Jackson databind 로 모델에 바로 바인딩하고 파서 설정으로 알 수 없는 키 · 중복 키를 막는다 | 규칙이 파서 설정에 숨고, 값마다 경로 · 위치를 달 수 없어 오류 위치를 알리기 어렵다 |
| JSON Schema 파일을 스키마 정본으로 둔다 | 날짜 패턴 · 시간대 · 필드 기준 고유성을 표현하지 못해 같은 규칙을 Java 에 또 두게 된다 |
| 운영자 값을 프리셋 위에 값 단위로 합친다 | 프로필 내용은 피드에 대한 사실이라 운영자마다 달라질 이유가 없다. 병합 규칙 · 값의 출처 표시가 필요하고, 프리셋 갱신이 저장된 운영자 값과 부딪혀 운영 중인 소스가 검증에 걸리는 경우가 생긴다 |
| 프리셋도 복사해서만 쓴다 | 프리셋을 고치지 않고 쓰는 소스가 언론사 형식 변경에 맞춘 프리셋 수정을 배포로 받지 못한다 |
| 수집 주기를 프로필 값으로만 둔다 | 주기만 바꾸려는 운영자도 프리셋을 복사해야 하고, 그러면 프리셋 수정을 잃는다 |
| 프리셋 참조를 프로필 텍스트의 프리셋 키로 나타낸다 | `sources.preset_key` 와 같은 사실의 사본이 된다 |
| 수집 주기 하한 5분, 또는 양수면 허용 | 운영 데이터 없이 언론사에 더 잦은 요청을 허용하게 된다. 기본값과 같은 15분에서 시작해 넘침 신호로 다시 판단한다 |
| 소스 단위 수집 주기 하나 | 같은 언론사의 피드끼리 받는 빈도를 다르게 할 수 없다 |
