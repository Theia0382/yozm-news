# ADR-0067: ADR 의 부분 대체는 상태 줄과 대체된 문장 위 표시로 알리고, 결정을 바꾸지 않는 보충은 후속 기록으로 남긴다

- 상태: 승인
- 날짜: 2026-11-04
- 근거: [이슈 #49](https://github.com/Theia0382/yozm-news/issues/49) — 기점 `d31e2a7` 의 ADR 66개에서 상태 줄 · `관련:` 줄 · 본문의 다른 ADR 인용 · 후속 기록을 서로 대조했고, 대체 표시를 표 · 목록 옆에 둔 견본을 CommonMark 렌더러(markdown-it-py, 표 확장)로 렌더링해 확인
- 관련: [ADR-0034](0034-module-spec-as-public-interface-specification-and-docs-by-kind.md)(문서를 종류 · 독자별 갈래로 나눈다 — 대체 표시가 가리키는 현재 상태 문서), [ADR-0037](0037-domain-may-use-non-replaceable-framework-types.md)(후속 기록은 다른 ADR 을 가리키는 자리)

## 맥락

- ADR 은 merge 뒤 본문을 고치지 않는다. 고칠 수 있는 것은 상태 줄 · 말미 후속 기록 · 형식 정정뿐이었고, 결정을 바꿀 때는 새 ADR 을 쓰고 옛 ADR 의 상태 줄만 고쳤다.
- 결정의 일부만 바꾸는 새 ADR 이 쌓였다. 결정 시점에 상태 줄이 알린 부분 대체는 ADR 18개에 33건이었다. 상태 줄은 "○○ 부분은 ADR-NNNN 이 대체"라고만 적어 본문의 어느 문장이 무효인지 알 수 없었고, 읽는 사람이 여러 ADR 을 겹쳐 읽으며 무효 문장을 머릿속으로 지워야 했다.
- 같은 성격의 변경을 ADR 마다 다른 말로 적었다 — 같은 좁힘 · 넓힘을 어떤 상태 줄은 "대체", 어떤 상태 줄은 "넓힘"으로 적었다. ADR 목록 표의 상태 열은 상태 줄을 다시 적은 사본이라, 대체한 ADR 번호가 다르거나 상태 줄의 "부분 대체"를 "대체"로 적은 행이 있었다.
- 새 ADR 이 `관련:` 줄이나 본문에서 옛 ADR 을 바꾸거나 보충한다고 선언했는데 옛 ADR 에는 기록이 없는 것이 13건이었다. 그 가운데 4건은 옛 문장을 지금 읽으면 틀린 것을 믿게 되는 변경이었다.
- 선별 기준은 공개 문서에 없었다. 갱신 트리거가 "ADR 선별 기준 충족"을 말했지만 정의한 곳이 없었다.

## 결정

- **부분 대체는 옛 ADR 의 상태 줄과, 대체된 문장 바로 위의 대체 표시 한 줄로 알린다.** 대체 표시를 merge 뒤 허용 수정에 더한다. 대체된 문장은 지우거나 고치지 않는다.
- **부분 대체와 보충은 질문 하나로 가른다 — 옛 문장을 지금 읽으면 지금 결정과 다른 것을 믿게 되는가.** 그렇다면 부분 대체다. 좁힘 · 넓힘 · 철회도 여기에 들고, 이름은 "부분 대체" 하나로 쓴다. 아니면 보충이다 — 미뤄 둔 사항을 다른 ADR 이 정했거나, 옛 범위 밖으로 더했거나, 문면이 구현과 어긋나는 것 등이고, 말미 후속 기록에 남긴다.
- **대체 표시는 대체한 ADR 과 지금 상태의 자리만 적는다.** 자리는 그 지식을 소유한 현재 상태 문서의 절이다 — `overview` · 모듈 Spec 에 그치지 않고 개발 인프라 · 운영 · 전환 중 문서까지 문서 위계 전체에서 고르고, 규칙 식별자가 있으면 함께 적는다. 소유 문서가 없으면 자리를 뺀다. 새 결정의 내용은 옮겨 적지 않는다.
- **상태 줄은 대체된 부분의 이름과 대체한 ADR 을, ADR 목록 표의 상태 열은 대체한 ADR 번호만 적는다.**
- **후속 기록은 날짜와 한 줄로, 옛 자리와 그 자리를 정하거나 보충한 ADR · 지금 상태 문서의 자리만 적는다.** 정해진 내용은 옮겨 적지 않는다.
- **새 ADR 은 `관련:` 줄에 옛 ADR 과 그 범위를 적고, 같은 작업에서 옛 ADR 에 알린다.**
- 이미 있는 ADR 에도 소급한다 — 상태 줄이 알린 부분 대체와, 새 ADR 이 선언했는데 옛 ADR 에 기록이 없는 것. 어느 쪽에도 선언되지 않은 부분 대체를 찾는 전체 감사는 하지 않는다.
- 규칙(선별 기준 · 결정 하나에 파일 하나 · 대체와 보충 · 대체 표시 · 상태 줄과 목록 표 · 후속 기록)의 정본은 [docs/adr/README.md](README.md#운영-규칙)다. merge 뒤 허용 수정의 목록은 [docs/README.md §4](../README.md#4-작성-규칙)가 갖는다.

## 결과

- 옛 ADR 을 연 사람은 상태 줄에서 무효인 부분을 보고, 본문에서 무효 문장 바로 위의 표시를 따라 지금 상태 문서로 간다. 여러 ADR 을 겹쳐 읽지 않아도 된다.
- 결정 내용은 새 ADR 과 현재 상태 문서에만 있다. 표시 · 상태 줄 · 후속 기록 · 목록 표는 가리키기만 하므로, 그 결정이 다시 바뀌어도 낡은 사본이 남지 않는다. 대신 무엇이 정해졌는지 알려면 링크를 따라가야 한다.
- 표시는 원문의 구조 안에 들어간다. 표 안의 문장은 표 바로 위에, 하위 목록 안의 문장은 상위 항목의 들여쓰기에 맞춰 단다. 최상위 목록 항목 사이에 단 표시는 목록을 둘로 나누지만 화면에서는 이어진 목록에 표시가 끼어든 모양이다. 표시 바로 다음이 표 · 문단이면 빈 줄이 없을 때 그 줄이 표시에 붙으므로 빈 줄을 둔다.
- 현재 상태 문서의 내용이 다른 문서로 옮겨지면 표시의 자리가 낡는다. 링크가 깨지면 문서 검사가 잡지만, 절이 남고 내용만 옮겨진 경우는 잡지 못한다 — 옮기는 작업이 표시도 고친다.
- 새 ADR 을 쓰는 작업이 옛 ADR 몇 곳을 함께 고친다. 판정이 질문 하나라 쓰는 사람마다 갈리기 어렵지만, 어느 문장이 대체됐는지는 쓰는 사람이 읽고 정한다.
- 기존 후속 기록의 요지 서술은 기록이라 고치지 않는다. 새 항목만 가리키는 꼴로 쓴다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 상태 줄만 고친다(지금까지의 방식) | 본문의 어느 문장이 무효인지 읽는 자리에서 알 수 없다 — 이 결정이 고치려는 문제다 |
| 말미 후속 기록에만 적는다 | 무효 문장과 기록이 떨어져 있어, 본문을 읽는 사람이 끝까지 내려가 맞대 봐야 한다 |
| 부분 대체를 금지하고, 일부를 바꿀 때도 옛 ADR 을 전체 대체하는 새 ADR 을 다시 쓴다 | 바뀌지 않은 결정까지 새 ADR 에 옮겨 적어 사본이 생기고, 묶음 ADR 하나를 바꿀 때마다 큰 문서를 다시 쓴다 |
| 대체 · 좁힘 · 넓힘 · 철회를 종류로 나눠 모두 표시한다 | 같은 변경을 어느 이름으로 적을지가 쓰는 사람마다 갈린다 — 지금 이미 갈렸다 |
| 대체만 표시하고 좁힘 · 넓힘 · 철회는 후속 기록으로 둔다 | 좁혀지거나 철회된 문장도 지금 읽으면 틀린 것을 믿게 하는데, 읽는 자리에서 알 수 없다 |
| 지금 상태의 자리를 `overview` · 모듈 Spec 으로 한정한다 | 대체된 지식의 3분의 1 남짓은 개발 인프라 · 운영 · 전환 중 문서가 소유해 가리킬 곳이 없다. 대체한 ADR 을 거쳐 찾게 되는데, 그 ADR 도 다시 대체될 수 있다 |
| 상태 줄과 목록 표 모두 대체된 부분을 서술한다 | 같은 서술이 상태 줄 · 목록 표 · 표시 세 곳에 생기고, 이미 어긋났다 |
| 상태 줄과 목록 표 모두 대체한 ADR 번호만 적는다 | 긴 ADR 에서 무효인 자리를 찾으려면 본문의 표시를 다 훑어야 한다 |
| 후속 기록에 정해진 내용의 요지를 한 구절 허용한다 | 보충한 결정이 바뀌면 그 요지가 낡는다 — 대체 표시가 피하는 사본이 후속 기록에 생긴다 |
| 선언되지 않은 부분 대체까지 모든 ADR 을 내용으로 감사한다 | 끝을 정하기 어렵고, 옛 문장마다 현재 상태 문서와 맞대는 별개의 일이다. 발견될 때 이 규칙대로 고친다 |
