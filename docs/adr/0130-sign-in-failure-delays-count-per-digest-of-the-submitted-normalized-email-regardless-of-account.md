# ADR-0130: 로그인 실패 지연은 제출된 정규화 이메일의 다이제스트마다 세고, 계정 유무와 무관하게 같은 기록과 지연을 준다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #145](https://github.com/Theia0382/yozm-news/issues/145) — 기점 `a02a205` 의 설계 문서가 실패 횟수를 계정이 있을 때만 있는 자격 행에 두어, 없는 계정에는 지연이 걸리지 않음을 확인
- 관련: [ADR-0044](0044-screen-api-results-as-flat-discriminated-200-and-rfc9457-problems.md)(대기는 판정 결과 200), [ADR-0123](0123-v1-login-is-local-only-and-oidc-and-account-linking-come-after-v1.md)(복구 코드 — 같은 규칙을 따를 대상)

## 맥락

- 로그인 실패는 계정 유무와 상관없이 같은 응답이어야 하고, 연속 실패에는 잠금이 아니라 지연을 점점 늘린다.
- 실패 횟수를 계정 행에 두면 없는 이메일에는 지연이 걸리지 않는다. 몇 번 틀린 뒤 "기다리라"는 응답이 오면 계정이 있다는 뜻이 된다.
- 지연 중에 비밀번호를 대조하고 결과만 늦게 주면 서버가 요청을 붙잡고 기다려야 한다.

## 결정

- **실패 기록은 제출된 이메일을 정규화한 값의 SHA-256 다이제스트마다 하나다.** 계정 유무와 무관하다. 다이제스트에 열쇠를 두지 않는다 — 있는 계정의 이메일은 DB 의 계정 표에 이미 있고, 없는 이메일의 기록은 24시간 뒤 지운다.
- **지연 일정** — 마지막 실패에서 24시간 안의 연속 실패가 3회까지는 지연이 없고, 4회째부터 1초에서 두 배씩 늘어 15분이 상한이다. 성공하면 기록을 지운다.
- **지연 중에는 비밀번호를 대조하지 않는다** — 맞는 비밀번호도 받지 않는다. 응답은 판정 결과(대기 · 남은 초)다.
- **한 시도는 실패 기록 행을 잠근 트랜잭션 하나다** — 같은 이메일의 동시 시도는 줄을 서서 지연을 건너뛰지 못한다.

## 결과

- 있는 계정과 없는 계정이 같은 기록 · 같은 지연 · 같은 응답을 받는다. 있는 계정에서는 계정별 지연과 같다.
- 남의 이메일로 일부러 틀려 그 사람의 로그인을 지연 상한(15분)까지 늦출 수 있다. IP 별 요청 제한이 함께 줄인다.
- 시도마다 DB 연결을 해시 대조 시간만큼 쥔다.
- 없는 이메일의 기록도 쌓이므로 작업 역할이 오래된 기록을 지운다. 일정 값은 [user Spec](../specs/user.md#로그인) user-R19 가 정본이다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 계정의 자격 행에 실패 횟수 | 없는 계정에 지연이 걸리지 않아 계정 존재가 드러난다 |
| 지연 중에도 대조하고 응답만 늦춘다 | 서버가 요청 스레드를 붙잡아, 공격자가 서버 스레드를 묶을 수 있다 |
| 다이제스트에 운영 비밀 열쇠(HMAC) | 새 필수 비밀 설정이 필요한데, DB 를 가진 사람은 있는 계정의 이메일을 이미 본다 |
