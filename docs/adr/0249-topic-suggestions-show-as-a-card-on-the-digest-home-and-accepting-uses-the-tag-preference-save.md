# ADR-0249: 구독 제안은 다이제스트 홈에 카드로 보이고 수락은 태그 선호 저장을 쓴다

- 상태: 승인
- 날짜: 2026-11-19
- 근거: [이슈 #188](https://github.com/Theia0382/yozm-news/issues/188) — 제안을 둘 화면(다이제스트 홈 · 관심 설정 · 관심사 히스토리)을 정함. 구현 커밋 `ac24312` · `b9ad4a3`
- 관련: [ADR-0237](0237-the-digest-home-shows-the-latest-date-and-every-date-has-its-own-page-and-a-list.md)(다이제스트 홈), [ADR-0192](0192-reader-screens-are-composed-by-the-reader-module-over-module-public-queries.md)(제안 조회는 `reader` 가 엮는다), [ADR-0246](0246-a-declined-topic-suggestion-returns-only-after-a-period-and-a-higher-interest-and-a-decline-is-not-an-interest-signal.md)(거절의 효과)

## 맥락

- 다이제스트 홈은 사용자가 매일 들어오는 곳이다. 관심 설정 · 관심사 히스토리는 드물게 연다.
- 제안은 날짜에 묶이지 않은 지금의 판정이다.
- 주제 구독의 저장은 관심 설정의 태그 선호 저장 하나이고, 선호 전체(주제 · 지역 · 형식)를 화면이 본 체계 버전과 함께 보낸다.
- 거절 뒤 다시 내지 않는 기간의 값은 서버의 상수다.

## 결정

- **제안은 다이제스트 홈에만 카드로 보인다.** 제안이 있을 때만 그리고, 날짜마다의 화면에는 두지 않는다. 주제는 "대분류 · 중분류" 이름으로 보이고 "구독" · "괜찮아요" 를 고른다.
- **수락은 태그 선호 저장을 쓴다.** 화면이 지금 선호에 그 중분류를 더해 제안이 낸 체계 버전과 함께 보낸다. 제안과 선호의 버전이 다르면 보내지 않고 둘을 다시 읽는다. 수락을 따로 기록하지 않는다.
- **거절은 `user` 의 거절 처리기로 보낸다.** 체계 버전이 바뀌었으면 안내 없이 제안과 선호를 다시 읽는다.
- **문구에 다시 권하지 않는 기간의 숫자를 적지 않는다.** 문구의 정본은 화면 코드 한 곳이다.
- 지금 상태는 [reader Spec "구독 제안"](../specs/reader.md#구독-제안) reader-R12 다.

## 결과

- 좋아요를 누른 다음 날 홈에서 제안을 본다. 홈을 열 때마다 제안 조회가 관심 재료를 읽는다 — 비용은 재지 않았다.
- 수락과 관심 설정 화면의 저장이 같은 저장을 지나 같은 규칙(정규화 · 이력 · 버전 검사)을 따른다. 다른 탭에서 선호를 바꾸는 중이면 늦게 쓴 쪽이 이긴다 — 관심 설정 화면과 같다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 관심 설정 화면의 "구독할 주제" 위에 둔다 | 드물게 여는 화면이라 제안을 보지 못한다 |
| 관심사 히스토리 화면에 둔다 | 가장 드물게 여는 화면이고, 히스토리 응답과 화면 갈래가 섞인다 |
| 수락용 "주제 하나 더하기" 처리기를 새로 연다 | 주제 구독의 저장이 둘이 된다 |
