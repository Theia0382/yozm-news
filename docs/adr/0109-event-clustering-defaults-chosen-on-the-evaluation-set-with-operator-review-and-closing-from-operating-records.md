# ADR-0109: 사건 묶기 기본값은 기본 임베딩 모델에 맞춰 평가 세트로 견주고 운영자 표본 검수로 확인해 정하며, 반감기는 상수로 두고 닫는 기간은 시간 창에 늦은 수집의 여유를 더한다

- 상태: 승인
- 날짜: 2026-11-11
- 근거: [이슈 #102](https://github.com/Theia0382/yozm-news/issues/102) — 측정 인스턴스에서 라벨 기준 2판 평가 세트로 사건 기준 · 반감기 · 핵심 말 가중치 · 시간 창과 임베딩 모델 셋을 견주고, 리드가 고른 값의 사건 표본을 검수하고, 실측 인스턴스의 운영 기록으로 닫는 기간을 정함
- 관련: [ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)(결정 절 "임계값 · 시간 창 · 모델은 평가 세트로 정한다"와 결과 절 "운영자가 표본을 검수해 임계값을 조정한다"의 첫 값 — 보충), [ADR-0081](0081-event-assignment-criteria-in-settings-and-rejudgement-within-stored-scores.md)(사건 기준 · 저장 기준 기본값의 "측정 전 목표" — 보충), [ADR-0086](0086-events-close-after-an-idle-period-since-the-last-join-or-a-maximum-period-since-opening.md)(닫는 기간 · 최대 기간 기본값의 "측정 전 목표" — 보충), [ADR-0102](0102-an-event-is-the-reports-of-one-happening-narrowed-by-the-event-membership-question-wording.md)(반감기의 값 — 보충), [ADR-0090](0090-article-embedding-defaults-to-an-in-app-local-model-with-an-openai-compatible-api-by-setting.md)(기본을 외부로 옮길 조건 — 보충), [ADR-0096](0096-instance-bound-evaluation-data-kept-out-of-the-public-repository-and-defaults-cite-only-the-evaluation-set.md)(근거 수치를 공개 문서에 적지 않는다)

## 맥락

- 사건 기준(시간 창 · 위 · 아래 · 확률 기준) · 저장 기준 · 닫는 기간 · 최대 기간의 기본값과, 점수 산식의 반감기 · 핵심 말 가중치 상수는 측정 전 목표였다.
- 점수 분포는 임베딩 모델마다 크게 다르다. 기본 로컬 모델은 다른 일의 기사 쌍도 점수가 높아, 측정 전 기본값에서는 시각이 가까운 후보 대부분이 Jev 에 묻는 띠에 들었다. Jev 호출은 운영자 비용이다.
- 기준을 바꾸면 앱은 저장된 점수 · 확률로 지난 배정을 다시 판정한다([ADR-0081](0081-event-assignment-criteria-in-settings-and-rejudgement-within-stored-scores.md)). 이 재판정은 이미 묶인 상태에서 출발하므로 처음부터 그 기준으로 묶은 결과와 같지 않다. 반감기 · 가중치는 저장된 점수를, 시간 창은 후보를 바꾸므로 재판정으로 견줄 수 없다.
- 평가 세트는 하루 단위 라벨이고 묶음 정확도(B-cubed)를 잰다([ADR-0095](0095-event-clustering-evaluated-by-an-operator-tool-comparing-admin-api-results-with-full-day-labels.md)). 표본은 이틀치다.

## 결정

- **기본값은 기본 임베딩 모델에 맞춰 평가 세트로 정한다.** 사건 기준 후보는 기준만 바꾼 재판정으로 추리고, 반감기 · 가중치 · 시간 창은 처음부터 다시 묶어 견주며, 고른 조합은 처음부터 다시 묶어 확인한다. 차이는 정답 사건 단위로 다시 뽑은 구간으로 보고, 구간 안의 차이는 같은 품질로 본다. 같은 품질의 후보 가운데서는 처음부터 다시 묶어 확인하고 표본 검수를 거친 조합을 고른다.
- **고른 값은 운영자 표본 검수로 확인한다.** 그 값으로 묶은 사건(기사 2건 이상)을 씨앗을 밝혀 무작위로 뽑고, 운영자가 사건마다 다른 일의 기사가 섞였는지 판정한다. 같은 일이 여러 사건으로 갈렸는지는 표본 검수가 아니라 평가 세트의 재현율로 본다.
- **반감기 · 핵심 말 가중치는 코드 상수로 두고 값만 정한다.** 하나의 값이 측정한 임베딩 모델 모두에서 그 모델의 최선과 구별되지 않으면 설정으로 올리지 않는다.
- **기본 임베딩 모델은 그대로 둔다.** 같은 평가 세트에서 외부 모델 둘과 견줬고 묶기 품질이 구별되지 않았다. 외부 모델은 그 모델에 맞춘 기준에서 Jev 호출이 더 적었지만, 운영자에게 외부 키 · 임베딩 비용 · 수집마다의 외부 호출이 더해진다.
- **측정한 외부 모델의 권장 기준은 운영 안내에 둔다.** 같은 평가 세트로 정한 값이고, 측정한 모델에만 맞는다.
- **닫는 기간은 시간 창에 늦은 수집을 덮는 여유를 더한 값으로, 운영 기록으로 정한다.** 시간 창보다 오래 쉰 사건에는 기사가 붙지 않으므로 그보다 긴 닫는 기간은 사건이 열린 시간만 늘린다. 실측 인스턴스의 늦은 수집과 사건 안 기사 간격으로 여유를 정했다. 최대 기간은 측정이 그 길이를 담지 못해 측정 전 목표로 둔다.
- 값의 정본은 설정 클래스 · 산식 상수와 [event Spec §7](../specs/event.md#7-설정) · [§4](../specs/event.md#4-내부-구조)이고, 근거 수치는 공개 문서에 적지 않는다([ADR-0096](0096-instance-bound-evaluation-data-kept-out-of-the-public-repository-and-defaults-cite-only-the-evaluation-set.md)).

## 결과

- 기본값은 측정 인스턴스(그 소스 구성의 한국어 기사, 기본 로컬 모델)의 분포에 맞춰졌다. 다른 소스 구성이나 모델에서는 운영자가 표본을 검수해 맞춘다.
- 아래 기준이 Jev 가 같은 사건이라 답하는 일이 드문 점수 구간 위로 올라가, 그 구간의 기사는 묻지 않고 새 사건을 연다.
- 반감기가 길어져 시각 차가 큰 같은 일의 기사가 붙기 쉬워졌다. 반감기는 기준 이력에 들지 않아 반감기만 바뀐 판으로 올리면 재판정이 돌지 않는다. 재판정은 언제나 저장된 점수(판정 때의 반감기)로 하고, 새 반감기는 새 배정과 병합의 점수부터 쓴다.
- 운영 안내의 표에 없는 모델로 바꾸는 운영자는 기준을 직접 맞춘다.
- 평가에서 병합 판정은 같은 일인 사건 쌍도 대부분 합치지 않았다. 기준값이 아니라 병합 질문의 꼴(사건 하나의 대표 기사와 다른 사건의 기사들)에서 오는 것으로 보고 따로 본다([미결 사항](../open-questions.md) 28).
- 최대 기간은 측정 전 목표로 남는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 측정 전 기본값을 그대로 둔다 | 기본 로컬 모델에서 거의 모든 기사가 Jev 에 묻는 띠에 들고, 평가 세트에서 고른 값보다 묶음이 나빴다 |
| 기준만 바꾼 재판정의 결과로 고른다 | 재판정은 이미 묶인 상태에서 출발해, 처음부터 묶은 결과와 칸 사이 차이만큼 달랐다 |
| 반감기를 사건 기준 설정으로 올린다 | 한 값이 측정한 모델 모두에서 최선과 구별되지 않아 운영자가 맞출 값이라는 근거가 없다. 공개 타입 · 기준 이력 · 운영자 API · 화면이 늘어난다 |
| 기본 임베딩을 외부 모델로 바꾼다 | 묶기 품질이 구별되지 않았고, 운영자에게 외부 키 · 임베딩 비용 · 수집마다 외부 호출이 생긴다 |
| 날짜를 더 라벨링해 상위 후보를 가른다 | 표본을 늘려도 구간이 줄어드는 폭이 상위 후보 사이의 차이를 가르기에 모자란다 |
| 표본 검수에서 갈림도 판정한다 | 갈린 조각을 표본 사건 곁에 정확히 보일 방법이 없어 판정이 어렵고, 평가 세트의 재현율이 더 잘 잰다 |
| 닫는 기간을 시간 창과 같게 둔다 | 늦게 수집된 기사가 창 끝에서 붙을 여지가 없어진다 |
