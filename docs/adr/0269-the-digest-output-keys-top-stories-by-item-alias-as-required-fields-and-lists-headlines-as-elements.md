# ADR-0269: 다이제스트 출력의 주요 뉴스 칸은 항목 별칭을 키로 한 필수 칸이고, 헤드라인 칸은 원소 배열이다

- 상태: 승인
- 날짜: 2026-11-20
- 근거: [이슈 #182](https://github.com/Theia0382/yozm-news/issues/182) — 측정 인스턴스에서 사건 단위 다이제스트를 일정 생성으로 받자 일부에서 LLM 이 첫 주요 뉴스 하나만 쓰고 나머지 항목을 건너뛰었다(종료 사유 정상 · JSON 유효). 프롬프트는 이미 "항목을 빼지 않는다"를 지시했고, 정적 배열 스키마는 원소 수를 요구하지 않았다. 출력 계약으로 막는 안을 골랐다. 두 칸 모두 키 꼴로 바꾸자 Anthropic 이 헤드라인이 많은 요청의 출력 스키마를 거부해, 키 꼴을 주요 뉴스 칸으로 좁히는 안을 골랐다. 구현 커밋 `7d22f46` · `921910f`
- 관련: [ADR-0262](0262-chosen-events-are-grouped-into-items-by-containment-tree-top-code-splits-top-stories-and-headlines-the-llm-writes-per-item-and-an-item-has-one-badge.md)(부분 대체 — 결정 "출력은 기사를 인용하지 않는다"의 주요 뉴스 칸에서 모르는 항목 별칭 · 다른 칸의 항목 · 앞에서 이미 쓴 항목을 버린다는 부분, 결과의 출력 상한 20 · 150 항목), [ADR-0270](0270-an-item-missing-from-the-output-is-asked-once-more-and-then-kept-as-a-headline-and-the-counts-are-recorded.md)(빠진 항목의 처분)

## 맥락

- 항목은 코드가 정한다 — 무엇을 주요 뉴스 · 헤드라인으로 둘지까지 정해 생성에 넘긴다. LLM 의 일은 항목마다 쓰는 것뿐이다.
- 출력이 항목 별칭을 가리키는 원소의 배열이면, 스키마가 원소 수를 요구하지 않는 한 구조화 출력이 켜져 있어도 원소 하나짜리 배열이 유효하다. 빠진 항목은 고른 사건이 다이제스트에서 사라지는 것이다. 관찰된 누락은 가장 값진 칸인 주요 뉴스가 첫 하나만 남은 모양이었다.
- 구조화 출력은 공급자마다 받는 스키마 키워드가 다르다. 관문의 공급자 맞춤은 Anthropic · OpenRouter 에서 배열 개수 제약(`minItems` · `maxItems`)을 지우고, 세 공급자 모두 `required` 와 `additionalProperties: false` 는 지킨다.
- Anthropic 구조화 출력은 스키마를 문법으로 컴파일하고 크기 · 복잡도 한도로 거부한다. 공개된 한도는 요청 안 스키마 전체에서 선택 매개변수 24 개 · union 타입 매개변수 16 개이고, 문법 크기의 한도는 수치가 공개되지 않았다. 항목 별칭을 키로 한 객체는 항목 수만큼 문법이 커져, 잰 바로는 주요 뉴스 꼴의 키 20 개는 받고 22 개는 "문법이 너무 크다"로 거부했다. 헤드라인 항목은 최대 후보 수만큼 늘 수 있다.

## 결정

- **출력 서술은 요청마다 그 항목 집합에서 만든다.** `top_stories` 칸은 주요 뉴스 항목의 별칭(항목 순서)을 키로 한 객체이고 키마다 값은 `title` · `summary` 다. JSON Schema 는 모든 키를 필수로, 모르는 키를 허용하지 않게 그린다. 주요 뉴스 항목이 없으면 빈 객체다. 주요 뉴스 항목은 많아야 큰 슬롯 수 상한과 큰 슬롯 밖 주요 뉴스 수의 합이다.
- **`headlines` 칸은 원소 배열이다** — 원소는 `ref`(항목 별칭) · `title` · 선택 `note` 이고, 헤드라인 항목이 없어도 배열이다. 개수 상한은 두지 않는다 — 서술 밖 별칭은 대조가 찾지 않고 원문 크기는 관문의 본문 상한이 묶는다. 별칭이 16 코드 포인트를 넘는 원소는 버린다.
- **스키마와 읽기는 그 서술 하나에서 나온다** — 같은 항목 집합이면 같은 서술이다.
- **읽기는 공급자에게 요구한 것보다 관대하다.** 주요 뉴스 칸에서 없는 키 · `null` 인 키는 출력 전체를 읽지 못한 것이 아니라 그 항목이 빠진 것이고, 서술하지 않은 키는 무시한다. 헤드라인 원소는 별칭으로 모은다 — 같은 별칭이 또 나오면 처음 원소만 쓰고, 모르는 별칭 · 주요 뉴스 항목의 별칭은 대조가 찾지 않는다. `null` 원소와 칸 안의 빈 제목 · 요약 · 타입 틀림은 출력 전체를 읽지 못한 것이다. 제목 · 요약이 상한을 넘으면 그 칸 · 원소만 버린다 — 그 항목이 빠진 것이 된다.
- **주요 뉴스 칸이 가득 찬 출력 스키마를 지시 예약에 넣는다.** 구조화 출력이어도 공급자가 스키마를 입력으로 셀 수 있어 늘 센다. 헤드라인 칸은 항목 수와 함께 늘지 않아 사건 하나의 어림 몫에는 스키마를 넣지 않는다. 값은 측정 전 목표다.
- **주요 뉴스 항목 수의 위쪽은 잰 키 한도 안이어야 한다** — 시험이 묶는다. 큰 슬롯 수 상한이나 큰 슬롯 밖 주요 뉴스 수를 올리면 그 한도를 다시 잰다.

## 결과

- 구조화 출력을 쓰는 공급자에서 주요 뉴스 칸이 빠진 출력은 공급자 쪽에서 막힌다. 헤드라인 누락과 구조화 출력이 없는 모델의 누락은 지시에 실은 스키마 · 읽기 · 대조와 [ADR-0270](0270-an-item-missing-from-the-output-is-asked-once-more-and-then-kept-as-a-headline-and-the-counts-are-recorded.md) 의 처분이 맡는다.
- 칸마다 계약이 다르다 — 주요 뉴스는 키, 헤드라인은 원소의 `ref`.
- 출력 스키마의 크기는 주요 뉴스 항목 수만큼만 커진다. 지시 예약이 커지고 사건 하나의 어림 몫은 그대로다.
- 문법 크기 한도는 공개되지 않아 공급자가 낮추면 시험이 아니라 생성 실패로 드러난다 — 조용하지 않다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 지시 문면만 강화한다 | 이미 "항목을 빼지 않는다"를 지시했는데 빠졌다 — 강제 수단이 없다 |
| 배열을 두고 개수 제약(`minItems` · `maxItems`)과 별칭 `enum` 을 더한다 | Anthropic · OpenRouter 맞춤이 개수 제약을 지운다 — 누락이 난 공급자에서 효과가 없다 |
| 두 칸 모두 항목 별칭 키 꼴 | Anthropic 이 키가 많은 스키마를 거부한다 — 헤드라인이 많은 다이제스트를 만들지 못한다 |
| 항목 수가 한도 안이면 키 꼴, 넘으면 배열 | 계약이 둘이고, 공개되지 않은 공급자 한도를 코드의 경계 값으로 둬야 한다 |
| 칸을 여러 요청으로 나눠 생성한다 | 입력(기사 줄)을 요청마다 다시 내 사용자 비용이 약 두 배다 |
| 배열로 되돌리고 누락은 다시 묻기 · 대체에만 맡긴다 | 가장 값진 주요 뉴스가 빠지면 다시 묻는 비용이 들고, 끝내 빠지면 요약 없는 헤드라인이 된다 |
| 읽기도 엄격하게(키가 없으면 출력 전체 실패) | 다시 묻기 · 실패로 가서 이미 쓴 항목까지 잃는다 |
