# ADR-0242: 내 스토리라인 구독 목록은 키가 있어야 가는 스토리라인 화면에 둔다

- 상태: 승인
- 날짜: 2026-11-18
- 근거: [이슈 #186](https://github.com/Theia0382/yozm-news/issues/186) — 기점 `33ab070` 의 키 관문(서버 · 화면)과 구독 · 카드 처리기를 대조하고 리드와 정함
- 관련: [ADR-0190](0190-storyline-subscription-handlers-are-open-without-a-key.md)(보충 — 맥락 "내 구독 목록을 관심 설정 화면에 둘지 스토리라인 화면에 둘지는 구독 화면을 만들 때 정한다"를 정한다), [ADR-0160](0160-users-without-a-key-may-use-key-account-and-notice-handlers.md) · [ADR-0179](0179-interest-settings-handlers-are-open-without-a-key.md)(관련 — 키 없이 가는 화면의 열거는 그대로다), [ADR-0159](0159-having-a-key-means-having-any-stored-key-regardless-of-its-status.md)(관련 — 키를 모두 지우면 키 화면만 남는다)

## 맥락

- 구독 처리기 셋(내 구독 · 구독 · 해제)은 키 없이 열린다. 내 구독은 스토리라인 ID · 구독 시각 · 지금 상태만 내고 제목을 내지 않는다.
- 스토리라인의 제목(대표 기사 제목)은 카드 처리기 `GET /api/storyline-cards` 가 내고, 기사 내용을 내므로 키 관문 뒤다.
- 화면은 키 없는 사용자를 키 없이 가는 화면(키 · 설정 · 비밀번호 변경 · 알림 · 관심 설정) 밖에서 키 화면으로 보낸다. 스토리라인 목록 · 타임라인은 그 밖이다.
- 구독 · 해제 버튼을 두는 화면(목록 · 타임라인)이 모두 키 뒤라, 화면을 거쳐 구독을 가진 키 없는 사용자는 키를 등록해 구독한 뒤 키를 모두 지운 사용자뿐이다. 그 사용자의 다이제스트는 쓸 모델이 없어 만들어지지 않는다.

## 결정

- **내 구독 목록은 스토리라인 화면 묶음의 한 화면이고, 키가 있어야 간다.** 제목은 카드 처리기로 붙인다. 키 없이 가는 화면의 열거는 바꾸지 않는다.

## 결과

- 목록의 행마다 제목 · 상태 · 마지막 기사 시각이 있고, 구독 버튼이 있는 화면과 한 묶음이라 오가기 쉽다.
- 키를 모두 지운 사용자는 화면에서 구독을 보거나 해제하지 못한다 — 처리기는 그대로 열려 있고, 키를 다시 등록하면 구독이 그대로 보인다. ADR-0190 결과의 "키를 모두 지운 사용자도 구독을 보고 해제할 수 있다"는 처리기 수준의 결과로 남는다.
- 키 없이 가는 화면이 키 뒤 처리기(카드)를 부르는 일이 생기지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 관심 설정 화면에 내 구독 절을 둔다(키 없이 간다) | 키 없는 사용자는 카드가 403 이라 제목 없는 목록(ID · 구독 시각 · 상태)만 본다 — 무엇을 구독했는지 알아보기 어렵고, 그 사용자는 키를 지운 사용자뿐이다 |
| 스토리라인 화면에 두고 관심 설정 화면에는 구독 수와 링크만 둔다 | 키 없는 사용자에게는 링크가 키 화면으로 가 위 결정과 같고, 관심 설정 화면에 줄 하나가 더 생긴다 |
