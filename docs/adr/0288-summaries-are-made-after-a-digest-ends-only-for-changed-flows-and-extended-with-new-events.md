# ADR-0288: 정리는 다이제스트가 끝난 뒤 바뀐 흐름만, 지난 정리에 새 사건을 더해 고친다

- 상태: 승인
- 날짜: 2026-11-23
- 근거: [이슈 #245](https://github.com/Theia0382/yozm-news/issues/245) — 정리 호출은 사용자 비용이다. 실측 인스턴스의 덤프에서 사용자 넷의 14일을 다시 돌려 보니, 새 사건만 더해 고치는 방식의 입력 토큰이 날마다 처음부터 다시 쓰는 방식의 14 ~ 22% 였고, 처음 정리 31번 가운데 29번이 사건 60개 이하였다. 계기 · 추론 강도 · 실패의 처분 · 길이를 넘는 글의 처분 · 사건이 없는 꼭대기의 처분을 정했다. 구현 커밋 `776e35e` · `d552119`
- 관련: [ADR-0287](0287-user-storyline-summaries-are-made-and-stored-by-user-with-the-users-key-and-digest-supplies-the-flow-standing.md)(만들고 저장하는 자리), [ADR-0278](0278-followed-flows-are-tops-at-or-above-the-follow-threshold-or-subscribed-less-the-excluded-and-the-keep-threshold-is-0-2.md)(근거 — 관심 흐름의 수가 정리 호출 수이고 사용자 비용이다)

## 맥락

- 관심 흐름이 무엇인지는 다이제스트의 노출과 반응으로 달라지고, 흐름의 새 사건은 다이제스트가 사용자에게 보인 뒤에야 그 사용자에게 뜻이 있다.
- 흐름 하나의 사건은 수백 개까지 늘 수 있다.
- 호출이 실패해도 공급자는 토큰을 쓴다. 늘 실패하는 흐름을 다이제스트마다 다시 부르면 비용만 쌓인다.

## 결정

- **계기는 다이제스트의 끝이다.** 내용 있음 · 후보 없음으로 끝나면 그 사용자의 정리 작업 하나를 등록한다. 실패로 끝나면 등록하지 않는다. 작업은 재시도하지 않는다.
- **흐름마다 처분은 다섯이다.** 정리가 없는 관심 흐름은 새로 만들고, 추적 대상이 정리 때와 달라졌으면 처음부터 다시 만들고, 새 사건이 생겼으면 지난 글과 새 사건만으로 고치고, 재료가 그대로면 부르지 않고, 관심 흐름도 남길 흐름도 아니면 지운다.
- **한 호출에 넣는 사건과 한 실행의 호출 수에 상한을 둔다.** 사건이 있는 꼭대기는 모두 사건을 하나 이상 받는다. 상한에 걸려 넣지 못한 사건도 넣은 것으로 기록한다.
- **사건은 대표 기사의 제목과 저장된 요약문으로 싣는다.** 본문은 싣지 않는다.
- **추론 강도는 낮음으로 고정한다.** 사용자의 추론 강도 설정을 따르지 않는다.
- **글의 길이는 지시로 권하고, 권하는 길이의 두 배를 넘으면 그 지점에서 잘라 저장한다.** 넘었다고 실패로 치지 않는다.
- **사건이 없는 꼭대기는 글 없이 둔다.** 모델에 묻지 않고 지어내지 않는다.
- **호출마다 시도 기록을 남긴다.** 호출 수와 토큰 합은 저장한 것 · 버린 것 · 실패한 것을 모두 센다. 연속 실패가 n 번이면 n 일(7일까지) 쉰다. 저장에 성공하면 연속 실패는 0 이다.
- **키 쪽의 실패는 그 실행을 멈춘다.** 같은 실행의 다른 흐름도 같은 까닭으로 실패한다.
- **저장할 때 사용자 스토리라인 · 추적 대상 · 정리의 판이 호출 때와 같은지 견준다.** 다르면 결과를 버린다.

## 결과

- 흐름의 글은 길어야 다음 다이제스트까지 묵는다. 다이제스트를 받지 않는 사용자의 정리는 고쳐지지 않는다.
- 고쳐 쓴 글은 지난 글을 거쳐 온 것이라 오래된 흐름일수록 처음 사건의 세부가 흐려질 수 있다.
- 상한에 걸려 넣지 못한 사건은 글에 반영되지 않는다.
- 상한 · 길이 · 쉬는 기간의 값은 측정 전 목표다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 다이제스트마다 관심 흐름을 처음부터 다시 정리한다 | 재생에서 입력 토큰이 고쳐 쓰는 방식의 네 배 반에서 일곱 배였다 |
| 화면을 열 때 만든다 | 화면이 생성 호출을 기다리고, 열 때마다 비용이 든다 |
| 정해진 시각에 모든 사용자를 훑는다 | 다이제스트를 받지 않은 사용자의 흐름은 달라질 것이 없다 |
| 실패를 로그에만 남긴다 | 실패에 쓴 토큰이 사용자에게 보이지 않고, 같은 실패가 다이제스트마다 되풀이된다 |
| 길이를 넘은 글을 실패로 친다 | 쓸 수 있는 글을 버리고 그 호출의 토큰만 쓴다 |
| 사용자의 추론 강도 설정을 따른다 | 주어진 사건 줄을 간추리는 일이라 높은 강도의 비용이 값을 하지 못한다 |
