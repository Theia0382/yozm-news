# ADR-0052: 기사의 소스는 피드별 기록이 갖고, 제목 판정은 그 소스의 기록이 있는 기사에서 하며, 지운 피드의 늦은 항목은 버린다

- 상태: 승인
- 날짜: 2026-11-02
- 근거: [이슈 #61](https://github.com/Theia0382/yozm-news/issues/61) — 기존 엔트리의 소스를 피드 행으로 채우는 마이그레이션을 이전 버전 스키마에서 실행해 확인하고, 제목 판정 범위와 늦은 항목 버림을 시험으로 확인. 구현 `64811af`(엔트리의 소스 · 제목 판정 범위) · `3096bdf`(기사 쪽 삭제 · 늦은 항목)
- 관련: [ADR-0032](0032-same-article-matching-avoids-false-merges-with-per-feed-entries-under-source-lock.md)(같은 기사 판정 — L2 의 범위를 이 ADR 이 대체한다), [ADR-0051](0051-operator-hides-or-deletes-sources-and-feeds-and-deletion-removes-exclusive-articles.md)(소스 · 피드 삭제), [ADR-0013](0013-architecture-patterns.md)(모듈 사이는 공개 API · 이벤트)

## 맥락

- 기사는 처음 저장한 소스 하나(`articles.source_id`)를 가졌고, 같은 정규 URL 로 다른 소스가 붙은 기록은 엔트리(기사, 피드)에만 남았다. 엔트리는 피드 ID 만 가져, 기사의 소스를 알려면 `source` 의 피드 행을 읽어야 했다.
- 운영자가 소스를 지우면(ADR-0051) 그 소스만 가진 기사를 지우고 다른 소스도 가진 기사는 남겨야 한다. 기사에 대표 소스가 하나면 대표 소스를 지울 때 다른 소스로 넘기는 규칙이 따로 필요하다.
- 제목 판정(L2)은 "같은 소스"의 기사를 후보로 삼았다 — 기사의 대표 소스로 걸렀으므로, 다른 소스가 먼저 저장하고 이 소스의 한 피드가 URL 로 붙은 기사는 이 소스의 다른 피드에서 같은 제목으로 와도 후보가 아니었다.
- 수집은 피드 요청을 트랜잭션 밖에서 하고 결과를 발행한다. 운영자가 그 사이 피드 · 소스를 지우면, 지운 뒤에 처리되는 늦은 항목이 지운 피드의 기사를 다시 저장한다.

## 결정

- **대표 소스를 없앤다. 엔트리가 그 피드의 소스를 갖고, 기사의 소스는 엔트리들이 가리키는 소스들이다.** `article_feed_entries.source_id` 를 더하고(기존 행은 피드 행으로 채운다) `articles.source_id` 를 지운다.
- **제목 판정의 범위는 "이 소스의 엔트리가 있는 기사"다.** 다른 소스가 먼저 저장한 기사도 이 소스의 피드가 붙었으면 후보다. 이 소스의 엔트리는 이 소스의 잠금 안에서만 생기므로, 소스 단위 잠금이 판정 대상 전체를 덮는다는 결론(ADR-0032)은 그대로다.
- **지운 소스 · 피드의 기사는 엔트리로 지운다.** `SourceDeleted` · `FeedDeleted` 를 받아 그 소스 단위 잠금 안에서 그 소스(피드)의 엔트리를 지우고, 엔트리가 남지 않은 기사를 지운다. 다른 소스 · 피드의 엔트리가 남은 기사는 처음 값 그대로 남는다. 다시 처리해도 결과가 같다.
- **늦은 항목은 `article` 이 `source` 에 피드가 있는지 물어 버린다.** 소스 단위 잠금 뒤 공개 조회 `SourceDirectory.feedExists` 가 거짓이면 저장하지 않고 정보 로그를 남긴다. 잠금 안에서 묻으므로 피드가 있어 저장한 항목은 뒤이은 삭제 처리가 지운다. 숨긴 피드는 있는 피드다.
- **기사 삭제와 다른 소스의 같은 기사 처리가 겹치는 경합에 잠금을 더하지 않는다.** 기사 FK 로 한쪽이 실패하고 이벤트 재처리로 수렴한다.
- **기사가 지워질 수 있다는 것을 다른 모듈이 따르는 길은 미설계로 둔다.** 기사를 ID 로 가리키는 모듈은 아직 없다 — 그 모듈을 구현할 때 정한다.

## 결과

- 기사의 소스 목록이 `article` 안에서 바로 읽힌다. 소스 · 피드 삭제가 공유 기사를 남기는 규칙이 엔트리 하나로 정해진다.
- 다른 소스가 먼저 저장한 기사에 이 소스의 여러 섹션 피드가 같은 제목으로 실으면 한 기사로 합쳐진다. 이 소스와 관계없는 다른 소스의 기사는 여전히 후보가 아니다 — 다른 소스의 같은 제목은 사건 묶기의 몫이다.
- 항목마다 피드 행 조회가 하나 는다.
- `article` → `source` 에 공개 조회 의존 하나와 이벤트 둘이 더해진다. 방향은 그대로다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 대표 소스를 두고, 대표 소스를 지우면 남은 엔트리의 소스로 다시 지정한다 | 다시 지정하는 규칙이 하나 더 생기고, 대표가 아닌 소스는 기사의 소스로 보이지 않는다 |
| 기사에 소스 목록 열을 둔다 | 엔트리와 같은 사실을 두 곳에 두어 어긋날 수 있다 |
| 제목 판정 범위를 대표 소스로 둔다 | 다른 소스가 먼저 저장한 기사에 이 소스의 섹션 피드들이 따로 저장된다 |
| 늦은 항목을 수집 쪽에서 막는다(발행 전에 피드를 다시 확인) | 확인과 처리 사이의 겹침이 남는다 — 저장하는 쪽이 같은 잠금 안에서 확인해야 닫힌다 |
| 늦은 항목의 확인을 소스 존재로 한다 | 피드만 지운 경우를 놓친다. 소스를 지우면 피드도 지우므로 피드 존재로 둘 다 덮는다 |
| 기사 삭제를 다른 소스의 처리와 같은 잠금으로 묶는다 | 드문 경합을 위해 소스를 건너는 잠금이 생긴다. 재처리로 수렴하므로 결과가 같다 |
