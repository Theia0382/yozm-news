# ADR-0029: RSS 요약문은 기본 무기한 보존하고, 자동 삭제는 운영 설정으로 켠다

- 상태: 승인
- 날짜: 2026-10-27
- 근거: [이슈 #36](https://github.com/Theia0382/yozm-news/issues/36) — 기점 `e4dbe0d` 의 보존 정책 초안([data-model.md](../data-model.md)) · 저작권 규칙([security.md](../security.md))을 확인
- 관련: [ADR-0025](0025-long-term-personal-news-history-in-v1.md)(장기 기능), [ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)(사건 묶기 — 요약문으로 임베딩), [ADR-0027](0027-pgvector-for-vector-storage.md)(기사 벡터 재계산)

## 맥락

- 보존 정책 초안은 RSS 요약문을 90일 뒤 삭제한다. 이유는 언론사 콘텐츠 보관을 최소화하는 것이었다. 특정 약관이나 법 조항에서 나온 값은 아니다.
- 요약문은 화면과 외부 API 에 노출하지 않는다. 보존 기간은 내부 처리에 쓸 수 있는 기간만 바꾼다.
- 장기 기능에는 요약문이 필요한 일이 있다. 태그 체계에 새 주제를 더했을 때 과거 기사를 다시 평가하기, 임베딩 모델을 바꿨을 때 과거 기사의 벡터를 다시 계산하기, 과거 기사 검색이다.
- 보관 기간이 길어진다고 저장한다는 행위의 성격이 바뀌지는 않는다. 판단 기준은 각 소스의 RSS 이용조건이고, 소스를 켜기 전에 확인한다.
- 셀프 호스팅 운영자마다 보관에 대한 판단이 다를 수 있다.

## 결정

- **요약문은 기본으로 무기한 보존한다.**
- **자동 삭제는 운영 설정(보존 일수, 기본 꺼짐)으로 켠다.**
- 화면 · 외부 API 에 요약문을 노출하지 않는 규칙과, 언론사가 삭제를 요청하면 요약문을 지우는 운영자 기능은 그대로 둔다.
- **장기 기능은 요약문이 없는 기사에서도 동작한다.** 재평가 · 벡터 재계산은 요약문이 남은 기사만 대상으로 하고, 검색은 제목 · 메타데이터로 대신한다. 이슈를 이을 때는 과거 기사의 요약문 대신 이슈마다 저장한 현재 상태 요약을 다이제스트 호출에 넘기고, 변화 리포트의 입력에는 원래 요약문이 들어가지 않는다.

## 결과

- 저장 공간이 늘어난다. 하루 4,000건에 1,000자 이하라 1년에 수 GB 이하로 추정한다.
- 자동 삭제를 켠 인스턴스에서는 오래된 기사의 재평가 · 재계산 · 검색이 제목 수준으로 줄어든다.
- 소스 하나만 짧게 보관해야 하는 이용조건이 나오면 소스별 설정이 필요해진다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 90일 삭제를 유지한다 | 새 주제의 과거 시계열 · 벡터 재계산 · 과거 검색을 포기하게 된다 |
| 전체 보존 기간만 늘린다(예: 2년) | 그 기간이 지나면 같은 문제가 다시 생기고, 운영자마다 다른 판단을 담을 수 없다 |
| 수집 프로필에 소스별 보존 기간을 둔다 | 지금은 그렇게 제한하는 소스가 없다. 필요해지면 더한다 |
