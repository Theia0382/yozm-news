# ADR-0185: 운영자 경로는 LLM 키 관문 밖이다 — 역할만 본다

- 상태: 승인
- 날짜: 2026-11-15
- 근거: [이슈 #149](https://github.com/Theia0382/yozm-news/issues/149) — 백엔드 `e2656e8`, 화면 `089c7cc`
- 관련: [ADR-0158](0158-requests-of-session-users-without-a-key-are-closed-by-default-and-handlers-open-without-a-key-carry-a-platform-annotation.md)(부분 대체 — 결과 절 셋째 항목: 운영자 경로가 키 관문과 무관한 까닭), [ADR-0183](0183-admin-paths-open-with-admin-account-sessions-and-keep-the-operator-token-as-an-optional-script-bearer-with-csrf-only-for-sessions.md)(운영자 경로의 인증)

## 맥락

- LLM 키가 없는 세션 사용자에게는 키 없이도 여는 표시가 있는 처리기만 연다(ADR-0158). 운영자 경로는 운영자 토큰의 다른 체인이라 이 규칙과 무관했다.
- 운영자 경로가 계정 세션으로 열리면 운영자도 세션 사용자다(ADR-0183). 키 관문을 그대로 적용하면 키를 등록하지 않은 운영자는 운영자 화면을 쓰지 못한다.
- 운영자 기능(수집 · 평가 · 사건 · 스토리라인 · 계정 운영)은 운영자 비용 기능이고 사용자 LLM 키와 무관하다. 키 관문의 까닭은 사용자 LLM 비용을 쓰는 기능을 키 없이 열지 않는 것이다.

## 결정

- **운영자 경로의 인가는 운영자 토큰 · 세션 사용자 · 비밀번호 변경 · 역할만 본다** — LLM 키를 묻지 않는다.
- 운영자 화면도 키가 없다고 키 화면으로 보내지 않는다.

## 결과

- 첫 운영자는 키를 등록하지 않고도 소스를 켜고 인스턴스를 꾸린다.
- 같은 운영자가 사용자 화면에서 다이제스트 등 키가 필요한 기능을 쓰려면 키를 등록한다 — 세션 체인의 키 관문은 그대로다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 운영자 경로에도 키 관문을 건다 | 다이제스트를 쓰지 않는 운영자도 LLM 키를 사야 하고, 첫 운영자가 소스를 켜기 전에 키부터 넣어야 한다. 지금 상태(운영자 경로는 키 관문 밖)를 뒤집는다 |
