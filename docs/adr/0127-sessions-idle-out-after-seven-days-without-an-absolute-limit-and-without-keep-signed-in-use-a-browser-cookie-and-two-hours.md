# ADR-0127: 세션은 비활성 7일이고 절대 상한이 없으며, 로그인 유지를 끄면 브라우저 세션 쿠키와 비활성 2시간이다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #145](https://github.com/Theia0382/yozm-news/issues/145) — 사용자 결정. Spring Session 4.1.1 소스로 로그인 유지 장치(로그인 유지 요청 속성이 있으면 쿠키 수명을 서버 만료에 맡김)를 확인
- 관련: [ADR-0126](0126-user-paths-authenticate-with-a-jdbc-session-holding-only-the-user-id-and-cookie-csrf-reading-the-account-per-request.md)(세션에 담는 것)

## 맥락

- 요즘뉴스는 하루 한 번 다이제스트를 보러 들어오는 서비스다. Spring Session 의 기본(마지막 요청 뒤 30분, 브라우저 세션 쿠키)이면 거의 매번 로그인한다.
- 공용 기기에서 쓰는 사람은 세션이 기기에 남지 않기를 바란다.

## 결정

- **세션 수명은 마지막 요청 뒤의 비활성 기간이고 절대 상한이 없다.**
- **로그인 때 "로그인 유지"를 고른다(기본 꺼짐).** 켜면 비활성 7일이고 세션 쿠키는 지속 쿠키다 — 쿠키 수명은 서버 만료에 맡긴다. 끄면 비활성 2시간이고 세션 쿠키는 브라우저 세션 쿠키다.

## 결과

- 매일 쓰는 사람은 로그인 유지로 다시 로그인하지 않는다.
- 훔친 세션도 계속 쓰이는 동안은 끝나지 않는다 — 절대 상한이 없다. 세션은 계정 상태를 요청마다 읽으므로 정지 · 탈퇴로 끊을 수 있다.
- 로그인 유지를 끄고 브라우저를 열어 둔 공용 기기에는 2시간 남는다. 브라우저의 "이전 세션 복원"은 브라우저 세션 쿠키도 되살린다.
- 두 값은 세션 수명 상수 둘이다([user Spec](../specs/user.md#세션) user-R8).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 비활성 30분 · 브라우저 세션 쿠키(기본) | 하루 한 번 쓰는 서비스에서 거의 매번 로그인한다 |
| 비활성 14일 + 절대 상한 30일, 선택 없음 | 사용자 결정 — 상한 없이 비활성 7일, 공용 기기를 위한 선택을 둔다 |
| 로그인 유지를 끄면 비활성 7일(쿠키만 다름) | 선택이 쿠키 수명 하나만 바꾼다. 브라우저를 열어 둔 공용 기기에 7일 남는다 |
| 로그인 유지를 끄면 비활성 30분 | 다이제스트를 읽는 동안 끊길 수 있다 |
