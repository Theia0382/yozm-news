# ADR-0180: `UserSettingsChanged` 를 내지 않고 소비자가 조회한다

- 상태: 승인
- 날짜: 2026-11-15
- 근거: [이슈 #151](https://github.com/Theia0382/yozm-news/issues/151)
- 관련: [ADR-0028](0028-explicit-signals-and-interest-weighted-candidates.md)(관심도는 조회할 때 계산한다)

## 맥락

- 시스템 지도에는 `user` 가 사용자 설정이 바뀌면 `UserSettingsChanged` 를 내고 `digest` 가 받는 화살표가 있었다. 발행 시점 · 내용은 정하지 않았다.
- 다이제스트 일정은 1분마다 생성 시각이 다가온 사용자를 찾아 설정을 매번 읽고, 관심도는 조회할 때 신호 이력을 읽는다. 받는 쪽은 아직 코드가 없다.

## 결정

- **사용자 설정 · 태그 선호가 바뀌어도 이벤트를 내지 않는다.** 소비자(다이제스트 · 관심도 · 변화 리포트)는 `user` 의 공개 조회로 그때의 값을 읽는다.
- 이벤트가 필요해지면 그 소비자의 작업이 소비 계약과 함께 더한다.

## 결과

- 받을 쪽이 없는 계약을 미리 굳히지 않는다. 설정 사본이 이벤트로 퍼지지 않는다.
- 소비자용 공개 조회도 소비자의 작업이 연다 — 그 조회가 소비자의 필요를 담는지는 그때 확인된다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 사용자 ID 와 바뀐 갈래만 싣고 낸다 | 갈래의 단위가 맞는지 확인할 소비자가 없는데 계약이 먼저 굳는다 |
| 바뀐 뒤의 설정 전체를 싣는다 | 설정 사본이 퍼지고 이벤트 재처리 때 옛 사본이 최신 값을 덮을 수 있다 |
