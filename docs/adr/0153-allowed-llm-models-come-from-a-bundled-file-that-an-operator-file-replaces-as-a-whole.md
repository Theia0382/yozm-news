# ADR-0153: 허용 모델 목록은 앱에 든 파일이 정본이고, 운영자는 자기 파일로 통째로 바꾼다

- 상태: 승인
- 날짜: 2026-11-14
- 근거: [이슈 #148](https://github.com/Theia0382/yozm-news/issues/148) — 운영자가 다루는 값의 기존 꼴 셋(설정 키 · 저장소 파일이 정본 · 첫 기동 적재와 화면)과 배포 구성을 확인
- 관련: [ADR-0008](0008-v1-llm-providers.md)(운영자가 공급자별 허용 모델 목록을 관리한다 — 관리 방법을 보충), [ADR-0024](0024-collection-profile-yaml-and-preset-reference-or-own-profile.md)(프리셋은 저장소 파일이 정본 — 같은 꼴), [ADR-0056](0056-platform-reads-yaml-text-and-applies-common-rejection.md)(YAML 원문 읽기)

## 맥락

- 운영자가 공급자별 허용 모델 목록을 관리하고, 모델마다 입력 토큰 예산과 구조화 출력 지원 여부를 함께 갖는다([ADR-0008](0008-v1-llm-providers.md)).
- 목록의 대부분은 모델의 사실이다(모델 ID · 구조화 출력 지원 여부). 공급자는 한 해에 여러 번 새 모델을 낸다.
- 운영자 설정을 첫 기동에 DB 로 적재하는 꼴은 이미 적재한 인스턴스에 소프트웨어 개정의 기본값이 닿지 않는다.
- 배포 구성은 앱에 환경 변수만 넘긴다.

## 결정

- **허용 모델 목록의 정본은 앱에 든 기본 파일이다.** 소프트웨어 개정이 기본 목록을 바꾸면 운영자 파일을 쓰지 않는 인스턴스에 그대로 닿는다.
- **운영자는 자기 목록 파일을 설정으로 가리켜 목록을 통째로 바꾼다.** 기본 목록과 합치지 않는다.
- **목록은 기동 때 읽고, 틀리면 기동하지 않는다.** 운영자 파일을 가리켰는데 없거나 틀리면 기본 목록으로 떨어지지 않고 멈춘다.
- **배포 구성은 설정 디렉터리를 앱에 언제나 읽기 전용으로 마운트한다.** 운영자는 그 디렉터리에 파일을 두고 환경 변수 한 줄로 가리킨다.
- DB · 운영자 화면 · 변경 이력을 두지 않는다.

규칙은 [llm Spec](../specs/llm.md#공급자와-허용-모델-목록) llm-R2 ~ R4, 운영 안내는 [운영 설정 — 허용 모델 목록](../operations/configuration.md#허용-모델-목록)에 있다.

## 결과

- 목록을 바꾸려면 파일을 고치고 앱을 다시 띄운다. 누가 언제 바꿨는지는 남지 않는다.
- 운영자 파일을 쓰는 인스턴스는 소프트웨어 개정의 새 모델을 스스로 더해야 한다.
- 목록에서 빠진 모델을 골라 둔 사용자가 남을 수 있다 — 그 사용자를 어떻게 다룰지는 모델 선택을 저장하고 생성하는 쪽이 정한다. 목록 조회는 없는 모델에 빈 값을 낸다.
- 조회는 공개 API 뒤에 있어, 나중에 운영자 화면의 덮어쓰기를 더해도 쓰는 쪽은 바뀌지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| DB 의 운영 설정 + 운영자 화면(첫 기동 적재) | 적재한 인스턴스에 개정의 기본 목록이 닿지 않아, 새 모델마다 운영자가 예산 · 지원 여부를 손으로 넣는다 |
| 기본 파일 + 운영자 덮어쓰기(DB · 화면) | 기본과 덮어쓰기를 합치는 규칙이 생긴다. 지금 필요한 것보다 크다 |
| 운영자가 Compose 덮어쓰기 파일로 마운트를 더한다 | 운영자가 Compose 문법을 다루고 덮어쓰기 파일을 관리해야 한다 |
| 환경 변수에 목록 원문을 넣는다 | 한 줄에 긴 원문을 적어 읽고 고치기 어렵다 |
