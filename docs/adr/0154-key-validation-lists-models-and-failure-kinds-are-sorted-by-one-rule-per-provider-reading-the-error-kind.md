# ADR-0154: 키 검증은 모델 목록 조회이고, 실패 종류는 공급자마다 오류의 종류까지 읽는 정본 하나가 가른다

- 상태: 승인
- 날짜: 2026-11-14
- 근거: [이슈 #148](https://github.com/Theia0382/yozm-news/issues/148) — 두 공급자의 공식 오류 문서와, 모델 목록 엔드포인트에 가짜 키로 보낸 요청의 실제 응답
- 관련: [ADR-0003](0003-byok-personalized-digest.md)(키의 유효성 · 한도 · 요금 부족이 다이제스트 실패 원인이 된다)

## 맥락

- 키를 등록할 때 공급자에 가벼운 요청을 보내 검증하고, 실패하면 저장하지 않는다([security.md](../security.md#byok-키-보관)). 실패는 무효 · 권한 · 한도 · 일시 장애로 가른다.
- 모델 목록 조회는 과금되지 않는 요청이라 잔액 · 지출 한도 소진을 드러내지 않는다. 그것은 생성 요청에서 드러난다.
- 두 공급자 모두 요청 제한과 한도 소진을 같은 상태 코드 429 로 답한다. OpenAI 는 오류의 `code` 로, Anthropic 은 `retry-after` 헤더가 있는지로 갈린다.
- 같은 분류를 생성 호출의 실패(다이제스트 실패 · 키 무효 판정)가 다시 쓴다.

## 결정

- **키 검증의 요청은 모델 목록 조회 하나다.** 정상 응답이면 유효다. 잔액 · 지출 한도와 특정 모델을 쓸 권한은 확인하지 않는다.
- **검증은 짧은 마감으로 한 번만 보낸다.** 다시 시도하지 않는다.
- **실패 종류는 다섯이다** — 무효 · 권한 · 한도 · 일시 장애, 그리고 넷 어디에도 들지 않는 예상 밖의 답.
- **분류의 정본은 공급자마다 함수 하나이고, 검증과 생성 호출이 함께 쓴다.** 입력은 상태 코드와 오류의 종류(`code` · `type`), `retry-after` 헤더 유무다. 오류의 문구로 가르지 않는다.

규칙은 [llm Spec](../specs/llm.md#키-검증) llm-R6 ~ R8 에 있다.

## 결과

- 검증에 사용자 비용이 들지 않고, 모델을 고르기 전에도 검증할 수 있다.
- 한도가 소진된 키도 등록 때는 유효로 나온다. 첫 생성에서 한도 실패로 드러난다.
- 목록 조회 권한이 없는 키는 생성 권한이 있어도 등록되지 않을 수 있다.
- Anthropic 의 429 를 `retry-after` 헤더 유무로 가르는 근거는 공급자 문서의 서술이다 — 요청 제한의 429 에 헤더가 없으면 한도로 잘못 간다. Anthropic 이 운영자가 정한 지출 한도 도달에 주는 400 은 종류로 갈리지 않아 예상 밖의 답이 된다.
- 예상 밖의 답을 일시 장애로 뭉개지 않는다 — 부르는 쪽이 다섯 종류를 모두 다뤄야 한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 최소 생성 요청으로 검증한다 | 검증마다 사용자 비용이 들고, 어느 모델로 보낼지가 필요하다 |
| 목록 조회 뒤 모델을 고르면 그 모델로 최소 생성 요청을 한다 | 검증 경로가 둘이 되고 모델 선택에 묶인다 |
| 상태 코드만으로 가른다 | 429 가 요청 제한과 한도 소진을 함께 뜻해 둘이 갈리지 않는다 |
| 공급자 공통 분류 함수 하나 | 429 를 가르는 근거가 공급자마다 다르다 |
