# ADR-0054: 태그 체계는 기본 YAML 파일을 첫 기동에 버전 1로 들이고, 버전 내용은 바꾸지 않으며, 질문은 태그 종류마다 둔 틀에 태그 설명을 끼워 만든다

- 상태: 승인
- 날짜: 2026-11-02
- 근거: [이슈 #68](https://github.com/Theia0382/yozm-news/issues/68) — 기점 `385aaef` 의 저장소(수집 프로필 프리셋의 적재 · 읽기 코드, 설계 문서의 태그 체계 모델)와 조사 초안의 체계를 대조해 확인
- 관련: [ADR-0010](0010-tag-taxonomy.md)(태그 체계 — 태그 종류 · 통제 어휘 · 버전과 질문 표. 질문 문구의 자리를 이 ADR 이 구체화한다), [ADR-0024](0024-collection-profile-yaml-and-preset-reference-or-own-profile.md)(수집 프로필 프리셋 — 같은 YAML 표기), [ADR-0056](0056-platform-reads-yaml-text-and-applies-common-rejection.md)(YAML 공통 읽기)

## 맥락

- 평가 결과는 태그 체계 버전을 가리킨다(ADR-0010). 설계 문서(파이프라인의 공유 평가 절)는 질문 문구 · 태그 설명 · 점수 기준을 코드가 아니라 버전과 함께 DB 에 두고, 문구 하나를 바꿔도 새 버전으로 정했다. 그래서 체계는 DB 의 버전이 정본이어야 한다 — 수집 프로필 프리셋처럼 파일을 참조하고 DB 에 복사하지 않는 모델은 쓸 수 없다.
- 첫 체계는 조사 초안으로 시작하고, 파일럿 뒤 문구 · 기준을 고치는 변경이 저장소에 들어온다. 운영자가 자기 체계를 쓰는 길(체계 변경)은 따로 생긴다.
- 체계를 처음 넣는 길은 셋이었다 — Flyway 데이터 마이그레이션, 저장소의 YAML 파일을 기동 때 적재, 운영자가 API 로 가져오기.
- 형식의 기본 제외(보도자료 · 단신)와 형식 · 중요도 질문 문구를 담을 자리가 설계에 없었고, 주제 · 지역 질문은 태그 종류마다 틀 하나(ADR-0010 의 질문 표)와 태그마다 질문 문장(설계의 데이터 모델 `tags.question_text`)으로 갈려 있었다.

## 결정

- **기본 체계는 저장소의 YAML 파일 하나(`backend/src/main/resources/tag-sets/default.yaml`)다.** 기동 때 두 역할 모두 검증하고, 실패하면 기동하지 않는다.
- **버전이 하나도 없을 때만 그 파일을 버전 1 · 활성으로 적재한다.** 한 트랜잭션에서 표를 잠그고 하므로 여러 프로세스가 동시에 떠도 하나만 들어간다. 적재는 싱글톤을 모두 만든 뒤, 웹 서버 · 작업 서버가 시작하기 전에 한다. 버전이 이미 있으면 파일이 바뀌어도 적재하지 않는다 — 파일은 새 인스턴스의 시작점이고, 이미 적재한 인스턴스는 체계 변경으로 새 버전을 들인다.
- **운영자가 자기 체계로 시작하는 길을 따로 두지 않는다.** 소스가 꺼진 채 등록되므로 소스를 켜기 전에 체계 변경으로 새 버전을 만들면 평가된 기사 없이 자기 체계로 시작한다. 코드 · 설정은 기본 체계의 키를 알지 않는다.
- **버전 내용은 만든 뒤 바꾸지 않는다** — 질문 틀 · 질문 · 태그 · 이름 · 설명 · 중요도 기준 · 기본 제외. 태그 기준 · 저장 기준만 버전의 설정으로 바뀐다([ADR-0055](0055-tag-and-store-thresholds-change-with-history-and-warn-instead-of-blocking.md)).
- **주제 · 지역 질문은 태그 종류마다 둔 틀에 태그 설명을 끼워 만든다.** 틀은 자리표시자 `{description}` 을 정확히 하나 갖고, 태그는 설명 한 줄만 갖는다. 형식 Choice · 중요도 Score 의 질문 문구도 버전에 둔다.
- **형식의 기본 제외는 형식 태그의 속성이다.**
- **태그 키는 태그 종류 안에서 고유하고, 중분류는 대분류 키를 붙인 전체 키(`politics.executive`)다.** 파일에는 짧은 조각만 적어 부모 관계가 두 곳에 적히지 않는다.

## 결과

- 문구를 고치는 변경은 파일을 고치는 PR 이고, 새 인스턴스는 고친 문구로 시작한다. 이미 적재한 인스턴스는 파일 개정을 자동으로 받지 않는다 — 알릴지는 체계 변경을 만들 때 정한다.
- 첫 체계와 운영자 체계가 같은 YAML 표기 · 같은 검증기를 쓸 수 있다. YAML 읽기는 `platform` 의 공통 타입을 쓴다(ADR-0056).
- 태그의 뜻(무엇을 포함하고 무엇을 빼는지)이 설명 한 곳에만 있다. 대신 틀 하나에 그 태그 종류의 모든 태그가 맞아야 해, 태그마다 질문 문장을 따로 다듬을 수 없다 — 설명은 틀에 끼울 수 있는 명사구로 쓴다.
- 어떤 역할의 프로세스도 활성 버전 없이 요청 · 작업을 받지 않는다.
- 첫 체계의 중분류는 46개다 — ADR-0010 의 "45" 는 센 수의 오류다(ADR-0010 후속 기록).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| Flyway 데이터 마이그레이션으로 첫 체계를 넣는다 | 적용된 마이그레이션은 고칠 수 없어 문구를 고치는 변경이 새 마이그레이션이 된다. 그 마이그레이션이 활성 버전을 바꾸면 운영자가 고른 버전을 덮고, 바꾸지 않으면 새 인스턴스가 옛 버전으로 시작한다. 첫 체계가 `domain` 검증기를 거치지 않는다 |
| 씨앗 없이 운영자가 API 로 가져온다 | 모든 운영자가 시작 전에 한 단계를 더 하고, 평가가 "활성 체계 없음"을 늘 다뤄야 한다 |
| 설정으로 첫 기동 씨앗 파일을 바꾼다 | 첫 기동 뒤에는 설정이 아무 효과가 없어 혼동되고, 진입 경로가 둘이 된다 |
| 기동 적재를 `ApplicationReadyEvent` 에서 한다 | 웹 서버가 먼저 요청을 받을 수 있다 |
| 태그마다 완결된 질문 문장과 설명을 따로 둔다 | 태그의 뜻이 두 필드에 적힌다. 둘 다 요청에 실으면 토큰이 두 배, 하나만 실으면 다른 하나는 사본이다 |
| 형식의 기본 제외를 사용자 기본값을 만들 때(가입) 정한다 | 버전 내용은 바꾸지 않으므로 이미 적재한 버전에 값을 채울 길이 새 버전뿐이고, 코드에 키를 둘 유혹이 생긴다 |

## 후속 기록

- 2026-11-02: 결과 절이 남긴 "파일 개정을 알릴지"의 답 — 버전이 이미 있고 기본 체계 파일과 내용이 같은 버전이 하나도 없으면 기동 때 정보 로그 한 줄을 남긴다(태그 기준 · 저장 기준은 비교하지 않는다). 체계 변경의 방식은 [ADR-0062](0062-tag-set-versions-from-operator-text-activated-forward-with-key-lineage-and-recent-reevaluation.md)
