# ADR-0152: 비밀 값 평문의 래퍼 `SecretValue` 는 `platform` 의 공개 타입이고, 직렬화하면 실패한다

- 상태: 승인
- 날짜: 2026-11-14
- 근거: [이슈 #148](https://github.com/Theia0382/yozm-news/issues/148) — 키 검증의 인자 타입을 정하며 키를 다루는 모듈들의 의존 방향을 확인
- 관련: [ADR-0003](0003-byok-personalized-digest.md)(BYOK 키 보관)

## 맥락

- 사용자 LLM 키의 평문은 래퍼 타입으로 다루기로 했다 — 문자열 표현이 값을 숨기고 직렬화를 막는다([security.md](../security.md#byok-키-보관)).
- 그 타입을 쓰는 곳은 여럿이다 — 키를 받는 쪽, 암호화해 보관하는 쪽(`credential`), 검증하고 호출하는 쪽(`llm`).
- 모듈 사이의 순환 의존은 검증이 실패로 판정한다. 타입을 `llm` 에 두면 `credential` → `llm` 이, `credential` 에 두면 `llm` → `credential` 이 그 타입 하나로 정해진다.

## 결정

- **`SecretValue` 는 `platform` 의 공개 타입이다.** 어느 모듈의 지식도 아닌 횡단 장치다.
- **직렬화하면 실패한다.** Java 직렬화를 구현하지 않고, JSON 으로 쓰려 하면 예외가 난다 — 조용히 빠지지 않는다.
- 문자열 표현은 값을 숨긴다. 값 비교 · 해시를 내놓지 않는다. 평문은 꺼내는 메서드 하나로만 나온다.

규칙은 [platform Spec](../specs/platform.md#비밀-값) platform-R22 에 있다.

## 결과

- 키를 다루는 모듈들의 의존 방향이 이 타입 때문에 정해지지 않는다.
- 어느 모듈이든 평문 래퍼를 만들 수 있다. 저장한 키의 평문이 어디까지 가는지는 타입의 자리가 아니라 복호화를 내놓는 쪽의 공개 API 가 막는다.
- 응답 · 이벤트 · 로그의 객체에 실수로 담기면 조용히 새지 않고 그 자리에서 실패한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| `llm` 의 공개 타입으로 둔다 | `credential` → `llm` 의존이 정해져, 저장한 키로 호출하는 길이 의존을 뒤집는 장치를 요구한다 |
| `credential` 의 공개 타입으로 둔다 | `llm` → `credential` 의존이 정해지고, 타입 하나 때문에 모듈을 앞당겨 만든다 |
| 직렬화할 때 그 속성을 조용히 뺀다 | 잘못 담긴 것을 알 수 없다 |
