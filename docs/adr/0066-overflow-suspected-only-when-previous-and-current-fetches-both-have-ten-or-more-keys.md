# ADR-0066: 넘침 의심은 직전 · 이번 수집의 키가 모두 10개 이상일 때만 본다

- 상태: 승인
- 날짜: 2026-11-04
- 근거: [이슈 #83](https://github.com/Theia0382/yozm-news/issues/83) — 48시간 연속 수집 실측의 넘침 의심 4회를 원인별로 보고, 프리셋 피드 44개를 한 번씩 받아 항목 수와 발행 시각 범위를 잼(원문은 저장하지 않음). 구현 `83e9c6e`
- 관련: [ADR-0033](0033-feed-polling-db-lease-per-feed-new-items-and-per-source-request-spacing.md)(넘침 의심의 조건을 이 ADR 이 부분 대체), [ADR-0024](0024-collection-profile-yaml-and-preset-reference-or-own-profile.md)(수집 주기 하한을 넘침 신호로 다시 판단한다)

## 맥락

- ADR-0033 은 넘침 의심을 "직전 키가 있고 비어 있지 않고, 이번 항목이 있는데 하나도 겹치지 않을 때"로 정했다. 건수는 보지 않는다.
- 피드가 항목을 싣는 방식은 둘이다. 건수 상한 피드는 최신 C 건을 싣고, 새 기사가 가장 오래된 것을 밀어낸다 — 한 간격에 새 기사가 n 건이면 겹침 0 ⇔ n ≥ C 이고, 놓침은 n > C 일 때뿐이다. 시간 창 피드는 최근 일정 기간의 기사를 싣는다 — 겹침 0 은 직전 항목이 모두 기간 밖으로 나갔다는 뜻이고 새 기사의 수와 상관없다.
- 항목이 적으면 두 방식 모두 평범한 갱신에서 겹침 0 이 난다. 상한 1건 피드는 새 기사 하나에 겹침 0 이 되지만, 실제 놓침(한 간격에 2건 이상)은 그 가운데 일부다 — 기사가 간격당 평균 0.1건꼴로 무작위(포아송 분포)로 오면 약 4.9%다.
- 48시간 실측의 넘침 의심 4회 가운데 3회는 동아일보의 일괄 게시(직전 50 · 이번 50, 실제 57 · 80건)였고, 1회는 항목이 1 ~ 2건인 JTBC 날씨 피드에서 기사 하나가 바뀐 것(1 · 1)이었다.
- 프리셋 피드 44개를 한 번 받아 보니 동아일보 16개 · 경향신문 12개는 모두 50건, SBS 8개는 29건 · 101건이라 건수 상한으로 보였다. JTBC 8개는 2 ~ 54건이고 범위가 약 하루로 비슷해 시간 창으로 보였다. 10건 아래는 JTBC 의 2 · 4 · 6건 셋이다.
- WordPress 의 피드 기본 크기는 최신 10건이다.

## 결정

- **넘침 의심은 직전 키 수와 이번 키 수가 모두 10 이상이고 겹치는 키가 하나도 없을 때다.** 첫 수집 · 빈 피드 · 직전이 빈 피드는 키 수가 0 이라 빠진다.
- **키 수는 서로 다른 항목 키의 수다.** 정규화에서 건너뛴 항목과 한 수집 안의 같은 키는 세지 않는다.
- **10 은 코드 상수 하나다.** 운영자 설정 · 프로필 값으로 두지 않는다.
- **이미 쌓인 넘침 시각 · 횟수는 그대로 둔다.** 다시 세지 않는다.

## 결과

- 항목이 10건보다 적은 피드는 넘침 의심이 나지 않는다. 시간 창 피드의 기간 이탈과 작은 상한 피드의 평범한 교체가 경고 · 횟수에서 빠진다.
- 넘침 의심은 한 간격에 새 기사가 10건 이상 나왔다는 뜻이 된다 — 15분 간격이면 시간당 40건 이상이다.
- 상한이 10건보다 작은 건수 상한 피드는 실제 넘침이 나도 신호가 없다.
- 상한이 정확히 10건인 피드는 한 회차에 항목 하나만 정규화에서 빠지거나 키가 겹쳐도 키 수가 9 라 그 회차는 신호가 없다.
- 이 결정 전에 쌓인 넘침 횟수에는 옛 조건으로 센 값이 섞여 있다.
- 키 형식이나 피드 주소가 바뀌어 직전 키와 이어지지 않는 회차는 건수가 10 이상이면 넘침 의심이 된다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 피드에서 관측한 최대 키 수(용량)를 기록하고, 직전 · 이번이 그만큼 찼을 때만 넘침 의심으로 본다 | 1건 고정 피드와 두 건이 함께 바뀐 2건 피드는 여전히 넘침이다. 시간 창 피드는 큰 수가 한 번 관측되면 다시 차지 않아 신호가 꺼지고, 언론사가 상한을 줄여도 관측 최대가 남는다. 컬럼 · 마이그레이션이 는다 |
| 직전 · 이번 건수가 같을 때(피드가 찼을 때)만 넘침 의심으로 본다 | 1 · 1 을 그대로 넘침으로 둔다 |
| 지금 조건을 유지하고, 작은 피드의 경고는 대부분 놓침이 아니라고 적는다 | 경고 · 횟수가 계속 소음이라 수집 주기를 다시 판단하는 근거로 쓰지 못한다 |
| 최소 키 수 5 | 5 ~ 9건 시간 창 피드(JTBC 6건)에서 직전 항목이 한꺼번에 기간 밖으로 나가는 회차에 경고가 남을 수 있다 |
| 최소 키 수 20 | 흔한 10건 상한 피드(WordPress 기본)의 실제 넘침을 놓친다 |
| 최소 키 수를 피드 · 소스마다 운영자 설정이나 프로필 값으로 둔다 | 지금 피드 크기 분포에는 값 하나가 맞는다. 운영 데이터 하나를 위해 설정 표면이 는다 |
