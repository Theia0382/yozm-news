# ADR-0136: 안 읽은 알림 수는 화면 이동 · 창 포커스 때 다시 읽고, 주기 조회를 하지 않는다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #146](https://github.com/Theia0382/yozm-news/issues/146) — 구현 `6f88871`
- 관련: [ADR-0127](0127-sessions-idle-out-after-seven-days-without-an-absolute-limit-and-without-keep-signed-in-use-a-browser-cookie-and-two-hours.md)(세션은 마지막 요청 뒤의 비활성 기간으로 만료한다 — 이 결정이 지키는 것), [ADR-0011](0011-no-email-in-v1.md)(알림은 다음 로그인 때 보여준다 — 실시간 전달을 요구하지 않는다)

## 맥락

- 로그인한 화면의 머리줄에 안 읽은 알림 수를 보인다. 머리줄은 화면을 옮겨도 다시 그려지지 않는다.
- 알림은 실시간으로 전할 필요가 없다.
- 세션은 마지막 요청 뒤의 비활성 기간(로그인 유지를 끄면 2시간)으로 만료한다. 열어 둔 탭이 주기적으로 요청하면 그 탭이 열린 동안 세션이 만료되지 않는다.

## 결정

- **안 읽은 수는 로그인한 화면에 들어올 때 읽고, 경로를 옮길 때 · 창으로 돌아올 때 · 다시 연결될 때 다시 읽는다.** 같은 경로에서 질의만 바뀌면 다시 읽지 않는다.
- **주기 조회를 하지 않는다.**
- 알림 페이지에서 읽음을 보내면 안 읽은 수를 다시 읽는다.

## 결과

- 요청은 사용자의 행동에 비례하고, 열어 둔 탭이 세션 만료를 미루지 않는다.
- 한 화면에 오래 머무는 동안 생긴 알림은 화면을 옮기거나 창으로 돌아올 때까지 수에 나타나지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 위에 더해 주기 조회(예: 5분) | 열린 탭마다 사용자 수 × 탭 수에 비례하는 요청이 나가고, 탭을 열어 둔 동안 세션 비활성 만료가 사실상 무력해진다 |
| 서버가 밀어 준다(SSE · WebSocket) | 실시간 요구가 없는데 연결 유지 구성 요소와 프록시 설정이 는다 |
