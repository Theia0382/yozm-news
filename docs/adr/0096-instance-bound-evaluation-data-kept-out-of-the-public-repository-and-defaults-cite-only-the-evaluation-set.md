# ADR-0096: 인스턴스에 묶인 평가 데이터는 공개 저장소 밖에 두고, 기본값의 근거는 "평가 세트로 정했다"로 적는다

- 상태: 승인
- 날짜: 2026-11-08
- 근거: [이슈 #100](https://github.com/Theia0382/yozm-news/issues/100) — 평가 세트의 자리를 리드와 정하고 도구를 그에 맞춰 구현(`d4e2db7`)
- 관련: [ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)(결정 절 "평가 세트의 실제 기사 텍스트는 공개 저장소에 넣지 않는다"에 라벨 · 결과 기록의 자리를 더한다 — 보충), [ADR-0047](0047-self-hosted-software-run-by-instance-operators.md)(공식 인스턴스 없는 셀프 호스팅 소프트웨어), [ADR-0095](0095-event-clustering-evaluated-by-an-operator-tool-comparing-admin-api-results-with-full-day-labels.md)(평가 방법)

## 맥락

- 공개 저장소는 인스턴스 운영자가 띄우는 소프트웨어다. 개발팀은 공식 인스턴스를 운영하지 않는다([ADR-0047](0047-self-hosted-software-run-by-instance-operators.md)). 개발팀의 실측도 인스턴스 하나에서 한다.
- 사건 묶기 평가의 라벨은 그 인스턴스 DB 의 기사 ID 에 묶이고, 라벨러가 읽는 기사 텍스트는 그 DB 에 있다. 그 DB(와 덤프)가 없으면 라벨은 뜻이 없고, 덤프에는 텍스트가 있어 공개할 수 없다.
- 결과 기록은 그 인스턴스의 소스 구성 · 임베딩 모델 · 기준 · 기간의 값이라 다른 인스턴스로 옮겨지지 않는다.
- 기사 텍스트는 공개 저장소에 넣지 않는다([ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)).

## 결정

- **라벨 파일 · 라벨러의 메모 · 결과 기록은 인스턴스 쪽에 두고 공개 저장소에 두지 않는다.** 운영자가 고른 디렉터리(체크아웃 밖)이고, 평가 도구는 그 경로를 꼭 받는다 — 기본 경로를 두지 않는다.
- **도구 · 라벨 기준 · 파일과 결과 기록의 형식 · 실행 안내는 소프트웨어로서 공개 저장소에 둔다.**
- **기본값을 평가 세트로 정하면 공개 문서(ADR 포함)에는 "평가 세트로 정했다"만 적는다.** 측정 인스턴스의 수치는 적지 않는다.

## 결과

- 측정은 그 인스턴스(또는 그 덤프를 복원한 인스턴스)에서만 다시 할 수 있다. 운영자는 평가 디렉터리를 배포 설정 파일과 함께 백업한다.
- 기본값의 근거 수치는 공개 문서에 없다 — 값이 측정 인스턴스의 분포에 맞춰졌다는 사실만 남는다.
- 도구에 기본 경로가 없어 평가 파일이 체크아웃 안에 저절로 생기지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 텍스트가 없는 라벨과 결과 수치를 공개 저장소에 둔다 | 기사 ID 는 그 인스턴스 DB 밖에서 뜻이 없어 그 라벨로 측정을 재현할 사람이 없다. 결과는 한 인스턴스의 값이다 |
| 체크아웃 안의 정해진 디렉터리에 두고 무시 목록으로 뺀다 | 소스 트리 안에 인스턴스 데이터가 섞이고, 무시 파일까지 지우는 정리 명령에 함께 지워진다 |
| 인스턴스 DB 에 둔다(라벨 · 결과 테이블과 화면) | 앱 기능(테이블 · API · 화면)이 된다 — 평가가 필요한 만큼보다 크다 |
| 기본값 ADR 에 측정 수치를 요약해 적는다 | 한 인스턴스의 수치가 소프트웨어의 문서에 남아, 다른 구성의 운영자에게 근거처럼 읽힌다 |
