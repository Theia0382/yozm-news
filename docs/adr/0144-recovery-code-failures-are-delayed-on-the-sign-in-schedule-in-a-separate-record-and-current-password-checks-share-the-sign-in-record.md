# ADR-0144: 복구 코드 실패는 로그인과 같은 일정 · 같은 키의 다른 기록으로 지연하고, 현재 비밀번호 확인 실패는 로그인 실패 기록을 쓴다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #147](https://github.com/Theia0382/yozm-news/issues/147) — 구현 `830d39d`
- 관련: [ADR-0130](0130-sign-in-failure-delays-count-per-digest-of-the-submitted-normalized-email-regardless-of-account.md)(로그인 실패 지연 — 그 기록의 범위를 넓힌다), [ADR-0011](0011-no-email-in-v1.md)(복구 코드)

## 맥락

- 로그인 실패는 제출된 정규화 이메일의 다이제스트마다 세어 지연한다([ADR-0130](0130-sign-in-failure-delays-count-per-digest-of-the-submitted-normalized-email-regardless-of-account.md)).
- 복구 코드 재설정과, 로그인한 사람의 비밀번호 변경 · 복구 코드 재발급도 비밀을 대조한다. 지연이 없으면 추측의 길이 된다.
- 비밀번호를 잊은 사람은 로그인을 여러 번 실패한 뒤 복구로 온다.

## 결정

- **복구 코드 대조 실패는 로그인과 같은 일정 · 같은 키(제출된 이메일의 다이제스트)로, 다른 기록에 센다.**
- **현재 비밀번호 확인(비밀번호 변경 · 복구 코드 재발급)의 실패는 그 계정 이메일의 로그인 실패 기록에 센다.**
- 기록은 종류(로그인 · 복구)와 이메일 다이제스트의 짝마다 하나다. 정리 · 일정은 종류와 무관하게 같다.

## 결과

- 로그인을 거듭 실패한 사람이 복구에서 기다리지 않는다. 한 이메일의 추측 예산은 비밀(비밀번호 · 복구 코드)마다 하나다.
- 세션을 얻은 사람이 현재 비밀번호 확인으로 비밀번호를 추측해도 로그인과 같은 예산을 쓴다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 복구도 로그인 실패 기록을 함께 쓴다 | 비밀번호를 잊어 로그인을 거듭 실패한 사람이 복구 전에 기다린다 |
| 현재 비밀번호 확인을 따로 센다 | 같은 비밀(비밀번호)의 추측 예산이 둘이 된다 |
