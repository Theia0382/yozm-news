# ADR-0046: 운영자 원문을 고치면 읽기 설정이 바뀐 켜진 피드(검토일이 사라지면 소스)를 끄고, 피드 켜기는 저장 직전에 읽기 설정 전체를 다시 대조한다

- 상태: 승인
- 날짜: 2026-10-31
- 근거: [이슈 #25](https://github.com/Theia0382/yozm-news/issues/25) — 기점 `94495a8` 의 관문 판정 순서와 PostgreSQL 기본 격리 수준(READ COMMITTED)에서의 갱신 경합을 분석하고, 그 경합을 막는 피드 행 버전(낙관적 잠금)을 시험으로 확인. 구현 `ac2837a`
- 관련: [ADR-0041](0041-activation-gate-previews-a-feed-on-enable-and-judges-by-code-constants.md)(활성화 관문 — 판정 순서 · 기준값은 그대로, 저장 직전 대조의 대상을 이 ADR 이 넓힌다), [ADR-0024](0024-collection-profile-yaml-and-preset-reference-or-own-profile.md)(운영자 프로필은 완결된 프로필, 화면에서 원문을 편집)

## 맥락

- 활성화 관문은 꺼진 피드를 켜는 순간에만 판정하고, 이용조건 검토일은 소스를 켤 때만 본다. 수집은 매번 그때의 원문으로 프로필을 얻는다.
- 등록된 운영자 원문을 고치는 유스케이스가 없었다. 원문만 바꿔 저장하게 하면 켜진 피드의 URL · 읽기 규칙을 미리보기 없이 바꾸고, 켜진 소스의 검토일을 지울 수 있다. 고칠 수 없으면 오타 하나에도 새 소스를 등록해야 하고, 소스 · 피드는 지우지 않아 버린 소스가 쌓인다.
- 피드 켜기의 저장 직전 판정은 피드 URL 만 대조했다. 켜기와 원문 수정이 서로 다른 행만 쓰면(켜기는 피드 행, 수정은 소스 행) READ COMMITTED 에서 둘 다 커밋된다.
- 이름공간 접두사는 검증 때 이름공간 URI 로 풀려 읽을 곳의 요소 이름에 든다. 날짜 형식 값은 패턴과 컴파일한 형식기를 함께 갖는데, 형식기는 값으로 비교되지 않는다.

## 결정

- **피드 읽기 설정을 정본 하나로 둔다.** 한 피드를 받아 기사로 만드는 데 쓰이는 프로필 값 — 피드 URL · 소스 언어(날짜 텍스트의 로캘) · 사전 보정 · 읽을 곳 · 날짜 해석. 이름 · 홈페이지 · 섹션 · 검토일 · 수집 주기는 읽기 설정이 아니다. 프로필 모델에 값이 늘면 분류 표 시험이 실패한다. 날짜 형식은 패턴 문자열로 비교한다.
- **운영자 원문을 고치면** 새 원문을 검증하고(실패면 아무것도 바꾸지 않는다), 켜진 피드 가운데 옛 · 새 원문 모두에 있고 읽기 설정이 같은 것만 켜진 채 둔다 — 원문에서 빠졌거나 옛 원문이 검증에 걸렸던 피드도 끈다. 켜진 소스는 새 원문에 검토일이 없으면 끈다. 새로 생긴 피드는 꺼진 채 더한다. 피드 행은 지우지 않는다. 한 트랜잭션이다.
- **수정은 그 소스의 피드 행을 바뀌지 않았어도 모두 저장한다.** 피드 행의 낙관적 잠금 버전이 올라, 켜기와 겹치면 늦은 쪽이 실패한다.
- **피드 켜기의 저장 직전 판정은 그 피드의 읽기 설정 전체를 미리본 것과 대조한다.** 다르면 켜지 않는다(URL 만 다를 때도 같다).
- **프리셋 소스의 원문은 없다.** 프리셋 배포로 바뀐 프리셋은 다시 판정하지 않는다 — 프리셋의 품질은 개발팀의 시험이 맡는다(ADR-0041 그대로).

## 결과

- 운영자는 등록된 원문을 고칠 수 있고, 수집에 영향을 주는 수정은 그 피드를 다시 관문에 세운다. 이름 · 섹션 · 주기만 고치면 수집이 멈추지 않는다.
- 사전 보정 · 읽을 곳 · 날짜 · 언어는 소스 전체의 값이라 하나만 고쳐도 그 소스의 켜진 피드가 모두 꺼진다.
- 수정 결과(끈 피드 · 소스를 껐는지 · 더한 피드)가 운영자에게 간다.
- 켜기와 수정이 겹치면 한쪽이 동시 수정(409)으로 실패하고, 운영자가 다시 시도한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 원문은 등록할 때만 쓰고 고치지 않는다 | 관문 우회는 없지만, 오타 · 언론사 주소 변경마다 새 소스가 생기고 옛 소스 · 피드는 지울 수 없어 남는다 |
| 고쳐도 켜진 상태를 그대로 둔다(프리셋 배포와 같은 신뢰) | 켜진 피드가 미리보기 없이 다른 주소 · 규칙으로 수집되고, 검토일 없는 소스가 계속 수집한다 |
| 원문이 바뀌면 그 소스의 켜진 피드를 모두 끈다 | 이름 · 섹션 같은 표시 값만 고쳐도 수집이 멈춘다 |
| 저장 직전 판정은 URL 만 대조한다 | 미리보는 동안 읽기 규칙 · 검토일이 바뀐 원문으로 옛 미리보기의 피드가 켜진다 |
| 수정은 바뀐 피드 행만 저장한다 | 켜기와 수정이 서로 다른 행만 써 둘 다 커밋되는 경합이 남는다 |
