# ADR-0244: 스토리라인 구독 이력의 화면 처리기는 `user` 가 키 없이 열고, 소비자 조회 대신 같은 모듈의 유스케이스가 최근부터 쪽으로 읽는다

- 상태: 승인
- 날짜: 2026-11-18
- 근거: [이슈 #186](https://github.com/Theia0382/yozm-news/issues/186) — 기점 `33ab070` 의 소비자 조회 `StorylineSubscriptionDirectory.changes` · 구독 처리기 · 이력 색인을 대조하고 리드와 정함
- 관련: [ADR-0190](0190-storyline-subscription-handlers-are-open-without-a-key.md)(보충 — 결정 "스토리라인 구독 처리기를 키 없이 연다"의 처리기에 구독 이력 처리기가 든다), [ADR-0228](0228-consumer-queries-scoped-by-a-user-argument-may-be-called-on-screen-paths-with-the-session-user.md)(관련 — 결과 "같은 읽기에 화면용 조회를 따로 열지 않는다"와의 관계는 결과 절), [ADR-0191](0191-the-consumer-query-of-storyline-subscriptions-is-opened-with-the-subscriptions-and-resolves-ids-without-writing.md)(관련 — 남는 쪽으로 푸는 규칙은 한 곳), [ADR-0192](0192-reader-screens-are-composed-by-the-reader-module-over-module-public-queries.md)(관련 — 구독 화면은 데이터를 가진 모듈이 연다), [ADR-0243](0243-the-subscription-history-on-the-subscription-screen-shows-only-the-users-own-subscribe-and-unsubscribe.md)(보이는 행)

## 맥락

- 사용자가 정해 두는 것(구독 등)의 화면 처리기는 그 데이터를 가진 모듈이 연다. 스토리라인 구독은 `user` 의 것이다.
- 소비자 조회 `changes` 는 기간 하나의 이력 행 전부를 오래된 것부터, 모든 원인을 낸다. 건수 상한이 없고, 구독 · 해제 처리기에는 요청 제한이 없어 한 사용자의 이력은 한없이 길어질 수 있다.
- 화면은 사용자 행만, 최근부터, 한 쪽씩 필요하다. 이력 테이블에는 사용자 · 시각 · 행 순 색인이 있다.
- 기록된 스토리라인 ID 를 지금 남는 ID 로 푸는 일은 구독 따라가기와 소비자 조회가 이미 한다.
- 구독 이력은 스토리라인 ID · 더함 뺌 · 시각만 내고 기사 내용을 내지 않는다.

## 결정

- **구독 이력의 화면 처리기는 `user` 의 구독 처리기 옆에 두고 키 없이 연다.** 세션 사용자로만 읽는다.
- **소비자 조회를 거치지 않고, 같은 모듈의 유스케이스가 저장소에서 사용자 행을 최근부터 (시각, 행) 커서로 한 쪽씩 읽는다.** 읽기 전용이다 — 설정 행을 잠그지 않고 구독을 따라가지 않는다. 한 쪽은 50건이다(측정 전 목표).
- **기록된 ID 를 지금 남는 ID 로 푸는 정본은 하나다.** 구독 따라가기 · 소비자 조회 · 구독 이력이 함께 쓴다.

## 결과

- 이력의 길이와 상관없이 응답 하나의 크기가 한 쪽으로 묶인다. 한 쪽은 카드 처리기 한 번의 상한 이하라 화면이 제목을 카드 한 번으로 붙인다.
- 소비자 조회의 계약(기간 · 모든 원인 · 오래된 것부터)은 그대로이고 다른 모듈이 쓰지 않는 쪽 메서드가 공개 계약에 생기지 않는다.
- ADR-0228 의 "같은 읽기에 화면용 조회를 따로 열지 않는다"는 다른 모듈의 처리기가 소비자 조회를 엮는 경우다. 이 읽기는 고르는 행 · 순서 · 쪽이 다른 데이터 소유 모듈 안의 읽기다 — 같은 모듈에서 화면의 지금 구독(잠금 · 따라가기 · 상태)과 소비자의 지금 구독(쓰지 않음 · ID 순)이 갈린 것과 같은 꼴이다.
- 키를 모두 지운 사용자도 처리기로는 이력을 읽는다. 화면은 키 뒤다([ADR-0242](0242-the-storyline-subscription-list-lives-on-the-key-gated-storyline-screen.md)).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 화면이 소비자 조회 `changes` 를 기간(예: 최근 90일)으로 부른다 | 기간 안 행 수에 상한이 없고, 오래된 것부터라 화면 순서와 거꾸로다 |
| 소비자 조회 인터페이스에 쪽 메서드를 더한다 | 다른 모듈이 쓰지 않는 메서드가 공개 계약에 생긴다 |
| 응답에 제목을 싣는다(`user` 가 대표 기사를 읽는다) | 구독 처리기는 스토리라인의 표시 정보를 내지 않는다 — 제목은 카드 처리기가 낸다 |
| 읽을 때 설정 행을 잠그고 구독을 따라간다 | 이력은 추가만 하는 행이고 지금 ID 는 읽을 때 풀어 낸다 — 쓸 것이 없다 |
| 키 관문 뒤에 둔다 | 내용을 내지 않는 구독 처리기를 키 없이 여는 기준(ADR-0190)과 어긋난다 |
