# ADR-0010: 태그 체계: 축 분리 + 통제 어휘 다중 태그

- 상태: 승인
- 날짜: 2026-10-25
- 관련: [ADR-0002](0002-shared-evaluation-with-jev.md)의 "다중 카테고리(확률 상위 최대 2개)" 부분을 대체한다
- 근거 자료: [research/2026-10-news-categories.md](../research/2026-10-news-categories.md)

## 맥락

- 국내 포털 분류는 주제, 지역, 형식을 한 목록에 섞는다. 그래서 기사 하나에 하나를 고르는 분류에서는 경계가 모호해진다.
- 실제 기사는 여러 주제와 지역에 동시에 걸친다. 예: 반도체 수출 규제 → 산업·기업 + 국제, 한미 관세 협상 → 국내 + 미국.
- Jev의 질문 형식은 Choice(선택지 하나), Score(순서 척도), Yes/No 세 가지다. Choice는 선택지 하나를 고르는 분포라서, 여러 주제에 걸친 기사는 확률이 나뉘어 각각 낮게 나온다. 다중 소속을 판단하는 근거로 쓰기 어렵다.
- Choice의 선택지 상한은 자료마다 다르게 적혀 있다(255개 또는 10단계). TypeSafe는 여러 요인을 따지는 판단을 좁은 질문 여러 개로 나누라고 권장한다. 한 요청에 질문을 여러 개 넣을 수 있고, 각 질문은 병렬로 평가된다고 한다.

## 결정

### 태그 축

기사에는 **운영자가 관리하는 통제 어휘(태그 체계)에서 고른 태그**를 붙인다. 자유 키워드 태그는 아니다.

| 축 | 다중 여부 | 어휘 | Jev 질문 |
|---|---|---|---|
| 주제 `topic` | 다중 | 2단계: 대분류 9개, 중분류 45개 | 중분류마다 Yes/No: "이 기사는 {설명}을 주요하게 다루는가" |
| 지역 `region` | 다중 | 국내, 북한·한반도, 미국, 중국, 일본, 유럽, 기타 해외 | 지역마다 Yes/No |
| 형식 `format` | 단일 | 스트레이트, 분석·해설, 오피니언·칼럼, 인터뷰, 보도자료·홍보, 단신·공지 | Choice 하나(선택지 6개) |
| 중요도 | 단일 값 | — | Score |

- 대분류 태그는 Jev에 묻지 않는다. 중분류 태그에서 파생한다(중분류가 붙으면 부모 대분류도 붙는다).
- 모든 질문을 **기사당 요청 하나**에 담는다. state(제목·요약문)는 한 번만 보낸다.
- 기존 `digest_worthy` Yes/No 질문은 형식 축으로 대체한다. 보도자료·홍보와 단신·공지는 기본적으로 후보에서 뺀다.

### 태그 판정과 저장

- 판정 규칙: 태그별 확률이 임계값 `τ` 이상이면 붙인다. 임계값은 축별로 두고, 태그 체계 버전의 설정으로 관리한다.
- 주제 태그가 하나도 붙지 않으면 확률이 가장 높은 태그를 하나 붙이고 `low_confidence`로 표시한다. 그래도 하한 미만이면 `미분류`로 둔다.
- **정규화 저장**: 태그는 `article_tags(article_id, dimension, tag_key, probability, evaluation_id)` 행으로 저장한다.
  - 저장 하한(예: 0.1)을 넘는 태그는 확률과 함께 모두 저장한다.
  - "붙었는지"는 조회 시 현재 임계값으로 판단한다. 그래서 **임계값을 바꿔도 다시 평가하거나 데이터를 다시 쓸 필요가 없다.**
  - 전체 응답 원본은 `article_evaluations.raw_response`에 따로 남는다.
- 사용자 선호도 같은 방식으로 정규화한다: `user_tag_preferences(user_id, dimension, tag_key, mode)`. `mode`는 `SUBSCRIBE` 또는 `EXCLUDE`다. 대분류를 구독하면 하위 중분류 전체를 구독한 것으로 처리한다.

## 결과

- 경계에 걸친 기사가 해당하는 모든 주제·지역 구독자의 후보에 들어간다.
- 질문 수가 늘어난다. 주제 45개 + 지역 7개 + 형식 + 중요도로 질문 약 54개이고, 기사당 입력은 약 1,700토큰으로 추정한다. 하루 4,000건 기준 **월 약 $9**다. 사용자 수와는 여전히 무관하다.
- 대분류를 먼저 묻고 해당 대분류의 중분류만 다시 묻는 2단계 방식이면 토큰이 약 20% 줄어든다. 하지만 요청이 두 번이 되고 구현이 복잡해진다. 비용 차이가 월 $2 안팎이라 단일 요청을 택했다.
- Yes/No 확률은 질문마다 독립적이라, 일반적인 기사에 태그가 너무 많이 붙을 수 있다. 파일럿에서 축별 평균 태그 수를 보고 임계값과 설명 문구를 조정한다.
- 고유명사(기업명, 인물 등)를 자유 태그로 붙이는 일은 Jev로 할 수 없다. 텍스트를 생성하지 않기 때문이다. 필요해지면 별도 개체명 추출 단계를 검토한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 주제 Choice 하나 + 확률 상위 2개 | 여러 주제에 걸친 기사는 확률이 나뉘어 판단 근거가 약해진다. 선택지 상한도 불확실하다 |
| 대분류만 사용 | 너무 거칠어 사용자 후보가 커지고 LLM 비용이 늘어난다 |
| 2단계 질의(대분류 → 중분류) | 위 "결과" 참고 |
