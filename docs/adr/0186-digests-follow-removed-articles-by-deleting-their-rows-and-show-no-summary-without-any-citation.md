# ADR-0186: 다이제스트는 지운 기사의 행을 따라 지우고, 인용이 하나도 없는 종합문은 생성 때도 기사 삭제 뒤에도 보이지 않는다

- 상태: 승인
- 날짜: 2026-11-16
- 근거: [이슈 #8](https://github.com/Theia0382/yozm-news/issues/8) — 다이제스트 모듈의 출력 검증 · 저장과 지운 기사 따르기를 설계. 구현 `8895f31`(출력 읽기 · 인용 검증) · `6d0301a`(생성 · 저장) · `2da10e7`(지운 기사 따르기)
- 관련: [ADR-0051](0051-operator-hides-or-deletes-sources-and-feeds-and-deletion-removes-exclusive-articles.md)(보충 — 결과 절의 "다이제스트가 삭제를 따르는 길은 미설계"를 정함), [ADR-0060](0060-article-deletion-announced-by-removed-article-ids-and-followed-by-referencing-modules.md)(보충 — 따르는 범위를 행에서 섹션까지 넓힘)

## 맥락

- 다이제스트는 LLM 이 후보 기사를 별칭으로 인용해 쓴 종합문(개요 · 주요 뉴스 · 추가 헤드라인)이다. LLM 출력은 데이터로 다루고, 인용은 후보 목록과 대조해 후보에 없는 별칭을 지우며, 인용이 빈 항목은 버린다(pipeline). 별칭을 모두 지어낸 출력은 개요만 남는다 — 개요는 인용이 없어 근거 기사와 대조할 수 없다.
- 후보가 없는 기간의 다이제스트는 `EMPTY` 다 — "기간에 후보 없음"이고 LLM 을 부르지 않은 경우다.
- 운영자가 소스 · 피드를 지우면 그것만 가진 기사가 지워진다. 언론사의 삭제 요청을 처리하는 길이기도 하다([ADR-0051](0051-operator-hides-or-deletes-sources-and-feeds-and-deletion-removes-exclusive-articles.md)). 기사를 ID 로 가리키는 모듈은 `ArticlesRemoved` 를 받아 자기 행을 지운다([ADR-0060](0060-article-deletion-announced-by-removed-article-ids-and-followed-by-referencing-modules.md)). 데이터 모델은 기사 메타데이터를 "지난 다이제스트의 링크를 유지하기 위해" 무기한 보존한다고 적어 이 삭제와 어긋나 있었다.
- 다이제스트의 인용은 노출 기록이고 관심도가 노출 수로 쓴다. 지운 기사의 태그도 같은 이벤트로 지워져, 노출 행만 남겨도 주제로 셀 수 없다.

## 결정

- **생성 때 검증 뒤 인용이 하나도 남지 않으면 그 다이제스트는 실패(`FAILED`, 인용 없음)다.** 개요만 있는 다이제스트를 `READY` 로 두지 않고, `EMPTY` 와 섞지 않는다.
- **지운 기사를 따를 때 그 기사의 후보 · 인용 행을 지우고, 인용이 모두 지워진 주요 뉴스 · 추가 헤드라인 섹션을 지운다.** 인용 섹션이 하나도 남지 않은 다이제스트는 개요도 지운다.
- **다이제스트 행(상태 · 기간 · 공급자 · 모델 · 토큰 · 소요 시간)은 남긴다.** 사용자 비용의 기록이다. 인용 섹션이 모두 지워진 다이제스트는 내용 없는 `READY` 다.
- 기사 정보를 다이제스트에 복사해 두지 않는다 — 인용은 기사 ID 로만 가리킨다.

규칙은 [digest Spec](../specs/digest.md#5-규칙과-불변식) digest-R6 · digest-R8 · digest-R10 에 있다.

## 결과

- 저장된 다이제스트는 생성 때와 같은 기준을 지킨다 — 남은 주요 뉴스 · 추가 헤드라인은 기사를 하나 이상 인용하고, 인용이 하나도 없는 다이제스트는 종합문을 보이지 않는다.
- 별칭을 지어낸 출력이 실패율에 드러난다. 사용자 비용을 쓴 생성이 화면에 아무것도 남기지 않을 수 있다 — 다시 부를지는 실제 생성기가 정한다.
- 언론사 삭제 요청으로 지운 기사의 제목 · 링크가 지난 다이제스트에 남지 않는다. 남은 개요 · 주요 뉴스의 요약에는 지운 기사의 내용을 종합한 문장이 남을 수 있다.
- 같은 "인용 없음"이 생성 때는 `FAILED`, 기사 삭제 뒤에는 내용 없는 `READY` 로 상태가 갈린다. 화면은 내용 없는 다이제스트를 따로 그린다.
- 기사 메타데이터의 무기한 보존은 운영자 삭제의 예외를 갖는다 — 지운 기사의 지난 다이제스트 링크는 유지하지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 인용 없는 출력을 개요만 있는 `READY` 로 | 근거와 대조할 수 없는 종합문을 보인다. 실패가 성공으로 숨는다 |
| 인용 없는 출력을 `EMPTY` 로 | `EMPTY` 의 뜻("기간에 후보 없음")이 둘로 갈려 사용자에게 틀린 까닭을 보인다 |
| 지운 기사의 행만 지우고 섹션은 남김 | 생성 때 버렸을 인용 없는 주요 뉴스가 저장 뒤에는 남는다 — 두 규칙이 된다 |
| 인용 섹션이 모두 지워져도 개요는 남김 | 인용 없는 개요만 있는 다이제스트가 생겨, 생성 때 실패로 막는 꼴과 저장 뒤의 꼴이 다르다 |
| 기사 정보(제목 · 링크 · 출처 · 시각)를 생성 때 복사해 남김 | 삭제 요청으로 지운 기사의 제목 · 링크가 사용자 화면에 남는다. 기사 정보의 두 번째 사본이다. 행을 남기고 조회 때 거르는 꼴은 [ADR-0060](0060-article-deletion-announced-by-removed-article-ids-and-followed-by-referencing-modules.md)이 기각했다 |
| 다이제스트 행까지 지움 | 사용자 비용(토큰 · 모델)의 기록이 사라진다 |
