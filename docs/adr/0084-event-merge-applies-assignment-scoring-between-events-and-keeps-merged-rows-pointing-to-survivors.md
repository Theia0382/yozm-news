# ADR-0084: 사건 병합은 배정 산식 · 판정을 사건 대 사건에 쓰고, 합쳐진 사건은 남는 사건을 가리키는 행으로 남긴다

- 상태: 승인. 부분 대체 — 임베더가 없는 프로세스의 건너뜀([ADR-0093](0093-worker-role-does-not-run-without-an-embedder-built-only-in-the-worker-role.md))
- 날짜: 2026-11-07
- 근거: [이슈 #98](https://github.com/Theia0382/yozm-news/issues/98) — 병합의 판정 기준 · 실행 자리 · 합쳐진 사건 행을 리드와 정하고 구현(`8eba5ca` · `bb34862` · `ac942e1`)
- 관련: [ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)(결정 절 "4. 정리"의 병합을 정한다, 후속 기록), [ADR-0071](0071-event-membership-judged-from-article-ids-with-questions-built-in-evaluation.md)(사건 소속 판정 — 공개 API 를 바꾸지 않고 쓴다), [ADR-0080](0080-event-centroids-and-key-terms-accumulated-with-article-counts-and-updated-incrementally.md)(누적 갱신 — 합친 중심은 기사 수 가중 평균), [ADR-0081](0081-event-assignment-criteria-in-settings-and-rejudgement-within-stored-scores.md)(사건 기준 — 병합도 같은 기준을 쓴다), [ADR-0087](0087-closed-event-assignments-are-not-rejudged-and-closing-and-merging-are-not-undone.md)(합치기는 되돌리지 않는다)

## 맥락

- 사건 배정은 기사가 들어온 순서대로 하나씩 판정해, 같은 사건이 여러 사건으로 쪼개질 수 있다. 정리 단계의 병합이 이를 보완한다고 정했다([ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)).
- 사건은 중심 · 기사 수 · 핵심 말(말마다 그 말을 가진 기사 수) · 첫 ~ 마지막 기사 시각을 갖는다. 배정 점수 산식은 기사 대 사건이고, 기사 자리에 사건을 두면 시각 차는 두 시각 범위 사이의 간격이 된다. 핵심 말 겹침은 기사 쪽 말을 기준으로 세는 비대칭 식이다.
- 띠의 판정은 `evaluation` 의 사건 소속 판정("이 기사는 사건 X 를 다루는가")이 한다. 공개 API 는 판정할 기사 하나와 후보 사건 · 그 서술 기사를 ID 로 받는다([ADR-0071](0071-event-membership-judged-from-article-ids-with-questions-built-in-evaluation.md)).
- 합쳐진 사건의 ID 는 다른 모듈 · 저장 후보 · 판정 원본에 남는다. 사건 행에는 기사 수 1 이상 제약이 있고, 배정의 사건은 FK 다.
- 사건 묶기 반복 작업은 1분마다 표현 · 배정 · 재판정 회차를 차례로 돈다. 열린 사건 수는 재지 않았다 — 매번 모든 쌍을 비교하면 제곱으로 는다(추정). 두 사건의 점수는 중심 · 핵심 말 · 시각 범위로만 정해져, 둘 다 바뀌지 않았으면 그대로다.

## 결정

- **병합은 사건 하나를 기사 자리에 둔 배정이다.** 점수는 배정 산식(코사인 · 핵심 말 겹침 · 시각 감쇠)을, 판정은 배정의 판정 규칙과 위 · 아래 · 확률 기준을 그대로 쓴다. 위 기준 이상이면 합치고, 띠는 사건 소속 판정에 묻는다. 사건 대 사건에만 필요한 것만 더한다 — 시각 차는 두 시각 범위 사이의 간격이고, 핵심 말 겹침은 기사 수가 적은 쪽(같으면 나중에 연 쪽)의 핵심 말을 기준으로 세어, 어느 쪽에서 보아도 같은 쌍은 같은 점수다.
- **묻기는 사건 소속 판정 공개 API 를 바꾸지 않고 쓴다.** 판정할 기사는 바뀐 사건의 서술 기사 하나이고, 후보는 상대 사건과 그 서술 기사다. 받은 확률은 순서 없는 쌍마다 한 번 남기고, 사건이 바뀌어도 다시 묻지 않는다. 판정 원본은 그 기사의 판정으로 `evaluation` 이 남긴다.
- **병합은 사건 묶기 반복 작업의 네 번째 회차다.** 재판정 회차 다음에, 지난 확인 뒤 고쳐진 열린 사건만 본다 — 사건 값을 쓸 때마다 느는 정수(고친 횟수)를 확인한 값 · 기준과 비교한다. 기준이 바뀌면 열린 사건을 한 번씩 다시 본다. 회차마다 보는 사건 수에 상한이 있다.
- **같은 모델 버전의 열린 사건끼리만 합친다. 남는 사건은 기사 수가 많은 쪽, 같으면 먼저 연(ID 가 작은) 쪽이다.** 합친 값은 중심이 기사 수 가중 평균, 수는 합, 첫 기사 시각 · 연 시각은 이른 쪽, 마지막 기사 시각 · 마지막으로 붙은 시각은 늦은 쪽, 핵심 말은 말마다 수를 더한 것이다. 기사 표현을 읽지 않는다.
- **합쳐진 사건 행은 지우지 않는다.** 상태 `MERGED` 로 남는 사건을 바로 가리키고(사슬을 두지 않는다 — 남는 사건이 다시 합쳐지면 가리키던 행도 새 남는 사건을 가리킨다), 합칠 때의 값을 남긴다. 배정은 사건만 남는 사건으로 옮긴다. 남는 사건이 비어 지워지면 합쳐진 행 · 그 사건들을 가리키는 저장 후보 · 병합 판정 기록을 함께 지운다. 사건 ID 로 찾는 공개 조회는 합쳐진 사건이면 남는 사건을 낸다.
- **잠금은 배정 행(기사 ID 순) → 사건(ID 순)이다.** 지운 기사 따르기 · 재판정과 같은 순서다. 잠근 뒤 두 사건이 열려 있고 모델 버전이 같고 잠근 배정 수가 사건의 기사 수와 같을 때만 합치고, 아니면 되돌려 다음 회차가 다시 본다. 같은 반복 작업 안이라도 이 순서와 확인에 기댄다 — 지운 기사 따르기는 다른 스레드에서 돈다.

## 결과

- 들어온 순서 때문에 쪼개진 사건이 배정 직후 합쳐져, 뒤 기사가 합친 사건을 후보로 본다. 병합 기준이 배정과 같아 새 설정 · 측정 대상이 없다. 배정 산식을 사건 대 사건에 쓰는 근거는 측정 전이고, 평가 세트로 병합 전후의 묶음 정확도를 잰다.
- 띠 쌍마다 Jev 요청이 한 번 는다(운영자 비용) — 바뀐 사건 하나에 요청 하나다. 묻는 쪽은 비대칭(바뀐 사건의 서술 기사)이고 기록은 순서 없는 쌍이다.
- 합쳐진 사건 ID 를 가진 쪽은 사건 ID 로 찾아 남는 사건을 얻는다. 합쳐진 사건의 기사 조회는 빈 목록이다.
- 합칠 때마다 남는 사건의 고친 횟수가 늘어 다음 회차가 다시 본다. 열린 사건 수가 줄기만 하므로 사슬 병합은 끝난다.
- 기준을 바꾼 뒤에는 열린 사건 모두가 대상이라, 회차 상한만큼씩 지나는 동안 새로 바뀐 사건이 뒤에 선다(열린 사건 수는 측정 전).
> 부분 대체 — [ADR-0093](0093-worker-role-does-not-run-without-an-embedder-built-only-in-the-worker-role.md). 지금 상태: [event Spec §5](../specs/event.md#사건-묶기-대기와-회차) event-R7
- 임베더가 없는 프로세스에서는 다른 회차와 함께 건너뛴다.
- 합친 사건을 사건 단위로 다시 나누는 경로는 없다([ADR-0087](0087-closed-event-assignments-are-not-rejudged-and-closing-and-merging-are-not-undone.md)). 합친 사건 안의 기사는 기사 단위로 재판정된다([ADR-0085](0085-rejudgement-knows-opened-events-from-an-assignment-flag-and-reads-merged-candidates-as-survivors.md)).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 배정 산식 · 위 기준만 쓰고 띠는 묻지 않는다 | 띠의 쌍을 산식만으로 가를 수 없어, 배정이 판정으로 가르는 구간이 병합에서는 늘 "합치지 않음"이 된다 |
| 병합 전용 기준 둘(중심 코사인 · 핵심 말 겹침)을 둔다 | 설정 둘과 측정 대상이 늘고, 배정 기준과 어긋나면 붙이지는 않았을 사건끼리 합치는 경우가 생긴다 |
| 사건 대 사건을 묻도록 사건 소속 판정의 질문 · 공개 API 를 바꾼다 | `evaluation` 의 질문 · 원본 형식이 바뀐다. 서술 기사 하나를 판정할 기사로 두면 지금 API 로 물을 수 있다 |
| 쌍마다 작은 사건의 서술 기사로 묻는다 | 바뀐 사건 하나에 질문이 후보 수만큼 생긴다 |
| 따로 둔 반복 작업(예: 1시간마다) | 배정과 동시에 돌아 잠금으로만 막아야 하고, 다음 실행까지 쪼개진 사건에 기사가 계속 나뉘어 붙는다 |
| 바뀐 사건을 바뀐 시각으로 고른다 | 같은 시각에 두 번 바뀌면 놓치고, 시험 시계와 DB 시계가 섞인다 |
| 병합 대기 테이블을 둔다 | 사건을 바꾸는 모든 쓰기(열기 · 붙이기 · 빼기 · 옮기기 · 합치기)에 넣기를 더해야 한다 |
| 합쳐진 사건 행을 지운다 | 다른 모듈 · 저장 후보 · 판정 원본에 남은 ID 를 이어서 조회할 수 없다 |
| 합쳐진 사건이 바로 앞 남는 사건을 가리키는 사슬로 둔다 | 조회 · 재판정이 사슬을 끝까지 따라가야 한다 |
