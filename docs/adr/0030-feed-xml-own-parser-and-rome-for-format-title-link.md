# ADR-0030: 피드 문서는 자체 구성한 XML 파서로 읽어 DTD 선언을 거부하고, Rome 은 형식 판별 · 제목 · 링크에만 쓴다

- 상태: 승인
- 날짜: 2026-10-28
- 근거: [이슈 #18](https://github.com/Theia0382/yozm-news/issues/18) — Rome 2.1.0 · JDOM 2.0.6.1 · jsoup 1.23.2 바이너리를 JDK 25 에서 실행해 확인. 구현 `ace31a1`(문서 읽기) · `cdc9aa3`(필드 규칙) · `cb2a62f`(정규화 조립)
- 관련: [ADR-0004](0004-tech-stack.md)(RSS 파싱은 Rome — 이 ADR 이 Rome 의 역할을 좁힌다), [ADR-0015](0015-source-presets-and-collection-profiles.md)(보정은 수집 프로필로), [ADR-0024](0024-collection-profile-yaml-and-preset-reference-or-own-profile.md)(수집 프로필 형식)

## 맥락

- 피드는 신뢰할 수 없는 입력이고, 국내 RSS 는 형식 이상이 흔하다([조사 자료](../research/2026-10-rss-survey.md)). 보정은 수집 프로필이 고른 것만 적용해야 한다([ADR-0015](0015-source-presets-and-collection-profiles.md)).
- Rome 의 기본 사용법(`SyndFeedInput.build(Reader)`)에는 다음 성질이 있다.
  - 날짜를 자기 규칙(관대 모드 `SimpleDateFormat`, 영어 로캘)으로 해석하고, 해석하지 못하면 원문을 남기지 않는다. `2026-10-25 09:31:38` · 한국어 날짜 · 오프셋 없는 값이 모두 빈 값이 된다.
  - 원문 보정기(healer)가 기본으로 켜져 있다. 프로필과 무관하게 HTML 4 엔티티를 바꾸고, 맨 `&` 를 고치며, 선언 앞 공백을 지운다.
  - DOCTYPE 을 허용하면 내부 subset 의 엔티티를 펼친다. 거부 설정은 JDOM 의 공유 파서 팩토리에 남아, 같은 JVM 의 다른 빌더에도 걸린다.
  - 접두사 없는 비표준 요소를 버리고, guid 가 없으면 항목 식별자를 링크로 채운다.
- JDOM 은 엔티티를 펼치지 않을 때만 DTD 선언 처리기를 파서에 붙이고, 붙이지 못해도 오류를 내지 않는다.
- 외부 DTD 를 가리키는 문서에서는 파서가 정의되지 않은 엔티티를 오류 없이 건너뛴다.

## 결정

- **XML 은 우리가 구성한 파서로 읽는다.** 피드 바이트 → 문자(인코딩 판정) → 프로필의 사전 보정 → 호출마다 새로 만든 SAX 파서 → JDOM 문서 순서다. Rome 에는 그 문서를 넘긴다. Rome 의 원문 보정기와 JDOM 의 공유 팩토리는 쓰지 않는다.
- **DTD 는 해석하지 않는다.**
  - 외부 엔티티 · 외부 DTD 를 읽지 않는다.
  - DOCTYPE 자체는 받는다(공개 DTD 를 가리키는 RSS 0.91 을 읽는다).
  - DTD 선언(요소 · 속성 · 엔티티 · 표기법)이 하나라도 있거나 선언되지 않은 엔티티를 만나면 문서를 읽지 않는다.
- **Rome 은 형식 판별과 제목 · 링크만 맡는다.** 발행 시각 · 요약문 · 기자 · 카테고리 · 썸네일 · 항목 식별자는 Rome 항목과 순서대로 짝지은 항목 요소의 원문에서 읽는다. 발행 시각은 수집 프로필의 날짜 규칙 하나로만 해석한다.
- **`$standard` 는 그 피드 형식의 명세가 정한 요소다.** RSS 2.0 의 `dc:date` · `dc:creator` 처럼 형식 밖의 요소는 프로필이 요소 이름으로 가리킨다.
- **HTML 제거와 HTML 엔티티 표는 jsoup 을 쓴다.** 버전은 직접 고정한다.

## 결과

- 선언 거부는 JDOM 이 선언 처리기를 붙이는 조건에 기대지 않는다. 선언 처리기는 우리가 직접 등록하고, 등록하지 못하면(파서 보안 설정을 적용하지 못할 때와 같이) 수집을 멈춘다.
- 보정은 프로필의 사전 보정 규칙에서만 일어난다. 정의되지 않은 엔티티가 있는 피드는 `replace-undefined-entities` 를 고르지 않으면 읽히지 않는다. 외부 DTD 를 가리키는 피드도 마찬가지다.
- 내부 subset 에 선언이 있는 피드는 어떤 프로필로도 읽을 수 없다.
- Rome 항목과 항목 요소의 짝은 Rome 이 항목 요소를 빠짐없이 순서대로 처리한다는 데 기댄다. 개수가 다르면 수집이 예외로 멈춘다. Rome 을 올릴 때는 형식별 정규화 테스트로 다시 확인한다.
- Rome · jsoup 의 버전은 직접 올린다. Rome 2.1.0 이후 새 판이 없으므로, 형식 해석의 결함은 우리가 떠안는다.
- RSS 2.0 에서 `dc:date` 로 발행 시각을 주는 피드는 프로필에 매핑이 있어야 한다. 빠뜨리면 활성화 미리보기의 날짜 해석률이 드러낸다.
- Atom 의 상대 링크는 `xml:base` 로 풀지 않아 그 항목을 건너뛴다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| Rome 기본 경로(`SyndFeedInput.build(Reader)`)만 쓴다 | 날짜 원문이 사라지고, 프로필과 무관한 보정이 모든 소스에 적용되며, XML 보안 설정이 라이브러리 기본값과 JVM 전역 상태에 묶인다 |
| Rome 의 DOCTYPE 허용 설정을 쓴다 | 내부 엔티티를 펼친다 — DTD 를 해석한다 |
| DOCTYPE 이 있으면 거부한다 | 공개 DTD 만 가리키는 정상 RSS 0.91 이 영구 실패가 되고 프로필로 고칠 수 없다 |
| 사전 보정 규칙 `strip-doctype` 을 더한다 | 프로필 형식이 넓어지지만 쓰이는 피드가 확인되지 않았다 |
| StAX(`SUPPORT_DTD=false`) + JDOM StAX 빌더 | 내부 subset 문서가 실패하는 것은 JDOM 의 DocType 처리 부산물이라 정책으로 기댈 수 없다 |
| 파싱 전에 원문에서 DOCTYPE 을 정규식으로 검사한다 | 주석 · 처리 명령 · 따옴표를 따로 다뤄야 하고, 파서와 다른 해석기가 하나 더 생긴다 |
| Rome 은 형식 판별만 하고 모든 필드를 직접 읽는다 | Atom 텍스트 구성 · RSS 1.0 · 링크 선택을 다시 구현하게 된다 |
| Rome 이 해석한 날짜를 쓴다 | 프로필 시간대 · 날짜 형식을 적용할 수 없고, 날짜 해석 규칙이 두 곳이 된다 |
| `$standard` 를 Rome 이 채우는 범위(RSS 2.0 의 Dublin Core 포함)로 한다 | 표준의 정의가 라이브러리 판에 달리고, 표준 밖 요소를 프로필로 찾는다는 규칙이 흐려진다 |
| HTML 제거 · 엔티티 표를 직접 구현한다 | HTML 파싱 규칙과 엔티티 표를 우리가 정본으로 들고 있어야 한다 |
