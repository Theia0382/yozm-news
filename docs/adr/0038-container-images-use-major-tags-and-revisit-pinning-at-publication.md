# ADR-0038: 컨테이너 이미지는 모두 메이저 태그로 받고, 버전 고정과 갱신 자동화는 이미지를 게시할 때 다시 본다

- 상태: 승인
- 날짜: 2026-10-29
- 근거: [이슈 #43](https://github.com/Theia0382/yozm-news/issues/43) — 기점 `7c15503` 의 `FROM` · `image:` 를 전수 대조, `ghcr.io` 의 `navikt/mock-oauth2-server` 태그 목록과 다이제스트를 2026-10-29 에 실측
- 관련: [ADR-0016](0016-containerized-checks.md)(검사 이미지의 베이스 이미지는 메이저 태그 — 이 ADR 이 적용 범위를 모든 이미지로 넓힌다), [ADR-0022](0022-image-targets-per-side-dockerfile-without-run-in-runtime-stage.md)(측별 Dockerfile · 실행 기반 이미지), [ADR-0027](0027-pgvector-for-vector-storage.md)(pgvector 이미지의 `pg18-trixie` 형식 태그 — 그 이미지의 재빌드 주기는 [미결 #25](../open-questions.md))

## 맥락

- [ADR-0016](0016-containerized-checks.md)은 검사 이미지의 베이스 이미지를 메이저 태그로 고정했다. 실행 기반 이미지 · 개발용 서비스 이미지 · DinD 이미지의 태그 방식은 어디에도 정해지지 않았다.
- 저장소의 이미지 참조는 하나를 빼고 모두 메이저 태그였다 — 개발용 OIDC 공급자(`mock-oauth2-server`)만 정확한 버전(`6.1.3`)이었고, 그렇게 고정한 이유는 기록에 없었다. 이 이미지는 메이저 태그(`6`)도 게시하며, 그 태그는 최신 패치와 같은 다이제스트이고 `linux/amd64` · `linux/arm64` 를 모두 갖는다.
- 메이저 태그는 다시 빌드하거나 받을 때 그 메이저의 최신 패치를 가져온다. 보안 패치가 따로 손대지 않아도 들어오지만, CI 에서 검사한 이미지와 나중에 빌드한 이미지의 패치가 다를 수 있다.
- 배포 이미지는 아직 레지스트리에 게시하지 않는다. 운영자는 저장소를 받아 소스에서 빌드한다. 이미지 갱신을 자동으로 올리는 장치(Dependabot 등)는 없다.

## 결정

- **모든 이미지는 메이저 태그로 받는다.** 검사 · 실행 기반 이미지(`FROM`), 개발용 서비스 · DinD 이미지(`image:`)가 모두 해당한다. 변형이나 OS 계열을 붙인 태그(`-slim` · `-dind` · `-jdk` · `pg18-trixie` 형식)도 메이저 태그로 본다.
- **메이저 태그가 게시되지 않는 이미지만 정확한 버전으로 두고, 그 줄에 사유를 적는다.**
- **메이저를 올리는 변경은 그 버전에 묶인 것을 함께 바꾼다.** JDK · Node 는 버전 정본(Gradle toolchain · `frontend/.nvmrc`)과 함께, PostgreSQL 은 배포 DB 를 덤프 · 복원으로 옮기는 절차와 함께 바꾼다.
- **정확한 버전 · 다이제스트 고정과 갱신 자동화는 배포 이미지를 레지스트리에 게시할 때 다시 본다.**

## 결과

- 이미지 태그를 정하는 규칙이 하나다. 개발용 OIDC 공급자는 메이저 태그로 바뀌었다.
- 다시 빌드하면 패치가 들어오고, 갱신 PR 을 검토할 일이 없다.
- CI 가 검사한 이미지와 운영자가 나중에 빌드한 이미지의 패치가 같다고 보장하지 않는다. 소스에서 빌드하는 동안에는 이 차이를 감수한다.
- 패치가 바뀌어 검사가 깨지면 원인이 저장소 밖에 있을 수 있다 — 같은 커밋이 어제는 통과하고 오늘은 실패할 수 있다.
- GitHub Actions 의 참조 방식(태그 · 커밋 SHA)은 이 결정의 범위가 아니다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 정확한 버전(패치까지)으로 고정하고, Dependabot 이 갱신 PR 을 올린다 | CI 가 검사한 버전이 그대로 쓰이지만, 갱신 PR 이 꾸준히 생기고 merge 하지 않으면 보안 패치가 멈춘다. `FROM …:${JAVA_VERSION}-jdk` 처럼 보간한 태그를 Dependabot 이 갱신하는지 확인되지 않았다 — 갱신하지 못하면 JDK 버전을 Dockerfile 안에 두 번 적어야 한다. 이미지를 게시하지 않는 지금은 고정의 이득(같은 이미지의 재현)을 받는 사람이 없다 |
| 다이제스트로 고정하고 Dependabot 으로 갱신한다 | 재현성 · 공급망 고정이 가장 강하지만 위 부담에 더해 태그의 메이저 의미가 문면에서 사라진다 |
| ADR-0016 대로 검사 베이스 이미지만 메이저 태그로 두고 나머지는 이미지마다 정한다 | 이미지마다 방식이 갈려, 정확한 버전 하나가 이유 없이 남은 지금 상태가 반복된다 |
