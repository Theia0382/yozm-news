# ADR-0145: 비밀번호 알림은 비밀번호 변경과 복구 코드 재설정에 남기고, 첫 로그인의 강제 변경에는 남기지 않는다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #147](https://github.com/Theia0382/yozm-news/issues/147) — 구현 `830d39d`
- 관련: [ADR-0011](0011-no-email-in-v1.md)(보안 알림은 화면 내 알림 — 남기는 때를 정한다), [ADR-0134](0134-in-app-notices-are-one-row-per-recipient-with-a-closed-kind-and-per-kind-jsonb-content-and-read-notices-are-deleted-after-ninety-days.md)(알림의 꼴)

## 맥락

- 메일이 없어 보안 알림은 화면 내 알림이다([ADR-0011](0011-no-email-in-v1.md)).
- 비밀번호는 셋으로 바뀐다 — 로그인한 사람의 변경, 복구 코드 재설정, 첫 로그인의 강제 변경.
- 강제 변경은 남이 정한 초기 비밀번호를 계정 주인이 처음 바꾸는 단계다.

## 결정

- **비밀번호 변경과 복구 코드 재설정마다 그 계정에 비밀번호 알림 하나를 남긴다** — 내용은 방법(변경 · 복구 코드)과 시각이다. 모으지 않는다.
- **첫 로그인의 강제 변경에는 남기지 않는다.**
- 복구 코드 재발급에는 남기지 않는다.

## 결과

- 다른 기기에서 비밀번호가 바뀐 것을 계정 주인이 다음 로그인 때 본다. 복구 코드로 재설정한 기록도 남는다.
- 막 만든 계정의 첫 화면에 자기가 방금 한 변경의 알림이 쌓이지 않는다.
- 복구 코드를 바꿔치기한 것은 알림으로 남지 않는다 — 재발급은 현재 비밀번호를 아는 사람만 한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 비밀번호 변경에만 남긴다 | 복구 코드로 재설정한 때가 남지 않는다 |
| 복구 코드 재발급에도 남긴다 | 알림이 늘고, 재발급은 이미 현재 비밀번호를 확인한다 |
| 강제 변경에도 남긴다 | 계정 주인이 막 한 일을 알린다 |
