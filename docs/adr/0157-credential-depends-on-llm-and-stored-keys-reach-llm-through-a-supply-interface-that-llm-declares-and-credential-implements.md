# ADR-0157: `credential` 이 `llm` 에 의존하고, 저장한 키는 `llm` 이 선언한 공급 인터페이스를 `credential` 이 구현해 낸다

- 상태: 승인
- 날짜: 2026-11-14
- 근거: [이슈 #150](https://github.com/Theia0382/yozm-news/issues/150) — 키 등록(검증 성공 때만 저장)과 저장한 키로 호출하는 길이 요구하는 의존 방향을 확인
- 관련: [ADR-0152](0152-secret-value-is-a-platform-public-type-that-fails-on-serialization.md)(결과 절 "저장한 키의 평문이 어디까지 가는지는 복호화를 내놓는 쪽의 공개 API 가 막는다" — 그 막는 방법을 이 ADR 이 정한다), [ADR-0013](0013-architecture-patterns.md)(포트는 외부 의존성에만 — 이 ADR 의 공급 인터페이스는 그 포트가 아니다), [ADR-0003](0003-byok-personalized-digest.md)

## 맥락

- 키 등록은 `llm` 의 키 검증이 성공할 때만 저장한다 — 등록을 가진 `credential` 이 `llm` 을 부른다. 공급자 타입 `Provider` 도 `llm` 의 것이다.
- 저장한 키로 공급자를 부르는 것은 `llm` 이다 — `llm` 이 저장한 키를 받아야 한다. 두 방향이 함께 있으면 순환이다.
- 복호화한 키는 `llm` 밖으로 나가면 안 된다. 키가 무효임을 알게 되는 계기는 저장한 키로 공급자에 물은 결과다 — 다시 검증과, 뒤에 생기는 생성 호출이다.

## 결정

- **`credential` 이 `llm` 에 의존한다.** 등록은 `credential` 이 `llm` 의 키 검증을 부른다.
- **저장한 키는 `llm` 이 선언한 공급 인터페이스 `StoredKeySource` 로 받고, `credential` 이 그 인터페이스를 구현한다.** `llm` 은 저장한 키의 길에서 그 인터페이스로 키를 받아 공급자에 묻고, 결과를 같은 인터페이스로 알린다. `credential` 은 그 결과로 키의 상태를 전이한다.
- **이 인터페이스는 포트가 아니라 공급 인터페이스다.** 외부 의존을 가리는 것이 아니라, 모듈 사이의 방향을 뒤집으려고 한 모듈이 선언하고 다른 모듈이 구현하는 공개 인터페이스다.
- **그 인터페이스는 `credential` 에만 연다.** `llm` 최상위 패키지의 두 타입(`StoredKeySource` · `StoredKey`)을 명명 인터페이스 `stored-key` 로 표시하고 `credential` 만 그것을 허용으로 선언한다. 의존 선언이 없는 모듈까지 막으려고, `llm` · `credential` 밖의 클래스가 두 타입에 의존하지 않는다는 구조 시험을 함께 둔다.
- `credential` 은 복호화한 키를 내놓는 공개 API 를 두지 않는다.

규칙은 [llm Spec](../specs/llm.md#저장한-키의-길) llm-R17 · R18, [credential Spec](../specs/credential.md#저장한-키와-상태) credential-R13 에 있다.

## 결과

- 저장한 키의 평문이 나가는 길은 `llm` 의 인터페이스 하나다. `llm` 은 `platform` 밖의 모듈을 모르는 관문으로 남는다.
- 무효 표시가 계기마다 따로 생기지 않는다 — 다시 검증도 생성 호출도 같은 인터페이스로 결과를 알린다.
- 다른 모듈이 구현하는 공개 인터페이스는 이 코드베이스의 첫 사례다. 구현이 없는 구성(시험 조각 등)에서는 `llm` 의 서비스가 서지 않는다.
- 좁힘의 장치가 둘이다. 한쪽만 고치면 어긋날 수 있어 둘을 함께 본다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| `llm` 이 `credential` 의 복호화 API 를 부르고, 등록의 검증은 `credential` 이 선언한 인터페이스를 `llm` 이 구현한다 | `credential` 이 `Provider` 를 쓸 수 없어 공급자를 문자열로 다루거나 타입을 옮겨야 한다. 관문이 보관 모듈을 알게 된다 |
| 등록 유스케이스를 `llm` 에 두고 `credential` 은 암호화 · 저장만 한다 | 키 화면의 API · 상태 · 무효 알림 · 격리가 공급자 관문의 책임이 된다 |
| 다시 검증의 결과를 `credential` 의 유스케이스가 받아 직접 쓴다 | 생성 호출은 `credential` 을 거치지 않아 무효 표시가 계기마다 따로 생긴다 |
| 의존 선언이 없는 모듈에 선언을 더해 Modulith 만으로 좁힌다 | 그 모듈들의 지금 의존을 모두 적어야 한다. 선언을 빠뜨린 새 모듈은 다시 열린다 |
