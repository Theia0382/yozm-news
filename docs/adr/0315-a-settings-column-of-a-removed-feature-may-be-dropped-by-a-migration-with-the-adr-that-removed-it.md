# ADR-0315: 기능을 없애 앱이 읽지 않고 사용자에게 보이지 않는 설정 칸은 그 결정을 기록한 ADR 과 함께 마이그레이션이 지울 수 있다

- 상태: 승인
- 날짜: 2026-11-24
- 근거: [이슈 #235](https://github.com/Theia0382/yozm-news/issues/235) — 자유 텍스트 관심사 칸(`user_settings.interest_text`)을 지우는 마이그레이션이 "사용자 데이터를 지우는 마이그레이션을 쓰지 않는다"와 부딪힘을 대조함. 구현 커밋 `d561e61`(V84)
- 관련: [ADR-0212](0212-migrations-never-delete-user-data-or-the-shared-rows-and-ids-it-references-and-moved-data-is-checked-by-a-data-test.md)(부분 대체 — 사용자 데이터를 지우지 않는 범위), [ADR-0314](0314-the-free-text-interest-setting-is-removed-and-its-stored-values-are-dropped-by-migration.md)(이 예외를 쓴 결정)

## 맥락

- 마이그레이션은 사용자 데이터를 지우지 않는다(ADR-0212). 대상은 보존 정책 표의 사용자 데이터 전부이고, 설정 행(`user_settings`)도 든다. 이 규칙이 근거로 든 것은 관심사 히스토리 · 변화 리포트의 근거가 되는 이력과, 그 이력이 가리키는 공유 데이터의 행 · ID 다.
- 기능을 없애면 그 기능의 설정 칸이 남는다. 그 칸은 이력이 아니라 현재 설정값이고, 기능이 없어지면 앱이 읽는 자리도 사용자가 보는 화면도 없다. 칸을 남기면 읽지도 보이지도 않는 개인정보를 사용자가 탈퇴할 때까지 보관하고, 쓰는 쪽은 칸의 제약(`NOT NULL` 등)을 맞추려고 쓰지 않는 값을 계속 넣는다.
- ADR-0314 가 자유 텍스트 관심사 설정을 없애면서 그 칸이 처음으로 이 경우에 들었다.

## 결정

- **기능을 없애 앱이 다시 읽지 않고 사용자도 볼 수 없게 된 설정 칸은 마이그레이션이 지울 수 있다** — 그 기능을 없앤 결정을 ADR 로 기록하고, 그 ADR 이 칸을 지우는 것까지 정할 때만이다.
- **이력과 그것이 가리키는 공유 데이터는 이 예외 밖이다** — 관심 신호 이력 · 다이제스트 · 노출 기록 · 변화 리포트 같은 이력과, 기사 · 태그 · 태그 체계 · 사건 · 스토리라인의 행 · ID 는 ADR-0212 그대로 지우지 않는다. 설정 행 자체도 지우지 않고 칸만 지운다.

규칙은 [CONTRIBUTING.md §7](../../CONTRIBUTING.md#7-코드)에 있다.

## 결과

- 없앤 기능의 설정값이 사용자 데이터로 남지 않는다. 쓰는 쪽이 쓰지 않는 칸을 맞추는 코드가 없다.
- 칸을 지운 값은 업그레이드 뒤 되돌릴 수 없다 — 그 결정을 ADR 이 사용자 비용과 함께 적는다.
- 예외가 넓게 읽힐 위험은 ADR 을 요구하는 것과 리뷰가 막는다(ADR-0212 결과 "지키는 장치는 규칙과 리뷰다").

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| 칸을 남기고 쓰지 않는다 | 읽지도 보이지도 않는 개인정보를 무기한 보관한다. 쓰는 쪽이 제약을 맞추려고 쓰지 않는 값을 넣거나 제약을 풀어야 하고, 나중에 지우려면 같은 예외가 다시 필요하다 |
| 기능을 없애는 ADR 마다 ADR-0212 를 따로 굽힌다 | 같은 예외가 결정마다 흩어져 규칙의 범위를 한곳에서 읽을 수 없다 |
| 사용자 데이터의 칸이면 무엇이든 지울 수 있게 한다 | 이력의 칸까지 들어가 ADR-0212 가 지키려는 근거를 잃는다 |
