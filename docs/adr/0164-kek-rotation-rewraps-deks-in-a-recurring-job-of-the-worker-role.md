# ADR-0164: KEK 교체의 재암호화는 작업 역할의 반복 작업이 한다

- 상태: 승인
- 날짜: 2026-11-14
- 근거: [이슈 #150](https://github.com/Theia0382/yozm-news/issues/150)
- 관련: [ADR-0163](0163-the-app-does-not-start-when-stored-keys-point-to-a-kek-version-missing-from-the-configuration.md)(옛 버전을 일찍 지웠을 때)

## 맥락

- KEK 교체는 새 버전 추가 → 저장된 DEK 를 새 버전으로 다시 감싸기 → 옛 버전 제거의 순서다. 다시 감싸는 것은 DEK 뿐이고 키의 암호문은 건드리지 않는다.
- 운영자 기능은 화면과 API 를 늘릴수록 시험과 문서가 는다.

## 결정

- **작업 역할의 반복 작업이 활성 버전이 아닌 키를 찾아 DEK 를 다시 감싼다.** 운영자가 따로 시작하지 않는다.
- 운영자는 새 버전을 더해 앱을 다시 띄우고, 로그에서 남은 키가 0 이 된 것을 본 뒤 옛 버전을 지운다.

규칙은 [credential Spec](../specs/credential.md#kek) credential-R7 에 있다.

## 결과

- 운영자 화면 · API 가 늘지 않는다. 작업은 여러 번 돌아도 결과가 같고, 실패한 키는 다음 회차가 다시 잡는다.
- 끝났는지는 로그로 확인한다. 주기와 한 회차의 키 수는 재지 않은 목표값이다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 운영자가 운영자 API · 화면으로 시작하고 진행을 본다 | 화면 · API · 시험이 늘고, 누르지 않으면 옛 버전의 키가 남는다 |
| 기동 때 한 번 다시 감싼다 | 실패한 키를 다시 잡지 못하고, 키가 많으면 기동이 길어진다 |
