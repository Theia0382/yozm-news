# ADR-0340: 없앤 리포트 갈래의 저장된 섹션과 스냅숏 칸은 지우지 않고 읽지 않으며, 스냅숏 3판은 2판을 읽는 길을 둔다

- 상태: 승인
- 날짜: 2026-11-26
- 근거: [이슈 #242](https://github.com/Theia0382/yozm-news/issues/242) — 개요(ADR-0338)와 구독 주제 보도량(ADR-0339)을 없앨 때 측정 인스턴스의 리포트 16편 모두에 그 종류의 섹션 행이 있었다. 앞선 갈래 제거(V80 — `RISE_AND_FALL`)처럼 종류 제약을 좁히면 행이 있는 DB 에서 마이그레이션이 실패해 앱이 뜨지 않는다. `report_sections` 를 읽는 곳은 섹션 조회 하나다. 구현 `cd3cdb7`
- 관련: [ADR-0212](0212-migrations-never-delete-user-data-or-the-shared-rows-and-ids-it-references-and-moved-data-is-checked-by-a-data-test.md)(따른다 — 사용자 데이터를 마이그레이션으로 지우지 않는다), [ADR-0304](0304-a-change-report-takes-previous-values-from-the-previous-reports-snapshot-matched-one-to-one-and-keeps-them-in-its-own-snapshot.md)(결과 "판을 올리면 옛 판을 읽는 길이나 옮기는 마이그레이션" — 읽는 길을 고른다)

## 맥락

- 리포트 섹션 · 스냅숏은 사용자 데이터다 — 마이그레이션으로 지우려면 ADR-0212 를 대체해야 한다.
- 스냅숏 2판에는 구독 주제 보도량 칸이 있고 흐름 줄에 생성 때 상태가 없다. 3판은 상태를 더하고 구독 주제 칸을 쓰지 않는다. 옛 행의 상태는 어느 마이그레이션도 채우지 못한다.
- 옛 리포트는 공개 배포 전이라 측정 인스턴스에만 있다.

## 결정

- **섹션 종류 제약은 그대로 두고, 섹션 조회가 지금 섹션 종류만 고른다** — 옛 종류(개요 · 구독 주제 보도량)의 행은 남지만 화면 · 직전 리포트 글에 나오지 않는다. 섹션 종류 enum 에 옛 값을 두지 않는다.
- **스냅숏 3판은 2판을 읽는다** — 2판의 흐름 줄은 상태가 없고(null), 2판의 구독 주제 칸은 읽지 않는다. 주간의 직전 값 잇기는 2판 스냅숏의 흐름 기사 수도 읽는다. 저장된 스냅숏은 고치지 않는다.

규칙은 [report Spec](../specs/report.md#리포트-조회) report-R12 · R19 와 §6 에 있다.

## 결과

- 섹션이 개요 · 구독 주제뿐이던 옛 리포트는 보일 섹션이 없어 "갈래 섹션이 모두 숨음" 안내가 보인다.
- 옛 행을 나중에 지우려면 ADR-0212 를 부분 대체하는 ADR 과 마이그레이션이 필요하다 — 데이터가 남아 있어 옛 섹션을 다시 보이는 쪽으로도 돌아갈 수 있다.
- 종류 제약이 앱이 쓰지 않는 종류를 받는다 — 그 까닭은 report Spec §6 에 적는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 저장된 대로 보인다 — enum 에 옛 값을 읽기 전용으로 남기고 화면이 개요 · 구독 주제 표를 계속 그린다 | 생성이 쓰지 않는 갈래의 길이 조회 · 화면용 API · 화면에 남는다 |
| 마이그레이션으로 옛 행을 지우고 제약을 좁힌다 | 사용자 데이터를 지운다(ADR-0212) |
| 스냅숏을 3판으로 옮기는 마이그레이션 | 구독 주제 칸을 지우면 사용자 데이터를 지우고, 남기면 3판 행에 3판 꼴 밖의 칸이 남으며, 어느 쪽도 상태를 채우지 못한다 |
