# ADR-0231: 수동 생성은 오늘 다이제스트를 같은 기간으로 다시 만들거나 새로 만들고, 하루 횟수는 사용자 시간대의 오늘 만든 수동 행으로 센다

- 상태: 승인
- 날짜: 2026-11-18
- 근거: [이슈 #178](https://github.com/Theia0382/yozm-news/issues/178) — 수용 기준 "수동 재생성 — 사용자당 하루 N회. 결정: 기존 요청 제한(창 1시간 이하)과의 관계와 하루의 경계(사용자 시간대)", 리드 답("바로 받고 싶으면 수동 생성을 활용한다"). 구현 커밋 `d114b4e`(수동 생성 공개 API · 대상 규칙)
- 관련: [ADR-0230](0230-scheduled-digests-are-made-after-the-generation-time-and-a-period-runs-from-the-last-ready-or-empty-end-to-that-time.md)(관련 — 같은 기간 산식 · 날짜 순서), [ADR-0170](0170-request-limits-count-fixed-windows-in-a-user-postgresql-table-with-a-code-constant-policy-table.md)(관련 — 요청 제한을 쓰지 않는 이유)

## 맥락

- 일정은 생성 시각 뒤 2시간만 따라잡는다 — 그 밖의 "지금 받기"와 실패한 날 다시 받기는 수동 생성의 몫이다.
- 요청 제한은 유닉스 기원의 고정 창이라 하루 창의 경계가 UTC 자정이고, 기록은 "창은 길어야 1시간"으로 고지하며, 거절한 요청도 센다.
- 수동 생성은 `digests` 에 계기 `MANUAL` 의 행과 만든 시각을 남긴다.

## 결정

- **오늘(사용자 시간대) 날짜의 다이제스트가 있으면 그 날짜를 같은 기간으로 다시 만들고, 없으면 오늘 날짜로 요청 시각까지의 새 기간(일정과 같은 산식)을 만든다** — 오늘보다 늦은 날짜가 있으면(시간대를 서쪽으로 바꾼 뒤) 그 날짜를 다시 만든다. 오늘을 수동으로 먼저 만들면 그날 일정은 만들지 않는다.
- **하루 횟수는 `MANUAL` 행 가운데 만든 시각이 사용자 시간대의 오늘인 것을 센다 — 3회(측정 전 목표)** — 다 쓰면 사용자 시간대의 다음 날 0시까지 받지 않는다.
- **생성 중이거나 쓸 모델이 없으면 받지 않고 세지 않는다** — 같은 사용자의 요청 · 일정 행 만들기는 사용자 잠금으로 줄을 서 확인과 행 만들기 사이에 끼지 않는다.
- 화면용 API 처리기 · 버튼은 다이제스트 화면(#179)이 붙이고, 이 모듈은 공개 API(`DigestRequests`)를 낸다. 시간대는 사용자 하나의 조회(`UserTimezones`)로 읽는다.

## 결과

- 하루의 경계 · 보존 · 고지가 기존 다이제스트 데이터로 맞는다.
- 요청 폭주는 "진행 중이면 거절"이 막는다 — 짧은 창의 요청 제한은 두지 않았다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 가장 최근 날짜를 같은 기간으로만 다시 만든다 | 새 사용자 · 일정을 놓친 날에 바로 받을 길이 없다 |
| 언제나 새 기간으로만 만든다 | 실패한 날을 같은 기간으로 다시 받을 수 없다 |
| 요청 제한 정책 표에 하루 창 | 경계가 UTC 자정이고, 고지를 바꾸며, 거절된 요청도 센다 |
