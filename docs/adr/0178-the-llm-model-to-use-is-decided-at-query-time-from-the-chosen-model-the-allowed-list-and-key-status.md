# ADR-0178: 쓸 LLM 모델은 고른 모델 · 허용 목록 · 키 상태로 조회 때 정한다

- 상태: 승인
- 날짜: 2026-11-15
- 근거: [이슈 #151](https://github.com/Theia0382/yozm-news/issues/151)
- 관련: [ADR-0008](0008-v1-llm-providers.md)(보충 — 사용자가 모델을 고르지 않았거나 고른 모델을 쓸 수 없을 때), [ADR-0153](0153-allowed-llm-models-come-from-a-bundled-file-that-an-operator-file-replaces-as-a-whole.md)(보충 — 결과 절이 미룬 "목록에서 빠진 모델을 골라 둔 사용자"), [ADR-0159](0159-having-a-key-means-having-any-stored-key-regardless-of-its-status.md)(관문의 "키가 있다"는 상태 무관 — 이 ADR 의 "쓸 수 있는 키"와 다른 물음이다)

## 맥락

- 사용자는 허용 모델 목록에서 공급자 · 모델을 고른다. 계정은 키보다 먼저 생기므로 만들 때는 고를 수 없다.
- 고른 모델은 키 · 목록과 따로 쓸 수 없게 된다 — 목록 교체로 빠지거나, 그 공급자의 키를 지우거나, 키가 무효가 된다. 사용자는 공급자마다 키를 하나씩 가질 수 있다.

## 결정

- **쓸 모델은 조회 때 정한다** — 고른 모델이 허용 목록에 있고 그 공급자의 키가 유효(`VALID`)하면 그것, 아니면 유효한 키가 있는 공급자(공급자 선언 순)의 허용 목록 첫 모델, 그것도 없으면 쓸 모델이 없다.
- **조회 결과는 고른 값 · 쓸 값 · 고른 값을 못 쓴 까닭(고르지 않음 · 목록에서 빠짐 · 키 없음 · 키 무효)을 함께 낸다.** 화면이 대체를 알린다.
- **고르기는 키가 있는 공급자(상태 무관)의 허용 모델만 받는다** — 무효 키를 고치는 동안에도 고른 값을 지킨다.

## 결과

- 고르지 않음 · 목록에서 빠짐 · 키 삭제 · 키 무효가 규칙 하나로 끝난다. 키만 등록해도 쓸 모델이 있다.
- 사용자가 고르지 않은 모델 · 공급자로 사용자 비용이 나갈 수 있다 — 허용 목록에서 공급자마다 첫 모델이 대체의 기본이라는 뜻을 갖는다(운영 안내).
- 다이제스트 · 리포트 일정의 제외는 "쓸 모델이 없는 사용자"가 된다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 고른 값만 두고 쓸 수 없으면 "쓸 모델 없음"으로 일정에서 뺀다 | 키를 등록하고 모델을 안 고른 사용자는 다이제스트를 못 받고, 목록 교체 · 키 삭제마다 다시 골라야 한다 |
