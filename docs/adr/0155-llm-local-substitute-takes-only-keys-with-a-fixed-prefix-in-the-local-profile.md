# ADR-0155: `llm` 의 로컬 대체물은 `local` 에서 정해진 접두의 키만 받는다

- 상태: 승인
- 날짜: 2026-11-14
- 근거: [이슈 #148](https://github.com/Theia0382/yozm-news/issues/148) — 평가기 · 임베더의 로컬 대체물 등록 조건을 확인
- 관련: [ADR-0012](0012-swappable-external-dependencies.md)(의존성 표의 LLM 행 — 로컬 대체물을 보충), [ADR-0057](0057-local-substitutes-registered-only-in-local-profile-without-operator-switch.md)(로컬 대체물의 등록 조건)

## 맥락

- 개발 환경은 외부 계정이나 비밀 값 없이 전체 흐름을 돌릴 수 있어야 한다([ADR-0012](0012-swappable-external-dependencies.md)). LLM 의 로컬 대체물은 고정 응답 다이제스트 생성기 하나로 적혀 있었다.
- 그것만으로는 로컬 개발에서 키 등록이 실제 공급자 키를 요구한다.
- 평가기의 로컬 대체물은 Jev 키가 없을 때만 서고, 키를 주면 로컬 개발에서도 실제 구현이 선다. LLM 키는 운영자 설정이 아니라 사용자가 넣는 값이라 "키가 없을 때"로 가를 수 없다.
- 로컬 대체물은 profile `local` 에서만 등록하고 켜는 운영 설정을 두지 않는다([ADR-0057](0057-local-substitutes-registered-only-in-local-profile-without-operator-switch.md)).

## 결정

- **`llm` 에 공급자 클라이언트의 로컬 대체물을 둔다.** profile `local` 에서만 등록한다.
- **대체물은 정해진 접두로 시작하는 키만 받는다.** 접두 뒤의 낱말이 검증의 결과(성공과 실패 종류)를 정한다.
- **그 밖의 키는 로컬 개발에서도 실제 공급자로 간다.**
- 접두는 실제 공급자 키의 접두와 겹치지 않게 한다.

규칙은 [llm Spec](../specs/llm.md#로컬-대체물) llm-R16 에 있다.

## 결과

- 로컬 개발과 화면 확인에서 외부 계정 없이 키 등록의 성공과 실패 종류를 모두 볼 수 있다.
- 로컬 개발에서 실제 키로 공급자를 확인하는 길이 남는다.
- 로컬 개발이 아니면 대체물이 없어 가짜 키는 실제 공급자에서 무효로 끝난다.
- 생성 호출의 로컬 대체물은 호출 API 를 만드는 작업이 더한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 로컬 개발에서는 언제나 대체물 | 로컬 개발에서 실제 공급자를 확인할 수 없다 |
| `llm` 에 대체물을 두지 않는다 | 로컬 개발의 키 등록이 실제 키를 요구한다 |
