# ADR-0345: 화면용 API 명세의 스키마 이름은 생성기가 정한 단순 이름을 그대로 쓰고, 서로 다른 타입이 같은 이름을 받으면 명세 생성이 실패한다

- 상태: 승인
- 날짜: 2026-11-26
- 근거: [이슈 #174](https://github.com/Theia0382/yozm-news/issues/174) — 생성기 소스(swagger-core 2.2.55 · springdoc 3.2.0)에서 이름이 정해지고 덮어쓰이는 자리를 대조했다. 구현 커밋 `b5a94f7`
- 관련: [ADR-0020](0020-screen-api-contract-from-committed-openapi-spec.md)(화면 계약의 정본은 커밋된 명세 — 보충)

## 맥락

- 명세 생성기(springdoc → swagger-core)는 응답 · 요청 타입의 단순 클래스 이름을 스키마 이름으로 쓴다. 중첩 타입도 바깥 이름 없이 단순 이름이다.
- 다른 모듈에 단순 이름이 같은 타입이 있으면 생성기의 모델 맵에서 나중에 정의된 쪽이 앞의 스키마를 경고 없이 덮어쓴다. 한 처리기의 응답 스키마가 다른 모듈 타입의 꼴로 바뀐 명세가 나온 적이 있고, 명세 diff 를 사람이 읽다 잡았다.
- 커밋된 명세와의 대조 시험은 덮어쓰인 결과끼리 비교하므로 잡지 못한다. 프론트엔드 빌드는 화면이 사라진 칸을 쓸 때만 잡는다.
- 생성기는 변환기 안에서 난 예외를 경고 로그로 삼키고 그 스키마를 뺀 명세를 낸다. 변환기는 JVM 정적 목록에 등록되고, 같은 클래스의 앞 인스턴스는 새 context 가 설 때 갈아 끼워진다. 생성 하나는 한 스레드에서 돈다.

## 결정

- **스키마 이름은 생성기가 정한 단순 이름을 그대로 쓴다.** 이름 규칙을 다시 구현하지 않는다.
- **서로 다른 타입이 같은 스키마 이름을 받으면 명세 생성이 실패한다.** 메시지에 그 이름과 두 타입의 전체 이름을 낸다. 같은 타입을 여러 처리기 · 문맥에서 쓰는 것은 겹침이 아니다.
- **기록은 변환기, 실패는 생성 끝이다.** `platform` 의 변환기가 생성기의 스키마 정의마다 이름과 타입을 기록하고, 생성 끝의 명세 고침 장치가 겹침을 보면 예외를 낸다.
- **기록의 단위는 명세 생성 한 번이고 스레드에 둔다.** 생성 시작에 새 기록을 걸고 끝에서 꺼내 지운다. 변환기 인스턴스에 두지 않는다.
- **타입은 생성기의 타입 표현으로 정규화해 비교한다.** 생성기의 문맥 정보(애너테이션 · 속성 위치)가 달라도 같은 타입은 같다.
- **변환기가 보지 못한 스키마가 명세에 있으면 실패한다.** 변환기가 사슬에서 빠지면 검사가 조용히 꺼지는 대신 생성이 실패한다.
- 규칙 본문은 [platform Spec](../specs/platform.md) platform-R128 이다.

## 결과

- 모든 모듈의 화면 API 응답 · 요청 타입은 단순 이름이 화면용 API 전체에서 겹치지 않아야 한다. 겹치면 명세 갱신과 대조 시험이 실패하고 메시지가 바꿀 타입을 알려 준다.
- 실행 중인 앱의 명세 엔드포인트는 기본으로 닫혀 있어 이 실패가 사용자에게 닿지 않는다. 명세 생성 실패는 문제 응답 500 이 되므로, 대조 시험이 처리된 예외의 메시지를 실패 설명에 싣는다.
- 생성기 판을 올려 이름 · 정의 · 예외 처리 기제가 바뀌면 겹침을 일부러 만든 통합 시험이 알린다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 정규화된 이름(`springdoc.use-fqn`) | 겹침은 생기지 않지만 모든 스키마 이름이 패키지 경로가 되어 프론트엔드의 스키마 참조를 모두 바꿔야 한다 |
| 시험에서 처리기의 타입을 리플렉션으로 훑어 단순 이름 대조 | 생성기의 타입 순회(제네릭 · 중첩 · 무시 규칙)를 다시 구현하는 사본이라 생성기와 어긋나면 놓친다 |
| 변환기 안에서 예외 | 생성기가 경고로 삼키고 그 스키마를 뺀 명세를 내 생성이 실패하지 않는다 |
| 기록을 변환기 인스턴스에 둠 | 시험 JVM 에서 사슬에 든 인스턴스와 구성의 bean 인스턴스가 다를 수 있어 다른 context 의 기록이 섞이거나 빈 기록을 읽는다 |
