# ADR-0325: 실패한 리포트는 화면에서 같은 행을 다시 생성을 기다리게 해 리포트마다 세 번까지 다시 만든다

- 상태: 승인
- 날짜: 2026-11-25
- 근거: [이슈 #240](https://github.com/Theia0382/yozm-news/issues/240) — 수용 기준 "수동 재생성 여부". 구현 `d4662ad`
- 관련: [ADR-0319](0319-the-change-report-screen-has-a-list-per-kind-and-a-report-page-with-four-states-and-the-failure-cause-only.md)(부분 대체 — 결정의 "다시 만들기 버튼은 없다"), [ADR-0323](0323-report-generation-jobs-and-stalled-report-recovery-follow-the-digest-and-a-report-ending-without-a-start-records-the-zone.md)(다시 만든 행의 시작 기한)

## 맥락

- 리포트는 일정이 기간이 끝난 뒤 2시간 안에서만 만든다(ADR-0321). 일시 장애 · 키 무효로 실패한 주 · 달은 다시 받을 길이 없었다.
- (사용자, 종류, 기간)마다 행은 하나다(ADR-0323). 실패 행을 남기고 새 행을 만들면 유일 제약 · 목록 · 직전 리포트 조회가 같은 기간의 여러 행을 다뤄야 한다.
- 다이제스트의 수동 생성은 사용자 하루 세 번이다. 리포트의 다시 만들기는 실패한 리포트에만 있어, 횟수를 리포트에 붙이면 요청 기록 없이 행의 칸 하나로 센다.

## 결정

- **실패한 리포트만 다시 만든다** — 주간 · 월간 모두. 실패가 아니면 받지 않는다.
- **같은 행을 생성을 기다림으로 되돌린다.** 시작 · 결과 · 시작의 기록(스냅숏 · 직전 리포트 · 시간대)을 비우고 새 토큰으로 커밋 뒤 등록한다. 만든 시각은 그대로이고 예약 시각은 받은 때다 — 거두기의 시작 기한을 이 시각으로 잰다.
- **리포트마다 세 번까지다** — 리포트 하나의 생성은 많아야 넷이다. 쓸 모델이 없으면 받지 않는다. 처리기에 요청 제한 표시를 두지 않는다 — 받은 뒤 이어지는 요청은 행 하나를 읽고 "실패가 아님"으로 끝난다.
- 다시 만들기에 기한은 없다.
- 화면은 실패한 리포트에 남은 횟수와 다시 만들기 버튼을 보이고, 다 쓰면 버튼 없이 안내한다. 받지 않으면 까닭을 보인다.

규칙은 [report Spec](../specs/report.md#다시-만들기) report-R32 · [reader Spec](../specs/reader.md#변화-리포트) reader-R16 에 있다.

## 결과

- 일시 장애 · 키 교체 뒤 그 주 · 그 달의 리포트를 되찾는다. 목록 · 알림 링크(같은 리포트 ID)가 그대로다.
- 앞선 실패의 코드 · 메시지가 행에서 사라진다 — 알림에는 갈래 · 실패 시각이 남는다.
- 오래전에 실패한 리포트를 다시 만들면 기간 집계는 같은 기간을 세지만 흐름의 정리 · 추적 흐름은 다시 만들 때의 것이라 기간 뒤 전개가 글에 들 수 있다.
- 횟수는 리포트마다 세 번이고 날짜와 무관하다 — 하루 상한은 없고, 사용자 하나가 다시 만들 수 있는 수는 실패한 리포트 수 × 3 이다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 다시 만들기를 두지 않는다 | 일시 장애로 실패한 주 · 달을 다시 받을 길이 없다 |
| 일시 장애 실패는 일정이 한 번 자동으로 다시 만든다 | 사용자가 모르는 두 번째 비용이고, 장애가 길면 두 번 다 실패한다 |
| 새 행을 만들고(실패 행은 남김) 사용자 하루 세 번 | 유일 제약을 실패 밖으로 좁혀야 하고, 목록에 같은 기간 줄이 여럿 생기며 직전 리포트 조회가 여러 행을 다뤄야 한다 |
| 같은 행, 사용자 하루 세 번 | 하루 횟수를 세려면 요청 기록(시각)이 따로 필요하다 |
