# ADR-0063: Jev 는 System One 스키마 하나로 부르고, 문맥 초과는 빈 state 로 다시 물어 원인을 가리며, 모델 기본값은 최신 별칭이다

## 맥락

- Jev 의 공식 HTTP 경로는 TypeSafe 의 System One API(`POST /v1/systemone`)다. OpenRouter 는 같은 요청 · 응답 스키마의 호환 경로(기본 주소 `https://openrouter.ai/api`, 모델 이름은 `typesafe/` 이름공간)와 모양이 다른 자체 경로를 둔다. Cloudflare · Vercel AI Gateway 경유는 공식 문서에 없고 3자 자료상 다른 스키마다.
- 요청 하나에 질문 수 상한은 없고, 문맥 한도가 있다 — 요청 전체(state + 질문 전부) 64k 토큰, 질문 하나(state + 그 질문) 32k 토큰. 문맥을 넘으면 어느 한도든 같은 응답(400, `error_type` `max_tokens_exceeded`)이 온다.
- 평가 요청은 기사마다 state 만 다르고 질문 · 모델 · 키는 모든 기사가 같다. PostgreSQL 에 저장되는 문자는 Jev 가 모두 받는다. 그래서 기사 내용 때문에 거부되는 길은 문맥 초과 하나이고, 나머지 오류는 모든 기사가 같은 원인이다. 문맥 초과는 긴 기사(제목에 길이 상한이 없다)로도, 큰 태그 체계(태그 수에 상한이 없다)로도 난다.
- 실패 갈래를 잘못 고르면 결과가 크다 — 모든 기사가 같은 원인을 기사 거부로 내면 회차마다 묶음 전체가 영구 실패로 남고, 기사 탓을 평가기 사용 불가로 내면 풀린 점유가 평가 가능 시각을 그대로 두어 다음 회차도 같은 기사에서 멈춘다.
- 모델은 별칭(`jev-latest`)과 버전 ID(`jev-1.14.0` 등)로 고른다. 별칭을 보내도 응답에는 답한 버전 ID 가 오고, 평가마다 저장된다. 같은 요청도 확률이 조금씩(관찰 최대 0.06) 다르다.

## 결정

- **Jev 는 System One 스키마 하나로 부른다.** 설정은 기본 주소 · 모델 · 키뿐이고, 같은 스키마를 내는 경로(OpenRouter 의 호환 경로 등)는 기본 주소와 모델 이름을 바꿔 쓴다. 다른 스키마로 옮기는 변환은 두지 않는다 — Cloudflare AI Gateway 경유는 지원하지 않는다.
- **문맥 초과면 같은 질문을 빈 state 로 한 번 더 묻는다.** 그것도 넘으면 체계 탓(평가기 사용 불가 — 회차 멈춤), 받으면 기사 탓(기사 거부)이다. 확인 요청은 평가가 아니고 그 답은 쓰지 않는다. 그 밖의 거부와 읽을 수 없는 응답은 평가기 사용 불가이고, 시간이 지나면 풀릴 수 있는 것(연결 실패 · 마감 초과 · 408 · 429 · 5xx)만 일시다.
- **모델 기본값은 최신 별칭(`jev-latest`)이다.** 운영자는 설정으로 버전 ID 를 고정할 수 있다.

## 결과

- 확인된 스키마 하나로 TypeSafe 직접과 OpenRouter 를 덮고, 확인할 수 없는 변환이 코드에 없다. Cloudflare 경유가 필요해지면 그 스키마를 확인할 수 있을 때 구현을 더한다.
- 큰 체계는 회차를 멈춰 기사를 잃지 않고, 긴 기사만 실패로 남는다. 드문 문맥 초과에서만 요청이 하나 는다(체계가 정상이면 체계 질문만큼의 토큰). 회차 묶음 × 기사당 요청 둘 × 요청 마감이 점유 기간 안에 들어야 해, 요청 마감이 그 부등식에 묶인다.
- 기본 구성은 손대지 않아도 새 모델을 받고, 옛 버전이 내려가 회차가 멈출 일이 없다. 대신 별칭이 바뀌면 분포가 운영자 모르게 움직여 태그 기준 · 저장 기준이 어긋날 수 있다 — 저장된 모델 버전으로 추적하고, 기준을 맞춘 운영자는 버전을 고정한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| OpenRouter 자체 경로 전용 변환을 더한다 | 요청 · 응답 · 오류 변환이 둘이 되고, 같은 스키마의 호환 경로로 이미 쓸 수 있다 |
| Cloudflare Workers AI 경로 변환을 더한다 | 스키마가 공식 문서에 없어 확인할 수 없다 |
| 기사 탓 거부(문맥 초과)만 기사 거부, 나머지는 사용 불가 — 확인 요청 없이 | 체계가 요청 전체 문맥을 넘으면 회차마다 묶음 전체가 영구 실패로 남는다 |
| 4xx 거부와 읽을 수 없는 응답을 모두 기사 거부로 | 구성 결함 · 큰 체계 · API 변경이 모든 기사를 영구 실패로 태운다 |
| 체계 쪽에 질문 수 · 길이 상한을 두어 문맥 초과를 막는다 | 토크나이저가 공개되지 않아 앱이 토큰을 셀 수 없다 — 정확한 경계가 없다 |
| 모델 기본값을 버전 ID 로 고정한다 | 옛 버전이 내려가면 운영자가 설정을 바꿀 때까지 회차가 멈추고, 새 모델 개선을 받지 못한다 |
| 모델을 코드에 고정한다 | 모델을 바꾸려면 새 릴리스가 필요하다 — 셀프 호스팅 운영자가 고를 수 없다 |
