# ADR-0082: 큰 사건은 기간 안의 서로 다른 소스 수와 중요도 평균이 둘 다 기준 이상인 사건이고, 조회할 때 지금 기준으로 판정한다

- 상태: 대체됨([ADR-0116](0116-storyline-big-judgement-starts-with-a-provisional-rule-of-distinct-sources-and-mean-importance-judged-at-query-time.md))
- 날짜: 2026-11-07
- 근거: [이슈 #99](https://github.com/Theia0382/yozm-news/issues/99) — 판정 재료(배정 · 기사 소스 · 중요도)의 위치와 다이제스트 · 운영자 화면 · 리포트의 요구를 조사해 리드와 정하고 구현(`1434b77` · `bd84e7d`)
- 관련: [ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)(결정 절 "큰 사건은 조회 시점에 판정한다 — 사건의 서로 다른 소스 수와 기사의 Jev 중요도"의 식을 정한다, 후속 기록), [ADR-0083](0083-big-event-criteria-as-operator-settings-with-append-only-history-and-preview.md)(기준을 둘 곳)

## 맥락

- ADR-0026 은 큰 사건을 조회할 때 서로 다른 소스 수와 기사의 Jev 중요도로 판정한다고만 정했다. 두 재료를 어떻게 합칠지, 기사 여럿의 중요도를 값 하나로 어떻게 모을지가 남았다.
- 다이제스트는 기간 안의 큰 사건 몇 개를 구독과 무관하게 넣고, 변화 리포트는 기간마다 큰 사건의 보도량을 비교하고, 운영자 화면은 사건 목록에 큰 사건 여부를 보인다. 모두 기간을 준다.
- 같은 사건을 다룬 다른 매체의 전재 기사는 같은 기사로 합치지 않고 따로 저장한다 — 사건 묶기가 같은 사건으로 묶는다. 기사의 소스는 기사가 가진 엔트리의 소스다.
- 중요도는 기사마다 기대값(1 ~ 5)이고, 평가하지 않았거나 확률 합이 0 이면 없다. 재료(소스 · 중요도)는 다른 모듈에 있고 나중에 바뀔 수 있다(엔트리가 늘거나 체계를 바꿔 다시 평가).

## 결정

> 부분 대체(판정의 단위) — [ADR-0103](0103-big-judgement-on-storylines-and-the-storyline-milestone-right-after-event-clustering-takes-over-big-events.md). 지금 상태: [storyline Spec 큰 판정](../specs/storyline.md#큰-판정) storyline-R19
- **큰 사건 = 기간 안 서로 다른 소스 수 ≥ 소스 기준, 그리고 기간 안 중요도 평균 ≥ 중요도 기준(경계 포함).** 두 기준을 따로 둔다 — 얼마나 널리 다뤘는가와 얼마나 중요하게 평가됐는가는 뜻이 달라 따로 조정한다.
- **중요도는 기간 안 기사 가운데 중요도가 있는 기사의 평균이다.** 평균은 소수 산술로 세어 기준과 같은 수 체계로 비교한다. 중요도가 없는 기사는 평균에서 빼고 소스 수에는 넣는다. 중요도가 있는 기사가 없으면 큰 사건이 아니다.
- **소스 수는 기간 안 기사들의 엔트리 소스의 서로 다른 수다.** 전재 기사는 다른 기사라 매체마다 하나씩 센다.
- **조회할 때 지금 기준으로 판정하고 결과를 저장하지 않는다.** 기간은 부르는 쪽이 주고(시작 포함 · 끝 제외), 기간 안 기사는 배정의 발행 시각으로 고른다. 재료는 그 조회 순간에 다른 모듈의 공개 조회로 읽는다.
- **큰 사건의 순서는 소스 수, 중요도 평균(둘 다 내림차순), 사건 ID 순이다.** 몇 개를 쓸지는 부르는 쪽이 정한다.
- 판정은 사용자를 모른다 — 사용자 제외 조건은 부르는 쪽이 걸러 대표 기사를 고를 때 쓴다.

## 결과

- 기준을 바꾸면 다음 조회부터 모든 기간에 적용되고, 재판정 장치가 없다. 제안 기준으로 같은 계산을 하면 미리보기가 된다.
- 판정은 조회 순간의 근사값이다 — 모듈 사이 재료가 한 스냅숏이 아니고, 다음 조회가 바로잡는다. 다이제스트가 큰 사건으로 넣은 사실은 다이제스트의 선정 이유가 남긴다.
- 큰 사건에 딸린 짧은 후속 기사가 많으면 평균이 내려간다 — 기준값으로 조정하고 평가 세트에서 다른 집계와 비교한다.
- `event` 가 기사의 소스 값 타입을 쓰므로 `event` → `source` 의존이 생긴다(값 타입 하나, 순환 없음).
- 조회마다 기간 안 배정 · 소스 · 중요도를 모두 읽는다. 부하는 재지 않았다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 두 재료를 정규화해 합성 점수 하나로 판정 | 가중치 · 정규화라는 값이 더 생기고 운영자가 점수의 뜻을 읽기 어렵다. 측정 전이라 가중치의 근거가 없다 |
| 소스 수만 판정하고 중요도는 순서에만 | ADR-0026 이 판정 근거로 중요도를 든다. 많이 실렸지만 가벼운 사건이 들어온다 |
| 중요도의 최댓값 | 기사 하나의 과대평가가 그대로 판정이 되고, 기사가 많을수록 값이 커지는 쪽으로 치우친다 |
| 중요도의 중앙값 | 기사 수가 적으면 평균과 다르지 않고, 짝수일 때의 규칙이 하나 더 붙어 설명이 길어진다 |
| 판정을 배정 때 저장 | 재료가 다른 모듈에서 나중에 바뀌고(엔트리 · 재평가), 기준을 바꾸면 다시 판정할 장치가 필요하다 |
