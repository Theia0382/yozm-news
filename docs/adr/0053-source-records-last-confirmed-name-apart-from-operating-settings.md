# ADR-0053: 출처는 source 가 프로필에서 마지막으로 확인한 소스 이름을 운영 설정과 다른 테이블에 기록한다

- 상태: 승인
- 날짜: 2026-11-02
- 근거: [이슈 #61](https://github.com/Theia0382/yozm-news/issues/61) — 프리셋이 사라지거나 운영자 원문이 검증에 걸린 소스의 운영 목록 이름이 비는 것을 확인하고, 이름 기록의 upsert 가 여러 번 · 여러 인스턴스에서 같은 결과를 내는지 시험으로 확인. 구현 `a0861bc`
- 관련: [ADR-0024](0024-collection-profile-yaml-and-preset-reference-or-own-profile.md)(프리셋 참조 — 프로필 값을 DB 에 복사하지 않는다), [ADR-0033](0033-feed-polling-db-lease-per-feed-new-items-and-per-source-request-spacing.md)(운영 설정과 수집 상태를 다른 행에 둔다), [ADR-0051](0051-operator-hides-or-deletes-sources-and-feeds-and-deletion-removes-exclusive-articles.md)(소스 삭제가 기록도 지운다)

## 맥락

- 소스 이름은 수집 프로필에만 있다. 프리셋 소스는 프로필을 DB 에 복사하지 않는다(ADR-0024).
- 프리셋이 배포에서 빠지거나 운영자 원문이 검증기 변경으로 걸리면 프로필을 얻지 못하고, 그 소스의 이름이 비어 운영자는 어느 언론사인지 모른다. 기사의 출처를 보일 때도 같다.
- 소스 행은 운영자가 쓰는 운영 설정이고 낙관적 잠금 버전을 갖는다. 다른 주체가 같은 행을 쓰면 운영자의 변경과 겹친다(ADR-0033 이 수집 상태를 다른 행에 둔 까닭과 같다).

## 결정

- **`source_attributions`(소스당 1행 — 이름 · 기록 시각)에 프로필에서 마지막으로 확인한 소스 이름을 기록한다.** 운영 설정 행 · 버전과 분리한다.
- **쓰는 때는 등록 · 운영자 원문 수정 · 기동 대조다.** 이름이 기록된 값과 다를 때만 쓰는 upsert 라 여러 번 · 여러 인스턴스가 불러도 결과가 같다. 이미 있는 소스는 다음 기동 대조가 채운다.
- **이름의 정본은 프로필이다.** 프로필을 얻으면 프로필의 이름을 보이고, 얻지 못하면 기록된 이름을 보인다. 기록은 프로필 값의 사본이 아니라 확인한 사실의 기록이다 — 프로필을 DB 에 복사하지 않는다는 결정(ADR-0024)과 충돌하지 않는다.
- 소스를 지우면 기록도 지운다(ADR-0051).

## 결과

- 프로필을 잃은 소스도 운영 목록에 이름이 남고, 기사의 출처를 보일 수 있다.
- 기록은 마지막으로 확인한 값이라 프로필을 잃은 뒤의 이름 변경은 따라가지 않는다.
- 쓰는 곳이 셋이고, 운영자의 소스 변경과 서로를 덮어쓰지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 이름을 기록하지 않는다(프로필을 잃으면 비운다) | 프로필을 잃은 소스 · 그 기사의 출처를 알 수 없다 |
| 소스 행(`sources`)에 이름 열을 둔다 | 기동 대조 · 원문 수정이 운영 설정 행을 써 운영자의 변경과 버전이 겹친다 |
| 프리셋 키를 이름 대신 보인다 | 운영자 원문 소스는 키가 없고, 키는 언론사 이름이 아니다 |
