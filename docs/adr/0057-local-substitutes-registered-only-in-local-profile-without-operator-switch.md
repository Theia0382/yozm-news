# ADR-0057: 로컬 대체물은 `local` profile 에서만 등록하고, 운영 설정으로 켜는 스위치를 두지 않는다

- 상태: 승인
- 날짜: 2026-11-02
- 근거: [이슈 #7](https://github.com/Theia0382/yozm-news/issues/7) — 첫 로컬 대체물 `FakeArticleEvaluator` 의 등록 조건을 정하며 배포 정의(`deploy/compose.yaml` 의 `SPRING_PROFILES_ACTIVE: web,worker`)와 확인용 · 시험 실행의 profile 을 확인
- 관련: [ADR-0012](0012-swappable-external-dependencies.md)(로컬 대체물 — "Fake 구현은 운영 프로필에서 활성화되지 않도록 기동 시 검사한다" 의 장치를 이 ADR 이 대체한다), [ADR-0042](0042-app-roles-as-web-worker-profiles-marked-by-platform-annotations.md)(역할 애너테이션)

## 맥락

- ADR-0012 는 개발 · 시험에 로컬 대체물(평가기 · 다이제스트 생성기 등의 Fake)을 두고, Spring profile `local` 이 그것을 기본으로 쓰며, Fake 가 운영에서 켜지지 않도록 기동 때 검사한다고 정했다. 그 뒤 Compose 프로필 `prod` 는 ADR-0021 이 대체해, "운영 프로필" 에 대응하는 Spring profile 이 없다. profile 은 역할 둘(`web` · `worker`)과 개발용 `local` 뿐이다.
- 로컬 대체물의 결과는 실제 데이터에 저장된다. Fake 평가기의 결과가 저장되면 모든 사용자의 후보 선별이 그 결과를 쓴다.
- 배포 정의는 profile 을 고정하고, 앱 컨테이너는 배포 정의에 적힌 환경 변수만 받는다. 배포 정의나 덧씌우기를 고치면 어떤 방식이든 Fake 를 켤 수 있다 — 막을 수 있는 것은 "배포 정의를 바꾸지 않고 켜는 길" 과 "실수로 켜는 길" 이다.
- 시험은 `local` 없이 돈다. 화면 확인용 인스턴스는 배포 정의로 띄운다.

## 결정

- **로컬 대체물의 결선은 `platform` 의 공개 애너테이션 `@LocalDevelopment`(profile `local`)를 달아 `local` 에서만 등록한다.** profile 이름의 코드 쪽 정본은 그 애너테이션의 상수다.
- **로컬 대체물을 켜는 운영 설정(설정 키 · 환경 변수)을 두지 않는다.** 운영 문서에 대체물을 켜는 값이 나타나지 않는다.
- **등록 조건이 운영에서 대체물을 막는 유일한 장치다.** 따로 기동 검사를 두지 않는다 — 같은 조건의 두 번째 사본이 된다. 규칙은 등록 조건이 결정되는 자리에서 확인한다(빈 등록 시험).
- 시험은 대체물을 직접 만들어 시험 구성에 넣는다. 확인용 인스턴스가 대체물을 쓰려면 profile 에 `local` 을 더한다.

## 결과

- 운영자가 대체물을 켜려면 이름부터 개발용인 profile 을 켜야 한다. 값 하나로 실제 평가를 Fake 로 바꾸는 길이 없다.
- 확인용 인스턴스가 대체물을 쓰면 `local` 의 다른 개발용 동작(명세 엔드포인트 열기 등)도 함께 켜진다. 배포 구성과 덜 같아진다.
- 다른 모듈의 로컬 대체물(다이제스트 생성기 · 리포트 생성기 등)도 같은 애너테이션을 단다.
- 실제 구현이 아직 없는 외부 의존은 `local` 밖에서 구현이 없다. 그때의 동작은 그 포트를 쓰는 쪽이 정한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 대체물마다 전용 설정 스위치(기본 끔, `local` 이 켬)를 둔다 | 대체물 하나만 켜는 운영 설정처럼 보이는 손잡이가 생긴다. 배포 정의가 그 값을 넘기게 하면 운영 설정 하나로 Fake 결과가 실제 기사에 저장된다. 켰을 때 경고 로그를 남기는 정도로만 완화된다 |
| 등록 조건과 별도로 기동 검사를 둔다 | 같은 조건의 사본이다. 등록 조건이 바뀌면 검사가 어긋난다 |
