# ADR-0048: 가입은 기본으로 닫고 운영자의 초대 링크와 계정 생성으로 사람을 들이며, 첫 운영자는 기동 때 로그의 초대 링크나 환경 변수로 만든다

- 상태: 승인
- 날짜: 2026-10-31
- 근거: [이슈 #55](https://github.com/Theia0382/yozm-news/issues/55) — 기점 `250d96f` 의 인증 설계([security.md](../security.md) §인증 · §악용 방지)와 ADR 을 대조해, 가입 자격과 첫 운영자 계정을 만드는 방법이 정해져 있지 않음을 확인
- 관련: [ADR-0047](0047-self-hosted-software-run-by-instance-operators.md)(운영자가 허락한 몇 사람이 함께 쓴다), [ADR-0009](0009-authentication-google-and-local.md)(로그인 수단 — 그대로이고 가입 자격을 이 ADR 이 더한다), [ADR-0011](0011-no-email-in-v1.md)(메일 없음 · 미인증 이메일 · 복구 코드 — 봇 가입 방어선의 범위를 이 ADR 이 좁힌다), [ADR-0012](0012-swappable-external-dependencies.md)(봇 차단은 교체 · 끄기)

## 맥락

- 한 인스턴스를 운영자가 허락한 몇 사람이 함께 쓴다([ADR-0047](0047-self-hosted-software-run-by-instance-operators.md)).
- 지금까지의 인증 설계는 누구나 가입하는 것을 전제로 방어를 짰다 — 가입 시 계정 존재를 감추는 일반 문구, 가입 요청 제한, 가입 화면 봇 차단. [ADR-0011](0011-no-email-in-v1.md) 결과도 "Turnstile과 요청 제한이 봇 가입의 주 방어선"이라고 적었다.
- 로그인 수단 둘의 이메일 신뢰가 다르다. OIDC 이메일은 `email_verified` 일 때만 믿고, 자체 로그인 이메일은 인증되지 않은 값이다([ADR-0011](0011-no-email-in-v1.md)). 그래서 "허락한 사람만"을 구현하는 방식마다 성립하는 로그인 수단이 다르다.
- 첫 운영자(`ADMIN`) 계정을 만드는 방법이 정해져 있지 않다. 가입이 열려 있으면 드러나지 않지만, 가입을 닫으면 운영자가 없는 새 인스턴스에는 아무도 들어올 수 없다.

## 결정

- **가입 정책**: 가입은 기본으로 닫혀 있고, 운영자가 운영 설정으로 공개 가입을 열 수 있다. 열면 열린 가입 방어(계정 존재 노출을 감추는 일반 문구 · 가입 요청 제한 · 가입 화면 봇 차단)를 모두 적용한다.
- **닫힌 가입에서는 두 방식으로 사람을 들인다.**
  - 초대 링크 — 운영자가 만든 일회용 · 만료 있는 링크를 직접 전한다(메일 없음). 토큰은 해시로만 저장하고 운영자가 취소할 수 있다. 받은 사람은 OIDC 나 자체 로그인 중 골라 가입한다.
  - 운영자 계정 생성 — 운영자가 이메일 · 초기 비밀번호로 자체 로그인 계정을 만든다. 첫 로그인 때 비밀번호 변경을 강제하고, 복구 코드는 그때 발급한다. OIDC 만 쓰는 사람은 초대 링크로 들인다.
- **첫 운영자**: 운영자(`ADMIN`)가 없으면 기동 때 일회용 운영자 초대 링크(짧은 만료)를 앱 로그에 출력한다(기본). 운영자가 생기면 출력하지 않는다. 환경 변수로 이메일 · 초기 비밀번호를 주면 링크 대신 그 값으로 자체 로그인 운영자 계정을 만든다.
  - 운영자가 없을 때만 적용하고, 그 뒤에는 무시하며 변수가 남아 있다고 경고 로그를 낸다.
  - 첫 로그인 때 비밀번호 변경을 강제하고, 복구 코드는 그때 발급한다.
  - 값이 비밀번호 규칙을 어기면 이유를 말하고 기동하지 않는다.
  - 값이 있으면 초대 링크를 출력하지 않는다.
- **OIDC 경로의 닫힘**: 가입이 닫힌 인스턴스에서는 초대 없이 처음 보는 OIDC 계정으로 로그인해도 계정을 만들지 않는다. 닫힘이 OIDC 경로에서도 성립하려면 필요하다.
- 설정 이름 · 초대 만료 값 · 저장 테이블 · 화면은 가입 기능을 만드는 작업이 정한다.

## 결과

- [ADR-0011](0011-no-email-in-v1.md)의 "Turnstile과 요청 제한이 봇 가입의 주 방어선"은 공개 가입을 연 인스턴스에만 해당한다. 닫힌 인스턴스에서는 초대가 가입 자격이고, 초대 링크 확인 요청은 누구나 보낼 수 있으므로 요청 제한이 남는다.
- 로그인 · 복구 코드 사용의 방어는 가입 정책과 무관하게 그대로다.
- 공개 가입 모드를 켤 수 있으므로 구현은 켠 상태와 끈 상태를 모두 테스트한다.
- 첫 운영자 초대 링크는 로그에 일부러 남기는 비밀이다. 로그 비밀 마스킹의 예외이고, 로그를 외부로 보내는 구성에서는 밖으로 나갈 수 있어 짧은 만료 · 일회용으로 범위를 줄인다.
- 환경 변수 초기 비밀번호는 `deploy/.env` 에 평문으로 남는다. 첫 로그인 변경 강제로 쓸모를 없앤다.
- 초기 비밀번호로 만든 계정(운영자가 만든 계정 · 환경 변수로 만든 첫 운영자 계정)은 가입 화면을 거치지 않는다. [ADR-0011](0011-no-email-in-v1.md)이 정한 복구 코드를 한 번 보여 주는 때(가입 직후)와 복구할 수 없음을 안내하는 자리(가입 화면)는 그 계정에서 첫 로그인 때다.
- 운영자가 계정을 잃었을 때의 복구 경로는 이 결정이 정하지 않는다.
- **M4 가 정할 것**:
  - 환경 변수 둘 중 하나만 준 경우의 처리(누락은 크게 실패하게)
  - "운영자가 없다"의 판정(정지 · 탈퇴한 운영자를 세는가)
  - 다시 기동할 때 이전 운영자 초대 링크를 무효로 하는가
  - 역할을 나눠 띄우거나 `web` 을 여러 개 띄울 때 어느 프로세스가 링크를 출력하고, 동시 기동 때 중복 발급을 어떻게 막는가([platform Spec](../specs/platform.md#역할) platform-R9)
  - 처음 보는 OIDC 계정을 거부할 때의 응답 문구
  - 기동 로그의 운영자 초대 링크에 담을 바깥 주소(운영 설정에는 앱의 바깥 주소가 없다 — proxy 공개 주소 · 포트는 호스트 바인딩이고, Tunnel 도메인은 앱이 모른다)
  - 환경 변수의 이메일이 이미 있는 계정의 이메일일 때(운영자가 없는 동안 공개 가입을 연 인스턴스에서 생길 수 있다)

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 초대 전용(공개 가입 모드 없음) | 공격면 · 테스트할 모드가 가장 작지만 운영자의 선택 폭을 줄인다(사용자 결정) |
| 기본 열림 + 운영자 설정으로 닫기 | 기본 구성으로 인터넷에 연 인스턴스가 누구나 가입하는 인스턴스가 된다 |
| 이메일 허용 목록 | 자체 로그인 이메일은 미인증이라 자격 근거가 되지 못한다 |
| 처음 가입한 계정을 운영자로 | 기동과 첫 가입 사이에 인스턴스가 인터넷에 열려 있으면 다른 사람이 먼저 운영자가 된다 |
| 관리 명령으로 운영자 초대 발급 | 로그에 비밀이 남지 않지만, 웹 · 작업 역할과 별개인 명령 진입점이 필요하다 |
| 환경 변수로 운영자 OIDC 이메일 지정 | 자체 로그인만 쓰는 인스턴스에서 성립하지 않는다 |

## 후속 기록

- 2026-10-31: 계정 인증 전까지 운영자 기능은 운영자 토큰(`YOZMNEWS_ADMIN_TOKEN`)으로 막는다 — [ADR-0043](0043-admin-functions-guarded-by-env-bearer-token-until-account-roles.md). 계정 인증이 생기면 운영자 경로는 이 ADR 의 `ADMIN` 계정이 연다.
