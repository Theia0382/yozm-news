# ADR-0161: KEK 는 설정 디렉터리의 파일로 받는다

- 상태: 승인
- 날짜: 2026-11-14
- 근거: [이슈 #150](https://github.com/Theia0382/yozm-news/issues/150) — 배포 구성이 비밀 값을 받는 길(`deploy/.env` 의 환경 변수)과 설정 디렉터리(`deploy/config/`)를 확인
- 관련: [ADR-0003](0003-byok-personalized-digest.md)(키는 envelope encryption 으로 보관), [ADR-0162](0162-neither-role-starts-without-a-well-formed-kek.md)(없을 때의 기동 규칙)

## 맥락

- 사용자 키를 감싸는 KEK 는 이 인스턴스에서 가장 무거운 비밀이다. KEK 와 DB 가 함께 새면 모든 사용자의 키가 드러난다.
- 배포 구성의 다른 비밀 값은 `deploy/.env` 의 환경 변수다. 운영자가 앱에 넘기는 파일을 두는 설정 디렉터리가 따로 있고 앱에 읽기 전용으로 붙는다.
- KEK 는 교체할 수 있어야 하므로 버전을 갖는다.

## 결정

- **KEK 는 파일로 받는다.** 설정이 파일의 경로를 가리키고, 배포 구성은 설정 디렉터리의 파일을 기본 경로로 쓴다.
- **파일은 한 줄에 `버전:Base64` 하나다.** 새로 암호화할 때는 가장 큰 버전을 쓴다.

형식과 규칙은 [credential Spec](../specs/credential.md#kek) credential-R5 에 있다.

## 결과

- 환경 파일을 복사하거나 백업할 때 KEK 가 딸려 가지 않고, 컨테이너의 환경 변수 목록에 값이 없다.
- 운영자가 파일 하나를 더 만들고, 앱 사용자가 읽을 수 있는 권한을 챙겨야 한다.
- 파일로 붙는 다른 비밀 값 전달 방식(Docker secrets 등)과 같은 꼴이라 경로만 바꾸면 된다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 환경 변수 하나(`버전:값` 목록) | 가장 무거운 비밀이 다른 값들과 같은 파일에 있고 컨테이너 환경에 드러난다 |
| YAML 파일 | 값 하나짜리 목록에 파서와 공통 거부를 끌어온다 |
