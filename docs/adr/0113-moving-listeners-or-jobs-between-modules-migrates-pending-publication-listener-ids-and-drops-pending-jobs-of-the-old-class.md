# ADR-0113: 모듈 사이로 리스너 · 반복 작업을 옮기면 미완료 발행의 리스너 ID 를 마이그레이션으로 옮기고, 옛 클래스의 남은 예약 작업을 지운다

- 상태: 승인
- 날짜: 2026-11-11
- 근거: [이슈 #130](https://github.com/Theia0382/yozm-news/issues/130) — 태그 쪽 리스너 · 반복 작업을 `evaluation` 에서 `tag` 로 옮기며, Spring Modulith 2.1.1 이 재제출 때 리스너를 찾는 방식을 확인함
- 관련: [ADR-0023](0023-jobrunr-oss-framework-schema-and-event-resubmission.md)(실패한 이벤트 발행의 재처리 — 리스너를 옮기는 배포에서 재처리가 이어지는 조건을 더함 — 보충), [ADR-0050](0050-operator-resubmits-once-or-discards-stranded-event-publications-read-from-registry.md)(운영자의 다시 처리 — 같은 조건 — 보충)

## 맥락

- 이벤트 발행 레지스트리는 발행을 리스너 ID 와 함께 저장한다. 리스너에 ID 를 적지 않으면 리스너 ID 는 클래스의 전체 이름 · 메서드 · 인자 타입으로 만들어진다. 이 저장소의 리스너는 모두 ID 를 적지 않는다.
- Spring Modulith 는 미완료 발행을 다시 처리할 때 같은 리스너 ID 의 리스너를 찾는다. 없으면 "Listener … not found" 를 남기고 발행을 실패로 둔다. 운영자의 다시 처리도 같은 경로다.
- 그래서 리스너 클래스를 다른 패키지로 옮긴 배포에서 옛 리스너 몫으로 남은 발행은 다시 처리되지 않는다. 기사를 평가 대기에 넣는 발행이면 그 기사는 평가되지 않고, 지운 기사를 따르는 발행이면 그 행이 남는다.
- JobRunr 반복 작업은 기동 때 같은 ID 로 정의를 다시 등록한다. 이미 만들어진 예약 · 대기 작업은 옛 클래스 이름으로 직렬화돼 있다.

## 결정

- **리스너 ID 는 Spring 의 기본 ID 를 그대로 쓴다.** 리스너를 옮길 때 ID 를 옛 문자열로 고정하지 않는다.
- **리스너를 다른 패키지로 옮기는 변경은 같은 변경에 Flyway 마이그레이션을 둔다.** 완료되지 않은 발행 행의 리스너 ID 를 옛 ID 에서 새 ID 로 바꾼다. 리스너 하나가 둘로 나뉘면 남은 행을 새 리스너마다 하나씩 되도록 복제한다.
- **마이그레이션의 리스너 ID 문자열은 시험이 실제 리스너의 ID 와 대조한다.**
- **반복 작업 클래스를 옮기면 같은 마이그레이션에서 그 반복 작업의 남은 예약 · 대기 작업 행을 지운다.** 반복 작업 ID 는 그대로 둔다 — 기동 때 새 정의가 같은 ID 로 등록되고 다음 회차를 만든다.

## 결과

- 리스너를 옮기는 배포에서도 남은 발행이 새 리스너로 이어진다. 운영자가 업그레이드 시점을 맞추지 않아도 된다.
- 앱 마이그레이션이 프레임워크 테이블(`event_publication` · `jobrunr_jobs`)의 행을 고친다. 그 열과 상태 이름은 쓰는 라이브러리 판에 기댄다 — 라이브러리 판을 올릴 때 다시 본다.
- 리스너 ID 형식은 Spring 의 기본 규약이다. 형식이 바뀌면 대조 시험이 실패한다.
- 옮기는 순간 처리 중이던 반복 작업은 JobRunr 의 고아 처리로 실패가 되고, 다음 회차가 이어 간다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 옮긴 리스너에 옛 기본 ID 를 `id` 로 고정한다 | 코드에 옛 패키지 이름이 남고 다른 리스너와 규약이 갈린다. 리스너가 둘로 나뉘면 옛 ID 를 하나만 가질 수 있어 한쪽 몫은 이어지지 않는다 |
| 옮기기만 하고 운영 안내로 다룬다(업그레이드 전에 발행을 비우거나 남은 것을 폐기) | 남은 발행의 일이 조용히 사라진다. 셀프 호스팅 운영자에게 숨은 업그레이드 조건이 생긴다 |
