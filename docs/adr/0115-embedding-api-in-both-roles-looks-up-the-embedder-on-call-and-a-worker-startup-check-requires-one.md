# ADR-0115: 기사 임베딩 공개 API 는 두 역할 공통 빈으로 두고 임베더는 부를 때 찾으며, 작업 역할의 임베더 요구는 `evaluation` 의 기동 검사가 맡는다

- 상태: 승인
- 날짜: 2026-11-11
- 근거: [이슈 #131](https://github.com/Theia0382/yozm-news/issues/131) — 임베더를 `evaluation` 으로 옮기며, 반복 작업의 생성자 주입이 하던 "작업 역할은 임베더 없이 뜨지 않는다"를 관문 쪽에서 어떻게 보장할지 리드와 정함

## 맥락

- 작업 역할은 임베더 없이 운영하지 않는다. 이 보장은 사건 묶기 반복 작업이 임베더(포트)를 생성자로 받는 것으로 걸려 있었다. 운영 임베더는 모델을 화면 역할에서 올리지 않도록 작업 역할에서만 만든다(ADR-0093).
- 임베더가 `evaluation` 으로 가면 `event` 는 포트가 아니라 관문의 공개 API 를 받는다(ADR-0114). 공개 API 를 어떻게 결선하느냐에 따라 같은 보장의 장치가 달라진다.
- `evaluation` 의 판정 공개 API 는 두 역할 공통 빈이고, 평가기는 부를 때 찾아 없으면 예외다(ADR-0073). 작업 역할이 평가기 없이 뜨지 않는 보장은 평가기 설정 옆의 기동 검사가 맡는다(ADR-0061).
- `event` 의 회차는 사건 소속 판정 공개 API 를 이미 생성자로 받는다.

## 결정

- **공개 API 구현은 두 역할 공통 빈이다.** 임베더는 생성자에서 필수로 받지 않고 부를 때 찾는다. 임베더가 없는 프로세스에서 부르면 예외다 — 임베딩은 작업 역할의 작업에서 부른다는 것을 공개 계약에 적는다.
- **작업 역할은 임베더 없이 뜨지 않는다 — 장치는 `evaluation` 의 작업 역할 기동 검사다.** 임베더 빈이 없으면 작업 역할이 뜨지 않는다. provider · 외부 설정이 틀리거나 로컬 모델을 열지 못하면 결선이 먼저 기동을 멈춘다.
- **운영 임베더는 여전히 작업 역할에서만 만든다.** 화면 역할에는 공개 API 빈만 있고 모델을 올리지 않는다.
- **`event` 의 회차는 공개 API 를 생성자로 받고, 반복 작업은 임베더를 받지 않는다.** 표현 회차는 텍스트 묶음을, 배정 회차는 지금 모델 버전을 공개 API 에 묻는다.

## 결과

- `evaluation` 의 공개 API 세 개(태그 판정 · 사건 소속 판정 · 임베딩)가 같은 결선 꼴이다. `event` 가 관문을 쓰는 방식도 생성자 주입 하나로 맞는다.
- 화면 역할에서 실수로 임베딩을 부르면 기동 실패가 아니라 호출 때 예외로 드러난다.
- 작업 역할의 기동 보장은 반복 작업의 의존이 아니라 `evaluation` 의 기동 검사에 있다. 결선 조건이 모든 provider 에서 임베더 하나를 등록하므로 지금 구성에서는 검사가 실패하지 않고, 결선 조건이 바뀌어 빈이 빠지면 문구와 함께 기동을 멈춘다.
- 두 역할을 한 프로세스에서 하면 임베더 설정 오류에 화면도 함께 뜨지 않는 것은 그대로다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 공개 API 구현을 작업 역할 전용 빈으로 두고 반복 작업이 생성자로 받아 회차에 넘긴다 | 반복 작업의 생성자 주입이라는 장치가 그대로 남지만, `evaluation` 의 다른 공개 API(두 역할 공통 · 부를 때 찾기)와 결선 꼴이 갈린다 |
| 포트를 그대로 공개 API 로 내고 반복 작업이 생성자로 받는다 | 관문이 결과 확인 · 트랜잭션 확인을 끼울 자리가 없다(ADR-0114) |
