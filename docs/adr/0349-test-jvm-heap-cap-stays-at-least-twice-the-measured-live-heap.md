# ADR-0349: 테스트 JVM 의 힙 상한은 잰 살아 있는 힙 최대의 두 배 이상으로 둔다

- 상태: 승인
- 날짜: 2026-11-27
- 근거: [이슈 #158](https://github.com/Theia0382/yozm-news/issues/158) — 지금 설정과 줄인 설정의 전체 테스트를 GC 로그 · 주기적 힙 검사(JFR)로 재고, 메모리 부족 순간의 힙 덤프로 무엇이 힙을 채우는지 확인함. 상한 확인 측정은 컨테이너 검사에서 커밋 `de083a6`
- 관련: [ADR-0016](0016-containerized-checks.md)(검사는 컨테이너에서 — 재는 곳), [ADR-0122](0122-test-postgresql-container-shared-per-test-jvm-with-an-empty-database-per-context.md)(테스트 DB 와 컨텍스트 캐시의 연결 수 한도 — 그대로), [ADR-0350](0350-test-jvm-exits-on-out-of-memory-without-a-default-heap-dump.md)(메모리 부족 시 종료), [ADR-0351](0351-non-web-test-contexts-are-generic-application-contexts.md)(웹이 아닌 시험 컨텍스트의 종류)

## 맥락

- 테스트 JVM 의 최대 힙은 Gradle 이 정한다. 기본값은 기기 메모리와 무관하게 512 MiB 이고, 이 값으로 로컬의 전체 테스트가 메모리 부족으로 실패했다. 그래서 상한 2 GiB 를 두었으나 힙이 어디서 차는지는 재지 않았다.
- 2 GiB 에서 잰 살아 있는 힙(강제 Full GC 뒤 크기) 최대는 1,373 MiB(상한의 67%)였고, GC 직전 최대는 1,956 MiB 로 상한에 거의 닿았다. 1 GiB 에서는 Full GC 를 775회 되풀이한 뒤 메모리 부족으로 끝났고, 정지 시간의 대부분이 마지막 약 209초에 몰렸다.
- 메모리 부족 순간의 덤프에서 힙의 약 37% 는 ArchUnit 으로 제품 코드 전체를 읽은 분석 결과였고, 그 가운데 약 25% 는 시험 클래스 셋이 static 필드에 한 벌씩 든 것이었다. 약 48% 는 컨텍스트 캐시(기본 32개)에 남은 컨텍스트였다. 캐시 안의 `@JdbcTest` 컨텍스트는 하나에 약 19 MB 였다.
- 두 덩어리를 줄였다 — 분석 결과는 시험 클래스 수명 동안만 들고([개발 인프라 — 테스트 JVM](../development/infrastructure.md#테스트-jvm)), 웹이 아닌 시험 컨텍스트는 종류를 바꿨다([ADR-0351](0351-non-web-test-contexts-are-generic-application-contexts.md)).

## 결정

- **힙 상한은 잰 살아 있는 힙 최대의 두 배 이상으로 둔다.** 살아 있는 힙은 강제 Full GC 뒤의 크기다. 지금 값은 2 GiB 이고, 잰 최대는 794 MiB(상한의 39%)다.
- **재는 곳은 컨테이너 검사다.** 측정 장치(GC 로그 · 20초마다 힙 검사를 일으키는 JFR `jdk.ObjectCount` · 컨텍스트 캐시 통계)는 저장소 파일을 바꾸지 않고 Gradle init 스크립트와 Compose 덧씌우기 파일로 붙인다.
- **컨텍스트 캐시 크기는 기본값 그대로 둔다.**
- 지금 상한과 다시 재는 방법은 [개발 인프라 — 테스트 JVM](../development/infrastructure.md#테스트-jvm)이 갖는다.

## 결과

- 확인 측정(커밋 `de083a6`, 4,833 tests, JDK 25.0.5): 살아 있는 힙 최대 794 MiB · GC 직전 최대 1,299 MiB · 컨텍스트 생성 107회. 줄이기 전 설정을 같은 장치로 호스트에서 잰 값은 각각 1,373 MiB · 1,956 MiB · 107회였다.
- 두 배 기준을 지키는 장치는 없다. 분석 결과 · 스캔 메타데이터 · 컨텍스트의 크기는 제품 클래스 수와 함께 늘므로, 다시 재는 것은 손으로 한다. 기준 아래로 줄면 상한을 올리거나 사용량을 줄인다.
- 상한이 빠지면 Gradle 기본 512 MiB 로 돌아간다. 잰 살아 있는 힙 최대(794 MiB)보다 작아 전체 테스트가 메모리 부족으로 실패할 것으로 보고(512 MiB 로 다시 재지는 않았다), 실패하면 바로 드러난다([ADR-0350](0350-test-jvm-exits-on-out-of-memory-without-a-default-heap-dump.md)).
- 상한은 빌드의 모든 시험 태스크에 걸린다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 잰 값의 두 배를 256 MiB 단위로 올린 값으로 낮춘다(약 1.75 GiB) | 낮출 실익이 없다 — CI 러너와 검사 컨테이너에 아낄 메모리 제약이 없다. 여유만 줄고 값이 측정마다 흔들린다 |
| 컨텍스트 캐시 크기를 줄인다(16) | 줄이기 전 설정에서 살아 있는 힙 최대를 169 MiB 줄였지만(다시 만든 컨텍스트 7개, 약 5초) 두 덩어리를 줄여 필요가 없어졌다. 테스트 DB 의 연결 수 한도가 캐시 크기에서 계산되어 함께 바꿔야 한다 |
| 상한만 두고 사용량은 그대로 둔다 | 여유 33% 가 제품 코드가 늘며 깎인다 |
| 컨텍스트 구성을 묶어 컨텍스트 수를 줄인다 | [ADR-0122](0122-test-postgresql-container-shared-per-test-jvm-with-an-empty-database-per-context.md) 의 기각 이유(슬라이스가 띄우는 범위가 넓어진다)가 그대로다. 메모리는 컨텍스트 종류를 바꿔 줄였다 |
