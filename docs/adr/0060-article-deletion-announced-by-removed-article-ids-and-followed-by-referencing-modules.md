# ADR-0060: 기사 삭제는 지운 기사 ID 이벤트로 알리고, 기사를 가리키는 모듈이 받아 자기 행을 지운다

- 상태: 승인
- 날짜: 2026-11-02
- 근거: [이슈 #69](https://github.com/Theia0382/yozm-news/issues/69) — 평가 결과가 기사 삭제를 따르는 길을 정하며 기사 삭제 유스케이스(지운 기사 수만 받음)와 모듈 사이 FK 규약을 확인. 구현 `6fe345f`(삭제 이벤트) · `a62ae65`(평가 쪽 리스너)
- 관련: [ADR-0051](0051-operator-hides-or-deletes-sources-and-feeds-and-deletion-removes-exclusive-articles.md)(소스 · 피드 삭제가 그것만 가진 기사를 지운다), [ADR-0052](0052-article-sources-live-in-feed-entries-and-late-items-of-deleted-feeds-are-dropped.md), [ADR-0023](0023-jobrunr-oss-framework-schema-and-event-resubmission.md)(이벤트 재처리)

## 맥락

- 운영자가 소스 · 피드를 지우면 `article` 이 그 소스 · 피드만 가진 기사를 지운다(ADR-0051). 다른 소스 · 피드의 엔트리가 남은 기사는 남는다 — 어느 기사가 지워졌는지는 `article` 만 안다.
- 기사를 ID 로 가리키는 모듈이 여럿이다 — 평가, 사건, 다이제스트. 모듈 사이에는 FK 를 두지 않는다.
- 평가 결과는 무기한 보존하고 운영자 화면의 분포 · 보도량이 센다. 지운 기사의 행이 남으면 그 수에 섞인다.

## 결정

- **`article` 은 기사를 지운 트랜잭션에서 지운 기사 ID 를 이벤트(`ArticlesRemoved`)로 발행한다.** 지운 기사가 없으면 발행하지 않는다. 한 이벤트에 1,000건까지 싣고 넘으면 나눠 발행한다.
- **기사를 가리키는 모듈은 그 이벤트를 받아 자기 행을 지운다.** 리스너는 다시 처리해도 결과가 같다. 실패는 이벤트 재처리가 메운다.
- 모듈의 비동기 작업이 지운 기사를 만나면(이벤트보다 먼저 시작한 작업) 그 작업이 스스로 정리한다 — 평가 작업은 기사 조회에서 없음을 받으면 대기 행을 지우고, 진행 중인 저장은 점유 토큰으로 버려진다.

## 결과

- 삭제가 그 순간 전파되고, 사건 · 다이제스트도 같은 이벤트를 받는다. 모듈마다 주기 대조를 두지 않는다.
- `article` 의 공개 계약에 이벤트가 하나 늘고, 기사 삭제 저장소가 지운 ID 를 돌려준다.
- 큰 소스를 지우면 이벤트가 여러 개 나간다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 각 모듈이 주기적으로 자기 행의 기사 ID 를 `article` 에 물어 없는 것을 지운다 | 무기한 보존하는 행 전체를 주기마다 훑는다. 지운 뒤 다음 주기까지 집계에 지운 기사가 섞인다. 모듈마다 같은 대조를 만든다 |
| 행을 남기고 조회할 때 기사가 있는 것만 쓴다 | 집계가 지운 소스의 기사를 계속 센다. 남는 행이 무기한 쌓인다 |
| 각 모듈이 `SourceDeleted` · `FeedDeleted` 를 직접 받는다 | 다른 소스 · 피드의 엔트리가 남은 기사는 지워지지 않으므로, 어느 기사가 지워졌는지 알 수 없다 |
| 모듈 사이 FK 의 cascade | 모듈 사이 참조는 ID 로만 한다 — 스키마가 모듈 경계를 넘는다 |
