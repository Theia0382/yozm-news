# ADR-0073: 사건 소속 판정 공개 API 는 두 역할 공통 빈으로 두고, 평가기는 부를 때 찾아 없으면 예외로 드러낸다

- 상태: 승인
- 날짜: 2026-11-05
- 근거: [이슈 #96](https://github.com/Theia0382/yozm-news/issues/96) — 사건 소속 판정 공개 API 를 만들며 평가기가 없는 프로세스의 동작을 정함. 구현 `a84cc1a`
- 관련: [ADR-0061](0061-worker-role-does-not-run-without-an-evaluator.md)(작업 역할은 평가기 없이 운영하지 않는다 — 작업 역할 밖에서 평가기를 쓰는 자리를 이 ADR 이 정한다), [ADR-0042](0042-app-roles-as-web-worker-profiles-marked-by-platform-annotations.md)(역할 소속 — 고치지 않는다), [ADR-0057](0057-local-substitutes-registered-only-in-local-profile-without-operator-switch.md)(로컬 대체물), [ADR-0058](0058-evaluator-failures-in-three-kinds-and-unavailable-evaluator-skips-article-retries.md)(평가기 실패 갈래)

## 맥락

- 애플리케이션 서비스 · 리스너는 두 역할 공통이고, 작업 역할에만 두는 것은 작업 진입점 등이다(ADR-0042). 공개 API 의 구현은 애플리케이션 서비스다.
- 평가기 빈은 키가 있으면 모든 역할에, `local` 이면서 키가 없으면 대체물로 등록된다. 키 없는 화면 역할 프로세스에는 평가기가 없다 — 화면 역할은 키를 요구하지 않는다(ADR-0061).
- 태그 평가는 작업 진입점이 평가기를 필수로 주입받아 공통 서비스에 넘긴다. 다른 모듈의 작업 진입점은 `evaluation` 의 내부 포트를 받을 수 없어 이 모양을 쓸 수 없다.
- 판정은 외부 호출이라 무거운 일이다. 무거운 일은 작업으로 등록해 작업 역할에서 한다(ADR-0042).

## 결정

- **판정 공개 API 는 역할 애너테이션 없는 공통 빈이다.** 평가기는 생성자에서 필수로 받지 않고 부를 때 찾는다.
- **평가기가 없는 프로세스에서 부르면 예외다.** 판정은 작업 역할의 작업에서 부른다는 것을 공개 계약에 적는다 — 그 밖의 자리에서 부르는 것은 부르는 쪽 결함이다. 실패 갈래(ADR-0058)는 평가기가 있을 때의 실패로만 쓴다.
- 판정은 DB 트랜잭션 밖에서 부른다 — 트랜잭션 안에서 부르면 예외다.

## 결과

- 역할 소속 규칙을 고치지 않고, 부르는 쪽은 동기 흐름(판정 결과를 받아 그 자리에서 배정)을 쓴다.
- 키 없는 화면 역할 프로세스도 지금처럼 뜬다. 잘못된 자리의 호출은 기동 때가 아니라 부를 때 드러난다.
- 작업 역할은 평가기 없이 뜨지 않으므로(ADR-0061) 정상 운영에서 이 예외는 나지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 평가기가 없으면 "평가기 사용 불가" 실패를 돌려준다 | 배치 결함이 키 문제와 같은 갈래로 보여 부르는 쪽의 멈춤 · 재시도에 조용히 흡수된다 |
| 공개 API 빈을 작업 역할 결선으로만 등록한다 | 애플리케이션 서비스를 작업 역할에만 두는 새 소속이라 역할 규칙을 고쳐야 하고, 부르는 쪽 공통 서비스가 이 API 를 생성자로 받을 수 없다 |
| 비동기로 한다 — 판정 요청을 대기에 받아 `evaluation` 의 작업이 판정하고 결과를 이벤트로 알린다 | 부르는 쪽 배정이 요청과 결과 받기의 두 단계가 되고, 대기 · 작업 · 이벤트가 새로 생긴다 |
