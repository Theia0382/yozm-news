# ADR-0314: 자유 텍스트 관심사 설정을 없애고 저장된 값은 마이그레이션에서 지운다

- 상태: 승인
- 날짜: 2026-11-24
- 근거: [이슈 #235](https://github.com/Theia0382/yozm-news/issues/235) — 관심사 글이 지나는 길(화면 → 처리기 → 설정 행 → 다이제스트가 읽는 관심 설정 → 후보 선별 → 프롬프트)과 그 값을 읽는 자리를 전수 대조함. 구현 커밋 `d561e61`(관심 설정 · 다이제스트 · 마이그레이션) · `5cfdcaa`(화면 · 고지)
- 관련: [ADR-0210](0210-candidate-selection-cuts-to-the-input-token-budget-with-one-estimate-the-prompt-follows.md)(부분 대체 — 예산 산식의 관심사 몫), [ADR-0211](0211-the-digest-consumer-query-of-interest-settings-writes-nothing-and-returns-followed-preferences-with-expanded-topics.md)(부분 대체 — 낸 값의 관심사 길이), [ADR-0219](0219-candidate-selection-hands-over-the-prompt-material-read-once-with-its-token-estimate.md)(부분 대체 — 프로필의 관심사 본문 · 낸 값의 관심사 본문), [ADR-0215](0215-interests-are-not-stored-entities-and-are-computed-from-signal-history-at-query-time.md)(관련 — 관심은 신호 이력에서 계산한다), [ADR-0315](0315-a-settings-column-of-a-removed-feature-may-be-dropped-by-a-migration-with-the-adr-that-removed-it.md)(관련 — 값을 지우는 근거인 마이그레이션 예외)

## 맥락

- 관심 설정에는 사용자가 적는 자유 텍스트 관심사(0 ~ 500 코드 포인트)가 있었다. 다이제스트는 그 본문을 사용자 구획의 프로필 칸 하나로 싣고, 그 길이만큼 후보 예산을 줄였다.
- 후보를 고르고 순위를 매기는 규칙은 이 값을 받지 않았다. 지시는 칸의 뜻만 적고 이 값으로 무엇을 하라는 규칙이 없었다. 항목은 코드가 정하고 LLM 은 항목을 합치거나 빼지 못하므로, 이 값이 결과에 닿을 길은 요약 · 코멘트의 말씨뿐이었다.
- 이 값을 다루는 결정은 나르고 세는 방식(ADR-0210 · ADR-0211 · ADR-0219)뿐이고, 이 값으로 무엇을 하려는지 정한 결정은 없었다. 세밀한 관심은 주제 중분류 · 스토리라인 관심도가 다룬다(ADR-0222 · ADR-0277).
- 값이 있으면 다이제스트마다 사용자가 고른 공급자에게 전송된다.

## 결정

- **관심 설정은 자유 텍스트 관심사를 받지 않는다** — 화면 · 처리기 · 설정 행 · 다이제스트가 읽는 관심 설정 · 프롬프트의 프로필 · 후보 예산 어림에서 모두 뺀다. 다이제스트의 관심은 태그 선호와 신호 이력으로 정한다.
- **저장된 값은 마이그레이션(V84)이 칸째 지운다** — 쓰지도 보이지도 않는 값을 보관하지 않는다. 사용자 데이터를 지우지 않는 규칙(ADR-0212)의 예외(ADR-0315)로 지운다.
- **코드 변경과 같은 배포에서 지운다** — 되돌릴 수 없는 스키마 변경을 두 번의 배포로 나누는 규칙([CONTRIBUTING.md §7](../../CONTRIBUTING.md#7-코드))을 이번에는 따르지 않는다. 릴리스가 없어 옛 판으로 되돌릴 운영 인스턴스가 없다.

## 결과

- 사용자가 효과를 기대하고 적는 입력이 없어진다. 관심의 정본이 명시 신호 · 구독 하나로 남는다.
- 후보 예산에서 관심사 몫이 빠지고, 공급자로 가는 항목에서 관심사가 빠진다.
- 업그레이드하면 저장돼 있던 관심사 글은 돌아오지 않는다.
- V84 뒤 옛 판 앱은 설정 행을 읽지도 만들지도 못한다 — 옛 판은 읽기 · 쓰기에 그 칸을 쓴다.
- 업그레이드 전에 받은 화면이 관심사 칸을 실어 보내도 처리기는 그 칸을 읽지 않고 나머지를 저장한다.

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| 생성에만 쓴다 — 지시에 규칙(관심사와 닿는 사실을 먼저 쓴다 등)을 넣고 화면에 쓰임을 안내한다 | 항목은 코드가 고르므로 효과가 말씨에 그친다. 효과를 잴 기준이 없어 규칙이 맞는지 확인할 수 없고, 매 다이제스트의 비용은 그대로다 |
| 선별에 쓴다 — 관심사 글로 후보를 고르거나 순위를 바꾼다 | 글과 사건을 맞추는 산식(임베딩 · LLM)과 비용 주체를 새로 설계해야 한다. 이 결정의 범위가 아니다 |
| 칸을 남겨 두고 쓰지 않는다 | 읽지도 보이지도 않는 개인정보를 보관한다. 되돌려도 그 값을 꺼낼 화면이 없다 |
| 두 번의 배포로 나눈다 — 이번에는 칸의 `NOT NULL` 을 풀고 쓰지 않으며, 다음 릴리스에서 칸을 지운다 | 릴리스가 없어 "다음 릴리스"의 시점이 없고, 칸을 지우는 두 번째 단계에도 같은 예외가 필요하다 |
