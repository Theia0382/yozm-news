# ADR-0329: 큰 규칙은 판단 하나씩 쪼개고, 원래 규칙 식별자는 하위 규칙을 덮는 묶음 머리로 남긴다

- 상태: 승인
- 날짜: 2026-11-25
- 근거: [이슈 #281](https://github.com/Theia0382/yozm-news/issues/281) — 모듈 Spec 의 규칙 535개 가운데 1,500자를 넘는 것이 25개, 하위 항목이 8개 이상인 것이 21개였다(가장 큰 `event-R13` 은 4,611자 · 하위 13개). 규칙 식별자는 backend 에서 3,355회, 문서에서 4,561회 인용된다. 구현 커밋 `c804fd3`
- 관련: [ADR-0034](0034-module-spec-as-public-interface-specification-and-docs-by-kind.md)(보충 — 규칙 식별자 문장)

## 맥락

- 규칙 하나에 판단 여럿이 들어 있으면, 그 식별자를 가리키는 테스트 · 주석이 어느 판단을 지키는지 알 수 없다.
- 규칙 식별자는 사라지거나 다른 뜻이 되면 안 된다. 코드 주석 · 테스트 · 다른 문서가 인용한다.
- 큰 규칙을 쪼개면서 원래 식별자를 첫 판단에만 남기면, 다른 판단 때문에 그 식별자를 인용한 곳이 좁아진 식별자를 가리킨다. `event-R13` 을 인용한 코드 39곳은 하위 13개 가운데 어느 하나를 뜻한다.

## 결정

- **규칙 하나는 판단 하나를 말한다.** 하위 항목은 그 판단의 조건과 예외만 쓴다. 판단이 여럿이면 쪼갠다.
- **쪼갤 때 원래 식별자는 묶음 머리로 남긴다.** 묶음 머리에는 무엇을 덮는지 한두 문장과 하위 규칙 식별자의 목록만 쓴다. 쪼갠 판단은 그 Spec 의 새 번호를 받는다.
- **묶음 머리를 인용한 곳은 하위 규칙 전부를 가리킨다.** 인용을 좁은 식별자로 옮기는 것은 그 코드를 고치는 작업이 한다.
- 규칙의 꼴은 [`specs/README` §3 규칙 2](../specs/README.md#3-쓰는-규칙)가 정본이다.

## 결과

- 기존 인용은 고치지 않아도 맞다. 새 인용은 좁은 식별자를 가리킬 수 있다.
- 묶음 머리는 내용을 반복하지 않으므로, 하위 규칙이 바뀌어도 묶음 머리를 고칠 일은 하위 규칙이 늘거나 줄 때뿐이다.
- 화면 동작을 화면 Spec 으로 옮긴 규칙도 같은 방식이다([ADR-0328](0328-the-frontend-has-one-screen-spec-web-holding-screen-names-routes-and-screen-behavior.md)). 원래 규칙은 옮긴 몫의 `web-R` 식별자를 가리키며 남는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 원래 식별자는 첫 판단에 남기고 나머지에 새 번호 | 다른 판단 때문에 원래 식별자를 인용한 곳이 좁아진 식별자를 가리킨다. 막으려면 코드 인용 수백 곳을 함께 대조해야 한다 |
| 쪼개지 않고 하위 항목만 판단 하나씩 정리 | 하위 항목을 가리킬 식별자가 계속 없다 |
| 하위 식별자(`event-R13.2` 꼴) | 식별자 꼴이 둘이 되고, 하위 항목의 순서를 바꾸면 번호가 바뀐다 |
