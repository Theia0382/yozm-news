# ADR-0217: 제목 판정은 이 피드에서 본 기사라도 읽은 발행 시각이 같으면 후보로 둔다

- 상태: 승인
- 날짜: 2026-11-18
- 근거: [이슈 #117](https://github.com/Theia0382/yozm-news/issues/117) — 사건 묶기 평가 표본([이슈 #100](https://github.com/Theia0382/yozm-news/issues/100)) 검토에서 같은 언론사가 같은 기사를 섹션 경로만 다른 URL 로 같은 피드에 다시 낸 쌍 둘(제목 비교 키 · 발행 시각이 같음)
- 관련: [ADR-0032](0032-same-article-matching-avoids-false-merges-with-per-feed-entries-under-source-lock.md)(같은 기사 판정 — L2 가 이 피드에서 본 기사를 빼는 규칙과, 같은 피드에 URL 만 바꿔 다시 올라온 기사가 두 건이 되는 결과를 이 ADR 이 대체한다), [ADR-0052](0052-article-sources-live-in-feed-entries-and-late-items-of-deleted-feeds-are-dropped.md)(제목 판정의 범위), [ADR-0212](0212-migrations-never-delete-user-data-or-the-shared-rows-and-ids-it-references-and-moved-data-is-checked-by-a-data-test.md)(마이그레이션은 기사 행을 지우지 않는다)

## 맥락

- 같은 언론사가 같은 기사를 섹션 경로만 다른 URL(예: `/society/…` 와 `/politics/…`)로 같은 피드에 다시 낸다. 정규 URL 은 자원을 바꾸지 않는 변환만 해서 섹션 경로가 남고, 제목 판정(L2)은 이 피드에서 이미 본 기사를 후보에서 빼므로 두 번째 항목이 새 기사가 된다.
- 같은 기사가 두 건이면 사건 안의 출처 수 · 기사 수가 부풀고, 평가 정답에서도 두 번 세어진다.
- L2 가 이 피드에서 본 기사를 빼는 까닭은 같은 피드에 날마다 같은 제목으로 나오는 정형 기사(`[게시판]` · 시세표 등)다. 정형 기사는 발행 시각이 날마다 다르다. 표본의 두 쌍은 발행 시각이 같았다.
- 발행 시각을 해석하지 못한 항목은 받은 시각이 발행 시각이 된다(source-R40). 한 수집에서 받은 같은 제목의 정형 기사 여럿은 추정한 발행 시각이 같다.

## 결정

- **제목 판정은 이 피드에서 본 기사도, 항목과 그 기사가 모두 피드에서 읽은 발행 시각을 갖고 그 시각이 같으면 후보로 둔다.** 그 밖의 이 피드에서 본 기사는 계속 후보에서 뺀다. 시간 창 · 후보의 순서는 그대로다 — 같은 시각인 후보는 시각 차가 0 이라 먼저 고른다.
- **섹션 경로를 지우는 규칙을 소스 프로필에 두지 않는다.**
- **이미 두 건으로 저장된 기사는 그대로 둔다.** 합치는 마이그레이션 · 작업을 두지 않는다.

## 결과

- 섹션 경로만 바꿔 같은 피드에 다시 낸 같은 기사가 한 건이 된다. 다른 피드에 다시 낸 경우는 이미 L2 가 합쳤다.
- 같은 피드에서 이렇게 붙은 항목은 엔트리를 새로 남기지 않는다 — (기사, 피드) 엔트리가 이미 있다. 그 항목 URL 은 어디에도 남지 않아, 다시 받으면 L2 를 다시 탄다. 후보가 같은 소스 · 같은 제목 · 같은 발행 시각의 기사이고 먼저 저장된 기사가 이기므로 같은 기사에 다시 걸린다. 중복률에는 들어가지 않는다.
- 같은 피드에 같은 제목 · 같은 발행 시각으로 실린 서로 다른 기사는 합쳐진다. 발행 시각이 초까지 같은 두 기사가 같은 제목인 경우다 — 정형 기사도 날마다 시각이 다르다. 발행 시각을 추정한 항목은 합치지 않으므로, 날짜 없는 피드의 정형 기사는 그대로 나뉜다.
- 신뢰할 수 없는 피드 입력이 이 규칙으로 할 수 있는 것은 같은 소스 안에서 자기 항목을 먼저 실은 기사에 붙이는 것뿐이다 — 제목 판정의 후보는 이 소스의 엔트리가 있는 기사다(ADR-0052).
- 운영자 설정이 늘지 않는다. 언론사마다 URL 구조를 조사해 적을 일이 없다.
- 이미 두 건인 기사는 그대로 남는다. 다른 모듈(평가 · 사건 · 다이제스트 인용 · 피드백)이 두 기사 ID 를 따로 가리키므로 합치려면 그 모든 참조를 옮겨야 하고, 마이그레이션은 기사 행을 지우지 않는다(ADR-0212). 남은 쌍은 사건 묶기가 같은 사건으로 묶는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 소스 프로필에 정규 URL 에서 섹션 경로를 빼는 규칙을 둔다 | 언론사마다 URL 구조를 조사해 적어야 하고, 잘못 적은 규칙은 서로 다른 기사를 같은 정규 URL 로 만들어 소스를 건너 조용히 합친다(정규 URL 은 원문 링크이기도 하다). URL 구조가 바뀌면 다시 나뉜다 |
| 발행 시각이 같으면 추정 여부와 관계없이 후보로 둔다 | 날짜 없는 피드에서 한 수집에 받은 같은 제목의 정형 기사가 받은 시각으로 같은 발행 시각을 가져 합쳐진다 |
| 같은 피드의 시각 차 허용 구간(예: 1시간)을 둔다 | 하루 여러 번 나오는 정형 기사를 합치고, 표본의 쌍은 시각이 같아 구간이 필요 없다 |
| 이미 두 건인 기사를 앱의 작업으로 합친다 | 기사를 가리키는 모든 모듈이 ID 를 옮겨야 하고, 잘못 합친 것은 되돌릴 수 없다. 남은 쌍은 사건 묶기가 받친다 |
