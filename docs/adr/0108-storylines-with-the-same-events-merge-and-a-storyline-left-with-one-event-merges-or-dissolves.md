# ADR-0108: 구성 사건이 같은 스토리라인은 합치고, 사건 하나만 남은 스토리라인은 그 사건을 가진 스토리라인에 합치거나 풀며, 합쳐진 스토리라인은 남는 쪽을 가리킨다

- 상태: 승인
- 날짜: 2026-11-10
- 근거: [이슈 #123](https://github.com/Theia0382/yozm-news/issues/123) — 같은 흐름이 둘로 남는 경로를 코드로 따라가 합치기의 범위 · 사건 하나만 남은 스토리라인의 처분 · 합쳐진 행의 처리를 리드와 정함
- 관련: [ADR-0106](0106-provisional-storyline-linking-opens-only-with-a-partner-event-and-adds-the-single-best-storyline-without-removal.md)(결과 "사건 하나인 스토리라인 · 같은 흐름이 둘로 열린 스토리라인이 남는다" — 부분 대체, 결정 "다시 판정의 계기" — 보충), [ADR-0105](0105-storylines-link-incrementally-from-event-change-notifications-and-events-publish-changed-event-ids.md)(결정 "구성 사건이 없는 스토리라인은 지운다" — 보충), [ADR-0101](0101-shared-storylines-connect-events-and-the-personal-side-is-storyline-subscriptions-and-interests.md)(결정 "공유 스토리라인의 책임 · 계약은 구현할 때 정한다"의 정돈 몫 — 보충), [ADR-0084](0084-event-merge-applies-assignment-scoring-between-events-and-keeps-merged-rows-pointing-to-survivors.md)(합쳐진 행이 남는 쪽을 가리키는 꼴 — 같은 꼴)

## 맥락

- 스토리라인은 소속 없는 두 사건의 짝으로 열리고, 판정은 소속을 빼지 않는다([ADR-0106](0106-provisional-storyline-linking-opens-only-with-a-partner-event-and-adds-the-single-best-storyline-without-removal.md)). 그래도 같은 흐름이 둘로 남는다.
  - 같은 일을 다룬 두 짝이 서로 기준 미만으로 따로 열린 뒤 사건 병합이 그 사건들을 합치거나, 이미 소속이 있는 사건이 다른 스토리라인에 더 붙으면, 구성 사건이 똑같은 스토리라인 둘이 생길 수 있다.
  - 짝으로 묶인 두 사건이 병합되거나(실은 한 번의 일이었다) 한쪽이 지워지면 사건 하나만 남은 스토리라인이 생긴다.
  - 표현만 비슷한 두 스토리라인, 사건 둘 이상이 다른 스토리라인에 포함된 스토리라인은 같은 흐름일 수도, 큰 흐름의 갈래일 수도 있다.
- 소속은 판정 트랜잭션에서만 바뀌고, 판정은 모듈 잠금으로 한 번에 하나다.
- 스토리라인 ID 는 구독 · 타임라인 · 리포트 인용이 가리킨다. 아직 가리키는 코드는 없다.
- 사건의 병합은 합쳐진 행을 지우지 않고 남는 사건을 평평하게 가리키게 한다([ADR-0084](0084-event-merge-applies-assignment-scoring-between-events-and-keeps-merged-rows-pointing-to-survivors.md)).

## 결정

- **소속이 바뀐 스토리라인을 같은 판정 트랜잭션에서 정돈한다.** 정돈은 구성 사건만 보고 기준값이 없다. 따로 도는 정리 작업은 두지 않는다.
- **구성 사건이 같은 스토리라인은 하나로 합친다.** ID 가 가장 작은 것이 남는다. 사건 둘 이상이 다른 스토리라인에 포함된 경우와 표현만 비슷한 경우는 합치지 않는다 — 구조로 같은 흐름인지 갈래인지 가를 수 없다.
- **사건 하나만 남은 스토리라인은 그 사건을 가진 다른 스토리라인에 합치고, 없으면 풀어 그 사건을 다시 판정한다.** 합칠 곳이 여럿이면 ID 가 가장 작은 것이다. 풀기는 스토리라인을 지우고 그 사건을 잇기 대기에 넣는다. 정돈을 거친 스토리라인은 늘 사건 둘 이상으로 된 흐름이다.
- **합쳐진 스토리라인은 행을 남겨 남는 스토리라인을 가리킨다.** 합쳐진 쪽의 소속 · 핵심 말은 지운다 — 같은 사건이 남는 쪽에 이미 있어 남는 쪽의 소속 · 표현은 바뀌지 않는다. 가리킴은 평평하고, 남는 쪽을 지우면 가리키는 행도 지운다. 합치기는 한 방향이다.
- **보존은 무기한이다.** 합쳐진 행도 남는 쪽을 지울 때까지 남는다.

## 결과

- 구독 · 리포트 인용이 합쳐진 스토리라인을 남는 쪽으로 따라갈 수 있다. 풀린 스토리라인의 ID 는 빈 스토리라인처럼 사라진다 — 가리키는 쪽이 생기면 지운 ID 를 알리는 장치가 맡는다([ADR-0105](0105-storylines-link-incrementally-from-event-change-notifications-and-events-publish-changed-event-ids.md)).
- 풀린 사건은 다시 짝을 찾거나 다른 스토리라인에 붙을 기회를 얻는다. 사건 하나만 남는 일은 사건 쪽 병합 · 삭제가 있어야 생기고 그것은 한 방향이라, 풀기와 다시 넣기가 끝없이 돌지 않는다.
- 표현만 비슷한 두 스토리라인과 사건 둘 이상의 포함은 남는다 — 잇는 방법 · 스토리라인 사이 관계가 다루지 않으면 계속 남는다.
- 정돈마다 첫 구성 사건을 가진 스토리라인들과 그 구성 사건을 읽는다. 비용은 재지 않았다.
- 이 결정 전에 남은 사건 하나짜리 · 구성 사건이 같은 스토리라인은 그 구성 사건이 다시 판정될 때 정돈된다. 운영자는 채우기로 다시 판정할 수 있다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 합치지 않는다 | 사건 병합 · 붙이기가 만든 똑같은 스토리라인 둘이 화면 · 구독 · 합계에 겹쳐 남는다 |
| 표현 유사도가 기준 이상인 스토리라인을 합친다 | 기준값이 하나 더 들고 한 방향이라 횡단 규약 "판정 시점"의 예외가 는다. 갈래를 큰 흐름에 녹여 포함 관계를 지울 수 있고, 잇는 방법이 바뀌면 함께 바뀌어야 한다 |
| 사건 하나만 남은 스토리라인을 남긴다 | 짝이 실은 한 번의 일이었던 가짜 흐름이 남고, 타임라인 · 큰 판정 · 관계가 사건 하나짜리를 다뤄야 한다 |
| 사건 하나만 남은 스토리라인은 포함될 때만 합치고 나머지는 남긴다 | 다른 소속이 없는 사건 하나짜리가 그대로 남는다 |
| 합쳐진 스토리라인을 지우고 지운 ID 를 알린다 | 구독은 해제할 수 있어도 지난 리포트의 인용이 가리킬 곳을 잃는다 |
| 합칠 때 소속을 남는 쪽으로 옮긴다 | 같은 집합 · 사건 하나의 포함에서는 남는 쪽이 그 사건들을 이미 가진다 |
| 같은 집합 찾기를 모든 구성 사건의 스토리라인으로 넓힌다 | 같은 집합은 첫 구성 사건을 반드시 가지므로 첫 사건 하나로 충분하다. 큰 스토리라인에서 조회가 구성 사건 수만큼 는다 |
| 이 결정 전 데이터를 마이그레이션에서 정돈한다 | 풀기의 다시 넣기가 사건 시각을 읽어야 해 `event` 의 테이블을 직접 읽는다 — 모듈 경계를 넘는다 |
