# ADR-0200: 생성 호출의 결과는 종료 사유와 스키마 강제 여부를 싣고, 실패는 검증과 같은 다섯 종류로 낸다

- 상태: 승인
- 날짜: 2026-11-17
- 근거: [이슈 #175](https://github.com/Theia0382/yozm-news/issues/175) — 두 공급자의 오류 문서(입력 초과 · 모델 없음 · 거절 · 잘림)와 Spring AI 2.0.2 의 응답 처리(바이트코드)를 대조하고, 실제 공급자에 없는 모델 ID 로 생성 요청을 보내 404 를 확인. 구현 `dba289d` · `9ddad52` · `2e6b35e`, 확인 장치 `45e420a`
- 관련: [ADR-0151](0151-spring-ai-and-sdk-types-stay-inside-llm-and-the-gateway-exposes-only-its-own-types.md)(보충 — "호출 API 가 생기면 그 요청 · 결과 타입"의 결과 쪽), [ADR-0154](0154-key-validation-lists-models-and-failure-kinds-are-sorted-by-one-rule-per-provider-reading-the-error-kind.md)(실패 종류 다섯과 분류 정본 — 그대로 적용), [ADR-0199](0199-generation-requests-carry-only-the-tasks-own-inputs-and-the-gateway-maps-them-to-each-provider.md)(요청 쪽)

## 맥락

- 생성 호출에는 키 검증에 없는 결과가 있다. 출력 토큰 상한에 닿아 잘린 응답과 모델이 거절한 응답은 공급자가 정상으로 답한 것(과금된다)이고, 그 본문은 출력 스키마에 맞지 않을 수 있다. 입력이 문맥 한도를 넘은 요청과 없거나 쓸 수 없는 모델은 오류로 돌아온다.
- 실패 종류는 다섯이고 공급자마다 오류의 종류(`code` · `type`)로 가르며 문구로 가르지 않는다([ADR-0154](0154-key-validation-lists-models-and-failure-kinds-are-sorted-by-one-rule-per-provider-reading-the-error-kind.md)). Anthropic 은 입력 초과를 400 의 문구로만 가르고, OpenAI 는 그 오류의 `code` 를 문서에 적지 않는다. 없는 모델은 두 공급자 모두 404 다.
- 다이제스트는 출력을 읽지 못하면 한 번 다시 묻는다 — 잘려서 못 읽은 출력은 같은 상한에서 다시 잘린다.
- Spring AI 는 내용이 없는 응답(내용 없이 온 거절 포함)에서 종료 사유 · 사용량 없이 빈 응답을 낸다.

## 결정

- **공급자가 답한 결과는 본문 · 입력/출력 토큰 · 소요 시간에 더해 종료 사유(끝까지 · 잘림 · 거절)와 스키마를 강제했는가를 싣는다.**
- **실패는 키 검증과 같은 다섯 종류로 낸다.** 생성 전용 실패 갈래를 두지 않는다 — 입력 초과와 없거나 쓸 수 없는 모델은 예상 밖의 답이다. 모르는 종료 사유와 내용이 없는 응답도 예상 밖의 답이다.
- 출력을 파싱 · 검증하지 않는다 — 부르는 쪽의 것이다.

규칙은 [llm Spec](../specs/llm.md#생성-호출) llm-R19 · R22 에 있다.

## 결과

- 부르는 쪽은 잘린 출력 · 거절과 모델이 틀리게 쓴 출력을 가른다. 스키마를 강제하지 않은 모델의 출력을 알아본다.
- 입력이 너무 긴 경우는 공급자의 답으로 알 수 없다 — 부르는 쪽이 보내기 전에 모델의 입력 토큰 예산으로 막는다.
- 실패 종류가 검증과 하나라 저장한 키의 상태 전이가 그대로 적용된다(인증 실패 → 무효, 그 밖은 그대로).
- 내용 없이 온 거절은 거절이 아니라 예상 밖의 답이 되고, 과금된 토큰이 결과에 없다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 생성 전용 실패 갈래(입력이 너무 김 · 모델을 쓸 수 없음)를 따로 둔다 | 입력 초과를 문서로 확인된 `code` · `type` 으로 가르는 공급자가 없어 그 갈래가 나오지 않는다 |
| 실패 종류(`LlmFailureKind`)에 값을 더한다 | 실패 종류 다섯을 바꾸고, 검증에서 나올 수 없는 값을 검증 쪽 · 키 상태 전이가 다뤄야 한다 |
| 잘림 · 거절을 실패로 낸다 | 공급자가 답했고 과금된 응답의 본문 · 토큰을 잃는다 |
