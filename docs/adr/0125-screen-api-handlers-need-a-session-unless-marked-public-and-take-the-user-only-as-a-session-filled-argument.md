# ADR-0125: 화면용 API 처리기는 공개 표시가 없으면 세션을 요구하고, 사용자는 세션에서 채운 인자로만 받으며, 등록 가드가 공개 표시나 격리 시험 등록을 강제한다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #145](https://github.com/Theia0382/yozm-news/issues/145) — 기점 `a02a205` 에서 운영자 경로 밖의 화면용 API 처리기가 `/api/ping` 하나이고, 작업 역할만 켠 프로세스의 `/api/ping` 이 404 인 시험(`WorkerRoleTests`)이 있음을 확인
- 관련: [ADR-0043](0043-admin-functions-guarded-by-env-bearer-token-until-account-roles.md)(결정 다섯째 항목의 "운영자 경로 밖은 모두 연다" — 부분 대체), [ADR-0042](0042-app-roles-as-web-worker-profiles-marked-by-platform-annotations.md)(`platform` 의 표시 애너테이션 — 선례), [ADR-0124](0124-security-configuration-lives-in-the-user-module-and-platform-keeps-only-the-screen-api-path-convention.md)(보안 구성의 자리)

## 맥락

- 사용자 데이터 경로(다이제스트 · 키 · 피드백 · 구독 · 리포트)가 이후 이슈마다 생긴다. 사용자 A 의 세션으로 B 의 데이터에 닿지 않아야 하고, 그 증명을 기본 시험 세트에 둔다([security.md](../security.md#인가와-데이터-격리)).
- 세션 없이 열어야 하는 처리기가 여러 모듈에 있다 — 배포 확인(`platform`), 로그인 · 상태 조회(`user`). 공개 여부를 체인의 경로 목록으로 두면 다른 모듈의 경로를 `user` 가 알아야 하고, 공개 여부를 확인하는 시험의 목록과 두 벌이 된다.
- "이후 이슈가 자기 경로를 격리 시험에 더한다"는 약속은, 더하지 않았을 때 무엇도 실패하지 않으면 지켜지지 않는다.

## 결정

- **공개 표시는 `platform` 의 애너테이션 `@PublicApi` 하나다.** 세션 없이 여는 처리기(클래스나 메서드)에 단다. 공개인 이유를 비울 수 없다. 세션 체인의 인가 · 명세 설정(거부 응답) · 등록 가드가 모두 이 표시를 읽는다.
- **표시가 없는 화면용 API 처리기는 세션 사용자를 요구한다.** 처리기가 없는 요청(없는 경로 · 다른 메서드 · 받지 않는 미디어 타입)은 체인이 막지 않고 MVC 가 404 · 405 · 415 를 낸다.
- **처리기는 사용자를 묶기 애너테이션이 없는 인자 타입 `UserId` 로만 받는다.** 세션 사용자로 채운다. 경로 · 질의 · 본문 · 헤더 · 쿠키에서 사용자 ID 를 받지 않는다.
- **등록 가드** — 시험이 앱의 처리기 매핑을 열거해, 운영자 경로 밖의 화면용 API 처리기마다 공개 표시가 있거나 격리 시험 클래스와 함께 등록되어 있는지(둘 중 하나만), 등록이 낡지 않았는지, 사용자 ID 를 요청에서 받지 않는지 확인한다. 열거한 처리기 수의 하한을 먼저 단언한다.

## 결과

- 사용자 데이터 처리기를 더하는 작업은 같은 변경에 격리 시험과 등록 한 줄을 더해야 빌드가 통과한다. 규범은 [test-strategy §13](../qa/test-strategy.md#13-사용자-격리-시험)이다.
- 공개 표시를 잊은 처리기는 세션을 요구하는 쪽으로 실패한다(닫힌 쪽).
- 처리기 없는 경로를 열어 두므로 익명에게도 404 가 그대로 보인다 — 처리기가 없으니 내줄 데이터도 없다.
- 세션 체인이 요청마다 처리기를 찾는다(MVC 가 다시 찾는 것과 별도로 한 번).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 체인에 공개 경로 목록 | 다른 모듈의 공개 경로를 `user` 가 알아야 하고, 등록 가드의 목록과 두 벌이 된다 |
| `user` 의 공개 API 로 공개 경로를 등록 | `platform`(배포 확인 처리기)이 `user` 에 의존하게 된다 |
| 처리기 없는 요청도 세션을 요구 | 익명에게 없는 경로가 401 이 되고, 작업 역할만 켠 프로세스의 404 가 401 로 바뀐다 |
| 공용 시험 도구만 두고 등록 가드 없음 | 새 경로가 격리 시험 없이 들어와도 아무것도 실패하지 않는다 |
