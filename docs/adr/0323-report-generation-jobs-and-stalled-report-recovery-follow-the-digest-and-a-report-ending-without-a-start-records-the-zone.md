# ADR-0323: 리포트의 생성 작업 · 거두기는 다이제스트를 따르고, 시작하지 않고 끝난 리포트도 그때의 시간대를 적는다

- 상태: 승인
- 날짜: 2026-11-25
- 근거: [이슈 #240](https://github.com/Theia0382/yozm-news/issues/240) — 수용 기준 "(사용자, 리포트 기간)마다 한 번 · 동시 실행 안전", "멈춘 생성의 처리". 구현 `c682149`(등록 토큰 · 시작 전 실패 · 기간마다 하나) · `99a33bc`(생성 작업) · `ffc913f`(거두기) · `d4662ad`(직전 리포트 줄)
- 관련: [ADR-0232](0232-a-running-digest-is-never-started-again-and-stalled-digests-end-interrupted-after-a-lease-or-a-start-deadline.md)(같은 꼴 — 다이제스트의 거두기), [ADR-0318](0318-change-report-period-days-are-written-in-the-users-zone-at-start-and-the-row-keeps-that-zone.md)(보충 — 시작하지 않고 끝난 행의 시간대), [ADR-0319](0319-the-change-report-screen-has-a-list-per-kind-and-a-report-page-with-four-states-and-the-failure-cause-only.md)(보충 — 결과의 "거두기 전에는", 부분 대체 — 결정의 "비교한 직전 리포트 줄은 내용 · 실패 리포트에만 그린다")

## 맥락

- 리포트는 예약 → 시작 → 끝의 상태를 갖지만 예약을 생성으로 잇는 작업이 없었다. 같은 사용자 · 기간을 두 번 예약하는 것도 막지 않았다.
- 다이제스트는 같은 문제를 행의 등록 토큰 · 커밋 뒤 등록 · 거두기(시작 기한 · 임대)로 풀었다(ADR-0232). 리포트도 사용자 키로 생성기를 부르는 같은 꼴이다.
- 쓸 모델이 생성 작업이 돌 때 사라지거나(키 무효) 계정이 없어지면 시작하지 않고 끝내야 한다. 테이블은 시작한 행만 실패를 허용했고, 시간대는 시작할 때만 적었다 — 시작하지 않고 끝난 행은 날짜를 지금 사용자 시간대로 적게 되어, 사용자가 시간대를 바꾸면 실패 리포트의 날짜가 바뀐다.

## 결정

- **생성 작업은 리포트 행 하나를 등록 토큰(작업 ID)으로 돈다.** 행을 만들거나 바꾼 트랜잭션이 커밋된 뒤 등록하고, 다시 시도하지 않는다. 생성을 기다리는 행만 진행한다.
- **(사용자, 종류, 시작, 끝)마다 행은 하나다** — 테이블의 유일 인덱스가 지킨다. 일정은 사용자 잠금 뒤 그 종류의 가장 늦은 끝을 다시 보고 만든다.
- **거두기는 다이제스트를 따른다.** 등록하고 15분 지나도 생성을 기다리면 새 토큰으로 다시 등록한다. 생성을 기다림이 된 시각(예약 시각)에서 1시간이 지나면 다시 등록하지 않고 끝나지 않은 실패(`INTERRUPTED`)로 끝낸다. 생성 중인 채 임대(생성 호출 최악 둘 + 10분)가 지나면 끝나지 않은 실패로 끝내고 다시 돌리지 않는다.
- **쓸 모델이 없거나 계정이 없으면 생성기를 부르지 않고 시작하지 않은 채 실패(`NO_USABLE_MODEL`)로 끝낸다.**
- **시작하지 않고 끝낼 때 그때의 사용자 시간대를 행에 적는다**(계정이 없으면 UTC). 끝난 행은 언제나 시간대가 있다 — 테이블 제약이 지킨다. 시작할 때 적는 규칙(ADR-0318)은 그대로다.
- **시작하지 않고 끝난 실패 리포트에는 화면이 비교한 직전 리포트 줄을 그리지 않는다** — 직전 값과 견주지 않았다. 줄은 내용 리포트와 시작한 실패 리포트에만 그린다.

규칙은 [report Spec](../specs/report.md#생성-작업) report-R29 · [report-R30](../specs/report.md#거두기) · [reader Spec](../specs/reader.md#변화-리포트) reader-R16 에 있다.

## 결과

- 같은 기간의 리포트를 두 회차 · 두 작업이 함께 다뤄도 행 하나 · 생성 한 번이다. 등록 전에 멈춘 행도 비용 없이 다시 등록된다.
- 생성기를 부른 뒤 멈춘 생성은 다시 돌리지 않아 비용을 되풀이하지 않는다 — 그 리포트는 실패로 남고 사용자가 다시 만들 수 있다([ADR-0325](0325-a-failed-report-is-regenerated-from-the-screen-on-the-same-row-up-to-three-times.md)).
- 끝난 리포트의 기간 날짜는 시간대를 바꿔도 그대로다. 생성을 기다리는 리포트만 지금 시간대로 적는다.
- 테이블에 이미 같은 (사용자, 종류, 시작, 끝)의 행이 둘 이상이면 유일 인덱스가 만들어지지 않아 마이그레이션이 멈춘다 — 행을 지우지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 생성 중인 멈춘 리포트를 다시 돌린다 | 생성기를 부른 뒤 멈췄으면 비용을 되풀이한다(ADR-0232 와 같은 까닭) |
| 예약할 때 기간을 정한 시간대를 행에 적는다 | ADR-0318 의 "시작할 때의 시간대"를 바꾸고 시작할 때의 쓰기 · 테이블 제약도 바뀐다 |
| 시작하지 않고 끝난 리포트는 시간대를 적지 않는다 | 시간대를 바꾸면 실패 리포트의 날짜가 바뀌고 실패 알림에 적힌 날짜와 화면 날짜가 달라진다 |
| 쓸 모델이 없는 리포트도 시작해 생성기의 키 없음 실패로 끝낸다 | 공급자 · 모델 없이 시작한 행이 생기고 테이블 제약(시작한 행은 공급자가 있다)을 깬다 |
