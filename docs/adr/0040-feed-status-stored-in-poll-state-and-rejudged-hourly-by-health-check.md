# ADR-0040: 피드 상태는 수집 상태 행에 저장하고, 피드 건강 검사가 매시간 켜진 피드를 다시 판정한다

- 상태: 승인
- 날짜: 2026-10-30
- 근거: [이슈 #22](https://github.com/Theia0382/yozm-news/issues/22) — 실제 PostgreSQL · JobRunr 작업 서버로 확인. 구현 `53a72cd`(판정 입력과 판정 규칙) · `248d59b`(피드 건강 검사)
- 관련: [ADR-0013](0013-architecture-patterns.md)("상태 머신" 행의 피드 상태 — 이 ADR 이 부분 대체한다. 피드 상태는 aggregate 메서드가 아니라 `domain` 의 판정 함수가 정하고 SQL 로 쓰며, 모든 전이가 허용된다), [ADR-0033](0033-feed-polling-db-lease-per-feed-new-items-and-per-source-request-spacing.md)("운영 설정과 수집 상태는 다른 테이블이다"의 "`feed_poll_states` 는 수집 작업만 쓴다" — 이 ADR 이 부분 대체한다. 피드 상태 두 열은 피드 건강 검사가 쓴다), [ADR-0010](0010-tag-taxonomy.md)(판정 시점 규약의 근거 — 이 ADR 이 대체하지 않는다), [ADR-0023](0023-jobrunr-oss-framework-schema-and-event-resubmission.md)(JobRunr 반복 작업), [ADR-0031](0031-feed-request-blocks-internal-addresses-with-apache-httpclient-deadline.md)(실패 이유와 일시 · 영구 분류)

## 맥락

- 피드는 계속 실패하거나(`DEGRADED`), 응답은 정상인데 오래 새 기사가 없을 수 있다(`STALE`). 국내 언론사 피드 조사에서 2024년 이후 갱신되지 않은 피드가 있었다. 운영자 화면과 로그가 이 상태를 보여야 한다.
- 수집 상태(`feed_poll_states`)는 이미 연속 실패 수 · 마지막 성공 · 새 항목이 있던 마지막 수집 시각을 남긴다. 다만 상태를 판정하기에는 두 가지가 모자랐다.
  - 마지막 실패만으로 영구 실패를 가르면 영구 · 영구 · 일시 순서에서 실패가 이어지는 중에 `DEGRADED` 가 풀린다.
  - 새 항목 키만 보면, 등록 때 이미 방치된 피드(첫 수집의 모든 항목이 새 항목이다)와 옛 항목을 돌려 싣는 피드가 계속 새 기사가 오는 피드로 보인다.
- `overview.md` §6 "판정 시점"은 바뀔 수 있는 임계값을 조회 시점에 적용하라고 한다. 그런데 상태가 언제 바뀌었는지를 로그하고 화면 내 알림(M4)에 넘기려면 직전 상태가 있어야 한다.
- 수집 상태 행은 수집 경로가 점유 토큰을 조건으로 행 전체를 갱신한다. 같은 행에 다른 쓰기가 들어오면 서로 덮어쓸 수 있다.

## 결정

- **상태는 저장하되, 매 실행 현재 기준으로 다시 판정한다.** 판정 시점 규약을 이렇게 굽힌다. `feed_poll_states` 에 상태와 상태가 바뀐 시각을 두고, 피드 건강 검사가 대상 전부를 매번 다시 판정해 바뀐 행만 쓴다. 기준을 바꿔 배포하면 다음 실행(최대 1시간)에 모든 피드가 새 기준으로 맞춰진다. 직전 상태가 있으므로 전이만 로그한다.
- **판정은 피드 건강 검사 하나가 한다.** JobRunr 반복 작업(`feed-health-check`)이고 1시간마다 돌며 재시도하지 않는다. 다음 회차가 재판정이다. 수집 경로는 판정 입력만 남기고 상태를 계산하지도 쓰지도 않는다.
- **대상은 소스 · 피드가 모두 켜진 피드다.** 꺼진 피드는 마지막 상태를 그대로 둔다. 켜고 끄는 것은 상태를 바꾸지 않는다. 프로필을 얻지 못한 켜진 피드도 대상이라, 시간이 지나면 `STALE` 이 될 수 있다(원인은 수집 미룸 경고 로그가 알린다).
- **`DEGRADED` 는 연속 실패 수 또는 그 가운데 영구 실패 수로 판정한다.** 수집 경로가 실패마다 영구 실패면 연속 영구 실패 수를 하나 더하고, 성공 · 변경 없음이면 0 으로 한다. 분류는 실패 이유의 일시 · 영구 분류(ADR-0031)를 그대로 쓴다.
- **`STALE` 은 두 신호 가운데 하나라도 기준만큼 오래면이다.** 하나는 새 항목이 있던 마지막 수집의 시각이고, 다른 하나는 새 항목의 발행 시각 가운데 가장 늦은 것이다.
  - 발행 시각 최댓값은 새 항목만으로 올린다. 그래서 옛 항목을 돌려 실어도 올라가지 않는다. 방치된 피드는 첫 수집의 옛 발행 시각이 그대로 최댓값이 된다.
  - 발행 시각을 추정한 항목은 받은 시각으로 센다. 옛 항목에만 발행 시각이 있는 피드도 새 기사가 오면 `ACTIVE` 로 돌아온다.
  - 성공했지만 새 항목이 한 번도 없었던 피드는 `STALE` 이다.
- **판정 순서는 `DEGRADED` → `STALE` → `ACTIVE` 다.** 성공은 `DEGRADED` 를 풀 뿐이고, 그때 `STALE` 조건이 맞으면 `STALE` 이다. 기준 미만의 실패는 `STALE` 을 풀지 않는다. 판정은 직전 상태를 받지 않는 순수 함수라 모든 상태 쌍의 전이가 허용된다.
- **쓰기를 나눈다.** 수집 작업은 판정 입력을 포함한 수집 상태를 쓰고, 상태 · 바뀐 시각은 쓰지 않는다. 건강 검사는 그 두 열만 쓴다. 건강 검사는 한 트랜잭션에서 대상 행을 행 잠금(`for update`, 기다림)으로 잡고 판정 · 쓰기를 한다. 잠근 동안 수집 결과 반영은 기다리고, 수집 대상 잠금은 그 행을 건너뛴다. 그래서 옛 입력으로 쓴 상태가 새 입력을 덮지 않는다. 순환 대기는 없다.
  - 수집 대상 잠금은 잠긴 행을 건너뛴다.
  - 결과 반영은 한 행을 다른 잠금 없이 쓴다.
  - 점유 기록은 자기가 잠근 행만 쓴다.
  - 건강 검사끼리는 피드 ID 순으로 잠근다.
- **기준값은 `domain` 의 상수다** — 연속 실패 5회, 그 가운데 영구 실패 2회, 무소식 7일. 측정 전 목표이고 운영 데이터로 다시 본다.

## 결과

- 운영자 화면은 저장된 상태와 바뀐 시각을 읽기만 하면 된다. 로그는 전이 때만 남는다(진입 WARN · 복귀 INFO).
- 기준값을 바꾸면 배포 뒤 최대 1시간 동안은 옛 기준의 상태가 남는다.
- 연속 실패 "횟수" 기준이 실제로 걸리는 시간은 수집 주기와 백오프에 따라 다르다.
- 꺼져 있던 피드를 다시 켜면 첫 수집 전 검사는 옛 입력으로 판정한다. 다음 수집 · 검사가 맞춘다.
- 이 ADR 이전부터 영구 실패가 이어지던 피드는 연속 영구 실패 수를 0 에서 다시 센다.
- 켜진 피드 전부를 한 트랜잭션에서 잠근다. 판정은 열 비교뿐이라 짧지만, 피드가 수천 개가 되면 다시 본다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 상태를 저장하지 않고 조회 때 판정한다 | 직전 상태가 없어 전이를 알 수 없다. 매시간 비정상 피드 전부를 다시 로그하게 되고, 화면 내 알림이 전이를 받을 수 없다 |
| 수집 결과를 반영할 때도 판정해 수집 상태와 함께 쓴다(시간만으로 바뀌는 것은 건강 검사가 맡는다) | 판정을 부르는 곳과 전이 로그가 둘이 된다. 건강 검사도 여전히 상태를 쓰므로 쓰는 쪽 둘의 경합은 줄지 않고, 수집 경로가 직전 상태 · 바뀐 시각까지 다뤄야 한다 |
| 마지막 실패가 영구면 더 적은 기준을 쓴다 | 영구 · 영구 · 일시 순서에서 실패가 이어지는 중에 `DEGRADED` 가 풀린다 |
| 새 항목 키만으로 `STALE` 을 판정한다 | 등록 때 이미 방치된 피드와 옛 항목을 돌려 싣는 피드를 놓친다 |
| `article` 이 `source` 공개 API 로 알리는 "이 피드에서 처음 본 기사"의 시각을 쓴다 | 등록 때 이미 방치된 피드를 놓친다. `source` 의 첫 공개 쓰기 API · `article` 리스너 · 두 모듈 Spec 변경이 들고, 수집 상태를 쓰는 쪽이 셋이 되며 신호가 비동기로 온다. `source` 가 `article` 의 이벤트를 들으면 모듈 의존이 순환한다 |
| 기준값을 운영 설정 키에 둔다 | 설정 검증 · 기동 실패 경로와 운영 문서가 늘고, 지금 바꾸려는 사람이 없다 |
| 수집 프로필에서 피드별 무소식 기준을 덮어쓴다 | 프로필 스키마 · 검증이 바뀐다. 원래 드물게 싣는 피드가 프리셋에 아직 없다 |
| 꺼진 피드도 판정한다 | 관측하지 않은 피드에 판정을 만든다. 켜고 끄는 것이 상태와 독립이어야 한다 |
| 잠그지 않고, 읽은 판정 입력이 그대로일 때만 상태를 쓴다 | 어느 열이 입력의 변경을 대표하는지에 기댄다. 판정 입력이 늘면 조건도 함께 고쳐야 한다 |
