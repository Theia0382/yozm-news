# ADR-0062: 태그 체계는 운영자 원문으로 새 버전을 만들어 앞으로만 켜고, 키 계보를 원문에 적으며, 켤 때 정한 일수 안에 처음 본 기사를 재평가 대기에 넣는다

- 상태: 승인
- 날짜: 2026-11-02
- 근거: [이슈 #71](https://github.com/Theia0382/yozm-news/issues/71) — 기점 `550bf48` 의 태그 체계 버전 저장(버전 1 만 만드는 팩터리 · 활성 표시를 바꾸는 쓰기 없음), 평가 회차(회차 앞에서 활성 버전을 한 번 읽고 토큰만 보고 대기 행을 지움), 결과 조회(가장 큰 버전 번호), 평가 대기의 넣기(`ON CONFLICT DO NOTHING`)를 확인. 구현 `f70f0d7`(태그 종류 공개) · `4f19256`(원문 계보 절 · 원문 쓰기) · `a9503d9`(버전 대조 · 계보 해석) · `b483cd9`(계보 테이블 · 다음 버전 저장) · `93f4b9e`(처음 본 시각 조회) · `4633031`(확인 · 활성화 · 재평가 · 회차의 활성 확인) · `c0d56c1`(운영자 HTTP)

## 맥락

- 버전 내용은 만든 뒤 바뀌지 않고, 문구 하나를 바꿔도 새 버전이다(ADR-0054). 첫 체계는 기본 체계 파일로 들어오고, 이미 적재한 인스턴스는 체계 변경으로 새 버전을 들인다. 그 길이 없었다.
- 평가 결과 · 사용자 선호 · 주제별 시계열은 태그 키로 태그를 가리킨다. 키 이름을 바꾸거나 태그를 나누거나 합치면, 이전 키의 기록이 새 키로 이어져야 시계열과 선호가 끊기지 않는다.
- 결과 조회는 기사의 평가 가운데 버전 번호가 가장 큰 것을 쓴다. 예전 버전을 다시 켤 수 있으면 활성 체계에 없는 키가 조회에 나온다.
- 평가 회차는 회차 앞에서 활성 버전을 한 번 읽고, 성공하면 토큰만 보고 대기 행을 지운다. 회차가 활성 버전을 읽은 뒤 활성이 바뀌면, 그 회차의 남은 기사는 옛 버전으로만 평가되고 새 버전 평가를 영영 받지 못한다 — 활성화가 다시 넣어도 이미 있는 행은 그대로라서다. 오류도 로그도 없다.
- 회차는 1분에 많아야 50건을 평가한다(ADR-0059). 하루 약 4,000건(측정 전 추정)이면 7일치 재평가는 약 28,000건 · 약 9시간 · 약 $2 다.
- 지금 운영자는 토큰 하나라 함께 검토할 사람이 없다([ADR-0043](0043-admin-functions-guarded-by-env-bearer-token-until-account-roles.md)).

## 결정

- **운영자는 체계 전체를 YAML 원문으로 낸다.** 기본 체계 파일과 같은 형식 · 같은 검증기를 쓰고, 선택 절 `lineage` 하나가 는다. 원문은 저장하지 않는다 — 버전의 원문이 필요하면 그 버전의 내용과 지금 태그 기준 · 저장 기준으로 만들어 낸다(주석 · 계보 절 없음).
- **초안을 저장하지 않는다.** 확인은 원문을 검증하고 그 순간의 활성 버전과 대조해 변경 목록과 재평가 대상 기사 수를 돌려줄 뿐 아무것도 쓰지 않는다. 활성화는 같은 판정을 한 트랜잭션의 표 잠금 안에서 다시 하고, 기준 버전을 끄고 새 버전을 활성으로 넣는다.
- **버전은 앞으로만 켠다.** 새 버전의 번호는 기준 버전 + 1 이고, 예전 버전을 다시 활성으로 바꾸지 않는다. 되돌리려면 그 버전의 원문을 새 버전으로 낸다. 그래서 활성 버전은 언제나 번호가 가장 크고, 결과 조회의 "가장 큰 번호" 규칙이 그대로 맞는다.
- **계보는 원문의 `lineage` 절에 명시하고 새 버전과 함께 저장한다.** 이름 변경 · 분할 · 병합마다 이전 키와 새 키를 적는다. 대분류 키가 바뀌면 바뀐 중분류 전체 키마다 따로 적는다 — 추론하지 않는다. 주제 계보는 같은 층끼리(대분류는 대분류로, 중분류는 중분류로) 잇는다 — 대분류 구독은 하위 전체 구독으로 해석되므로 층을 넘으면 선호의 뜻이 바뀐다. 이전 키가 새 버전에 남는 것은 그 항목의 새 키일 때(이전 키를 남기는 분할 · 병합)뿐이다.
- **계보 해석은 버전을 받아 그 버전의 키 전부를 활성 버전 키의 집합으로 옮긴 표를 낸다.** 키는 그 키가 속한 버전과 함께 푼다 — 지운 키를 뒤 버전이 다시 써도 옛 기록이 새 키로 이어지지 않는다. 조회 결과의 태그 키는 그 평가 버전의 키 그대로이고, 소비자가 이 표로 푼다.
- **재평가 기간은 활성화 요청이 정한다 — 0 ~ 30일, 기본 0.** 기간 안의 기사는 `article` 이 그 기간에 처음 본 기사다. 활성화 트랜잭션에서 대기에 넣고, 실패로 남은 행(기사 거부 · 시도 소진)도 되돌린다. 평가 가능 시각은 활성화 시각이고(정착 시간 없음), 대기 순서는 지금 그대로다(평가 가능 시각 순). 요약문이 없는 기사도 제목만으로 재평가한다.
- **회차는 결과를 쓰기 전에 자기가 읽은 버전이 아직 활성인지 본다.** 결과를 쓰는 트랜잭션은 `tag_sets` 표를 `SHARE` 로 잠그고 확인한다. 활성이 아니면 점유를 풀고(성공이면 그 버전의 결과는 저장한다) 회차를 멈춘다 — 대기 행은 기사에 지금 활성 버전의 평가가 있게 된 트랜잭션에서만 지운다. 태그 기준 · 저장 기준 변경도 같은 잠금으로 활성 전환과 줄을 선다. 활성화 · 첫 기동 적재는 `SHARE ROW EXCLUSIVE` 다.
- **운영자 HTTP 는 `admin` 이 낸다** — 버전 목록 · 원문 · 확인 · 활성화. 편집 화면은 이 결정에 들지 않는다.

## 결과

- 운영자는 활성 버전의 원문을 받아 고치고, 확인으로 변경 목록 · 계보 없이 지운 키 · 재평가 건수를 본 뒤 켠다. 확인과 활성화 사이에 다른 활성화가 끼어도 활성화가 다시 대조하므로 틀린 버전이 켜지지 않는다.
- 기본값 0 이라 아무것도 정하지 않은 전환은 비용이 들지 않는다. 이슈가 처음 적은 "기본 7일"과 다르다 — 문구만 고친 전환이 운영자도 모르게 재평가 비용과 새 기사 지연을 만들지 않게 했다.
- 기간을 정하면 그 기간의 재평가 행이 새 기사보다 먼저 평가된다. 하루 기간마다 새 기사가 약 80분 늦어진다(하루 4,000건 · 회차당 50건 추정 — 측정 전). 새 기사를 먼저 평가하는 순서는 대기 행에 구별 열과 점유 순서 변경이 필요해 택하지 않았다 — 확인이 재평가 건수를 먼저 보인다.
- 확인 · 활성화 결과를 결정하는 판정이 하나라 두 결과가 갈리지 않는다. 원문의 태그 기준 · 저장 기준만 고친 원문은 "같은 내용"으로 끝난다 — 그 변경은 태그 기준 · 저장 기준 운영(ADR-0055)으로 한다.
- 결과 쓰기마다 표 잠금 하나가 는다. `SHARE` 끼리는 막지 않고 전환과만 충돌한다. 전환은 잠금을 잡은 채 재평가 행을 넣는다(30일이면 약 120,000행).
- 회차가 은퇴한 버전으로 낸 결과도 저장되므로, 새 버전 결과가 생길 때까지 조회가 그것을 쓴다.
- 요약문 자동 삭제를 만들면 지운 요약문을 처음부터 없던 요약문과 구별해 재평가에서 빼야 한다 — 그 작업의 몫이다.
- 활성 전환을 알리는 이벤트는 없다. 사용자 선호 옮기기 · 계보 없이 지운 태그의 선호 해제는 그 기능을 만드는 작업이 이벤트와 함께 정한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 화면에서 태그를 하나씩 더하고 지우는 구조 편집 연산 | 연산마다 검증 · 결과 타입이 생기고 원문 검증기와 같은 규칙을 두 번째로 갖는다 |
| 저장된 초안(작성 · 확인 · 활성화 세 연산) | 초안 · 은퇴 상태와 그 전이, 버리는 초안의 번호 공백, 낡은 초안의 기준 버전 판정, 초안 삭제가 생긴다. 함께 검토할 사람이 없다 |
| 버전마다 받은 원문을 보관해 그대로 돌려준다 | 보관한 원문의 태그 기준 · 저장 기준은 만든 때의 값이라 조정한 지금 값으로 되돌아가고, 원문의 계보 절이 다음 원문에 따라와 매번 지워야 한다 |
| 예전 버전을 다시 활성으로 켠다 | 조회 규칙을 "활성 버전의 평가가 있으면 그것, 없으면 …"으로 바꿔야 하고 계보가 뒤로도 흘러 해석 방향이 둘이 된다 |
| 계보를 활성화 요청의 별도 인자로 받는다 | 문제를 원문 · 계보 두 갈래로 돌려주고, 원문과 계보를 따로 들고 다녀야 한다 |
| 대분류와 중분류를 서로 잇는 계보를 허용한다 | 대분류 선호(하위 전체 구독)가 중분류 하나로, 또는 그 반대로 바뀐다 — 쓸 경우가 없다 |
| 대분류 계보가 같은 조각의 중분류를 함께 잇는다 | 추론 규칙이 하나 생기고, 조각이 바뀌거나 다른 대분류로 옮긴 중분류와의 관계를 따로 정해야 한다 |
| 재평가 대상을 `evaluation` 의 평가 시각으로 고른다 | 늦게 평가한 옛 기사가 "최근"이 되고, 평가가 없는 기사(실패로 남은 행)는 고르지 못한다 |
| 재평가 기간을 운영 설정이나 고정 7일로 둔다 | 전환마다 비용이 다른데 한 값으로 묶이고, 고정이면 문구만 고쳐도 재평가가 돈다 |
| 새 기사를 먼저 평가하고 재평가는 남는 처리량으로 | 대기 행의 구별 열과 점유 순서 변경이 필요하다 — 운영자가 건수를 보고 기간을 고르는 것으로 대신했다 |
| 기간 안의 실패 행을 그대로 둔다 | 넣기가 이미 있는 행을 그대로 두므로, 그 기사는 뒤의 모든 전환에서도 재평가 대기에 들어가지 못한다 |
| 조회가 결과의 키를 활성 버전의 키로 풀어 낸다 | 분할이면 한 확률이 여러 키에 복사되고 병합이면 확률을 합치는 규칙이 새로 생긴다. 판정(`low_confidence`)은 그 버전 안에서 해야 맞다 |
| 요약문이 있는 기사만 재평가한다 | 처음부터 요약문이 없던 기사는 처음 평가와 같은 입력인데도 새 체계를 받지 못한다 |
| 전환이 점유 중인 대기 행의 토큰을 지운다 | 회차의 저장이 토큰 불일치로 버려져 결과를 잃고, 기간이 0 이거나 기간 밖인 기사는 처리되지 않는다 |
| 결과 쓰기에서 활성 행을 `FOR SHARE` 로 잠근다 | READ COMMITTED 에서 전환을 기다린 문장은 끈 옛 행만 보고 새 활성 행은 보지 못한다 — 활성 버전을 찾는 태그 기준 · 저장 기준 변경이 활성 버전 없음으로 실패한다 |
