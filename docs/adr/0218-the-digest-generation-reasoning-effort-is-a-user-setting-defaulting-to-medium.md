# ADR-0218: 다이제스트 생성의 추론 강도는 사용자 설정이고 기본은 보통이다

- 상태: 승인
- 날짜: 2026-11-18
- 근거: [이슈 #177](https://github.com/Theia0382/yozm-news/issues/177) — 리드가 정함(추론 강도는 사용자 설정, 기본 보통). 구현 커밋 `d3b074d`(설정 · `PUT /api/interests/effort`) · `9e1012a`(생성 요청) · `7094e6d`(관문 요청) · `3c4e6d0`(화면)
- 관련: [ADR-0199](0199-generation-requests-carry-only-the-tasks-own-inputs-and-the-gateway-maps-them-to-each-provider.md)(관련 — 추론 강도는 과제를 아는 부르는 쪽이 고른다)

## 맥락

- 관문은 생성 호출의 추론 강도(낮음 · 보통 · 높음)를 부르는 쪽이 고르게 한다. 추론 토큰은 출력으로 과금된다 — 사용자 비용이다.
- 다이제스트는 많은 후보를 흐름으로 종합한다. 추론이 깊을수록 종합의 품질이 나아질 수 있지만 측정 전이다. 추론이 길면 생성 마감(180초)에 닿기 쉽고, 마감 초과는 관문이 다시 보내지 않는다.
- 고를 수 있는 사람은 개발팀(상수) · 운영자(허용 모델 파일, 모델마다) · 사용자(설정)다. 모델은 이미 사용자가 고른다.

## 결정

- **추론 강도는 사용자 설정이다 — 낮음 · 보통 · 높음, 기본 보통.** 저장은 `user` 의 설정 행 칸이고 값의 꼴은 `llm` 의 `ReasoningEffort` 다. 다이제스트가 읽는 관심 설정 조회가 내고, 생성 요청이 그대로 관문에 넘긴다.
- **화면의 자리는 "모델" 구획이다** — 고른 모델 · 키와 무관하게 저장한다(`PUT /api/interests/effort`).
- 기본을 보통으로 둔 것은 리드 결정이다 — "기본값이 곧 사용자 비용" 원칙으로는 낮음이 기본이지만, 종합의 품질을 먼저 본다. #182 의 실측으로 다시 본다.
- 외부 전송 고지에는 넣지 않는다 — 요청 매개변수이지 사용자에 관한 내용이 아니다.

## 결과

- 비용을 내는 사용자가 모델과 함께 추론 강도를 고른다. 키를 등록하지 않은 사용자도 미리 고를 수 있다.
- 추론 강도 값이 `llm` 밖(설정 칸의 CHECK · 화면용 API 명세의 enum)에도 저장된다 — 값을 더하는 변경은 그 자리를 함께 고친다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 코드 상수(낮음 또는 보통) | 비용을 내는 사람이 바꾸지 못한다 |
| 운영자 파일에 모델마다 | 모델마다 뜻이 달라 단위는 맞지만, 비용을 내는 사용자가 고르지 못한다 |
| 운영자 파일의 모델마다 기본 + 사용자 설정 | 칸이 두 곳에 생기고 우선순위 규칙이 하나 는다 |
