# ADR-0272: 입력 토큰 예산은 안전 상한이고, 다이제스트 분량은 최대 후보 수 단계가 정한다

- 상태: 승인
- 날짜: 2026-11-21
- 근거: [이슈 #182](https://github.com/Theia0382/yozm-news/issues/182) — 측정 인스턴스에서 입력 토큰 예산이 다이제스트의 사건 수를 정해, 사용자가 고른 최대 후보 수의 보통 · 많이 단계와 큰 슬롯 수가 결과를 바꾸지 못했다. 예산을 안전 상한으로 올리고 분량은 최대 후보 수 단계로 정하는 안과 그 값을 골랐다. 구현 커밋 `26c97f4`

## 맥락

- 후보 선별은 최대 후보 수(사용자 설정)만큼 고른 뒤 입력 토큰 예산(허용 모델 목록 — 모델마다)으로 자른다(ADR-0209 · ADR-0210).
- 다이제스트 후보가 사건이 되고 사건마다 표본 기사를 여럿 넘기면서(ADR-0260 · ADR-0263) 사건 하나의 입력이 기사 하나의 몇 배가 되었다. 예산이 낮으면 대부분 날 예산이 사건 수를 정하고, 최대 후보 수 단계 · 큰 슬롯 수의 차이가 결과에 드러나지 않는다.
- 예산은 그래도 필요하다 — 사건 하나의 입력이 표본 수 · 소스의 요약문 길이에 따라 몇 배 차이 나므로, 최대 후보 수만으로는 공급자 입력 한도 초과와 하루 비용의 최악값을 막지 못한다.

## 결정

- **입력 토큰 예산은 공급자 입력 한도 초과와 비용 최악값을 막는 안전 상한이다.** 기본 허용 모델 목록은 모든 모델에 120,000 을 둔다. 운영자 파일은 모델마다 다른 값을 둘 수 있다.
- **다이제스트의 평소 분량은 최대 후보 수가 정한다.** 단계는 적게 20 · 보통 40 · 많이 60, 직접 입력은 10 ~ 100 이고 기본은 보통이다.

## 결과

- 기본 예산에서는 사건이 무거운 날이 아니면 최대 후보 수가 사건 수를 정한다 — 사용자의 단계 선택이 분량과 비용에 그대로 드러난다. 예산은 사건이 무거운 날 · 상한을 낮추기 전에 저장된 큰 직접 입력에서 자른다.
- 상한을 낮추기 전에 저장된 직접 입력 값(101 ~ 150)은 그대로 읽는다 — 범위는 저장할 때만 본다(ADR-0209). 그래서 다이제스트 하나의 항목은 저장된 값이 남아 있는 동안 150 까지 될 수 있고, 피드백 요청 제한 750 / 10분은 그대로다.
- 예산이 묶지 않으면 큰 화제 사건이 최대 후보 수의 절반까지 들어, 큰 화제의 몫(행마다 사건 상한 · 큰 슬롯 수 · 큰 판정 기준)이 예산이 묶을 때와 다른 뜻을 갖는다 — 지금 값은 그대로 두고 새 분량으로 다시 본다.
- 토큰 어림 상수(코드 포인트 × 1.0 · 지시 몫 6,000)는 그대로다 — 예산이 안전 상한이라 어림의 여유는 실패를 막는 쪽으로 남는다.
- 기본 목록의 OpenAI · Anthropic 모델은 공급자 문서에서 입력 120,000 과 출력 상한을 함께 받는 문맥 한도를 갖는다. OpenRouter 를 거치는 같은 모델은 원 모델의 한도를 따른다고 보고 따로 확인하지 않았다. Anthropic Claude Haiku 5.5 는 입력이 100,000 토큰을 넘는 요청에 더 높은 단가를 매기므로, 그 모델로 무거운 날의 다이제스트는 단가가 오른다.
- 단계 값은 측정 전 목표다 — 다이제스트에 기록되는 실제 입력 · 출력 토큰으로 다시 본다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 예산을 그대로 두고 단계를 예산에 맞춰 낮춘다 | 예산이 사건 수를 정하는 날이 남고, 사건이 가벼운 날 예산이 허락하는 분량을 버린다 |
| 단계를 그대로 두고 예산만 올린다 | 보통 60 · 많이 90 이면 입력 · 비용이 크게 늘고 무거운 날 여전히 예산이 묶는다 |
| 예산을 없애고 최대 후보 수만 둔다 | 사건 하나의 입력 차이가 커서 공급자 입력 한도 초과와 비용 최악값을 막지 못한다 |
| 토큰 어림 비율을 낮춰 같은 예산에 사건을 더 넣는다 | 실제 입력이 예산에 붙어 재지 않은 공급자에서 입력 초과가 날 수 있다 |
