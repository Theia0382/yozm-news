# ADR-0324: 리포트 실패는 받는 쪽 user 가 선언한 이벤트로 다이제스트와 같은 꼴의 알림이 되고, 실패 갈래 타입을 함께 쓴다

- 상태: 승인
- 날짜: 2026-11-25
- 근거: [이슈 #240](https://github.com/Theia0382/yozm-news/issues/240) — 수용 기준 "실패 처리". 구현 `24a0fcf`(갈래 타입 이름) · `0defd7c`(이벤트 · 알림 종류 · 화면)
- 관련: [ADR-0233](0233-digest-failure-notices-come-through-an-event-declared-by-the-receiving-user-module-for-every-failed-digest.md)(같은 꼴, 보충 — 갈래 타입 이름), [ADR-0240](0240-digest-failures-show-the-cause-action-and-the-code-and-never-the-failure-message.md)(같은 꼴 — 갈래 문구 · 메시지 없음)

## 맥락

- 리포트는 주 · 달에 한 번이라 실패해도 리포트 화면을 열지 않으면 모른다. 실패의 다수(키 무효 · 공급자 계정)는 다음 기간도 실패하게 하는 문제라 사용자가 알아야 고친다.
- 다이제스트 실패는 받는 쪽 `user` 가 선언한 이벤트로 알림이 된다(ADR-0233). `report` 는 `user` 의 공개 조회를 읽으므로 `report` 가 이벤트를 선언하면 두 모듈이 서로 기댄다.
- 다이제스트 실패의 갈래(키 · 공급자 계정 · 잠시 뒤 · 모델 출력)는 리포트 실패에도 그대로 맞는데 타입 이름이 다이제스트를 가리켰다.

## 결정

- **리포트 실패 이벤트(`ReportFailed`)는 받는 쪽 `user` 가 선언하고, `report` 가 실패를 쓰는 트랜잭션에서 낸다.** 생성 · 시작 전 끝내기 · 거두기 모두 한 정본(끝내기)을 지나 낸다.
- **알림은 실패마다 하나다** — 같은 리포트가 다시 만들어 또 실패하면 실패 시각이 다른 알림이 하나 더 생긴다. 같은 이벤트를 거듭 받아도 하나만 남는다(리포트 ID · 실패 시각의 고유 인덱스). 본문은 종류 · 기간 날짜(행의 시간대) · 갈래 · 실패 시각이고 메시지는 없다. 화면은 갈래마다 할 일을 보이고 그 리포트로 잇는다.
- **실패 갈래 타입은 다이제스트와 함께 쓴다** — 이름을 `GenerationFailureCause` 로 바꾼다. 실패 코드를 갈래로 옮기는 정본은 각 생성 모듈에 있고, 할 일 문구는 다이제스트와 리포트가 따로 둔다.

규칙은 [report Spec](../specs/report.md#끝내기와-실패-알림) report-R31 · [user Spec](../specs/user.md#화면-내-알림) user-R75 에 있다.

## 결과

- 리포트 화면에 가지 않는 사용자도 실패를 안다. 알림의 꼴이 다이제스트와 같아 배울 것이 없다.
- `report` 가 이벤트를 내는 모듈이 된다 — 의존은 이미 있는 `report → user` 그대로다.
- 키 문제면 같은 날 다이제스트 실패 알림과 리포트 실패 알림이 함께 온다.
- 갈래 목록은 한 곳이다 — 갈래가 늘면 두 생성 모듈의 옮기기와 두 문구 표가 함께 바뀐다(망라 분기가 잡는다).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 알림 없이 리포트 화면의 실패 상태만 둔다 | 화면을 열지 않으면 실패를 모르고, 키 · 계정을 고칠 계기를 잃는다 |
| `report` 가 이벤트를 선언한다 | `report` 가 `user` 를 읽으므로 두 모듈이 서로 기댄다 |
| 리포트마다 알림 하나(다시 실패해도 하나) | 다시 만든 리포트가 또 실패한 것을 모른다 |
| 리포트용 갈래 타입을 따로 둔다 | 같은 갈래 목록이 두 벌이다 |
| `DigestFailureCause` 이름 그대로 리포트 이벤트에 쓴다 | 리포트 이벤트가 다이제스트 이름의 타입을 싣는다 |
