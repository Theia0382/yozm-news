# ADR-0183: 운영자 경로는 `ADMIN` 계정 세션으로 열고, 운영자 토큰은 스크립트용 선택 Bearer 로 남기며, 세션 요청에만 CSRF 를 건다

## 맥락

- 운영자 경로(`/api/admin/**`)는 계정 인증보다 먼저 생겨, 환경 변수의 운영자 토큰 하나로 막았다(ADR-0043). 이제 계정 · 세션 · CSRF 와 첫 운영자가 있다.
- 운영자 토큰을 아는 사람은 모두 운영자다 — 사람마다 구별하거나 회수할 수 없다.
- 운영자 API 는 화면 밖에서도 쓰인다. 태그 체계 편집은 화면이 없어 curl 로 하고, 평가 도구는 운영자 API 를 읽으며, 배포 스모크는 시험 소스를 등록한다. 로그인은 봇 차단을 켠 인스턴스에서 사람 확인을 요구해 스크립트가 비밀번호로 로그인할 수 없다.
- 세션 생성 정책을 정한 보안 체인에는 Spring Security 의 세션 관리 필터가 서서, 세션에 문맥이 없는 인증된 요청의 인증을 세션 저장소에 저장하려 한다.

## 결정

- **운영자 경로는 `ADMIN` 계정 세션으로 연다.** 운영자 체인은 세션 체인과 같은 세션 인증 구성(사용자 ID 만 담은 세션 · 요청마다 계정 읽기)을 쓰고, 경로와 `ADMIN` 역할 판정은 그대로다. 비밀번호를 바꿔야 하는 운영자는 바꾸기 전에 쓰지 못한다.
- **세션으로 인증한 요청의 변경 메서드에 CSRF 를 건다** — 세션 체인과 같은 쿠키 · 헤더다.
- **운영자 토큰은 스크립트용 선택 설정의 Bearer 로 남긴다.** 형식 · 대조 규칙은 그대로다. 설정하지 않아도 운영자 기능은 세션으로 열린다 — "운영자 기능이 닫힌" 상태는 없다. 화면은 토큰을 받지도 보내지도 않는다.
- **`Authorization` 헤더를 낸 요청은 운영자 토큰으로만 판정한다.** 맞으면 운영자로 인증하고 CSRF 를 면한다(쿠키 자격이 아니다). 스킴 · 형식 · 값이 틀리거나 토큰을 설정하지 않았으면 세션으로 넘어가지 않고 거부한다.
- **운영자 토큰 인증은 세션에 남지 않는다.** 세션 저장소가 세션 사용자 인증만 쓴다.

## 결과

- 화면의 운영자 행동은 사람 계정에 묶인다. 운영자 토큰을 설정한 인스턴스에는 사람에 묶이지 않는 운영자 자격이 남는다 — 스크립트 · 도구가 쓰고, 운영자 경로만 연다.
- 틀린 Bearer 헤더와 세션 쿠키를 함께 낸 요청이 세션으로 인증돼 CSRF 를 면하는 길이 없다. 맞는 Bearer 요청 하나가 운영자 세션을 만드는 길도 없다.
- 운영자 계정이 운영의 필수가 되었지만, 운영자도 첫 운영자 값도 없는 인스턴스는 지금처럼 경고를 남기고 뜬다(ADR-0139 재검토의 결론) — 시험 · 개발 구성 · 스모크가 값 없이 뜨고, 운영자를 잃은 인스턴스는 값을 넣어 다시 띄운다.
- 운영 설정 이력의 행위자는 계정이 아니라 `OPERATOR` 그대로다 — 어느 운영자가 바꿨는지 적지 않는다(ADR-0140 이 미룬 계정 행위자).
- 운영자 화면 · 평가 도구 · 스모크의 시험은 세션 경로와 Bearer 경로를 따로 지킨다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 운영자 토큰을 지운다 | 화면이 없는 태그 체계 편집과 도구 · 스모크가 브라우저의 세션 쿠키를 복사해 써야 한다 — 그 쿠키는 계정 전체(키 등록 · 비밀번호 변경 포함)를 여는 자격이라 운영자 경로만 여는 토큰보다 넓다. 비밀번호 로그인 스크립트는 봇 차단과 함께 쓸 수 없다 |
| 운영자 토큰을 읽기(GET) 전용으로 남긴다 | 스모크의 시험 소스 등록 · 태그 체계 활성화(POST)는 토큰을 지울 때와 같은 문제를 진다. 같은 자격에 메서드별 권한이라는 규칙이 는다 |
| 계정마다 발급하는 운영자 API 토큰 | 사람에 묶이면서 스크립트도 쓰지만 발급 · 목록 · 회수와 저장이 새로 생기는 기능이다 — 필요해지면 이 토큰을 그것으로 바꾼다 |
| 운영자 경로를 세션 체인에 합친다 | 세션 체인의 판정이 역할 · 토큰을 알아야 하고, 처리기 없는 운영자 경로가 인증 전에 404 · 405 를 낸다 |
| 틀린 Bearer 헤더는 무시하고 세션으로 넘긴다 | 도구가 틀린 토큰에 로그인 요구를 받아 까닭을 모르고, CSRF 면제를 헤더 유무로 가르면 세션 요청이 비켜 간다 |
| 운영자 체인에서 세션 생성 정책을 빼 세션 관리 필터를 없앤다 | 두 체인의 세션 인증 구성이 갈린다. 저장소에서 거르면 어느 체인으로도 세션 사용자 인증 밖의 것이 세션에 남지 않는다 |
