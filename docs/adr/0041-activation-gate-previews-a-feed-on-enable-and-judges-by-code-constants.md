# ADR-0041: 활성화 관문은 피드를 켤 때 한 번 받아 미리보고, 코드 상수 기준으로 판정한다

- 상태: 승인
- 날짜: 2026-10-30
- 근거: [이슈 #23](https://github.com/Theia0382/yozm-news/issues/23) — 조사 자료의 공개 RSS 12곳을 한 번씩 받아 지표만 재고(원문은 저장하지 않음), 합성 피드로 기준의 경계를 시험. 구현 `e2a2c34`(미리보기 지표와 기준 판정) · `d321f49`(요청 시작 시각 예약 추출) · `2791095`(피드 켜기 관문과 원문 미리보기)
- 관련: [ADR-0015](0015-source-presets-and-collection-profiles.md)(활성화 관문 — 미리보기의 단위를 이 ADR 이 좁힌다), [ADR-0033](0033-feed-polling-db-lease-per-feed-new-items-and-per-source-request-spacing.md)(같은 언론사 요청 예약 — 미리보기도 같은 예약을 쓴다), [ADR-0030](0030-feed-xml-own-parser-and-rome-for-format-title-link.md)(`dc:date` 매핑 누락을 날짜 해석률이 드러낸다), [ADR-0032](0032-same-article-matching-avoids-false-merges-with-per-feed-entries-under-source-lock.md)(관문은 guid 유일성을 보지 않는다)

## 맥락

- ADR-0015 는 "소스와 피드를 켜기 전에 서버가 한 번 받아 미리보기를 만들고, 기준에 못 미치면 켜지 않는다"고 정했고, 기준값은 M1 에서 정하기로 남겼다. "미리보기만 보여 주고 활성화는 운영자 판단"은 기각했다.
- 등록 직후 소스와 피드는 모두 꺼져 있고, 수집은 소스와 피드가 모두 켜진 피드만 한다. 소스 켜기에는 피드 URL 이 없다 — 이용조건 검토일만 본다.
- 정규화 결과에는 미리보기의 재료가 이미 있다 — 기사 · 건너뛴 항목, 발행 시각 추정 여부, 요약문, U+FFFD 로 바꾼 자리 수.
- 조사 자료(`docs/research/2026-10-rss-survey.md`)의 12곳을 2026-10-30 에 한 번씩 받아 잰 값(11곳 응답, 매일경제 403):
  - 날짜 해석률은 0 아니면 1 이었다. 프로필 실수(경향 `dc:date` 매핑 누락, 블로터 형식 누락)는 0, 고친 프로필은 1. 날짜가 없는 피드(한겨레)와 시각 없이 날짜만 주는 피드(JTBC)는 프로필이 무엇이든 0 이다.
  - 건너뛴 항목은 11곳 모두 0 이었다.
  - 읽은 문자 수 대비 대체 비율: 정상 0, 문서 안 몇 바이트의 국소 손상 0.000039 ~ 0.000044, 문자셋을 통째로 잘못 읽은 경우 0.032 ~ 0.535.
- 실제 프리셋은 아직 없다. 첫 프리셋은 언론사 이용조건 검토가 앞선다.

## 결정

- **관문은 피드 켜기에만 든다.** 꺼진 피드를 켤 때 그 피드를 한 번 받아(조건부 요청 값 없이, 피드 요청 관문 `ArticleSource` 로) 미리보기를 만들고, 기준을 넘을 때만 켠다. 소스 켜기는 이용조건 검토일만 본다. 처음 수집되는 피드는 모두 피드 켜기를 지나므로 프리셋 · 운영자 프로필이 같은 관문을 지난다. 이미 켜진 피드를 다시 켜면 받지 않는다.
- **미리보기 요청도 같은 언론사 요청 간격을 지킨다.** 수집 작업과 같은 요청 직전 예약(ADR-0033)으로 시작 시각을 받고 그때까지 기다린다. 켜기 호출은 그 소스에 앞서 잡힌 예약 하나당 최대 10초를 더 기다린다.
- **켜기는 트랜잭션 셋으로 나눈다.** 읽고 판정 → 예약 → 트랜잭션 밖에서 요청 → 다시 읽고 판정 · 저장. 저장 직전에 프로필을 다시 얻어 피드 URL 이 미리본 것과 같을 때만 켠다.
- **기준은 넷이다.** 기사 수, 항목 수 대비 건너뛴 비율, 기사 수 대비 발행 시각을 해석한 비율, 읽은 문자 수 대비 U+FFFD 로 바꾼 비율. 비율은 분모가 0 이면 판정하지 않는다.
- **날짜가 없는 피드는 프로필의 선언으로만 인정한다.** 프로필이 발행 시각의 읽을 곳을 빈 목록(`items.publishedAt: []`)으로 선언하면 날짜 해석률을 보지 않는다. 빈 목록은 기본값(`[$standard]`)을 일부러 바꿔야 생기므로, 매핑 · 형식 누락 같은 실수는 그대로 거절된다.
- **요약문은 판정하지 않는다.** 요약문 길이 분포는 미리보기에 보이기만 한다 — 요약문이 없어도 데이터가 틀려지지 않는다.
- **대체 문자는 비율로 본다.** 정규화 결과에 읽은 문자 수(사전 보정 전 코드 포인트, BOM 제외)를 더해 분모로 쓴다. 문자셋 전체 오류와 국소 손상이 자릿수로 갈린다.
- **기준값은 코드 상수 한 곳이고 운영자 설정이 아니다.** 결정 시점의 값은 기사 1건 이상 · 건너뜀 10% 이하 · 해석 90% 이상 · 대체 0.1% 이하이고 잠정값이다 — 대체 0.1% 는 위 실측의 국소 손상보다 약 23배 위, 문자셋 전체 오류의 최솟값보다 약 32배 아래다. 건너뜀 10% 는 실측이 위치를 정하지 못했다. 첫 프리셋이 실제 피드로 확정하고, 어긋나면 상수를 고친다. 지금 값의 정본은 코드(`ActivationCriteria`)이고 Spec 규칙(source-R9)이 그 자리를 가리킨다.
- **미리보기는 저장하지 않는다.** 기사 · 수집 상태 · 조건부 요청 값에 쓰지 않고 호출자에게 돌려준다. 같은 언론사 요청 예약만 남는다. 미리보기에는 지표와 함께 기사 앞 5건의 제목 · 발행 시각 · 추정 여부를 담는다 — 관문이 잡지 못하는 결함(오류 없이 깨지는 문자셋, 시간대 오기재)을 운영자가 켜기 전에 본다. 표본은 판정에 쓰지 않는다.
- **판정은 켜는 순간에만 한다.** 켠 뒤의 품질 변화는 피드 상태(성공 · 실패 기록과 그 판정)가 지켜본다.
- **등록 전 원문도 같은 판정으로 미리본다.** 운영자 프로필 원문과 피드 식별자로 DB 를 거치지 않고 받아 판정한다. 소스 행이 없어 요청 간격 예약 밖이다.

## 결과

- 프로필 설정 실수와 형식 결함이 켜기 전에 드러나고, 거절 이유(받지 못한 이유 또는 못 미친 기준과 실제 값)가 운영자에게 간다.
- 피드 켜기는 외부 요청을 품어 길어진다 — 화면은 이 지연을 다뤄야 한다. 호출자는 트랜잭션 밖에서 부른다.
- 이용조건 검토일이 없는 소스의 피드도 켜기 · 원문 미리보기에서 요청 한 번은 나간다(수집은 소스 켜기가 검토일을 본 뒤에야 시작한다).
- 소스를 껐다 켜면 켜져 있던 피드는 다시 미리보지 않는다. 프리셋 배포로 켜진 피드의 URL · 읽을 곳이 바뀌어도 다시 보지 않는다 — 프리셋의 품질은 개발팀의 시험이 맡는다(ADR-0015).
- 날짜를 시각 없이 주는 피드는 지금의 해석기가 읽지 못해, 발행 시각을 읽지 않는다고 선언해야 켜진다(날짜를 버린다).
- 기준값은 잠정이라 첫 프리셋에서 다시 본다. 실측은 1회분이다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 소스 켜기 때도 그 소스의 켜진 피드를 모두 미리보고, 하나라도 미달이면 소스를 켜지 않는다 | 켜기 지연이 피드 수에 비례하고(요청 간격), 피드 하나의 일시 실패가 소스 전체를 막는다. 미달 피드를 자동으로 끄면 "켜고 끄는 것은 운영자의 선택"과 부딪친다 |
| 미리보기 요청은 요청 간격 예약을 하지 않는다 | 언론사에 대한 간격 규칙이 요청 주체에 따라 달라진다. 피드 여럿을 연달아 켜면 같은 언론사에 몇 초 안에 요청이 몰린다 |
| 날짜 해석률 기준에 예외를 두지 않는다 | 날짜가 없는 언론사, 해석기가 읽지 못하는 형식의 피드를 켤 수 없다 |
| 날짜가 없음을 새 프로필 키로 선언한다 | 빈 목록 선언과 실질이 같고 프로필 형식 · 검증기가 커진다 |
| 요약문 있는 기사 비율에도 하한을 둔다 | 제목만 주는 언론사를 막는다. 요약문을 실제로 주는데 프로필이 비우는 실수와 구별되지 않는다 |
| 대체 문자를 절대 개수로 본다 | 피드 길이에 따라 경계가 흐리다 — 짧은 피드의 전체 오류와 긴 피드의 국소 손상을 가르지 못한다 |
| 대체 문자가 든 기사 비율로 본다 | 피드가 본래 U+FFFD 를 실은 경우와 섞이고, 기사로 넘기지 않은 부분의 오류를 보지 않는다 |
| 기준값을 운영자 설정으로 연다 | ADR-0015 가 기각한 "활성화는 운영자 판단"을 되살린다 |
| 등록된 피드만 미리본다 | 운영자 원문은 고칠 수 없고 소스는 지울 수 없어, 프로필을 고쳐 볼 때마다 버린 소스가 쌓인다 |
| 미리보기에 지표만 담는다 | 관문이 잡지 못하는 결함이 켠 뒤 다이제스트에서야 드러난다 |
