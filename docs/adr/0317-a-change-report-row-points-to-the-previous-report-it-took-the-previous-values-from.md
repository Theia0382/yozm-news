# ADR-0317: 변화 리포트 행은 생성 때 직전 값을 꺼낸 직전 리포트를 가리킨다

- 상태: 승인
- 날짜: 2026-11-24
- 근거: [이슈 #241](https://github.com/Theia0382/yozm-news/issues/241) — 기점 `a599598` 에서 직전 리포트는 생성 때 찾기만 하고 행에 남지 않으며, 같은 (사용자, 기간)의 저장 제약이 아직 없음을 확인. 생성을 부르는 운영 코드가 없어 옮길 옛 행이 없다. 구현 `0fa4ab4`
- 관련: [ADR-0304](0304-a-change-report-takes-previous-values-from-the-previous-reports-snapshot-matched-one-to-one-and-keeps-them-in-its-own-snapshot.md)(보충 — 직전 값을 꺼낸 직전 리포트를 행에도 남긴다)

## 맥락

- 리포트의 직전 값은 직전 리포트의 스냅숏에서 꺼낸다(ADR-0304). 화면은 비교한 숫자가 어느 리포트의 것인지 보이고 그 리포트로 잇고 싶다.
- 직전 리포트를 읽을 때 같은 규칙으로 다시 찾으면, 생성 뒤 같은 기간의 리포트가 새로 생겼을 때 숫자를 가져온 리포트와 다른 행을 가리킨다. (사용자, 기간)마다 한 번의 저장 제약과 수동 재생성은 아직 정해지지 않았다.

## 결정

- **생성을 시작할 때 직전 값을 꺼낸 직전 리포트의 ID 를 리포트 행에 남긴다.** 재료 조립이 찾은 직전 리포트를 입력에 싣고, 시작 트랜잭션이 스냅숏과 같은 문장으로 쓴다. 스냅숏을 읽지 못해 비교가 비었어도 직전 리포트가 있으면 남긴다.
- 칸은 같은 테이블의 자기 참조 FK 이고, 직전 리포트가 지워지면 칸만 비운다. 자기 자신은 가리키지 않는다.
- **조회는 그 직전 리포트의 요약(기간 · 상태)을 한 편과 함께 낸다** — 같은 사용자 조건으로 읽는다. 화면은 링크를 달고, 없으면 비교가 빈 까닭을 안내한다.

규칙은 [report Spec](../specs/report.md#직전-리포트와-스냅숏) report-R18 과 §6 에 있다.

## 결과

- 링크가 숫자를 가져온 그 리포트를 언제나 가리킨다.
- 직전 리포트를 찾는 규칙은 생성 한 곳에만 있다 — 조회는 남긴 ID 를 읽는다.
- 마이그레이션으로 칸이 하나 는다. 옮길 옛 행은 없다.
- 스냅숏의 꼴은 바뀌지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 링크 없이 스냅숏의 비교만 보이고 이전 리포트는 목록에서 고른다 | 직전 값이 어느 리포트의 것인지 화면에 없고, 비교가 빈 까닭도 보이지 않는다 |
| 조회가 생성 때와 같은 규칙으로 직전 리포트를 다시 찾는다 | 같은 기간의 행이 새로 생기면 숫자를 가져온 리포트와 다른 행을 가리킨다 |
| 스냅숏 안에 직전 리포트 ID 를 넣는다 | 스냅숏은 생성에 쓴 통계이고, 키를 더하면 판 번호와 읽는 길을 함께 다뤄야 한다 |
