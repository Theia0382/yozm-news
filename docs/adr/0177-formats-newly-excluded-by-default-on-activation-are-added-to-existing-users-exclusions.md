# ADR-0177: 활성 전환 때 새로 생긴 기본 제외 형식은 기존 사용자의 제외로 넣는다

- 상태: 승인
- 날짜: 2026-11-15
- 근거: [이슈 #151](https://github.com/Theia0382/yozm-news/issues/151)
- 관련: [ADR-0054](0054-tag-set-seeded-from-default-yaml-on-first-start-with-immutable-versions-and-question-templates.md)(형식의 기본 제외는 형식 태그의 속성 — 그 기각 대안 "가입 때 정한다"는 속성을 어디 둘지의 기각이라 이 ADR 과 충돌하지 않는다), [ADR-0175](0175-tag-preferences-follow-tag-set-activation-events-and-are-rewritten-to-active-keys.md)(활성 전환 처리)

## 맥락

- 형식의 기본 제외는 체계 버전의 내용이고, 계정을 만들 때 활성 버전의 기본 제외 형식을 그 사용자의 제외로 넣는다.
- 그러면 운영자가 새 버전에 기본 제외 형식을 더해도 이미 있는 사용자에게는 닿지 않는다.

## 결정

- **활성 전환 때 새 버전에서 기본 제외이면서 어떤 이전 형식의 계보로도 이어지지 않은 형식을 모든 사용자의 제외로 넣고 알린다.**
- **이미 있던 형식의 기본 제외가 바뀐 것은 건드리지 않는다** — 사용자가 이미 본 형식의 선택을 존중한다.

## 결과

- 운영자가 새로 들인 형식의 의도가 기존 사용자에게도 닿는다. 새 형식에는 아무도 선택한 적이 없어 기본값이 사용자의 뜻을 덮지 않는다.
- 사용자 행에 기본값을 복사하므로, 기본 제외를 나중에 바꿔도 이미 있는 사용자의 선택은 그대로다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 계정을 만들 때만 넣는다 | 운영자가 새 버전에 기본 제외 형식을 더해도 기존 사용자에게 닿지 않는다 |
| 사용자 행에는 기본값과 다른 선택만 두고 조회 때 기본 제외와 합친다 | 사용자가 "기본값과 같은 선택"을 명시할 길이 없어 기본값이 바뀌면 선택이 뒤집히고, 이력의 투영이 체계와 섞인다 |
