# ADR-0175: 태그 선호는 체계 활성 전환 이벤트를 받아 활성 버전의 키로 고쳐 쓴다

- 상태: 승인
- 날짜: 2026-11-15
- 근거: [이슈 #151](https://github.com/Theia0382/yozm-news/issues/151) — 태그 키 계보 해석(tag-R26)과 계정을 만드는 길 넷의 트랜잭션을 확인
- 관련: [ADR-0010](0010-tag-taxonomy.md)(보충 — `user_tag_preferences` 의 체계 버전), [ADR-0028](0028-explicit-signals-and-interest-weighted-candidates.md)(보충 — 이력의 원인과 관심 신호), [ADR-0062](0062-tag-set-versions-from-operator-text-activated-forward-with-key-lineage-and-recent-reevaluation.md)(보충 — 결과 절이 미룬 활성 전환 이벤트와 선호 옮기기), [ADR-0176](0176-tag-set-changes-do-not-narrow-a-users-preferences-without-telling.md) · [ADR-0177](0177-formats-newly-excluded-by-default-on-activation-are-added-to-existing-users-exclusions.md)(고쳐 쓰는 규칙)

## 맥락

- 사용자의 태그 선호(주제 구독 · 지역 제외 · 형식 제외)는 태그 키로 가리킨다. 운영자가 새 체계 버전을 켜면 키가 이름을 바꾸거나 나뉘거나 합쳐지거나 계보 없이 사라진다.
- 계보는 "키를 그 키가 속한 버전과 함께" 푼다 — 지운 키를 뒤 버전이 다시 쓰면 같은 문자열이 다른 태그다. 키만 저장하면 계보를 풀 수 없다.
- 선호를 읽는 쪽은 여럿이다 — 관심 설정 화면, 다이제스트의 후보 선별, 변화 리포트. 계보 없이 지운 키의 선호는 해제하고 알려야 한다.
- 활성 전환과 선호를 고쳐 쓰는 처리 사이에는 틈이 있다 — 그 사이 사용자가 화면을 열거나 저장할 수 있고, 계정이 새로 만들어질 수 있다.

## 결정

- **`tag` 가 활성 전환을 이벤트 `TagSetActivated`(이전 · 새 버전 ID)로 낸다.** 활성화 트랜잭션에서 발행하고 사용자 정보는 싣지 않는다.
- **`user` 가 그 이벤트를 받아 선호를 계보대로 지금 활성 버전의 키로 고쳐 쓴다.** 이벤트의 두 버전을 믿지 않고 선호 버전이 지금 활성 버전과 다른 사용자를 모두 고친다 — 사용자마다 트랜잭션 하나다. 계보 없이 지운 키의 선호는 해제한다.
- **선호의 체계 버전은 사용자마다 하나다** — 현재 상태 전체가 그 버전의 키다. 이력 행은 기록 당시의 버전 · 키와 원인(사용자 · 계정을 만들 때 기본값 · 체계 변경)을 갖는다. 관심 신호는 원인이 사용자인 행만이다.
- **이력은 활성 키로 푼 집합이 바뀔 때만 남는다** — 이름 변경 · 정규화는 이력이 없고, 해제는 옛 키의 뺌, 더함은 새 키의 더함이다.
- **해제 · 더함이 있으면 사용자에게 알린다** — 사용자 · 활성 전환마다 알림 하나에 모두 싣는다.
- **조회 · 저장은 사용자의 설정 행을 잠근 뒤 선호 버전이 활성과 다르면 먼저 그 사용자를 고쳐 쓴다** — 리스너와 같은 정본이다. 리스너가 닿기 전에도 처리기는 활성 키만 다룬다.
- **새 설정 행은 울타리를 지난다** — 설정 행을 만드는 쪽은 advisory 공유 잠금을 잡은 뒤 활성 버전을 읽고, 리스너는 사용자를 훑기 전에 같은 키의 배타 잠금을 잡았다 놓는다. 활성 전환 전에 시작한 계정 생성이 훑기에서 빠지지 않는다.

## 결과

- 선호를 읽는 쪽은 계보를 모른다 — 현재 상태는 늘 활성 키다. 이력은 기록 당시 버전 그대로라 관심사 히스토리가 계보로 푼다.
- 이벤트 하나가 모든 사용자의 선호를 고친다 — 사용자 단위로 커밋해 중간 실패는 재처리가 나머지를 고친다.
- 다이제스트 · 리포트의 소비자 조회가 리스너가 닿기 전의 옛 버전 행을 어떻게 다룰지는 그 조회를 여는 작업이 정한다.
- 체계를 되돌려도 새 버전이라, 계보 없이 지운 키에서 해제된 선호는 돌아오지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 선호를 (버전, 키)로 두고 읽을 때 계보로 푼다 | 모든 소비자가 버전마다 계보 표를 받아 풀어야 한다. 지운 키의 행이 남아 "해제"가 이름뿐이다 |
| 선호 행마다 체계 버전 | 한 사용자 안에서 버전이 섞일 수 있어 불변식이 늘고, 선호 행이 없는 사용자를 활성 전환이 찾지 못한다 |
| 활성 전환 하나를 트랜잭션 하나로 | 사용자 수에 비례해 잠금이 길어지고 실패 하나가 전부를 되돌린다 |
| 주기 작업으로 옛 버전 행을 훑는다 | 그 주기만큼 옛 키가 남는다 |
| 리스너가 닿기 전 구간을 소비자에게 맡긴다 | 화면이 옛 키를 그리고, 저장이 옛 키의 뺌을 새 버전으로 남기며, 저장이 버전을 올려 해제 · 더함과 알림이 빠진다 |
