# ADR-0083: 큰 사건 기준은 운영자 설정으로 두고 추가 전용 이력과 미리보기를 둔다

- 상태: 대체됨([ADR-0118](0118-big-judgement-criteria-are-storyline-operator-settings-and-do-not-inherit-event-criteria-values-or-history.md))

## 맥락

- 큰 사건 기준(소스 기준 · 중요도 기준)은 측정 전 목표이고, 평가 세트와 운영자의 표본 검수로 여러 번 맞출 값이다. 운영자 화면에 큰 사건 판정 결과와 기준 조정이 있다.
- 사건 배정 기준은 설정(환경 변수)에 두었다. 운영자 설정(DB + 변경 이력)을 기각한 이유는 배정이 누적 상태라 미리보기를 줄 수 없다는 것이었다(ADR-0081).
- 큰 사건은 조회할 때 판정해 저장하는 것이 없다(ADR-0082). 바꾸면 다음 조회부터 반영되고, 제안 기준으로 같은 계산을 하면 미리보기가 된다 — ADR-0081 의 기각 이유가 들어맞지 않는다.
- 태그 기준 · 저장 기준도 조회 시점 판정이고, 운영자가 조정한 이력(누가 · 언제 · 이전 값)을 남긴다(ADR-0055).

## 결정

> 부분 대체(첫 문장) — [ADR-0103](0103-big-judgement-on-storylines-and-the-storyline-milestone-right-after-event-clustering-takes-over-big-events.md). 지금 상태: [storyline Spec 큰 판정](../specs/storyline.md#큰-판정) storyline-R20
- **큰 사건 기준은 `event` 의 운영자 설정이다.** 지금 값 한 행과 추가 전용 이력(이전 값 · 새 값 · 행위자 종류 · 시각)을 둔다. 변경은 공개 운영 API 가 받는다 — 지금 값 행을 잠근 한 트랜잭션이라 동시 변경이 줄을 서고 이력의 이전 값이 맞는다. 같은 값이면 바꾸지 않고, 범위 밖이면 거부한다. HTTP · 화면은 `admin` 이 맡는다.
- **처음 값은 코드 상수이고 기동 때 지금 값이 없으면 넣는다.** 넣었을 때만 행위자 `SYSTEM` 의 이력 한 행을 남긴다. 처음 값은 측정 전 목표다.
- **미리보기는 제안 기준으로 기간 안 큰 사건을 같은 판정으로 낸다.** 아무것도 쓰지 않는다.
- **행위자 종류는 태그 기준과 같은 공개 enum 을 쓴다.** 사용자를 가리키지 않는다 — 계정 인증이 생기면 한 곳에 사용자 식별자를 더한다.
- 범위: 소스 기준 1 이상, 중요도 기준은 중요도 수준의 범위 안 · 소수 둘째 자리까지.

## 결과

- 운영자는 재기동 없이 기준을 바꾸고, 바꾸기 전에 그 기준의 큰 사건을 미리 보고, 이력으로 언제 무엇을 바꿨는지 되짚는다.
- 사건 기준(배정)은 설정, 큰 사건 기준은 운영자 설정으로 자리가 다르다 — 판정이 누적 상태인지가 갈랐다.
- 테이블 둘(지금 값 · 이력)과 기동 적재, 공개 운영 API 가 생긴다. 이력은 무기한 보존한다.
- 다이제스트가 큰 사건으로 넣은 기사가 어느 기준 때문이었는지는 이력의 시각으로 되짚는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 설정(환경 변수, 사건 배정 기준처럼) | 화면에서 바꿀 수 없고, 표본 검수로 값을 맞추는 동안 바꿀 때마다 재기동한다. 누가 · 언제 바꿨는지 남지 않는다 |
| 운영자 설정, 지금 값만 | 큰 사건으로 넣은 기사가 어느 기준 때문이었는지, 언제 기준이 바뀌었는지 되짚을 수 없다. 태그 기준과 감각이 다르다 |
| 처음 값을 마이그레이션에 넣는다 | 정본이 SQL 리터럴과 코드 상수 둘이 된다 |
| 행위자 종류를 `event` 에 따로 둔다 | 같은 종류의 두 번째 사본 — 계정 인증이 사용자 식별자를 더할 때 두 곳을 고친다 |
