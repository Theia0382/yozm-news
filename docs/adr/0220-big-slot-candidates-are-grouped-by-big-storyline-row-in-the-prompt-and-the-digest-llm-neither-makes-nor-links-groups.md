# ADR-0220: 큰 슬롯 후보는 큰 판정 행마다 묶어 프롬프트에 보이고, 다이제스트 LLM 은 묶음을 새로 만들거나 잇지 않는다

- 상태: 승인
- 날짜: 2026-11-18
- 근거: [이슈 #177](https://github.com/Theia0382/yozm-news/issues/177) — 수용 기준의 결정 "스토리라인 정보를 프롬프트에 넣을지 · 어떻게 넣을지". 구현 커밋 `c3d15ed`(선별의 행 위치 · 묶음 · 묶음 몫) · `011bcbe`(묶음 줄 · 지시)

## 맥락

- 큰 슬롯은 큰 판정 행(스토리라인)마다 기간 안 사건 여러 개의 대표 기사를 넣는다(ADR-0208). 후보 줄만 보내면 LLM 은 큰 슬롯 기사가 왜 들어왔는지, 어느 기사들이 한 흐름인지 모른다.
- 스토리라인은 모든 사용자가 공유하고 생성형 LLM 없이 잇는다 — 다이제스트 LLM 은 스토리라인을 열거나 잇지 않는다(ADR-0101).
- 스토리라인에는 생성된 제목이 없다 — 알아보는 이름은 대표 사건의 대표 기사 제목이다.

## 결정

- **큰 슬롯 후보를 큰 판정 행마다 묶어 사용자 구획에 싣는다** — 묶음마다 요청마다의 별칭(`S1` …), 이름(스토리라인 대표 사건의 대표 기사 제목 — 읽지 못하면 묶음 첫 기사의 제목), 묶음에 든 후보 별칭. 스토리라인 ID 는 싣지 않는다. 자르기로 기사가 모두 빠진 묶음은 싣지 않는다.
- **지시는 묶음을 이미 정해진 흐름으로 다루게 한다** — 새로 묶거나 서로 잇지 않고, 한 묶음은 되도록 주요 뉴스 하나로 쓴다. 출력 스키마에 스토리라인 칸을 더하지 않는다.
- **구독 후보의 스토리라인 소속과 사용자의 스토리라인 구독은 싣지 않는다.**
- **묶음 줄도 토큰 어림에 든다** — 묶음마다 이름 + 고정 몫(`CandidateCost.STORYLINE_OVERHEAD`). 값은 측정 전 목표다.

## 결과

- 한 큰 흐름의 기사들이 주요 뉴스 하나로 모이기 쉽다. 품질은 #182 에서 본다.
- 큰 스토리라인 묶음(대표 기사 제목)이 공급자로 간다 — 외부 전송 고지 항목이다.
- 큰 판정 목록의 행 꼴이 바뀌면(포함 나무마다 한 행 등) 묶음도 그 행을 따른다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 스토리라인 정보를 넣지 않는다 | 큰 슬롯 기사가 들어온 까닭을 LLM 이 모르고, 한 흐름의 사건 여러 개를 따로 쓸 수 있다 |
| 모든 후보의 스토리라인 소속과 구독 여부까지 | 후보마다 조회가 더 들고, 후보 선별이 쓰지 않는 개인 정보(스토리라인 구독)가 공급자로 간다 |
