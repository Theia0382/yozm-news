# ADR-0344: 개인정보 고지의 수집 · 외부 전송 항목은 고지 화면 파일이 정본이고, 수집 항목은 보존 정책 표의 사용자 데이터를 덮는다

- 상태: 승인
- 날짜: 2026-11-26
- 근거: [이슈 #268](https://github.com/Theia0382/yozm-news/issues/268) — 기점 `53e8edf~1`(`df1568f`)에서 `security.md` "개인정보"의 수집 항목과 고지 화면 파일의 목록을 견주니 항목이 달랐고(사용자 스토리라인 · 구독 제안 거절이 화면에 없음), 둘 다 보존 정책 표의 사용자 데이터 일부(화면 내 알림 · 복구 코드 · 로그인 실패 기록 · 세션)를 덮지 못했다. 화면 목록을 고친 커밋 `53e8edf`
- 관련: [ADR-0167](0167-collected-and-externally-sent-items-are-shown-on-one-notice-page-open-without-sign-in.md)(수집 · 외부 전송 항목을 고지 페이지 하나에 둔다 — 보충), [ADR-0212](0212-migrations-never-delete-user-data-or-the-shared-rows-and-ids-it-references-and-moved-data-is-checked-by-a-data-test.md)(보존 정책 표가 사용자 데이터 대상의 정본이다), [ADR-0034](0034-module-spec-as-public-interface-specification-and-docs-by-kind.md)(`security` 의 횡단 정책은 그 문서에 남는다 — 보충)

## 맥락

- 고지 항목이 두 곳에 있었다. `security.md` "개인정보"가 수집 항목과 외부 전송 항목을 목록으로 적었고, 고지 화면 파일 `frontend/src/features/privacy/privacyTexts.ts` 가 사용자에게 보이는 같은 목록을 가졌다.
- 화면 파일만 자기를 "고지 문구의 정본"이라 하고 근거로 `security.md` 를 들었다. `security.md` 는 화면 파일을 가리키지 않았다.
- 두 목록은 항목이 달랐고, 어느 쪽도 보존 정책 표의 사용자 데이터를 다 덮지 못했다. 사용자 데이터 대상의 정본은 이미 보존 정책 표다(ADR-0212).
- 문서 위계에서 3층 코드는 클래스 내부 상세의 정본이다. 정책 목록의 정본을 코드에 두려면 위계의 예외로 적어야 한다.

## 결정

- **수집 · 외부 전송 항목의 목록과 문구는 고지 화면 파일 `frontend/src/features/privacy/privacyTexts.ts` 가 정본이다.** 사용자가 실제로 읽는 것이 정본이고, 목록은 한 곳에만 있다.
- **수집 항목은 보존 정책 표의 사용자 데이터를 빠짐없이 덮는다.** 사용자 데이터 테이블을 더하는 작업은 보존 정책 표의 행과 고지 항목을 함께 더한다.
- **외부 전송 항목은 각 생성의 입력을 따른다.** 입력을 바꾸는 작업은 고지 항목을 함께 고친다.
- **`security.md` 는 고지의 원칙과 이 파일의 위치만 갖는다.** IP 다이제스트를 IP 보관으로 고지하는 것, 클릭 · 열람을 추적하지 않는 것, 받는 쪽이 쓸 모델의 공급자인 것이 원칙이다.
- 문서 위계의 예외로 [`docs/README.md` §1](../README.md#1-문서-위계)에 적는다.

## 결과

- 고지 항목을 바꾸려면 코드 파일을 고친다. 문서만 읽는 사람은 목록을 화면 파일에서 본다.
- 목록이 하나라 문서와 화면이 어긋나지 않는다. 대상이 빠졌는지는 보존 정책 표와 견주어 리뷰가 본다. 자동 대조는 없다.
- 고지 페이지의 시험이 목록을 순서 · 문구 그대로 단언해, 항목을 바꾸면 시험도 함께 바뀐다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| `security.md` 목록이 정본이고 화면이 따른다 | 같은 목록이 문서와 코드에 둘 남고, 어긋남을 막는 장치가 없다. 이번 어긋남이 그 결과다 |
