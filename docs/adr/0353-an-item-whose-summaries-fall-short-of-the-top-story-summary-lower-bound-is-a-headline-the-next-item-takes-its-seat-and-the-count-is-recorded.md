# ADR-0353: 요약문이 주요 뉴스 요약 하한보다 짧은 항목은 헤드라인이고, 큰 화제 밖 빈자리는 다음 항목이 채우며, 그 수를 다이제스트 행에 남긴다

- 상태: 승인
- 날짜: 2026-11-27
- 근거: [이슈 #232](https://github.com/Theia0382/yozm-news/issues/232) — 측정 인스턴스의 다이제스트에서 입력 자체에 대한 서술("확인된 사실은 제한적이다" 꼴)과 재료보다 길게 쓴 요약이 기사 하나짜리 주요 뉴스에 몰렸다. 그런 항목은 RSS 요약문이 사용자의 주요 뉴스 요약 하한보다 짧았고, 요약 길이 단계가 길수록 더 많았다. 헤드라인의 짧은 코멘트에는 같은 서술이 없었다. 코드 규칙, 요약 하한을 기준으로, 큰 화제 항목 포함, 빈자리 채움, 다이제스트 행의 기록, 요약 길이 도움말의 안내를 골랐다. 구현 커밋 `172c7a2`(가르기) · `5fa088c`(기록) · `b4b012d`(화면 도움말)

## 맥락

- 주요 뉴스 · 헤드라인은 코드가 가르고([ADR-0262](0262-chosen-events-are-grouped-into-items-by-containment-tree-top-code-splits-top-stories-and-headlines-the-llm-writes-per-item-and-an-item-has-one-badge.md)), LLM 은 주요 뉴스 항목마다 사용자의 요약 길이 단계에 맞춘 길이 기준(하한 · 상한 — [ADR-0223](0223-the-digest-summary-length-is-a-user-setting-in-the-digest-volume-section.md))으로 요약을 쓴다. 지시는 "기사가 담은 사실이 적으면 길이 기준보다 짧게 써도 된다"를 허용한다.
- 생성에 넘기는 재료는 표본 기사의 제목과 RSS 요약문이다. 소스마다 RSS 요약문의 길이가 크게 다르다 — 사진 설명과 첫 문장 일부에서 끊는 소스, 약 200 자에서 끊는 소스, 본문 앞부분을 길게 싣는 소스가 있다.
- 요약문이 요약 하한보다 짧은 항목이 주요 뉴스가 되면, 모델은 기사에 없는 해석으로 늘려 쓰거나 입력 자체에 대한 말로 채웠다. 짧게 써도 된다는 허용만으로는 막지 못했다. 같은 항목이 헤드라인이면 짧은 코멘트라 그런 말이 나오지 않았다.
- 기사 수 · 형식으로는 이 항목을 가를 수 없다 — 같은 형식 · 비슷한 요약문 길이의 의견 기사 하나가 잘 쓰이기도 했다. 갈린 것은 재료의 양과 요구 길이의 차이였다.

## 결정

- **항목의 요약문 길이가 사용자의 주요 뉴스 요약 하한보다 짧으면 그 항목은 주요 뉴스가 아니라 헤드라인이다.** 항목의 요약문 길이는 생성에 넘기는 표본 기사 RSS 요약문의 코드 포인트 합이다. 제목은 세지 않고, 요약문이 없는 기사는 0 이다. 하한은 그 사용자의 요약 길이 단계에서 주요 뉴스 요약 길이 기준의 하한이고 새 상수를 두지 않는다. 하한과 같으면 주요 뉴스다.
- **큰 화제 항목에도 같다** — 큰 판정 나무의 항목도 요약문 길이가 하한보다 짧으면 헤드라인이다. 헤드라인에서도 선정 이유 배지(큰 화제)는 그대로다.
- **큰 화제 밖 주요 뉴스 다섯 자리는 하한 이상인 항목이 순위대로 채운다.** 채울 항목이 모자라면 주요 뉴스가 그만큼 준다. 큰 화제 항목이 헤드라인이 된 자리는 다른 항목이 채우지 않는다.
- **그 항목은 처음부터 헤드라인 항목이다** — LLM 은 다른 헤드라인과 같이 제목과 짧은 코멘트를 쓴다. 출력에서 빠진 항목([ADR-0270](0270-an-item-missing-from-the-output-is-asked-once-more-and-then-kept-as-a-headline-and-the-counts-are-recorded.md))이 아니고, 출력 계약([ADR-0269](0269-the-digest-output-keys-top-stories-by-item-alias-as-required-fields-and-lists-headlines-as-elements.md))은 그대로라 공급자 스키마 한도를 다시 잴 일이 없다.
- **요약문이 짧은 항목 수를 다이제스트 행에 남긴다** — 하한 이상이었으면 주요 뉴스가 되었을 항목의 수다. 큰 화제 항목 가운데 그런 항목과, 큰 화제 밖 자리가 남아 있는 동안 순위로 만난 그런 항목을 센다. 입력에서 정해지는 값이라 시작할 때 후보 수와 함께 적고 후보 수를 넘지 않는다.
- **관심 설정의 요약 길이 도움말이 이 효과를 알린다** — 기사 요약문이 고른 요약 길이보다 짧은 소식은 헤드라인이라, 길게 할수록 주요 뉴스가 줄 수 있다.

## 결과

- 요약문이 요구 길이에 못 미치는 항목에는 LLM 이 요약을 쓰지 않는다. 그런 항목의 늘려 쓰기 · 입력에 대한 서술이 주요 뉴스에서 줄 것으로 본다 — 측정 전 기대다.
- 요약 길이 단계가 주요 뉴스 구성에도 영향을 준다 — 길수록 주요 뉴스가 줄 수 있고, 같은 날 같은 흐름이어도 사용자마다 주요 뉴스가 다르다. 길이 기준의 하한을 고치면 주요 뉴스로 고르는 항목이 바뀐다.
- 기준은 소스의 RSS 요약문 길이 관행과 맞물린다 — 요약문을 약 200 자에서 끊는 소스는 "보통" 하한 200 의 양쪽에 걸린다. 규칙은 소스를 모르고 요약문 길이만 본다.
- 요약문은 하한 이상이지만 내용이 빈약한 항목(논지 중간에서 끊긴 요약문 등)은 이 규칙이 거르지 않는다.
- 큰 화제 항목이 헤드라인이 되면 그날 큰 화제가 주요 뉴스에 없을 수 있다.
- 모든 항목이 하한에 못 미치면 주요 뉴스가 없는 다이제스트다. 출력 계약은 빈 주요 뉴스 칸을 이미 정했고 화면은 주요 뉴스 구획을 그리지 않는다.
- 이 칸이 생기기 전에 시작한 다이제스트 행은 요약문이 짧은 항목 수가 비어 있다(기록 전).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| LLM 이 출력 계약의 칸(내릴 주요 뉴스 항목 별칭의 배열)으로 내린다 | 재료의 양으로 갈리는 대부분까지 모델 판단에 맡겨 결과가 정해지지 않고, 빈 배열이 언제나 유효해 쓰지 않을 수 있다. 출력 계약을 바꿔 공급자 스키마 한도를 다시 재야 한다. 빈자리를 채우려면 예비 항목의 요약 출력이 든다 |
| 코드 규칙에 LLM 의 내림을 더한다 | LLM 쪽 비용을 모두 지는데 규칙 밖에 남는 것이 작다 |
| 그대로 둔다(지시 규칙만) | 짧게 써도 된다는 허용에도 늘려 쓰기와 입력에 대한 서술이 남았다 |
| 기사 수 · 형식(의견 기사 등)으로 가른다 | 같은 형식 · 비슷한 요약문 길이의 항목이 잘 쓰이기도 했다. 형식 키는 운영자의 태그 체계 값이라 코드가 특정 키에 묶인다 |
| 요약 길이 단계와 무관한 고정 문턱 | 요구 길이가 긴 단계의 늘려 쓰기를 놓치고, 값의 근거가 표본 분포뿐이다 |
| 큰 화제 항목은 언제나 주요 뉴스 | 늘려 쓰기는 항목이 어디서 왔는지와 무관하다. 큰 화제라는 표시는 헤드라인의 배지가 남긴다 |
| 빈자리를 채우지 않는다 | 다음 항목이 추가 출력 없이 채울 수 있는데 주요 뉴스가 준다 |
| 기록 없이 로그만 | 저장된 다이제스트로는 그 수를 다시 셀 수 없다 — 두 목록을 합친 항목 순위와 설정 이력이 남지 않는다. 측정 · 운영에서 SQL 로 센다 |
| 수를 `READY` 에만 둔다(빠진 항목 기록과 같은 꼴) | 출력이 아니라 입력에서 정해지는 값이라 실패한 생성에도 그 입력의 성질로 남긴다 |
| 요약 길이 단계가 주요 뉴스 수를 직접 정한다 | 이 결정은 개수가 아니라 주요 뉴스가 되는 자격을 정한다 — 개수를 고르는 손잡이는 여전히 없다 |
