# ADR-0206: OpenRouter 로 보내는 출력 스키마는 두 공급자 맞춤을 함께 만족하고, 값 목록이 있는 선택 속성은 타입 없이 null 을 받는다

- 상태: 승인
- 날짜: 2026-11-17
- 근거: [이슈 #192](https://github.com/Theia0382/yozm-news/issues/192) — 실제 호출(2026-11-17): 값 목록과 `"null"` 을 더한 타입 배열을 함께 둔 마디를 Anthropic 계열이 OpenRouter 를 거쳐 400 으로 거절(`Enum value … does not match declared type`), 타입 없는 값 목록 · 값 목록 없는 `["string","null"]` 은 두 계열 모두 받음, 고친 맞춤으로 두 계열의 스키마 강제 생성 정상. 리드 결정(교집합 · 값 목록 꼴). 구현 `2669322` · `26b15fa`
- 관련: [ADR-0199](0199-generation-requests-carry-only-the-tasks-own-inputs-and-the-gateway-maps-them-to-each-provider.md)(보충 — 새 공급자의 스키마 맞춤)

## 맥락

- 관문은 표준 JSON Schema 를 받아 공급자가 받는 꼴로 맞춘다(ADR-0199). OpenAI 엄격 모드는 모든 속성의 `required` 를 요구하고(선택 속성은 null 을 받게 흉내), Anthropic 은 `maxItems` · `minItems` 를 받지 않고 `required` 를 그대로 받는다 — 두 맞춤은 서로의 규칙을 만족하지 않는다.
- OpenRouter 는 한 공급자 안에 여러 회사의 모델을 두고 그 회사나 호스팅 공급자로 옮겨 보낸다.
- 다이제스트 출력 스키마에는 값 목록이 없고, null 을 받는 속성은 `["string","null"]` 꼴이다.

## 결정

- **OpenRouter 로 보내는 스키마는 모델에 상관없이 하나의 맞춤이다** — 남기는 키워드는 두 맞춤의 허용 키워드 교집합, 모든 객체에 `additionalProperties: false`, 모든 속성을 `required` 에 넣고 원래 선택이던 속성은 null 을 받게 한다.
- **값 목록이 있는 선택 속성은 타입을 지우고 값 목록에 null 을 더한다.** 값 목록이 없는 선택 속성은 타입에 `"null"` 을 더한다.
- 모델 ID 로 맞춤을 고르지 않는다.

규칙은 [llm Spec](../specs/llm.md#생성-호출) llm-R21 에 있다.

## 결과

- 운영자 파일의 모델 ID 꼴에 기대는 규칙이 없다.
- OpenAI 계열에서도 배열 개수 제약이 빠진다 — 부르는 쪽의 읽기 상한이 지킨다.
- 타입을 지운 값 목록은 공급자가 값과 타입이 맞는지 막지 않는다 — 값 목록이 곧 허용 값이라 뜻은 같다.
- 실제로 확인한 모델은 두 계열에서 하나씩(`openai/gpt-6-luna` · `anthropic/claude-haiku-5.5`)이다. 다른 모델 · 다른 호스팅 공급자로 라우팅될 때의 수락은 재지 않았다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 모델 ID 접두(`openai/` · `anthropic/`)로 그 공급자의 맞춤을 고른다 | 모델 ID 의 꼴이 맞춤을 정하는 숨은 규칙이 되고, 꼴이 바뀌면 조용히 다른 맞춤이 간다 |
| 허용 모델 목록 파일에 모델마다 맞춤 칸을 둔다 | 목록 파일 형식과 공개 타입이 바뀌고 운영자가 알아야 할 것이 는다 |
| 값 목록이 있는 선택 속성도 타입에 `"null"` 을 더한다(OpenAI 엄격 맞춤과 같은 꼴) | Anthropic 계열이 400 으로 거절한다(실측) |
| 그대로 두고 값 목록 꼴의 제약만 문서에 적는다 | 지금 다이제스트에는 영향이 없지만, 유효한 스키마 하나가 한 계열에서 실패하는 맞춤이 남는다 |
