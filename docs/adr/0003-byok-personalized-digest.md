# ADR-0003: 사용자 BYOK LLM으로 개인화 종합 다이제스트 생성

- 상태: 승인
- 날짜: 2026-10-25

## 맥락

- 운영자가 생성형 LLM 비용을 부담하기 어렵다.
- 핵심 가치는 기사 목록이나 기사별 요약이 아니라, 사용자 관심에 맞춰 여러 기사를 종합한 요약이다.
- 본문이 궁금하면 원문 링크로 보면 된다.

## 결정

- 사용자가 자기 LLM API 키를 등록한다(BYOK). 다이제스트 생성 비용은 사용자 키로 나간다.
- 다이제스트는 **(사용자, 기간) 단위로 LLM을 한 번 호출해** 만든다. 입력은 공유 평가로 고른 후보 기사 목록과 사용자 관심사다. 출력은 개요, 여러 기사를 묶은 주요 이슈, 추가 헤드라인이다.
- 기사별 요약은 만들지 않는다. 따라서 사용자 간에 공유되는 생성물도 없다.
- **LLM 키가 없는 사용자에게는 키 등록 페이지만 보여준다.**
- 공급자 차이는 Spring AI로 흡수하고, 사용자 키로 요청마다 클라이언트를 만든다.
- 키는 envelope encryption으로 보관한다 ([06-security.md](../06-security.md)).

## 결과

- 운영자의 생성형 LLM 비용이 0이다.
- 가입 직후 바로 체험할 수 없다. 키 발급이라는 진입 장벽이 생긴다. 저가 모델 기반 기본 티어는 나중에 검토한다.
- 사용자 키의 유효성, 한도, 요금 부족이 다이제스트 실패 원인이 된다. 상태를 명확히 보여주는 UI가 필요하다.
- 키 보관이 보안상 가장 중요한 자산이 된다.
- 같은 사건을 다룬 여러 기사를 LLM이 하나의 이슈로 묶을 수 있다 ([ADR-0007](0007-defer-event-clustering.md)).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 운영자 부담 LLM | 비용을 감당할 수 없다 |
| 기사별 요약 후 공유 | 개인화된 종합이라는 핵심 가치와 맞지 않는다. 다른 사람의 키로 만든 결과를 공유하는 정책 문제도 생긴다 |
| 키 없는 사용자에게 Jev 결과 기반 헤드라인 목록 제공 | 사용자가 보류. 기본 티어와 함께 나중에 결정한다 |
