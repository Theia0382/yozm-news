# ADR-0007: 같은 사건 묶기는 v1에서 LLM 종합에 맡김

- 상태: 대체됨([ADR-0025](0025-long-term-personal-news-history-in-v1.md))
- 날짜: 2026-10-25

## 맥락

- 기획 초안의 "비슷한 주제의 기사 분류"와 "같은 사건을 다루는 중복 기사 처리"는 카테고리 분류와 다른 문제다. Jev는 정해진 선택지로 분류할 뿐 기사끼리 묶지 않는다.
- 묶으려면 임베딩 기반 클러스터링(pgvector 등)이 필요하다. 임베딩 비용과 운영 복잡도가 생긴다.
- 다이제스트는 사용자별로 LLM이 후보 전체를 한 번에 보고 종합한다.

## 결정 (제안)

- v1에서는 별도 클러스터링을 하지 않는다. 다이제스트 생성 프롬프트에서 같은 사건을 다룬 기사를 주요 이슈 하나로 묶고 `refs`로 여러 기사를 인용하게 한다.
- 중복 제거는 URL과 같은 소스 내 제목(L1·L2)까지만 한다.

## 결과

- 구성 요소가 늘지 않는다.
- 후보에 같은 사건 기사가 많으면 토큰이 낭비되고, 다른 기사가 후보 상한에서 밀려날 수 있다.
- 사용자 간에 "같은 사건" 판단을 공유하지 않는다. 사건 추적이나 장기 변화 추적 같은 확장 기능에는 결국 클러스터링이 필요하다.

## 재검토 조건

- 후보 중 같은 사건 기사 비율이 높아 다이제스트 품질이나 토큰 효율이 눈에 띄게 떨어질 때
- 사건 추적이나 주간 트렌드 기능을 시작할 때

## 검토한 대안

| 대안 | 보류 이유 |
|---|---|
| 외부 임베딩 API + pgvector | 운영자 비용이 생기고 구성이 늘어난다 |
| 로컬 다국어 임베딩 모델(ONNX) + pgvector | API 비용은 없지만 worker 메모리와 CPU 부담이 생긴다. 재검토 시 1순위 |
