# ADR-0092: 임베더 실패는 일시 · 입력 거부 · 사용 불가 셋으로 나누고, 입력 거부는 기사 하나씩 다시 불러 가린 뒤 거부 수가 상한에 이르면 사건 묶기 대기에서 뺀다

- 상태: 승인
- 날짜: 2026-11-07
- 근거: [이슈 #95](https://github.com/Theia0382/yozm-news/issues/95) — 운영 임베더(로컬 · 외부)의 실패 원천과 지금 회차의 처리(어떤 실패든 묶음 전체를 다음 회차가 다시 시도)를 확인하고 리드와 정함
- 관련: [ADR-0074](0074-article-features-built-by-event-intake-queue-job-and-skipped-without-an-embedder.md)(결정 절 둘째 항목의 끝 문장 "임베더가 실패하거나 결과가 어긋나면 점유를 풀고 회차를 끝낸다"를 입력 거부에 대해 부분 대체한다, 결과 절 넷째 항목의 미룬 사항을 정한다 — 후속 기록), [ADR-0058](0058-evaluator-failures-in-three-kinds-and-unavailable-evaluator-skips-article-retries.md)(평가기 포트의 같은 세 갈래 모양 — 그대로 따른다), [ADR-0090](0090-article-embedding-defaults-to-an-in-app-local-model-with-an-openai-compatible-api-by-setting.md)(운영 임베더)

## 맥락

- 표현 회차는 대기에서 넣은 순서로 최대 64건을 점유해 임베더를 한 번 부른다. 임베더가 예외를 던지거나 결과가 어긋나면 점유를 풀고 회차를 끝낸다 — 다음 회차가 같은 순서로 다시 점유한다([ADR-0074](0074-article-features-built-by-event-intake-queue-job-and-skipped-without-an-embedder.md)). 그래서 한 묶음이 계속 실패하면 그 뒤 기사도 처리되지 않는다.
- 운영 임베더의 실패는 원천이 다르다.
  - 외부 방식
    - 연결 · 마감 · 요청 제한 · 서버 오류는 시간이 지나면 풀린다
    - 키 · 권한 · 모델 없음 · 읽을 수 없는 응답은 임베더 자체를 쓸 수 없다
    - 입력 거부(400 류)는 같은 입력을 다시 보내도 같다. 외부 API 의 거부 응답은 묶음의 어느 입력 때문인지 알려 주지 않는다
  - 로컬 방식: 토크나이저가 어떤 문자열이든 나누고 512 토큰에서 자르며, 표현 텍스트는 공백 제목을 이미 거부한다. 추론 실패는 사실상 모델 · 런타임 쪽 결함이다
- 평가기 포트는 예상한 실패를 결과 값으로 돌려주고 일시 · 기사 거부 · 사용 불가 셋으로 나눈다([ADR-0058](0058-evaluator-failures-in-three-kinds-and-unavailable-evaluator-skips-article-retries.md)). 운영자는 같은 모양의 로그를 읽는다.

## 결정

- **포트는 예상한 실패를 결과 값으로 돌려준다.** 결과는 성공(텍스트마다 벡터) · 실패의 닫힌 종류다. 실패는 갈래와 운영자용 문구(비밀 값 · 응답 본문 · 입력 텍스트 없음)를 갖는다. 예상 못한 예외는 구현 결함이다.
- **갈래는 셋이다.**
  - 일시 — 점유를 풀고 회차를 끝낸다. 거부 수는 그대로이고, 다음 회차가 같은 묶음을 다시 시도한다
  - 임베더 사용 불가 — 일시와 같다
  - 입력 거부 — 회차를 끝내지 않는다. 묶음이 거부되면 기사 하나씩 다시 불러 거부된 기사만 가린다. 그 기사의 거부 수를 대기 행에 하나 올리고 점유를 푼다. 거부 수가 상한에 이르면 대기에서 빼고 경고를 남긴다
- **기사 하나씩 다시 부르는 도중 일시 · 사용 불가 · 예외 · 결과 어긋남이 나면 그 기사부터 남은 점유를 풀고 회차를 끝낸다.**
- **로컬 구현은 입력 거부를 내지 않는다.** 추론 · 토크나이저 실패는 사용 불가다.
- 오류 원인을 갈래에 대응시키는 것은 구현이 한다.

## 결과

- 한 기사 때문에 대기 전체가 멈추지 않는다. 거부 수의 상한으로 일시적 오분류에도 기사를 바로 잃지 않는다.
- 상한에 이르러 뺀 기사는 표현 · 배정 · 사건이 없다. 운영자 채우기가 그 기사를 거부 수 0 으로 다시 넣을 수 있다.
- 사건 묶기 대기에 거부 수 열이 생긴다.
- 키 오류 · 서버 장애는 기사 시도 수를 쓰지 않아 정상 기사가 빠지지 않는다. 대신 풀릴 때까지 매 회차 같은 묶음을 다시 부른다.
- 로컬 런타임이 망가지면 회차가 멈출 뿐 기사가 빠지지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 지금 그대로 — 어떤 실패든 회차를 멈추고 다음 회차가 묶음 전체를 다시 시도한다 | 다시 보내도 같은 입력 거부가 대기 전체를 영원히 막는다. 키 오류와 일시 오류를 로그로만 가른다 |
| 갈래를 나누지 않고, 묶음이 실패하면 기사 하나씩 다시 불러 실패한 기사만 세어 상한 뒤 뺀다 | 키 오류 · 서버 장애 때도 기사마다 시도 수를 써 상한 뒤 정상 기사까지 빠진다 |
| 묶음을 반으로 나눠 거부 기사를 찾는다 | 호출 수는 줄지만 거부가 드물고 묶음이 64 이하라 단순함이 낫다 |
| 거부 수를 메모리 · 로그에만 둔다 | 재기동 · 다른 회차에 이어지지 않아 상한이 성립하지 않는다 |
