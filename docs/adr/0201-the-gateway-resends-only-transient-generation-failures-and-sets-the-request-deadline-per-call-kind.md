# ADR-0201: 생성 호출은 관문이 일시 장애만 다시 보내고, 요청 하나의 마감은 관문이 호출 종류마다 정한다

- 상태: 승인
- 날짜: 2026-11-17
- 근거: [이슈 #175](https://github.com/Theia0382/yozm-news/issues/175) — 전송의 마감 결선과 Spring AI 의 요청 선택지 경로를 대조하고, 생성 마감 값은 리드가 정함(180초). 구현 `dba289d` · `9ddad52` · `2e6b35e`
- 관련: [ADR-0149](0149-llm-calls-use-spring-ai-2-without-the-starter-and-build-sdk-clients-with-explicit-address-key-and-log-level-and-close-them.md)(보충 — "SDK 의 자동 재시도를 쓸지와 마감은 호출마다 이 모듈이 정해 넘긴다"), [ADR-0150](0150-user-keys-travel-over-an-own-jdk-transport-for-the-sdks-without-redirects-or-proxy-and-with-a-response-body-cap.md)(전송 — 스트리밍 없이 응답 전체를 받는다), [ADR-0154](0154-key-validation-lists-models-and-failure-kinds-are-sorted-by-one-rule-per-provider-reading-the-error-kind.md)(검증은 짧은 마감으로 한 번만 — 그대로)

## 맥락

- 전송의 요청 마감은 키 검증에 맞춘 15초 하나였다. 생성 호출은 응답 전체가 만들어질 때까지 요청이 열려 있어(스트리밍 없음) 수십 초에서 분 단위가 걸릴 수 있다.
- Spring AI 의 호출 선택지에 마감 · 재시도가 있지만 SDK 의 요청 선택지로 가고, 이 모듈의 전송은 그 선택지를 읽지 않는다.
- 일시 장애(요청 제한 · 서버 오류 · 연결)는 시간이 지나면 풀릴 수 있다. 공급자가 기다릴 시간(`retry-after`)을 주면 그 값은 관문 안에서만 읽힌다. 생성 호출을 부르는 모듈은 둘(다이제스트 · 변화 리포트)이다.
- 응답 마감을 넘긴 요청은 공급자 쪽에서 생성이 끝나 과금됐을 수 있다.

## 결정

- **요청 하나의 마감은 관문이 호출 종류마다 정해 클라이언트를 열 때 넘긴다** — 키 검증 15초, 생성 호출 180초. 생성 마감은 측정 전의 잠정값이다.
- **생성 호출은 관문이 일시 장애만 다시 보낸다.** 응답 마감을 넘긴 실패는 다시 보내지 않는다. 한 호출에서 많아야 네 번 보낸다(다시 보내기 셋). 공급자가 준 기다릴 시간(60초까지)을 따르고, 없으면 2 · 4 · 8초를 기다린다. 무효 · 권한 · 한도 소진 · 예상 밖의 답은 다시 보내지 않는다.
- SDK 의 자동 재시도는 0 그대로다. 키 검증은 다시 시도하지 않는다.

규칙은 [llm Spec](../specs/llm.md#키-검증) llm-R7 · [생성 호출](../specs/llm.md#생성-호출) llm-R20 에 있다.

## 결과

- 다시 보내기 정책이 한 곳이다 — 부르는 모듈은 다시 보낸 뒤의 결과를 받는다.
- 한 생성 호출은 마감과 기다림을 합쳐 십여 분까지 걸릴 수 있다 — 화면 요청 안에서 부르지 않고 작업 역할에서 부른다. 작업 스레드를 그만큼 쥔다.
- 마감 초과를 다시 보내지 않아 과금이 겹치지 않는다. 공급자가 잠깐 느렸던 경우는 다음 생성 일정이 잇는다.
- 마감 · 간격 · 횟수는 재지 않은 값이다 — 허용 모델이 다이제스트 한 편을 쓰는 시간과 일시 장애가 풀리는 시간을 재서 고친다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 관문은 한 번만 보내고 부르는 쪽이 다시 보낸다 | 다시 보내기 정책이 부르는 모듈마다 생기고, `retry-after` 를 결과로 내보내야 한다 |
| 다시 보낼 횟수를 요청이 정한다 | 정책 값이 부르는 쪽마다 흩어진다. 지금 부르는 쪽 둘 다 작업 역할이라 가를 까닭이 없다 |
| 마감 초과도 다시 보낸다 | 한 호출이 마감 × 네 번까지 길어지고 과금이 겹친다 |
| 마감 초과는 한 번만 다시 보낸다 | 마감으로 끊긴 요청의 과금이 두 번까지 겹치고, 규칙이 하나 는다 |
| 생성 마감 60초 · 120초 · 300초 | 60초는 긴 응답을 끊어 과금만 남기고, 300초는 멈춘 요청이 스레드를 오래 쥔다. 120초 · 180초 가운데 리드가 180초를 골랐다 |
| 마감을 Spring AI 선택지 → SDK 요청 선택지로 넘긴다 | Spring AI 가 선택지를 옮기는지에 기대고, 검증 경로는 SDK 의 기본 마감으로 떨어질 수 있다 |
