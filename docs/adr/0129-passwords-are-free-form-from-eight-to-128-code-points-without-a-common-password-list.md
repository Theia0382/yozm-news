# ADR-0129: 비밀번호는 8 ~ 128 코드 포인트의 자유형이고 흔한 비밀번호 목록과 대조하지 않는다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #145](https://github.com/Theia0382/yozm-news/issues/145) — 사용자 결정. 공개 목록(SecLists `Common-Credentials`)을 10 ~ 128자로 걸러 소문자로 접고 중복을 뺀 크기를 잰 결과(상위 10만 → 9,084 항목, 상위 100만 → 142,518 항목)를 놓고 정했다
- 관련: [ADR-0009](0009-authentication-google-and-local.md)(Argon2id 해시 — 그대로)

## 맥락

- 설계 문서는 최소 10자 · 최대 128자 · 문자 종류 강제 없음 · 흔한 비밀번호 목록 대조를 정해 두었다.
- 목록 대조는 목록의 출처 · 크기 · 보관 위치를 정해야 한다. 최소 길이가 길수록 공개 목록에서 대조할 항목이 크게 준다. 외부 조회(Have I Been Pwned)는 셀프 호스팅 · 오프라인 인스턴스에서 성립하지 않는다.
- 한 인스턴스는 운영자가 허락한 몇 사람이 쓴다.

## 결정

- **비밀번호는 NFKC 로 정규화한 뒤 코드 포인트로 8 ~ 128 자다.** 문자 종류를 강제하지 않는다.
- **흔한 비밀번호 목록과 대조하지 않는다.**
- 최대 128 자는 해시 비용(입력 길이에 비례)의 상한이다 — 로그인에서 넘는 비밀번호는 해시하지 않고 실패로 센다.

## 결과

- 목록 파일을 저장소 · 이미지에 두지 않고, 갱신 · 출처 관리가 없다.
- 흔한 비밀번호도 8 자 이상이면 받는다. 대입 방어는 로그인 실패 지연([ADR-0130](0130-sign-in-failure-delays-count-per-digest-of-the-submitted-normalized-email-regardless-of-account.md))과 요청 제한이 맡는다.
- 규칙의 정본은 [user Spec](../specs/user.md#계정과-자격) user-R14 다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 최소 10자 + 공개 목록 상위 100만을 걸러 저장소에 둠 | 사용자 결정 — 최소 8자 자유형, 목록 없음 |
| 최소 10자 + 공개 목록 상위 10만 | 10자 이상 항목이 1만 개도 안 돼 대조하는 범위가 작다 |
| 외부 조회(Have I Been Pwned 범위 조회) | 외부 호출이 필요해 셀프 호스팅 · 오프라인에서 성립하지 않는다 |
