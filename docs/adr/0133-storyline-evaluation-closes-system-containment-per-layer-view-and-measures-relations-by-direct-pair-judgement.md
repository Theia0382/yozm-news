# ADR-0133: 스토리라인 평가는 시스템 쪽도 포함을 닫아 층 보기마다 견주고, 관계 품질은 시스템 스토리라인 쌍의 직접 판정으로 잰다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #122](https://github.com/Theia0382/yozm-news/issues/122) — 평가 세트의 정답 관계와 지표의 셈을 조사하고, 시스템 스토리라인 쌍을 직접 판정해 리드와 정함
- 관련: [ADR-0110](0110-storyline-evaluation-labels-system-events-of-a-fixed-dump-and-measures-overlapping-clusters-from-random-seed-events.md)(층 보기와 관계 지표 — 보충), [ADR-0131](0131-storyline-relations-are-explicit-links-with-containment-as-a-single-parent-tree-gathered-at-query-time.md)(시스템의 포함 — 조회 때 따라 모은다), [ADR-0132](0132-storyline-relations-are-judged-by-jev-on-candidate-pairs-and-linked-only-above-a-probability-threshold.md)(관계를 판정하는 방법과 포함 · 이어짐의 경계), [ADR-0096](0096-instance-bound-evaluation-data-kept-out-of-the-public-repository-and-defaults-cite-only-the-evaluation-set.md)(평가 데이터는 공개 저장소 밖)

## 맥락

- 스토리라인 평가 도구는 결과 파일의 스토리라인(기사 ID)과 관계를 받아 정답 라벨과 견준다. 정답 쪽은 포함을 따라 위로 닫아 세 보기(모든 층 · 최상위 · 말단)로 재고, 시스템 쪽은 닫지 않고 보기마다 같게 쓴다([ADR-0110](0110-storyline-evaluation-labels-system-events-of-a-fixed-dump-and-measures-overlapping-clusters-from-random-seed-events.md)).
- 확장 B-cubed 의 정밀도는 기사 쌍마다 함께하는 시스템 스토리라인 수와 정답 스토리라인 수를 견준다. 결과 파일이 하위의 기사를 상위에도 담으면, 하위 안의 쌍은 시스템 스토리라인 둘을 함께해 정답이 단층일 때 맞는 쌍도 깎인다.
- 관계 지표는 시스템 스토리라인을 정답 스토리라인 하나에 대응시켜 견준다. 시스템 스토리라인이 정답보다 좁아 정답 하나에 여럿이 대응되면, 그 사이의 포함은 양 끝이 같은 정답이 되어 틀림으로 센다.
- 평가 세트의 정답 관계는 몇 건뿐이다. 관계는 기간이 길수록 늘고, 평가 세트는 며칠치다.
- 시스템의 포함은 직접 소속을 저장하고 조회 때 따라 모은다([ADR-0131](0131-storyline-relations-are-explicit-links-with-containment-as-a-single-parent-tree-gathered-at-query-time.md)).

## 결정

- **결과 파일의 스토리라인은 직접 가진 기사만 담고, 포함은 `relations` 로 낸다.** 닫은 꼴에서는 직접 소속을 되살릴 수 없다.
- **도구가 시스템 쪽도 포함을 따라 위로 닫고, 정답과 같은 규칙으로 보기마다 좁혀 견준다.** 포함이 없는 결과 파일은 값이 그대로다. 결과 파일의 포함이 순환하면 거부한다.
- **양 끝이 같은 정답 스토리라인에 대응된 시스템 관계는 관계 지표의 판정에서 빼고 수를 남긴다.** 끝이 대응되지 않은 관계와 같은 처분이다.
- **관계 품질은 시스템 스토리라인 쌍을 직접 판정해 잰다.** 후보 쌍마다 두 스토리라인의 사건을 보고 포함(방향) · 이어짐(방향) · 한 사안이 갈라진 것 · 같은 상위 아래의 나란한 흐름 · 무관 · 주제 묶음 · 모름 가운데 하나를 적는다. 방법이 맺은 관계가 그 판정과 같은 종류 · 방향인지로 정밀도를, 판정된 관계 가운데 맺은 것으로 재현율을 센다. 기준은 [스토리라인 평가하기](../operations/storyline-evaluation.md)에 있다.
- **쌍 판정 세트는 인스턴스의 데이터다.** 공개 저장소에 두지 않고, 그 셈은 저장소의 도구가 하지 않는다([ADR-0096](0096-instance-bound-evaluation-data-kept-out-of-the-public-repository-and-defaults-cite-only-the-evaluation-set.md)).
- **라벨 기준은 그대로다.** 쌍 판정의 기준은 정답 스토리라인을 라벨에 적는 규칙이 아니다.

## 결과

- 포함이 잇기 지표에 주는 영향을 보기마다 따로 읽는다 — 최상위 보기는 큰 흐름끼리, 말단 보기는 갈래끼리 견준다. 모든 층 보기에서는 정답이 단층인 동안 하위 안의 쌍이 깎인다.
- 결과 기록의 칸이 늘어 형식 판이 오른다. 결과 파일의 형식 판은 그대로다.
- 쌍 판정은 스토리라인 ID 에 붙는다. 잇기 결과가 달라지면 쌍을 다시 대어야 하고, 후보 범위 밖의 관계는 세지 못한다.
- 판정은 사람마다 갈린다 — 포함과 이어짐, 포함과 한 사안이 갈라진 것의 경계에서 특히 그렇다.
- 관계의 재현율을 정답 라벨로 재려면 기간이 긴 평가 세트가 필요하다 — [미결 사항](../open-questions.md).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 결과 파일을 위로 닫은 꼴로 내고 도구는 그대로 둔다 | 맞게 이은 포함이 세 보기 모두에서 깎이고, 직접 소속을 되살릴 수 없다 |
| 결과 파일은 직접 가진 기사만 내고 도구는 시스템 쪽을 닫지 않는다 | 포함의 효과가 잇기 지표에 나타나지 않는다 |
| 양 끝이 같은 정답인 관계를 틀림으로 센다 | 정답이 단층인 세트에서 갈래를 이은 포함이 모두 틀림이 되어, 지표가 방법의 품질과 반대로 움직인다 |
| 정답 스토리라인 안의 갈래를 하위 스토리라인으로 라벨에 더한다 | 모든 정답 스토리라인의 갈래를 정해야 하고 경계가 주관적이다. 라벨이 바뀌어 앞 결과와 견주지 못한다 |
| 기간을 늘린 평가 세트를 새로 만들어 정답 관계로 잰다 | 평가 세트를 새로 만드는 일이고, 쌓인 데이터가 아직 며칠치다 |
| 지금 평가 세트의 정답 관계만으로 잰다 | 관계가 몇 건뿐이라 방법을 가르지 못한다 |
| 쌍 판정의 셈을 저장소의 도구에 넣는다 | 쌍 판정 세트의 꼴과 고르는 범위가 아직 한 번 써 본 것이다. 굳으면 도구로 옮긴다 |
