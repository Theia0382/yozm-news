# ADR-0075: 기사 벡터는 차원 없는 `vector` 컬럼에 기사 × 모델 버전마다 한 행으로 두고, 모델 교체는 새 행으로 한다

- 상태: 승인
- 날짜: 2026-11-05
- 근거: [이슈 #94](https://github.com/Theia0382/yozm-news/issues/94) — 기사 표현 테이블을 만들며 데이터 모델 문서의 "기사 × 모델 버전마다 1행"과 [ADR-0027](0027-pgvector-for-vector-storage.md)의 "모델을 바꾸면 새 컬럼"이 다른 방식임을 확인. 운영 임베딩 모델과 그 차원은 아직 정해지지 않았다
- 관련: [ADR-0027](0027-pgvector-for-vector-storage.md)(벡터 저장 — 결정 절 "벡터마다 임베딩 모델 버전을 기록한다" 항목의 둘째 문장을 기사 벡터에 대해 이 ADR 이 부분 대체한다), [ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)(임베딩 모델 버전 기록)

## 맥락

- 기사 벡터는 사건 배정의 입력이다. 사건 배정에 쓰는 기간에 여유를 더한 만큼만 보관하고, 필요하면 요약문으로 다시 계산한다([ADR-0027](0027-pgvector-for-vector-storage.md)).
- 사건 배정은 인덱스 없는 정확 검색이고, HNSW 인덱스는 사건 중심 벡터에만 건다([ADR-0027](0027-pgvector-for-vector-storage.md)). 기사 벡터에는 인덱스가 필요 없다.
- pgvector 는 차원을 정하지 않은 `vector` 컬럼을 받는다. 차원이 다른 두 벡터의 거리 계산은 오류다. 차원이 없는 컬럼에는 HNSW 인덱스를 걸 수 없다.
- 운영 임베딩 모델(로컬 모델 · 외부 API)과 그 차원은 기사 표현을 저장하는 변경보다 뒤에 정해진다. 개발 · 시험의 로컬 대체물도 자기 차원을 갖는다.
- [ADR-0027](0027-pgvector-for-vector-storage.md)은 "모델을 바꾸면 새 컬럼 · 재계산 · 전환 · 이전 컬럼 삭제"를 정했다 — 차원을 정한 컬럼을 모델마다 두는 방식이다. 데이터 모델 문서는 기사 표현을 "기사 × 모델 버전마다 1행"으로 그렸다.

## 결정

- **기사 벡터 컬럼은 차원을 정하지 않은 `vector` 하나다. 표현 행은 기사 × 임베딩 모델 버전마다 하나다.**
- **모델을 바꾸면 같은 컬럼에 새 모델 버전의 행을 쓴다.** 배정은 지금 모델 버전의 행만 읽는다.
- **차원은 쓰기 전에 앱이 확인한다** — 임베더가 밝힌 차원과 벡터 길이가 다르면 쓰지 않는다.
- 모델 버전은 임베더가 밝힌 값이다. 표현 텍스트 · 핵심 말 규칙의 변경은 모델 버전에 넣지 않는다 — 표현은 짧게 보관하므로 그 뒤 기사부터 새 규칙을 쓴다.

## 결과

- 운영 모델을 고르거나 바꿀 때 기사 벡터의 마이그레이션이 없다. 바꾸는 동안 두 모델 버전의 행이 같은 표에 함께 있다.
- 로컬 대체물이 운영 모델과 다른 차원을 가져도 된다.
- DB 가 차원을 지켜 주지 않는다 — 쓰기 경로의 확인이 유일한 장치다.
- 기사 벡터에는 HNSW 인덱스를 걸 수 없다. 기사 단위의 근사 검색이 필요해지면 다시 본다.
- 사건 중심 벡터에는 [ADR-0027](0027-pgvector-for-vector-storage.md)의 방식(차원을 정한 컬럼 · 모델을 바꾸면 새 컬럼)이 그대로다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 차원을 정한 `vector(n)` 컬럼을 두고 모델을 바꾸면 새 컬럼을 단다([ADR-0027](0027-pgvector-for-vector-storage.md)의 방식) | 지금 n 의 근거가 없어 운영 모델을 고를 때 마이그레이션을 다시 한다. 로컬 대체물의 차원이 운영 모델에 묶이거나 개발과 운영의 컬럼이 달라진다. 인덱스를 걸지 않는 짧게 보관하는 입력이라 차원 고정의 이득이 작다 |
