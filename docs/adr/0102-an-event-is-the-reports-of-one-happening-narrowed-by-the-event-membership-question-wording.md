# ADR-0102: 사건은 한 번 일어난 일을 다룬 보도들이고, 시스템의 사건 범위는 사건 소속 질문 문구로 좁힌다

- 상태: 승인
- 날짜: 2026-11-09
- 근거: [이슈 #116](https://github.com/Theia0382/yozm-news/issues/116) — 측정 인스턴스의 기사와 라벨 기준 2판 표본으로 문구 후보를 실제 Jev 에 물어 견주고 리드와 정함. 구현 `4dabf61`
- 관련: [ADR-0097](0097-event-clustering-evaluation-labels-reports-of-one-happening-narrower-than-the-system-event.md)(결정 "시스템은 바꾸지 않는다"와 결과 첫 항목 — 부분 대체), [ADR-0072](0072-event-membership-question-wording-as-one-code-constant-with-its-version-in-raw-records.md)(새 문구 판 — 보충), [ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)("같은 사건"의 범위 — 보충), [ADR-0101](0101-shared-storylines-connect-events-and-the-personal-side-is-storyline-subscriptions-and-interests.md)(사건 위의 층)

## 맥락

- 지금 사건은 같은 일과 그 직접 후속을 함께 묶는다 — 사건 소속 질문이 "그 일 또는 직접 후속을 다루는가"를 묻는다([evaluation Spec 사건 소속 판정](../specs/evaluation.md#사건-소속-판정) — evaluation-R37).
- 기본 임베딩 모델에서는 시각이 가까운 후보 대부분이 점수의 띠(아래 기준 ~ 위 기준)에 들어 질문을 거친다. 그래서 시스템의 사건 범위는 사실상 질문 문구가 정한다. 띠 위(위 기준 이상)는 질문 없이 산식으로 붙는다.
- 시간 쪽 범위는 점수의 시간 감쇠가 정한다. 반감기는 코드 상수이고, 같은 글이라도 시각 차가 커지면 아래 기준 밑으로 떨어져 새 사건을 연다. 사건 묶기의 기준값(시간 창 · 위 · 아래 · 확률 기준 · 닫는 기간)은 평가 세트로 정한다([ADR-0026](0026-event-clustering-with-local-embeddings-and-jev.md)).
- 평가의 정답 사건은 한 번 일어난 일로 좁혀졌고([ADR-0097](0097-event-clustering-evaluation-labels-reports-of-one-happening-narrower-than-the-system-event.md)), 갈래를 잇는 일은 스토리라인이 맡는다([ADR-0101](0101-shared-storylines-connect-events-and-the-personal-side-is-storyline-subscriptions-and-interests.md)).

## 결정

- **사건은 한 번 일어난 일을 다룬 보도들이다.** 같은 일의 속보 · 종합 · 추가 사실과 같은 취재물을 다시 낸 기사는 같은 사건이다. 다른 주체의 반응, 같은 사안의 다른 행위(다음 단계), 다른 곳에서 일어난 비슷한 일은 별개 사건이다. 특정한 일을 다루지 않는 경향 기사는 같은 경향을 다루고 시각이 가까우면 같은 사건이다.
- **시스템의 범위는 사건 소속 질문 문구 하나로 좁힌다(판 `membership-2`).** 문구는 판정할 기사가 후보 사건의 기사들이 이미 보도한 일 밖의 새 일을 전하지 않는지를 묻는다 — "예"가 같은 사건이다. 일은 한 번 일어난 행위 · 사건 · 발언 · 결정 하나다. 문구에는 분야별 예시를 넣지 않는다. 문구 원문의 정본은 코드 상수다.
- **시간("가까움")은 문구에 넣지 않는다.** 감쇠와 아래 기준이 정한다. 반감기는 코드 상수로 두고, 값은 평가 세트에서 시간 창과 함께 견줘 정한다.
- **기준값은 바꾸지 않는다.** 시간 창 · 위 · 아래 · 확률 기준 · 닫는 기간 · 최대 기간은 평가 세트로 정한다.
- **이전 문구 판의 확률은 다시 묻지 않는다.** 저장 후보의 확률 · 병합 판정 기록은 그대로 쓰이고, 판정 원본의 문구 판이 바꾼 전후를 가른다.
- 문구는 표본으로 확인했다 — 갈래(같은 일 · 재게시 · 반응 · 다음 단계 · 경향 · 같은 분야의 다른 일)를 고른 표본과, 실제 배정 산식으로 Jev 에 묻게 될 (기사, 후보 사건) 쌍을 뽑은 표본에서 여러 문구를 견줬다. 품질 측정은 평가 세트로 한다.

## 결과

- 표본에서 후보 문구들의 정확도는 비슷했고 틀리는 방향이 달랐다. 이 문구는 틀릴 때 다른 사건에 잘못 붙이기보다 같은 일을 새 사건으로 연다 — 잘못 붙인 기사는 사건 중심을 옮겨 번지게 하고, 갈린 사건은 병합과 스토리라인이 받을 여지가 있다. 병합은 같은 문구로 묻는다. 갈림의 비용은 평가 세트와 스토리라인 구현에서 잰다.
- 요약문이 반응이 아니라 원래 일만 다루는 반응 기사는 이 문구로 가르지 못한다.
- 같은 취재물을 다시 낸 기사를 따로 적은 조항은 없다 — "새 일이 없는가"에 든다. 표본에서 판정이 갈린 재게시가 있었다.
- 같은 경향의 기사를 묶으므로 경계가 흐려 번질 위험이 있다([ADR-0097](0097-event-clustering-evaluation-labels-reports-of-one-happening-narrower-than-the-system-event.md)이 라벨 기준에서 같은 경향끼리 묶기를 기각한 이유). 문구는 같은 분야라는 것만으로 묶지 않는다. 라벨 기준 2판은 경향 기사를 혼자인 사건으로 두므로, 평가에서 이 차이는 정의의 차이로 읽는다 — 문면은 [사건 묶기 평가하기](../operations/event-evaluation.md)에 있다.
- 산식으로 붙는 경로(위 기준 이상)는 문구가 좁히지 못한다. 핵심 말이 많이 겹치는 반응 · 다음 단계 기사가 질문 없이 붙을 수 있고, 이것은 위 기준의 측정으로 다룬다.
- 시간 쪽 범위는 반감기가 정한다. 그 값을 견주려면 코드를 바꿔 다시 빌드해야 한다.
- 문구가 후보마다 질문에 들어가므로 사건 소속 판정 요청의 입력 토큰이 후보 수만큼 늘어난다.
- 판정 원본은 문구 판으로 전후가 갈린다. 평가 결과를 견줄 때 그 기간의 문구 판을 함께 본다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 문구와 함께 닫는 기간 · 최대 기간 기본값을 지금 줄인다 | 범위를 좁히지 않는다 — 닫는 기간이 시간 창 이상이라 닫힐 사건은 이미 새 기사의 후보 밖이다. 근거 없는 값이다 |
| 문구와 함께 위 기준을 올린다 | 위 기준은 평가 세트의 측정 대상이다. 띠가 넓어져 Jev 비용이 늘고, 재판정이 정직하게 견주지 못하는 변경이다 |
| 반감기를 사건 기준 설정으로 올리거나 값을 바꾼다 | 설정 · 기준 이력 · 재판정 규칙이 바뀌는데 운영자가 맞출 값인지 근거가 없다. 값을 바꾸면 근거 없는 값이고, 다른 사건 쌍도 띠에 남아 질문이 는다 |
| 질문을 둘로 나눈다(같은 일인가 · 같은 경향인가) | 후보마다 확률이 둘이 되어 포트 · 배정 규칙 · 저장이 바뀐다 |
| 계기 없는 경향 기사는 혼자인 사건으로 둔다 | 같은 경향을 다룬 기사들이 다이제스트에서 따로 남고, 다시 낸 같은 취재물을 잇는 범위와도 어긋난다 |
| 분야별 단계 · 반응의 예시 목록을 문구에 넣는다 | 표본의 분야에 맞춘 문구가 되어 다른 분야에서 갈리지 않는다 |
| "같은 일인가"를 묻는 문구 | 표본에서 정확도는 비슷했지만 다른 사건에 잘못 붙이는 쪽으로 틀렸다 |
| 제목으로 기사가 다루는 일을 고르게 하는 문구 | 표본에서 효과가 없었다 |
