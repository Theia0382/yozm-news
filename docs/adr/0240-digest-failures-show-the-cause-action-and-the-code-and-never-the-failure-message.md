# ADR-0240: 다이제스트 실패는 갈래의 할 일과 코드의 무슨 일 두 층으로 보이고, 실패 메시지는 화면에 내지 않는다

- 상태: 승인
- 날짜: 2026-11-18
- 근거: [이슈 #179](https://github.com/Theia0382/yozm-news/issues/179) — 수용 기준 "`FAILED`(원인 · 키 재등록 안내)", 정함(갈래의 할 일과 코드의 무슨 일). 구현 커밋 `39e730a` · `cbe227c` · `7dbf1de` · `7fa1e6b`(알림) · `7af1a1c`(해결되지 않은 마지막 실패 — 서버) · `f113b4e`(알림의 링크 · 갈래 링크 표 — 화면). UI 확인 뒤 정함(다시 만들기 링크는 해결되지 않은 마지막 실패에만)
- 관련: [ADR-0233](0233-digest-failure-notices-come-through-an-event-declared-by-the-receiving-user-module-for-every-failed-digest.md)(보충 — 알림이 그 날짜의 다이제스트 화면으로 잇고 갈래 문구를 다이제스트 화면과 함께 쓴다)

## 맥락

- 실패 코드는 열둘이고, 코드를 사용자의 할 일 갈래 넷(키 · 공급자 계정 · 잠시 뒤 · 모델 출력)으로 옮기는 정본은 `digest` 에 있다.
- 실패 메시지는 관문 문구 · 읽기 진단으로, 운영 로그용 문면이다.
- 다시 만들기 버튼은 홈에만 있다. 홈의 다시 만들기는 언제나 오늘(또는 그보다 늦은 날짜)을 만들고, 실패한 기간은 다음 `READY` · `EMPTY` 가 덮는다.
- 실패 알림 응답은 다이제스트 ID 를 내지 않고 날짜 · 갈래 · 실패 시각만 낸다(ADR-0233). 실패 알림을 받는 `user` 는 `digest` 를 읽지 못한다.

## 결정

- **화면은 갈래의 할 일 문구와 코드마다의 "무슨 일" 한 줄을 함께 보인다** — 갈래는 서버가 정해 응답에 코드와 함께 싣고, 화면은 갈래를 다시 정하지 않는다.
- **갈래의 할 일 문구와 가 볼 화면은 실패 알림과 다이제스트 화면이 한 표씩 함께 쓴다** — 가 볼 화면은 키 갈래면 키 화면, 모델 출력 갈래면 관심 설정의 모델 절이고 그 밖은 없다. 다시 만들기가 할 일인 갈래(잠시 뒤 · 모델 출력)의 할 일 문구는 홈의 다시 만들기를 가리킨다 — 문구는 해결 여부와 무관하다. 알림은 그 날짜의 다이제스트 화면으로 잇는다.
- **알림의 "오늘 다이제스트에서 다시 만들기" 링크는 해결되지 않은 마지막 실패의 알림에만 단다** — 그 사용자의 가장 최근 실패 뒤(ID 가 더 큰 행)에 기간을 덮는 다이제스트(`READY` · `EMPTY`)가 없으면 해결되지 않았다(날짜 무관). 판정은 `digest` 가 하고 수동 생성 상태에 그 실패의 날짜 · 끝낸 시각을 싣는다. 알림 화면은 실패 알림 본문이 홈 응답을 읽어 날짜 · 끝낸 시각이 같은 알림에만 링크를 단다 — 두 시각은 다이제스트가 끝낸 시각을 저장 정밀도(마이크로초)로 잘라 갖기에 같은 값이다. 홈 응답을 읽지 못하면 그 링크만 달지 않는다.
- **실패 메시지는 화면 응답에 싣지 않는다.**

## 결과

- 할 일은 갈래 표 하나, 원인은 코드 표 하나에서 나온다.
- 잘림 · 거절 · 인용 없음을 사용자가 가려 모델을 바꿀지 다시 만들지 고를 수 있다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 갈래의 할 일 문구만 | 출력 실패의 종류를 가릴 수 없다 |
| 코드마다 할 일까지 따로 | 같은 갈래끼리 할 일 문구가 어긋날 수 있다 |
| 실패 메시지를 보인다 | 운영 로그용 문면이고 사용자가 할 일을 알려 주지 않는다 |
| 다시 만들기 링크를 갈래만 보고 늘 단다 | 이미 다음 다이제스트가 덮은 지난 실패에도 붙어, 실패한 날짜가 아니라 오늘을 만드는 링크가 여럿 보인다 |
| 화면이 홈 응답의 가장 늦은 날짜 · 가장 최근 시도로 해결을 추정한다 | 판정이 화면에 있고, 홈에 보이지 않는 날짜의 실패를 판정하지 못한다 |
| 알림 화면 전용 조회를 둔다 | 처리기 · 격리 등록 · 명세가 늘고 홈 응답의 캐시를 함께 쓰지 못한다 |
| 실패 시각을 허용 오차로 맞춘다 | 맞춤의 판단이 화면에 가고, 오차의 크기를 따로 정해야 한다 |
