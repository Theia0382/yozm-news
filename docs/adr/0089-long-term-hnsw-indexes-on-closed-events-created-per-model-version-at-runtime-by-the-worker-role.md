# ADR-0089: 장기 검색 HNSW 인덱스는 닫힌 사건에 모델 버전마다 작업 역할이 실행 중에 만든다

- 상태: 승인
- 날짜: 2026-11-07
- 근거: [이슈 #98](https://github.com/Theia0382/yozm-news/issues/98) — 인덱스를 둘 때와 자리를 리드와 정하고 구현, 실제 PostgreSQL 에서 생성 · 질의 계획의 사용을 확인(`0551eb3`)
- 관련: [ADR-0014](0014-spring-data-jdbc.md)(결정 표 "스키마" 행을 장기 검색 인덱스에 대해 부분 대체한다 — 좁힘), [ADR-0027](0027-pgvector-for-vector-storage.md)(결정 절 "HNSW 인덱스는 오래된 사건을 찾는 장기 검색에만 건다"의 인덱스를 정한다, 후속 기록), [ADR-0079](0079-event-centroids-in-a-dimensionless-halfvec-column-with-a-model-version-per-event.md)(결과 절 "운영 모델을 고르거나 바꿔도 사건 테이블의 마이그레이션이 없다"를 인덱스에서도 지킨다, 후속 기록)

## 맥락

- 사건 배정은 인덱스 없는 정확 검색이고, HNSW 인덱스는 오래된 사건을 찾는 장기 검색에만 건다([ADR-0027](0027-pgvector-for-vector-storage.md)).
- 사건 중심은 차원 없는 `halfvec` 이라, HNSW 는 모델 버전마다 차원을 정한 식(`centroid::halfvec(n)`)과 부분 조건으로만 걸 수 있다(실측 — [ADR-0079](0079-event-centroids-in-a-dimensionless-halfvec-column-with-a-model-version-per-event.md)). 모델 버전은 임베더가 밝히는 값이라 운영 중에 생긴다. 운영 모델을 고르거나 바꿔도 사건 테이블의 마이그레이션이 없다고 했다.
- 스키마의 정본은 Flyway 마이그레이션이다([ADR-0014](0014-spring-data-jdbc.md)).
- 열린 사건은 기사가 붙을 때마다 중심이 바뀌고, HNSW 는 행이 바뀔 때마다 항목을 더한다. 닫힌 사건은 지운 기사 따르기만 바꾼다.
- 장기 검색을 하는 조회는 아직 없다.

## 결정

- **작업 역할의 정리 작업이, 닫힌 사건이 있는 모델 버전마다 `events` 에 HNSW 식 · 부분 인덱스(닫힌 사건 · 그 모델 버전, 코사인 거리)를 없으면 만든다.** 동시 생성(`CREATE INDEX CONCURRENTLY`)으로 트랜잭션 밖에서 쓰기를 막지 않고 만든다. 이름은 모델 버전의 해시로 정하고, 실패로 남은 쓸 수 없는 같은 이름의 인덱스는 지우고 다시 만든다. 한 모델 버전의 닫힌 사건 차원이 하나가 아니면 만들지 않고 경고한다.
- **이 인덱스는 스키마 정본(Flyway 마이그레이션)의 예외다.** 이름 · 식 · 조건의 정본은 인덱스를 만드는 코드 하나다.
- **만들지 못하면(권한 · 잠금) 경고만 남기고 다음으로 간다.** 인덱스는 검색 속도만 바꾸고 결과를 바꾸지 않는다.
- 기사 표현과 열린 사건에는 인덱스를 두지 않는다.

## 결과

- 모델을 바꿔도 마이그레이션이 없다. 닫힌 사건만이라 중심 갱신 부담이 없다.
- 스키마의 일부가 마이그레이션 밖에 있다 — 장기 검색 인덱스의 목록은 DB 와 그 코드에서 읽는다.
- 인덱스를 만들려면 앱의 DB 계정이 `events` 의 소유자여야 한다. 외부 DB 에서 소유자가 아니면 경고만 남고 장기 검색이 느리다.
- 닫힌 사건이 많아진 뒤 처음 만들 때 오래 걸린다 — 쓰기를 막지 않는다.
- 이 인덱스를 쓰는 조회가 아직 없다. 쓰는 쪽이 다른 조건을 원하면 인덱스를 하나 더 만든다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 장기 검색을 쓰는 작업이 인덱스를 만든다(지금은 제약만 둔다) | 쿼리와 인덱스를 함께 정할 수 있지만, 사건 정리 때 두기로 한 계획을 미룬다 |
| 모델 버전마다 마이그레이션으로 만든다 | 모델 버전은 실행 중에 생겨 미리 둘 수 없고, 모델을 고르거나 바꿀 때마다 마이그레이션이 생긴다 |
| HNSW 를 열린 사건에도 건다 | 붙일 때마다 중심이 바뀌어 항목이 계속 는다. 열린 사건의 배정은 정확 검색이다 |
