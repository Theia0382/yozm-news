# ADR-0138: 관계 판정의 확률은 평가기가 저장된 원본 응답을 다시 읽어 운영자에게 낸다

- 상태: 승인
- 날짜: 2026-11-13
- 근거: [이슈 #125](https://github.com/Theia0382/yozm-news/issues/125) — 기점 `a9a9d71` 의 관계 판정 원본(`flow_relation_judgements` — 답마다의 확률 칸 없이 원본 응답을 `jsonb` 로 저장), Jev 어댑터의 관계 응답 읽기(응답 본문만으로 확률을 읽는다), 로컬 대체물의 원본 응답(답마다의 확률을 직접 적는다)을 확인

## 맥락

- 관계 판정은 답 다섯(해당 없음 · 포함 두 방향 · 이어짐 두 방향)의 확률과 두 흐름의 한 사안 확률을 받는다. 판정을 반영한 `storyline` 은 맺은 관계의 확률 하나만 남긴다. 판정 원본은 두 흐름 ID · 서술 · 평가기 · 모델 · 문구 판 · 원본 응답 · 입력 토큰 · 시각을 남기고, 답마다의 확률은 원본 응답 안에만 있다.
- 운영자가 관계 기준(확률 기준 · 한 사안 기준)을 고르려면 맺지 않은 쌍이 기준에 얼마나 못 미쳤는지 봐야 한다.
- 원본 응답의 형식은 평가기마다 다르다. 태그 판정은 이미 저장된 원본 응답을 평가기 포트의 다시 읽기 연산으로 읽는다([ADR-0069](0069-missing-tags-filled-by-the-evaluator-rereading-stored-raw-responses-over-an-operator-chosen-period.md)).
- 판정 원본은 보존 기간(초안 180일)이 지나면 지워질 수 있고, 관계 · 물은 기록은 무기한이라 그 ID 가 먼저 사라진 원본을 가리킬 수 있다.

## 결정

- **확률은 저장된 원본 응답을 평가기가 다시 읽어 낸다.** 평가기 포트에 관계 다시 읽기 연산을 더하고, 구현마다 자기 형식만 읽는다 — 요청을 보내지 않는다. 판정 원본 · 관계 · 물은 기록에 확률 칸을 더하지 않는다.
- **운영자 조회는 원본 ID 로 원본을 찾는 `evaluation` 의 공개 조회다.** 원본마다 모델 · 문구 판 · 입력 토큰 · 판정 시각과 다시 읽은 결과를 낸다. 원본 응답 텍스트는 내지 않는다.
- **읽지 못한 원본은 까닭과 함께 낸다** — 그 프로세스에 평가기가 없음, 다른 평가기가 남긴 원본, 읽을 수 없는 원본. 지워진 원본은 결과에서 빠지고, 부르는 쪽이 "원본 없음"으로 보인다.

## 결과

- 저장 형식이 바뀌지 않고, 지금 있는 원본의 확률도 읽힌다. 확률의 정본은 원본 응답 하나다.
- 평가기 구현마다 관계 다시 읽기가 하나씩 는다. 평가기를 바꾸면 그 전 평가기의 원본은 읽지 못한다.
- 원본 응답을 읽는 키는 코드 상수다 — 문구 판이 키를 바꾸면 그 전 판의 원본을 읽는 길을 지켜야 한다.
- 원본이 지워진 쌍은 확률을 보일 수 없다. 기준을 고르는 데는 최근 판정을 쓴다.
- 화면 역할 프로세스에 평가기가 없으면 확률을 보일 수 없다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 판정할 때 판정 원본에 확률 칸을 더한다 | 저장 형식이 바뀌고 지금 있는 원본은 칸이 비며, 원본과 함께 지워진다. 같은 값이 원본 응답과 칸에 두 번 있다 |
| 판정을 반영할 때 물은 기록에 확률 칸을 더한다 | 원본이 지워져도 남지만 저장 형식이 바뀌고 지금 있는 물은 기록은 칸이 빈다. `evaluation` 의 답이 `storyline` 에 사본으로 남고, 쌍마다 마지막 한 번뿐이다 |
