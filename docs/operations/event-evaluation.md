# 사건 묶기 평가하기

자기 인스턴스의 사건 묶기를 정답 라벨과 견줘 재는 방법이다 — 묶음 정확도(B-cubed). 사건 배정 기준을 맞추거나 임베딩 모델을 바꾼 뒤 다시 볼 때 쓴다. 큰 판정은 [스토리라인 평가하기](storyline-evaluation.md)가 잰다. 기본값도 이 방법으로 정한다.

도구는 저장소의 [`tools/event-eval`](../../tools/event-eval/)이고, 운영자 API 를 [운영자 토큰](configuration.md#운영자)으로 읽는다. 판정 규칙은 계산하지 않는다 — 시스템이 낸 사건을 받아 라벨과 견준다. 판단의 이유는 [ADR-0095](../adr/0095-event-clustering-evaluated-by-an-operator-tool-comparing-admin-api-results-with-full-day-labels.md) · [ADR-0096](../adr/0096-instance-bound-evaluation-data-kept-out-of-the-public-repository-and-defaults-cite-only-the-evaluation-set.md) · [ADR-0097](../adr/0097-event-clustering-evaluation-labels-reports-of-one-happening-narrower-than-the-system-event.md), 증거로서의 한계는 [테스트 전략](../qa/test-strategy.md) ⑪ 에 있다.

## 재는 것

- **B-cubed 정밀도 · 재현율 · F1** — 라벨 기사(뺀 기사 제외)마다, 같은 시스템 사건의 라벨 기사 가운데 같은 정답 사건인 비율(정밀도)과 같은 정답 사건의 라벨 기사 가운데 같은 시스템 사건인 비율(재현율)을 평균한다. 배정이 없는 기사는 그 기사 혼자인 묶음으로 센다

재지 않는 것: 병합 전후의 묶음 정확도, 닫는 기간 · 최대 기간.

## 준비

- **평가 디렉터리** — 표본마다 디렉터리 하나를 체크아웃 밖에 둔다(예: `~/event-eval/2026-11-04`). 라벨 · 결과는 이 인스턴스의 데이터라 저장소에 넣지 않는다. `deploy/.env` 와 함께 백업한다. 도구는 이 경로를 `--data` 로 꼭 받는다
- **운영자 토큰** — 환경 변수 `YOZMNEWS_ADMIN_TOKEN` 으로만 받는다. 셸 이력에 남지 않게 넣는다:

  ```bash
  read -rs YOZMNEWS_ADMIN_TOKEN && export YOZMNEWS_ADMIN_TOKEN
  ```

- **실행** — Python 3.12 이상이 있으면 저장소 루트에서 `python3 tools/event-eval/event_eval.py …` 로 돌린다. 운영자 API 주소는 `--base-url` 이고 기본은 배포 구성 proxy 의 기본 공개 주소 `http://127.0.0.1:8000` 이다. Python 이 없으면 공식 이미지로 배포 구성의 네트워크에서 돌린다:

  ```bash
  docker run --rm --network yozmnews-deploy_default -e YOZMNEWS_ADMIN_TOKEN \
    -v "$PWD/tools/event-eval:/tool:ro" -v "$HOME/event-eval/2026-11-04:/data" \
    python:3-slim python /tool/event_eval.py measure --data /data --base-url http://proxy:8080 --embedding-model onnx
  ```

  - 네트워크 이름은 Compose 프로젝트 이름(기본 `yozmnews-deploy` — [Compose](configuration.md#compose))에 `_default` 를 붙인 것이다
  - SELinux 를 쓰는 호스트는 바인드 마운트 끝에 `:z` 를 붙인다(`…:/tool:ro,z`, `…:/data:z`)
  - Docker 데몬이 root 로 돌면(rootless 가 아니면) 컨테이너가 쓴 시트 · 결과 기록이 root 소유가 된다 — `--user "$(id -u):$(id -g)"` 를 붙인다
  - `--env-file deploy/.env` 로 넘기지 않는다 — 다른 비밀 값까지 넘어간다

## 표본 고르기

- **날짜 단위 전수** — 시간대의 하루, 또는 이어진 며칠에 발행된 기사 전부에 라벨을 붙인다. 일부만 붙이면 라벨 밖 기사와의 잘못된 묶음이 지표에 드러나지 않는다. 시간 창보다 짧은 구간은 날짜를 넘는 잘못된 묶음을 거의 보지 못한다
- **배정이 끝난 뒤** — 그 날짜 기사의 사건 묶기가 끝난 뒤에 시트를 만들고 잰다. 사건 묶기가 도는 중에 재면 한 기사가 두 사건에 보이거나 빠진다 — 도구는 이를 알아채면 멈춘다(아래 [멈출 때](#멈출-때))
- **기간 상한** — 운영자 API 의 사건 조회 기간 상한을 넘으면 도구가 그 응답의 설명을 보이고 멈춘다
- 시트는 시트를 만들 때 사건에 배정된 기사만 담는다. 끝내 배정되지 않은 기사는 표본에서 빠진다

## 라벨 기준 2판

라벨을 붙이는 규칙(이 절의 항목)을 고치면 판을 올리고 도구의 판(`tools/event-eval/labels.py` 의 `LABEL_RULE_VERSION`)도 함께 올린다. 결과 기록은 쓴 판을 적고, 판이 다른 결과는 견주지 않는다.

- **같은 사건** — 한 번 일어난 일(사고 · 발표 · 결정 · 처리의 한 단계 · 한 사람의 발언 · 한 경기)을 다룬 보도들. 같은 일의 속보 · 종합 · 추가 사실은 같은 사건이다. 예정된 일을 앞서 다룬 보도(오늘 있을 선고 · 투표)는 그 일의 사건이다
- **다른 사건** — 다른 주체의 반응 · 입장(판결을 두고 낸 정당 논평, 선거 결과를 두고 낸 다른 나라의 반응)과 같은 안건의 다음 단계(법안의 위원회 통과와 본회의 상정, 사고와 다음 날의 구속영장 신청)는 날짜와 무관하게 별개 사건이다. 같은 인물 · 기관 · 분야라도 다른 일, 같은 일의 정례 반복(다른 날의 시황 · 다른 경기)도 다른 사건이다
- **사설 · 칼럼** — 매체의 논평이라 반응으로 보지 않는다. 한 일을 다룬 사설 · 칼럼은 그 일의 사건에 넣는다(판결을 두고 낸 사설은 그 판결의 사건). 특정한 일 없이 주제를 다룬 칼럼은 혼자인 사건이다
- **여러 일을 다룬 기사** — 중심이 되는 일이 있으면 그 일의 사건에 넣는다. 중심은 제목이 가리키는 일이고, 제목에 둘이 나란하면 요약문 첫 문장이 가리키는 일, 그래도 같으면 먼저 일어난 일이다. 중심이 없으면(여러 일을 모은 묶음 · 브리핑, 여러 일을 나란히 다룬 분석 · 사설 · 칼럼) 뺀다
- **행사 안의 발표** — 포럼 · 학술대회 · 박람회 안의 강연 · 축사 · 기업 발표는 하나하나가 일이다. 같은 발표를 다룬 기사끼리만 묶는다. 행사 자체(열림 · 규모 · 현장 · 전체 흐름)를 다룬 기사는 그 행사의 사건이고, 여러 발표를 정리한 기사는 위 "여러 일을 다룬 기사"를 따른다
- **일이 없는 경향 · 기획 기사** — 한 번 일어난 일이 없는 기사(소비 경향 · 기획 · 해설)는 혼자인 사건이다. 같은 취재물을 판 · 형식만 바꿔 다시 낸 기사(자막 영상판 · 지면판 · 웹판)와 다른 매체의 전재는, 첫 기사로부터 48시간 안이면 첫 기사와 같은 사건이다
- **뺀다(`-`)** — 여러 일을 모은 묶음 · 브리핑, 방송 · 연재의 예고와 편성표, 날씨 · 운세 · 광고성 기사
- **애매하면** — `note` 칸을 `?` 로 시작하고 이유를 적는다. 검토(`review --sample`)가 이 기사를 모두 보인다

## 지금 시스템과의 차이

라벨 기준 2판의 사건과 지금 사건 묶기의 사건은 같은 범위 — 한 번 일어난 일이다([사건 소속 판정](../specs/evaluation.md#사건-소속-판정) — evaluation-R37, [ADR-0102](../adr/0102-an-event-is-the-reports-of-one-happening-narrowed-by-the-event-membership-question-wording.md)). 다른 점은 아래이고, 평가에서는 정의의 차이로 읽는다.

- **일이 없는 경향 · 기획 기사** — 라벨은 혼자인 사건이고, 시스템은 같은 경향을 다룬 기사를 시각이 가까우면 같은 사건으로 묶는다. 정밀도 손실로 잡힌다
- **같은 취재물을 다시 낸 기사 · 전재** — 라벨은 첫 기사로부터 48시간 안이면 같은 사건이다. 시스템은 이 시간을 따로 두지 않고 점수의 시간 감쇠와 아래 기준이 정하며, 질문 문구에도 다시 낸 기사를 따로 적은 조항이 없다. 시각 차가 크거나 판정이 갈리면 새 사건이 되어 재현율 손실로 잡힌다
- **산식으로 붙는 쌍** — 점수가 위 기준 이상이면 질문 없이 붙는다. 핵심 말이 많이 겹치는 반응 · 다음 단계 기사가 이렇게 붙으면 정밀도 손실로 잡힌다

## 순서

1. 시트를 만든다 — `sample.json` 과 `articles.csv` 가 생긴다. 이미 있으면 덮지 않고 멈춘다

   ```bash
   python3 tools/event-eval/event_eval.py sheet --data ~/event-eval/2026-11-04 --from 2026-11-04 --to 2026-11-05 --zone Asia/Seoul
   ```

2. `articles.csv` 의 `event` 칸에 정답 사건 표지(아무 문자열 — 같은 사건이면 같은 표지)를 적는다. 뺄 기사는 `-`. 빈 칸이 남으면 다음 단계가 멈춘다
3. `review` — 정답 사건별 제목 목록을 보고 라벨을 고친다. `--sample N` 은 기사 2건 이상인 정답 사건 N 개를 무작위로(`--seed` 로 다시 뽑을 수 있다) 고르고, 애매한 기사를 모두 더한다
4. `measure` — 시스템의 지금 결과를 재고 결과 기록을 `results/` 에 쓴다. 임베딩 방식 · 모델은 운영자 API 가 내지 않으므로 `--embedding-model` 로 적는다. 앱 판 · 닫는 기간처럼 함께 남길 값은 `--note KEY=VALUE` 로 적는다

## 기준 비교

- **사건 배정 기준** — [환경 변수](configuration.md#사건-묶기)를 바꿔 앱을 다시 띄우고, 재판정이 끝난 뒤 다시 잰다. 두 결과 기록을 견준다
  - 정직하게 비교되는 변경: 위 기준 내리기, 확률 기준, 아래 기준 올리기처럼 띠가 넓어지지 않는 변경이고, 표본 사건이 열려 있을 때다. 결과 기록의 `counts.closedSystemEvents` 가 0 이 아니면 그 사건의 묶음은 바꾼 기준으로 다시 판정되지 않았다
  - 비교되지 않는 변경: 시간 창, 아래 기준 내리기, 위 기준을 올려 띠가 넓어지는 변경, 임베딩 모델 바꾸기 — 재판정은 저장해 둔 점수 · 확률 안에서만 다시 판정한다
- 작은 차이를 근거로 삼지 않는다 — 표본이 작으면 값이 흔들린다. 결과 기록의 건수를 함께 본다

## 파일

평가 디렉터리의 파일(UTF-8):

| 파일 | 형식 |
|---|---|
| `sample.json` | `labelRule`(라벨 기준 판) · `start` · `end`(날짜, 둘 다 포함) · `zone`(IANA 시간대) |
| `articles.csv` | 칸 `article_id,published_at,sources,title,event,note`. `published_at` 은 운영자 API 의 발행 시각(UTC, 소수 초가 있을 수 있다)이고 고치지 않는다. `sources` 는 출처를 `;` 로 잇는다. `event` 는 정답 사건 표지 또는 `-` |
| `results/<UTC 측정 시각>.json` | 결과 기록 — 아래 |

`measure` 는 라벨 기사의 발행 시각을 운영자 API 의 값과 견준다. 다르면 다른 인스턴스의 라벨일 수 있어 멈춘다.

## 결과 기록

| 키 | 내용 |
|---|---|
| `format` · `measuredAt` | 기록 형식 판(`3`) · 측정 시각(UTC) |
| `sample` | 기간 · 시간대 · 라벨 기준 판 — 판이 다른 결과는 견주지 않는다 |
| `labels` | `articles.csv` 의 sha256 — 어느 라벨로 쟀는지 |
| `counts` | 라벨 기사 · 뺀 기사 · 정답 사건 수, 소스별 · 날짜별 라벨 기사 수, 라벨 밖 시스템 기사 수(표본 날짜의 시스템 기사 가운데 시트에 없는 것), 라벨 기사가 속한 닫힌 시스템 사건 수 |
| `settings` | 지금 사건 배정 기준(시간 창 초 · 위 · 아래 · 저장 · 확률), 라벨 기사(뺀 기사 제외)의 사건 소속 판정에 쓰인 Jev 모델 판, 임베딩 방식 · 모델, 메모 |
| `bCubed` | 정밀도 · 재현율 · F1, 시스템 사건 수, 배정 없는 라벨 기사 수, 기사 하나뿐인 정답 · 시스템 묶음 수 |

주제별 건수 · 라벨 검수 불일치율처럼 운영자 API 가 내지 않는 값은 `--note` 로 남긴다.

## 멈출 때

| 종료 코드 | 뜻 |
|---|---|
| `0` | 성공 |
| `2` | 라벨 · 표본 파일이 형식에 어긋남(어긋난 줄을 보인다 — 많으면 앞부분과 나머지 수), 다른 판의 라벨 기준으로 만든 표본, 라벨과 시스템 결과가 어긋남(한 기사가 두 사건 · 발행 시각 불일치), 이미 있는 파일, 토큰 없음, 인자 오류 |
| `3` | 운영자 API 를 읽지 못함 — 연결 실패, 응답이 끊기거나 시간이 다 됨, JSON 이 아닌 응답, 401 · 403(토큰), 4xx 의 설명(예: 기간 상한), 리디렉션(따르지 않는다 — `--base-url` 을 확인한다), 목록을 읽는 중에 같은 사건 · 같은 쪽이 되풀이됨(사건 묶기가 도는 중이면 끝난 뒤 다시 잰다) |

결과 기록은 측정이 끝까지 성공했을 때만 쓴다.
