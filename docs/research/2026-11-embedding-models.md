# 기사 임베딩 모델 조사 (2026-11-07)

사건 묶기의 기사 임베딩을 앱 안 로컬 모델로 할지 외부 API 로 할지, 로컬이면 어떤 모델을 어떻게 배포할지 정하려고 한 조사다. 결정은 [ADR-0090](../adr/0090-article-embedding-defaults-to-an-in-app-local-model-with-an-openai-compatible-api-by-setting.md)(로컬 기본 + OpenAI 호환 외부 API)과 [ADR-0091](../adr/0091-local-embedding-model-is-multilingual-e5-small-int8-fetched-at-build-into-the-image-with-onnx-telemetry-off.md)(multilingual-e5-small int8)에 있다. 수치는 작성 시점의 한 표본에서 잰 값이고, 사건 묶기의 정식 품질 평가가 아니다.

## 1. 표본과 지표

**표본**

- 프리셋 언론사 피드의 RSS 를 직접 받아, 이틀 남짓(2026-11-05 ~ 11-07) 사이 기사에 사건 라벨을 붙였다 — 사건 38개 · 기사 139건(언론사 셋), 같은 사건 쌍 425 · 다른 사건 쌍 9,166
  - 같은 사건: 같은 사건을 다룬 기사, 그 사건에 대한 반응 기사
  - 뺀 것: 여러 사건을 묶은 기사(주요 뉴스 모음) · 예고 · 사설 · 방송 대담 · 경계가 애매한 기사
- **어려운 음성** — 같은 인물 · 같은 분야의 서로 다른 사건 짝 19개(쌍 536). 예: 같은 정치인의 다른 발표, 다른 회사의 해킹 사고, 다른 경기
- 텍스트는 사건 묶기의 표현 텍스트와 같다 — 제목 + 줄바꿈 + 요약문 앞 300자([event Spec](../specs/event.md#기사-표현))
- 한계: 언론사 셋 · 이틀 · 라벨러 한 명이다. 같은 사건 쌍의 36% 가 기사 18건짜리 사건 하나에서 나온다

**지표**

- AUC — 같은 사건 쌍이 다른 사건 쌍(전체 · 어려운 음성)보다 코사인이 높을 확률
- nn1 — 기사마다 가장 가까운 기사가 같은 사건인 비율
- 최대 F1 — 쌍을 코사인 문턱 하나로 같다 · 다르다 판정할 때의 최대 F1 과 그 문턱. 표본 안에서 고른 문턱이라 모든 모델에 낙관적이다
- 코사인 분위 — 같은 사건 쌍의 p10 · 중앙값, 어려운 음성 p90, 다른 사건 쌍 중앙값
- 표본 오차 — 사건 단위 bootstrap(사건을 복원 추출, 1,000회)의 95% 구간

## 4. 실행 비용

**로컬(JVM, ONNX Runtime + DJL 토크나이저)** — 표본 139건을 2회 반복, `--cpus 4`, root 가 아닌 컨테이너

| 구성 | 스레드 · 묶음 | 기사당 | 최대 RSS |
|---|---|---|---|
| 토크나이저만 | — | — | 511 MB |
| e5-small fp32 | 4 · 16 | 30.4 ms | 1,369 MB |
| e5-small int8 | 4 · 16 | 14.5 ms | 1,018 MB |
| e5-small int8 | 4 · 8 | 12.5 ms | 891 MB |
| e5-small int8 | 1 · 16 | 44.2 ms | 1,020 MB |

- RSS 는 측정 프로세스 전체이고, 아무것도 올리지 않은 JVM 은 41 MB 였다. 토크나이저(어휘 25만, `tokenizer.json` 17 MB) 적재가 약 0.47 GB · 4.5 ~ 4.9 초다
- 하루 1,168건 × 14.5 ms ≈ 17 초 — CPU 는 부담이 아니다
- 배포 이미지 안의 앱(2026-11-07, 기사 59건): 로컬 모델 1.21 ~ 1.29 GiB, 외부 방식(로컬 모델 없음) 0.87 GiB — 로컬 모델 몫은 약 0.3 ~ 0.4 GiB 로 하네스보다 작다(앱의 힙을 함께 쓴다). 이미지는 모델 계층 약 135 MB, ONNX Runtime · 토크나이저 jar 약 69 MB 가 는다

**직접 띄우는 임베딩 서버** — Hugging Face TEI 1.9(CPU) + e5-small, `--cpus 4`: 기사당 32.2 ms, 컨테이너 메모리 1.46 GiB, 이미지 938 MB. 모델을 기동 때 내려받고, amd64 · arm64 가 별도 태그이며, 기본 실행 계정이 root 다. 앱 안 로컬 모델보다 가볍지 않다

**arm64 · 실행 계정** — ONNX Runtime Java jar(1.29 · 1.31)와 DJL 토크나이저 jar 는 linux-aarch64 네이티브를 담는다. root 가 아닌 컨테이너(uid 65534, 홈 없음)에서 ONNX Runtime 네이티브가 `/tmp` 에 풀려 돌았고, arm64 는 QEMU 사용자 모드 에뮬레이션에서 결과까지 맞았다. 실기에서는 돌리지 않았다

**사용 통계** — ONNX Runtime 의 리눅스 네이티브는 기본으로 Microsoft 사용 통계 주소에 연결을 시도한다. API(`setTelemetry(false)`)로는 시도가 남았고, 환경 변수 `ORT_DISABLE_TELEMETRY=1` 로만 사라졌다

## 5. 외부 API 의 차이

OpenAI 호환 `/embeddings` 하나로 상용 API · 중계 · 직접 띄운 서버 대부분에 닿지만, 범용 클라이언트가 흡수해야 할 차이가 있다(제공자 공식 문서, 2026-11-07).

- `dimensions` — 이름이 다르거나(Voyage `output_dimension`), 받지 않거나(Cohere 호환 경로 · CLOVA Studio 는 1024 고정), 모델에 따라 오류를 내는 곳(vLLM · Fireworks)이 있다 → 보낼지 따로 정한다
- 정규화 — 보장되지 않는다(CLOVA Studio · Fireworks Qwen3 · Gemini 축소 벡터 · Perplexity) → 클라이언트가 정규화한다
- 한 요청의 입력 수 한도가 32 ~ 2,048 로 다르다 → 묶음 크기를 설정으로 둔다
- 역할 · 접두사 체계가 제각각이다(e5 `query: ` · Upstage query/passage 모델 · Cohere `input_type`) → 사건 묶기는 대칭 과제라 "입력 앞 문자열" 하나로 대부분 감당된다
- 단가(1M 토큰): OpenAI text-embedding-3-small $0.02 · -large $0.13, Upstage solar-embedding-2 $0.02(VAT 별도), gemini-embedding-001 $0.15, Voyage $0.02 ~ $0.12. CLOVA Studio 원화 단가 · Cohere 공식 단가는 확인하지 못했다
- 폐기 정책: Upstage v1 별칭은 2026-12-31 종료, Google text-embedding-004 는 2026-01-14 종료됐다
- 국내 제공자의 공개 평가(Kor-IR 등)는 질의 → 문서 검색 과제라 기사끼리 견주는 대칭 과제와 순위가 그대로 옮겨지지 않는다. CLOVA Studio 임베딩의 공개 평가는 찾지 못했다

## 6. 코사인 분포와 사건 기준

- 모델마다 코사인 분포가 크게 다르다 — 다른 사건 쌍의 중앙값이 0.06(titan-embed-text-v2) ~ 0.83(e5-large)이다. 사건 기준(위 · 아래 · 저장 기준)은 모델별로 맞춰야 한다
- 배정 점수는 시각 감쇠 × (0.7 × 코사인 + 0.3 × 핵심 말 겹침)이다([event Spec](../specs/event.md#사건-배정)). 아래는 기사 쌍의 분포로 본 근사다(실제 코사인은 기사와 사건 중심 사이)
  - e5-small: 시각 차 0 · 핵심 말 겹침 0 인 무관한 사건도 약 0.7 × 0.82 = 0.57 로 아래 기준(0.55)을 넘는다 — 시간 창 안의 거의 모든 후보가 Jev 에 묻는 구간에 든다. 어려운 음성 p90(0.878)은 핵심 말 겹침 약 0.62 이상이면 위 기준(0.80)에 닿아 Jev 없이 붙는다
  - bge-m3: 같은 사건 중앙값 0.731 로는 위 기준에 거의 닿지 않아 대부분 Jev 에 묻는다
- 사건 병합도 같은 점수 · 기준을 사건 대 사건에 쓰므로 같은 영향을 받는다
- 방식 · 모델을 바꾸면 모델 버전이 바뀌어 새 기사는 새 사건을 연다

## 7. 한계

- 표본이 작고(139건 · 사건 38개) 이틀 남짓이다. 라벨러가 한 명이다
- 쌍 단위 지표다 — 사건 묶기 전체(핵심 말 · 시각 감쇠 · Jev 판정 · 병합)의 정확도는 재지 않았다. 사건 기준의 기본값과 함께 사건 라벨을 붙인 평가 세트로 다시 잰다
- 실행 비용은 한 호스트(x86-64, AVX-VNNI)의 한 번 측정이다
- 외부 API 의 단가 · 모델 목록 · 폐기 일정은 작성 시점의 값이다
