# 보안 · 개인정보 · 저작권

## 인증

v1은 **Google 로그인**과 **자체 로그인(이메일·비밀번호)**을 지원한다 ([ADR-0009](adr/0009-authentication-google-and-local.md)). v1에는 메일 발송이 없으므로 자체 로그인의 이메일은 **미인증 값**이다 ([ADR-0011](adr/0011-no-email-in-v1.md)).

### 공통

- 세션 쿠키: `HttpOnly`, `Secure`, `SameSite=Lax`. 세션은 Spring Session JDBC로 DB에 저장한다.
- 로그인에 성공하면 세션 ID를 새로 발급한다(세션 고정 방지).
- CSRF: Spring Security의 쿠키 기반 CSRF 토큰을 SPA가 헤더로 돌려보낸다.
- 같은 이메일로 Google 계정과 자체 계정이 따로 생길 수 있다. 자동으로 합치지 않고, 로그인한 상태에서 명시적으로 연결해야 한다(계정 탈취 방지).

### 자체 로그인

| 항목 | 정책 |
|---|---|
| 비밀번호 저장 | Argon2id 해시. 파라미터는 서버 사양에 맞춰 로그인 1회가 수백 ms 이내가 되도록 조정하고, 파라미터를 해시 문자열에 함께 저장한다 |
| 비밀번호 규칙 | 최소 10자, 최대 128자. 문자 종류 강제 규칙은 두지 않는다(NIST SP 800-63B 방향). 흔한 비밀번호 목록과 대조한다 |
| 이메일 | 로그인 식별자로만 쓰고 인증하지 않는다. 신원 근거나 계정 연결 근거로 쓰지 않는다 |
| 복구 코드 | 가입 직후 한 번 보여주는 무작위 코드(128비트 이상). 해시로만 저장. 복구 코드로 비밀번호를 재설정하면 기존 코드는 폐기하고 새 코드를 보여주며, 다른 세션을 모두 끊는다. 설정 화면에서 재발급할 수 있다(현재 비밀번호 확인 필요) |
| 계정 복구 | 복구 코드 또는 연결된 Google 계정으로만 가능하다. 둘 다 없으면 복구할 수 없음을 가입 화면에서 안내한다 |
| 계정 존재 노출 방지 | 로그인 실패와 복구 코드 실패에 같은 응답을 준다. 가입 시 이메일 중복은 메일 없이는 숨길 수 없으므로 "가입할 수 없는 이메일"이라는 일반 문구를 쓰고, 가입 요청 제한을 강하게 건다 |
| 무차별 대입 방어 | 계정별 연속 실패 시 지연을 점점 늘린다(잠금이 아니라 지연). IP별 요청 제한, 가입·로그인·복구 코드 사용에 Turnstile |
| 비밀번호 변경 | 현재 비밀번호 확인 필수. 변경 시 다른 세션 종료, 화면 내 알림 기록 |
| 2단계 인증 | v1 범위 밖. 이후 TOTP 추가 검토 |

### 외부 로그인 (OIDC, 기본 Google)

- 공급자는 설정으로 등록한다. 등록된 공급자만 로그인 버튼에 나오고, 0개도 허용된다. 셀프 호스팅은 아무 OIDC 공급자나 붙일 수 있다 ([ADR-0012](adr/0012-swappable-external-dependencies.md)).

- OpenID Connect를 쓴다. `sub`를 식별자로 쓰고, 이메일은 `email_verified=true`일 때만 신뢰한다.
- `state`와 `nonce`는 Spring Security 기본 처리를 따른다.

## 인가와 데이터 격리

- 화면 · API 요청의 사용자 데이터 조회는 세션의 `userId`로 범위를 제한한다. 요청 파라미터로 받은 사용자 ID를 신뢰하지 않는다.
- 사용자 범위가 없는 조회는 백그라운드 작업(다이제스트 일정 · 보존 정리 등) 전용 조회 모델에만 두고, 화면 · API 경로에서는 쓰지 않는다. 사용자 A로 사용자 B의 다이제스트·키·피드백·이슈(`storyline`)·관심사 히스토리·변화 리포트에 접근하는 테스트를 기본 테스트 세트에 포함한다.
- 운영자 기능(`/api/admin/**`)은 `ADMIN` 역할만 접근할 수 있다. 운영자도 사용자의 LLM 키 평문은 볼 수 없다.
- 계정 · 역할 인증 전까지는 운영자 토큰(서버 설정 하나)이 `ADMIN` 역할을 준다 — 화면이 `Authorization: Bearer` 로 보내고, 토큰을 설정하지 않은 인스턴스는 운영자 기능이 닫힌다. 토큰 형식 · 대조 · 거부 응답의 규칙은 [platform Spec "운영자 접근 통제"](specs/platform.md#운영자-접근-통제)에 있다([ADR-0043](adr/0043-admin-functions-guarded-by-env-bearer-token-until-account-roles.md)).
- 계정 · 역할 인증을 들이면 운영자 경로와 `ADMIN` 역할 판정은 그대로 두고 토큰 인증을 세션 인증으로 바꾼다. 쿠키 세션과 함께 CSRF 토큰(공통 절)을 켠다 — 그 전까지는 브라우저가 자동으로 붙이는 자격이 없어 CSRF 를 쓰지 않는다.

## BYOK 키 보관

**Envelope encryption**을 쓴다.

```
KEK (환경 비밀 값, 버전 관리)
 └─ 암호화 → DEK (키마다 무작위 생성, AES-256)
              └─ 암호화 → 사용자 API 키 (AES-256-GCM, AAD = user_id + provider)
```

- DB에는 `ciphertext`, `encrypted_dek`, `kek_version`, 끝 4자리 `key_hint`만 저장한다.
- AAD에 사용자 ID와 공급자를 묶어서, 암호문을 다른 사용자 행으로 옮겨도 복호화되지 않게 한다.
- 복호화는 `llm` 모듈 안에서 **LLM 호출 직전에만** 한다. 평문은 `SecretValue` 같은 래퍼 타입으로 다룬다. 이 타입은 `toString()`이 마스킹된 값을 반환하고 직렬화를 막는다.
- 키 등록 시 공급자에 가벼운 요청(모델 목록 조회 등)을 보내 유효성을 검증한다. 실패하면 저장하지 않는다.
- API 응답에서 키를 돌려주지 않는다. 화면에는 `sk-…abcd`처럼 힌트만 보여준다.
- 로그·예외 메시지·오류 추적 서비스에 키가 남지 않게 한다. HTTP 클라이언트의 요청 로깅에서 `Authorization`, `x-api-key` 헤더를 마스킹한다.
- KEK 교체: 새 KEK 버전을 추가하고 배치 작업으로 DEK를 다시 암호화한 뒤 이전 버전을 폐기한다.
- 사용자가 키를 삭제하면 행을 즉시 물리적으로 삭제한다.

## LLM 입력과 출력

- RSS 제목과 요약문은 **신뢰할 수 없는 입력**이다. 프롬프트에서 구획을 명확히 나누고, 기사 내용 안의 지시를 따르지 않도록 명시한다.
- LLM 출력은 데이터로 다룬다.
  - 출력 JSON을 스키마로 검증하고, 인용 ID는 후보 목록과 대조한다.
  - 링크는 DB에서 렌더링한다. LLM이 생성한 URL은 쓰지 않는다.
  - 종합문은 일반 텍스트(또는 제한된 마크다운)로 렌더링하고, `dangerouslySetInnerHTML`을 쓰지 않는다. 마크다운을 쓴다면 HTML을 허용하지 않는 렌더러와 링크 허용 목록을 쓴다.
- 자유 텍스트 관심사(`interest_text`)도 프롬프트에 들어가지만, 본인 키로 본인 다이제스트를 만드는 데만 쓰이므로 영향 범위가 본인에게 한정된다.

## 악용 방지

| 대상 | 대책 |
|---|---|
| 가입, 로그인, 복구 코드 사용 | Turnstile + 사용자·IP별 요청 제한 |
| 키 등록, 키 검증 | 사용자·IP별 요청 제한 (Cloudflare 규칙 + 애플리케이션 레벨) |
| 수동 다이제스트 재생성 | 사용자당 하루 N회 |
| 자유 텍스트 관심사 | 길이 제한 |
| 운영자 토큰 | 32자 이상 무작위 값으로 대입을 막는다. 대조는 상수 시간이고 요청 제한은 두지 않는다 |
| 운영자 비용 (Jev) | 사용자 행동과 무관하게 기사 수에만 비례한다. 사용자 피드 추가를 열 때 별도 상한이 필요하다 |

## 개인정보

- 수집 항목: 이메일, 표시 이름, 비밀번호 해시(자체 로그인) 또는 Google 식별자 / 관심 설정 / 관심 신호 이력(좋아요 · 싫어요 · 이슈 추적 · 구독 변경) / 다이제스트 · 이슈 · 변화 리포트 / 암호화된 LLM 키.
- 클릭 · 열람은 추적하지 않는다. 원문 링크는 서비스를 거치지 않고 원문 사이트로 바로 이동한다 ([ADR-0028](adr/0028-explicit-signals-and-interest-weighted-candidates.md)).
- v1에서는 이메일을 외부로 전달하지 않는다. 메일 발송을 도입하면 발송 서비스를 처리 위탁으로 개인정보처리방침에 명시한다.
- **외부 전송 고지**: 다이제스트를 생성할 때 사용자 프로필(구독 주제 · 지역 선호 · 자유 텍스트 관심사 · 원하는 분량), 진행 중인 이슈(제목 · 현재 상태 요약), 후보 기사 정보가, 변화 리포트를 생성할 때 그 기간의 이슈 변화 · 보도량 · 관심도 통계와 직전 리포트의 요약이 **사용자가 선택한 LLM 공급자**에게 전송된다(입력의 정본은 [pipeline.md](pipeline.md) §6 · §10). 키 등록 화면과 개인정보처리방침에 명시한다.
- 탈퇴: 즉시 비식별화하고, 30일 후 완전히 삭제한다. 이슈 · 관심 신호 이력 · 변화 리포트도 대상이다. 키는 탈퇴 즉시 삭제한다.
- 공개 전에 개인정보처리방침과 이용약관이 필요하다.

## 저작권과 소스 이용조건

- 화면과 외부 API에 노출하는 것은 **LLM 종합문, 기사 제목, 출처, 발행 시각, 원문 링크**로 한정한다. RSS 요약문 원문은 화면에 그대로 노출하지 않는다.
- 썸네일 이미지는 v1에서 표시하지 않는다(이미지 저작권). 나중에 쓰더라도 원본 URL을 그대로 참조하고 복사본을 저장하지 않는다.
- 소스(언론사)마다 RSS 이용조건 검토 날짜를 수집 프로필의 `termsReviewedAt` 에 기록한다 — 프리셋은 개발팀이 반드시 적고, 운영자 프로필은 운영자가 적는다. 검토일과 소스 활성화의 규칙은 [source Spec](specs/source.md#등록과-켜기)에 있다.
- 프리셋의 이용조건 검토는 개인 · 비상업 셀프 호스팅 인스턴스에서의 이용을 전제로 한다. 프리셋이 있는 소스를 실제로 켤지는 인스턴스 운영자가 자기 인스턴스의 이용 형태로 판단한다.
- 언론사가 삭제를 요청하면 해당 소스를 비활성화하고, 기사 요약문을 삭제할 수 있는 운영자 기능을 둔다. 요약문의 보존 기간은 [data-model.md](data-model.md) 보존 정책을 따른다 ([ADR-0029](adr/0029-indefinite-summary-retention-with-optional-deletion.md)).
- 사건 묶기 평가 세트(사건 라벨을 붙인 기사 표본)의 실제 기사 제목 · 요약문은 공개 저장소에 넣지 않는다. 저장소에는 텍스트가 없는 라벨과 결과 수치만 둔다 ([ADR-0026](adr/0026-event-clustering-with-local-embeddings-and-jev.md)).
- 네이버 검색 API를 쓰지 않기로 한 결정은 [ADR-0001](adr/0001-news-source-rss.md) 참고.
